# 학생 시험 진행 작업 안내

- APP-20261008-03: 시험 시작 클릭은 진행 중 미리 받기에 먼저 가입한 뒤 hover 가입을 해제한다. 같은 인증 세대·배정의 준비 요청을 공유하며 개별 취소가 다른 가입자를 끊지 않는다. 필요한 공용 키를 직접 검증하고 캐시 누락/손상만 복구한다. 공용 자료 48시간·미사용 준비 24시간·미접수 답 삭제 금지를 유지한다. 서버 준비 RPC는 권한/기존 응시/구형 문제 선택 확인 후 한 번 호출한다.

- APP-20260929-12 자율연습은 `student-word-practice` 흐름이다. `contracts/practice` → `domain/practice-plan` → `server/practice-source|service|http`와 private 연습2표를 사용한다. 정규 배정·응시·오답·큐·포인트는 읽기만 한다. 공통 QuizPlayer의 전송 객체만 바꾸며 기본 경로는 정규 시험이다.
- 연습 시작은 같은 요청의 완료 영수증부터 조회한다. 원천 변경409만 새 미리보기로 돌아가고 결과 불명503은 같은 요청키로 확인한다. 내역 커서는 학생에 묶으며 계정 변경409에서 기존 화면을 폐기한다. 선택 최대500개는 키 필터 한 번, 조건 전체는 최대10,000개이고 초과를 조용히 자르지 않는다. 연습표와 RPC는 서비스 전용이며 실제 학생 시험을 검사 목적으로 만들지 않는다.

- 답 선택은 마지막 유효 입력 뒤20ms가 지나면 한 번만 전송한다. 대기 중 선택 표시는 정오답 피드백과 분리한다.
- 첫 시작은 `contracts/preparation` → `server/attempt-preparation` → `ui/prepared-quiz-player` → `controller/use-prepared-quiz` → `api/prepare-attempt` 순서다. 실제 시험 화면을 비활성 상태로 먼저 배치한 뒤 ready 요청으로 시각을 시작한다. 준비 중에는 private 계획만 있으며 기존 응시·답·포인트를 만들지 않는다. 응답 유실 재확인은 같은 시작 영수증을 쓴다.
- 최초 준비와 다음 문항 준비를 혼동하지 않는다. 최초 준비는 시작 시각이 없는 동안만 표시한다. 이미 시작한 시험의 복구에서는 같은 시각을 보존한다. 확정 만료·자료 변경409는 같은 준비 재시도가 아니라 목록에서 다시 시작하도록 안내한다.
- 서버가 확인한 정오답은250ms 표시한다. 그 안에 서버 다음문항 준비와 예약시간이 모두 끝나면 효과 없이 전환한다. 늦을 때만 기존 문제 위 블러와 '다음 문제 준비 중'을 보여준다. 표시·준비 중 터치/키보드·수동음성은 차단한다. 다음 문제에 미리 답을 예약하지 않는다.
- 준비 대기는 실제 시작 가능한 시각까지이며 UI 효과를 위해 추가 시간을 기다리지 않는다. 느린 경로의 걷힘만80ms이고 동작 줄이기 설정에서는 효과가 없다. JS 실행 자체가 막히면 안내도 늦을 수 있다.
- 250ms 안에 서버 확인이 끝났고 남은 것이 250ms 이하의 시작 예약뿐이면 정오답과 입력 잠금을 유지한 채 예약 만료에 바로 전환한다. 이 짧은 확인 대기에 블러/걷힘을 붙이거나 RTT 추정치로 풀이 시간을 깎지 않는다. 응답 미도착·복구·긴 구형 예약은 기존 준비 표시를 쓴다.
- 저장 응답 유실은 서버의 같은 문항·단계에 실제 저장된 선택/정오답/시간초과가 확인된 경우만250ms 먼저 보여주고 복원한다. 미답을 추정해서 정오답으로 표시하지 않는다. 정상표시 후 복구에 중복표시하지 않는다.
- 제한시간을 늘리거나 서버 판정을 바꾸지 않는다. 마감 전에 예약한 답을 자동 무응답/만료 요청이 가로채지 않게 하며, 복구 표시 시간도 기존 남은 시간 계산에 포함한다.

- 시험 진행 전체는 `npm run map:flow -- student-quiz-attempt`로 확인한다.
- 답 제출·시간초과·만료는 학생 결과만 바꾸는 것이 아니라 이어지는 배정 큐를 물질화할 수 있다.
  관련 변경이면 `assignment-series`도 함께 확인한다.
- 판정, 점수, 오답, 재시험, 다음 시험 생성은 클라이언트 화면 결과를 신뢰하지 않고 server와 DB에서 검증한다.
- 진행 중 시험의 snapshot과 타이밍은 캐시하지 않는다. 재시도는 같은 답을 두 번 반영하지 않아야 한다.

## APP-20261002-03 신규 응시

- 신규 local_batch_v1은 public-local-client → client/flows/local-quiz-preparation|prefetch|store|screen → client/controllers/use-local-quiz-player-controller → client/components/local-quiz-player를 따른다. 기존 QuizPlayer/PreparedQuizPlayer는 구형 규격 전용이다.
- 새 규격은 답과 다음 위치의 IndexedDB 거래 완료 뒤 채점/전환하고 최초/재시험 회차 종료 때 고정 묶음1개만 제출한다. 풀이 중 시간 확인/답 저장 API0이다. 미확정 답은 자동 삭제하지 않는다.
- 공용 표시는48시간, 진행 중 원판은 보존한다. 음원은 원래 CDN 주소와 일반 HTTP캐시/미리 불러오기를 사용하며 별도 파일 보관·중계·오프라인 보장을 추가하지 않는다.
- 공용 정적 화면만 서비스워커에 보관한다. API/개인 HTML/RSC는 제외한다. 설치·손상 복구는 공용 독점 잠금, 풀이 중 공유 잠금으로 분리하며 동시에 여러 누락 파일의 복구는 합친다.
- server/local-quiz-http|service|protocol-query가 본인/기기와 종료 접수 계약을 소유한다. 학생 ID를 클라이언트 요청에서 받지 않는다. SQL은 M03/M04와 포인트를 한 거래로 확정한다. 위 매 답 전송·snapshot 캐시 금지·서버 다음 문항 예약 지침은 구형 응시에만 적용한다.

## APP-20261002-03 새 시작 일시 중지

20261003114247은 기본 정상인 private.quiz_start_control 한 행과 기존 신규 INSERT 검사만 연결한다. 운영자 UPDATE는 해당 설정행만 바꾸는 짧은 거래로 즉시 확정한 뒤 배포/보존 검사를 한다. 학생→설정 FOR SHARE 순서를 뒤집지 않는다. 기존 시작 재접수·구형/신규 재시험·늦은 답 수신은 유지한다. 앱 역할은 설정 접근권한0, 자율연습은 제어 대상 밖이다. 복구는 paused=false이며 기존 기기답 수신 기능을 제거하지 않는다.

## APP-20261005-01 화면과 재사용

- 목록 시작은 준비 모달 후 `/quiz-offline`을 `@detail/(...)quiz-offline`에서 가로챈다. 직접 주소는 기존 공용 화면이다. 목록 문서는 service worker 제어를 기다리지 않고 등록 worker의 READY/REPAIR 응답을 확인한다.
- 타이머 위 시험 중지 확인은 원래 제한시간을 멈추지 않는다. 미저장 선택/저장 중/피드백은 ESC와 바깥 클릭도 닫지 못한다. 목록 복귀 때 기기 답을 지우지 않는다.
- 새 피드백 간격250ms이며 기존 기기답100ms와 혼합 묶음도 서버가 받는다. 첫 문항 openedMs=0 및 제한시간 검사는 그대로다.
- 미리받기 `includeRefs`는 새 클라이언트의 성공 캐시 확인용 선택값이다. 구 클라이언트에는 기존 packet 모양만 반환한다. 만료/누락/계정변경/실패/취소는 성공으로 재사용하지 않는다.
