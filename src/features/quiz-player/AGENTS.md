# 학생 시험 진행 작업 안내

- APP-20260929-12 자율연습은 `student-word-practice` 흐름이다. `contracts/practice` → `domain/practice-plan` → `server/practice-source|service|http`와 private 연습2표를 사용한다. 정규 배정·응시·오답·큐·포인트는 읽기만 한다. 공통 QuizPlayer의 전송 객체만 바꾸며 기본 경로는 정규 시험이다.
- 연습 시작은 같은 요청의 완료 영수증부터 조회한다. 원천 변경409만 새 미리보기로 돌아가고 결과 불명503은 같은 요청키로 확인한다. 내역 커서는 학생에 묶으며 계정 변경409에서 기존 화면을 폐기한다. 선택 최대500개는 키 필터 한 번, 조건 전체는 최대10,000개이고 초과를 조용히 자르지 않는다. 연습표와 RPC는 서비스 전용이며 실제 학생 시험을 검사 목적으로 만들지 않는다.

- 답 선택은 마지막 유효 입력 뒤20ms가 지나면 한 번만 전송한다. 대기 중 선택 표시는 정오답 피드백과 분리한다.
- 첫 시작은 `contracts/preparation` → `server/attempt-preparation` → `ui/prepared-quiz-player` → `controller/use-prepared-quiz` → `api/prepare-attempt` 순서다. 실제 시험 화면을 비활성 상태로 먼저 배치한 뒤 ready 요청으로 시각을 시작한다. 준비 중에는 private 계획만 있으며 기존 응시·답·포인트를 만들지 않는다. 응답 유실 재확인은 같은 시작 영수증을 쓴다.
- 최초 준비와 다음 문항 준비를 혼동하지 않는다. 최초 준비는 시작 시각이 없는 동안만 표시한다. 이미 시작한 시험의 복구에서는 같은 시각을 보존한다. 확정 만료·자료 변경409는 같은 준비 재시도가 아니라 목록에서 다시 시작하도록 안내한다.
- 서버가 확인한 정오답은100ms 표시한다. 그 안에 서버 다음문항 준비와 예약시간이 모두 끝나면 효과 없이 전환한다. 늦을 때만 기존 문제 위 블러와 '다음 문제 준비 중'을 보여준다. 표시·준비 중 터치/키보드·수동음성은 차단한다. 다음 문제에 미리 답을 예약하지 않는다.
- 준비 대기는 실제 시작 가능한 시각까지이며 UI 효과를 위해 추가 시간을 기다리지 않는다. 느린 경로의 걷힘만80ms이고 동작 줄이기 설정에서는 효과가 없다. JS 실행 자체가 막히면 안내도 늦을 수 있다.
- 100ms 안에 서버 확인이 끝났고 남은 것이 100ms 이하의 시작 예약뿐이면 정오답과 입력 잠금을 유지한 채 예약 만료에 바로 전환한다. 이 짧은 확인 대기에 블러/걷힘을 붙이거나 RTT 추정치로 풀이 시간을 깎지 않는다. 응답 미도착·복구·긴 구형 예약은 기존 준비 표시를 쓴다.
- 저장 응답 유실은 서버의 같은 문항·단계에 실제 저장된 선택/정오답/시간초과가 확인된 경우만100ms 먼저 보여주고 복원한다. 미답을 추정해서 정오답으로 표시하지 않는다. 정상표시 후 복구에 중복표시하지 않는다.
- 제한시간을 늘리거나 서버 판정을 바꾸지 않는다. 마감 전에 예약한 답을 자동 무응답/만료 요청이 가로채지 않게 하며, 복구 표시 시간도 기존 남은 시간 계산에 포함한다.

- 시험 진행 전체는 `npm run map:flow -- student-quiz-attempt`로 확인한다.
- 답 제출·시간초과·만료는 학생 결과만 바꾸는 것이 아니라 이어지는 배정 큐를 물질화할 수 있다.
  관련 변경이면 `assignment-series`도 함께 확인한다.
- 판정, 점수, 오답, 재시험, 다음 시험 생성은 클라이언트 화면 결과를 신뢰하지 않고 server와 DB에서 검증한다.
- 진행 중 시험의 snapshot과 타이밍은 캐시하지 않는다. 재시도는 같은 답을 두 번 반영하지 않아야 한다.
