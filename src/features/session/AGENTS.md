# 학생 세션 기능 안내

- APP-20260929-09: 명시적 로그아웃은 `SessionLogoutBoundary`와 `useSessionLogout`를 거친다. 관리자/학생 보호 layout 바깥에서 본문·상세 모달을 먼저 제거한 뒤 기존 캐시 폐기·종료 요청을 실행한다. 이탈 확인 승인도 같은 경로다. 실패 때 보호 자료를 복원하거나 재로그인 페이지로 단정하지 않고 종료 재시도만 제공한다. 성공 시 `/`로 문서 이동 한 번이며 `router.refresh()`를 추가하지 않는다. 로그아웃 이벤트에 한정한 `flushSync` 순서는 느린 요청·비동기 이탈 승인 검사로 보호한다.

- APP-20260919-01: 아래 초기 도입 기록의 내역 표시 상한은 더 이상 현재 동작이 아니다. 내역도 동일 인증표의 마지막 성공 목록을 유지한다. 새로고침 버튼·주기 조회는 추가하지 않으며 실제 변경·본문/탭 복귀·계정/권한 확인은 유지한다.

- 먼저 `npm run map:feature -- session`으로 세션 갱신 진입점과 계약을 확인한다.
- 이 폴더는 브라우저의 세션 갱신 요청·상태 표시와 로그인 세대에 묶인 개인 목록의 공통 수명만 맡는다.
- APP-20260906-12: 학생/배정/내역의 동일한 15/60/120초·현재 인증 전 숨김·공동취소·복귀 ticket을 public-client로 재사용한다. 저장소 인스턴스는 기능/사용자마다 분리하며 DTO/필터/포인트/DB버전은 각 기능 adapter가 맡는다. 이 범위 확대는 서버 권한 판단을 Client로 옮기는 것이 아니다.
- APP-20260907-01에서 배정 작성에 채택하고 APP-20260908-02에서 학생 관리에도 적용: `retainActiveSnapshot`으로 같은 현재 ticket의 마지막 성공 자료를 60초 이후에도 유지한다. 60초는 신선도 안내이며 주기 조회를 추가하지 않는다. 성공 자료와 성공 ticket을 함께 보관하고 실패한 요청의 ticket으로 바꾸지 않는다. 실제 본문 이동·복귀·계정·세대 변경과 현재 401/403은 기존 숨김/폐기, 내역의 기본 표시 상한은 유지한다.
- 쿠키 수명·권한·학생 식별은 `src/lib/auth`와 `src/lib/supabase` 경계에서 처리하며 Client에 비밀 값을 노출하지 않는다.
- APP-20260908-02: 보호 layout의 `children` 슬롯을 안정적인 문자열로 비교하여 ticket과 요청 취소를 함께 판단한다. `@detail` 왕복은 배경 목록 이동이 아니다. 실제 본문 이동·탭 복귀·계정·변경 신호의 재인증은 유지한다. 만료 뒤 재조회 대기에는 옛 오류 대신 로딩을 표시한다.

## APP-20261002-03 기기 답 보존 경계

- student-private-cache-events의 지속 계정 세대는 새로고침·탭 사이의 개인 화면 숨김에 사용한다. 개인 답의 자동 삭제 신호가 아니다.
- 신규 공용 시험 화면은 보호 layout의 주기 세션/알림 갱신을 마운트하지 않는다. 관측한 계정 전환은 즉시 가리고 서버 제출/재인증에서 현재 학생 권한을 확인한다. 오프라인 중 서버 철회는 즉시 관측할 수 없다는 한계를 기록한다.
