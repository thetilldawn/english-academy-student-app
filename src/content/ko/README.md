# 한국어 UI 문구 카탈로그

화면의 정적 제목·라벨·도움말은 페이지와 컴포넌트별 TypeScript 객체에서
관리합니다. JSON은 주석을 지원하지 않으므로 `as const` 객체를 사용합니다.

- 키 위의 주석은 실제 화면 위치입니다.
- 문자열 값만 바꾸면 해당 값을 불러오는 화면에 반영됩니다.
- 오류 코드, 서버 검증 메시지, 감사 로그처럼 동작 계약에 속하는 문구는 이
  폴더로 옮기지 않습니다.
  이는 원문을 그대로 화면에 보여주라는 뜻이 아닙니다. 서버/통신 실패 종류는 계약으로 유지하고,
  화면에는 검토된 쉬운 한국어 문구를 연결합니다. 알 수 없는 오류에도 안전한 기본 안내를 사용합니다.
- 새 문구는 가장 가까운 페이지 파일에 추가하고 컴포넌트에서 직접 문자열을
  중복 작성하지 않습니다.

## 파일 구분

- `common.ts`: 여러 화면에서 함께 쓰는 문구
- `admin-shell.ts`: 관리자 브랜드·내비게이션·로그인
- `admin-overview.ts`: 관리자 Overview
- `admin-students.ts`: 학생 관리와 학생 상세
- `admin-learning.ts`: 학습 관리와 각 배정 모달
- `admin-history.ts`: 내역 목록과 상세 모달
- `student-app.ts`: 학생 로그인·시험 목록·응시 화면
- `notifications.ts`: 학생·관리자 일회성 알림
- `../format.ts`: `{count}` 같은 자리표시자를 실제 값으로 바꾸는 함수

문구를 바꿀 때 키 이름과 객체 구조는 유지하고 따옴표 안의 값만 수정합니다.

## 오류·빈 상태 문구

- [개발 기준 3절](../../../docs/개발_지시서와_검증_기록.md)의 상태 판정·쉬운 문구·복구 기준을 따릅니다.
- 미입력/미선택, 정상 조회 0건, 통신/서버 실패, 없는 페이지(404)를 구분합니다. `없음`이나 `검토 중`으로 실패를 숨기지 않습니다.
- 무엇이 안 됐는지와 다음 행동을 짧게 설명합니다. 개발 용어·영어 오류 원문·확인하지 못한 원인을 표시하지 않습니다.
- 같은 의미의 문구는 재사용하되 서로 다른 업무 상태를 하나의 문구로 합치지 않습니다.
- 기능 지시서에 문구 키와 실제 표시 예·복구 행동·검사 T번호를 연결합니다. 문구 검사(ui-copy)와 상태/복구 검사(error-ui)를 함께 기록합니다.
