# 공용 UI 작업 안내

## 이 폴더에 두는 것

- `primitives`: 버튼·입력·대화상자처럼 업무 기능을 모르는 가장 작은 UI다.
- `patterns`: 여러 기능에서 같은 의미와 동작으로 반복되는 UI 묶음이다.
- `patterns/filter-workspace`: 검색·필터 펼침·선택 조건·초기화 배치만 소유한다. 기능별 필터 값과 검색 요청은 각 기능이 유지한다.
- 색상·간격·상태·접근성 규칙은 기존 공용 부품을 먼저 고치고 기능 화면에서 다시 만들지 않는다.
- APP-20260908-03: `NumericInput`은 문자열 편집/공백/선행0/휠값 변경 방지만 소유한다. 업무상 범위·서버 전송 차단은 기능의 domain/application이 맡는다.
- 비활성 이유는 Tabs→HelpTip으로 호버·초점·터치에서 제공한다. `aria-disabled` 버튼은 설명만 열고 선택 콜백을 실행하지 않는다.
- Confirmation은 한 번의 승인/취소만 돌려준다. 소유 대상 변경·종료는 취소이며, 기능이 승인 뒤 대상/버전을 재확인하고 실제 요청을 보낸다. 승인 후 Promise 재개 시점의 수명 검사는 생략하지 않는다.
- Dialog는 공통 어두운 backdrop+3px 흐림, 모바일 compact 폭, 최상위 Escape·스크롤 잠금·초점 복귀를 소유한다. 확인창 취소 초점은 부모 초점 저장 뒤 effect에서 옮긴다.

## 이 폴더에 두지 않는 것

- 학생, 배정, 시험, 오답처럼 특정 기능의 자료 형태나 업무 판단
- API 호출, Server Action, Supabase 접근, 캐시 무효화
- 특정 페이지에서만 쓰는 상태 제어 hook

## 변경할 때 확인할 범위

1. `rg`로 모든 사용처를 찾는다.
2. 모바일·태블릿·PC와 밝은 화면·어두운 화면에서 달라지는 상태를 확인한다.
3. 키보드 focus, `aria-*`, 오류·비활성·loading 상태를 확인한다.
4. 공용 계약 테스트와 실제 사용 기능의 대표 테스트를 함께 실행한다.
5. 기능 전용 판단이 필요해지면 공용 부품에 조건을 늘리지 말고 해당 `src/features/<기능>`에서 조합한다.

이 폴더의 기본 소유자는 `shared-ui`이며, 변경 영향 검사는 `architecture/기능_소유권.json`의
관련 기능 흐름과 사용처를 함께 표시해야 한다.
직접 등록된 공용 UI와 소유 디렉터리는 `npm run map:owner -- shared-ui`로 출력한다.
