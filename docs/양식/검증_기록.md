- 작업 번호 / 지시서 / JSON:

- 입력 묶음: fingerprint 명령 결과의 관련 코드·테스트·설정 해시. verification 자체는 제외:
- 자료/계정: 가짜·테스트 학생 여부, 변경 허용 범위. 토큰·비밀번호·실제 개인정보 기록 금지:

## 필수 위험 검토

- 잘못된 입력, 권한 없음/만료/다른 학생, 직접 API 접근, 자료·정답 노출:
- 초기 대기/갱신/미입력·미선택/정상 빈 결과/조회 실패/저장 실패/404/예외와 안전한 복구·식별번호:
- 중복 제출·재시도·취소·늦은 응답·동시 변경·입력 보존:
- 캐시 사용자 격리·저장 후 갱신·로그아웃/전환 폐기·첫 진입/재방문 측정:
- 모바일/PC, 키보드·focus·모달 직접 접근/뒤로가기, 음성·타이밍 실확인:
- 해당 없는 항목은 이유와 지시서 영향 판단에 연결. 필수 요구 제외는 D번호 필요:

## 상태·쉬운 문구 실행 근거 — 원요구 4번

| R/T번호·검사 주제 | 발생 조건·현재 요청 | 실제 표시 위치·부품·문구·버튼 | 나타나면 안 되는 표시 | 입력 보존·복구 결과 | 근거·통과/실패/미실행 |
|---|---|---|---|---|---|
| / error-ui, ui-copy | | | | | |

- 필수 입력 누락과 선택값 빈 입력을 구분했는가? 정상 0건/null과 필수 응답 누락·요청 실패를 구분했는가?
- 이전 0건 뒤 새 검색이 실패했을 때 실패와 `조건에 맞는 내역이 없습니다`가 함께 나오지 않는가?
- 없는 주소/대상(404), API 실패, 모달 직접 접근·새로고침을 각각 확인했는가?
- `Failed to fetch` 같은 원문·개발 용어·내부정보·정답은 표시되지 않는가? 확인 못한 원인을 단정하지 않는가?
- 실제 쉬운 한국어 문구가 무엇이 안 됐는지·다음 행동을 설명하는가? 문구 검토자와 검토 결과:
- 재시도 성공·저장 결과 확인·입력 보존·중복 제출 방지·키보드/focus·접근성 안내가 실제 작동하는가?
- 자동 누락 검사, 코드/컴포넌트 실행, 브라우저 확인, 사람 문구 검토를 서로 구분해 기록한다.
  문서·도구만 바꿨다면 실제 화면 검사는 `미실행/범위 밖`으로 적고 적용 완료로 표현하지 않는다.

## 실패 이력과 완료 판정

- 실패 시각 / 원인 / 보완 / 재검사 결과를 누적한다. 실패를 삭제하거나 통과로 바꾸지 않는다.
- 현재 코드와 다른 과거 실행은 당시 근거로 남기며 현재 완료에 재사용하지 않는다.
- 미검증/실환경 확인 필요 항목과 그 영향:
- 독립 리뷰 지적·조치·잔여 위험:
- 완료 관문 명령·결과, 실제 구현 경로/흐름, 문서 링크 검사:
- 배포/DB는 별도 명시 승인과 검증이 있는가? 해당 없으면 로컬 검증만 명시:

실패·건너뜀·미실행은 필수 검사 통과가 아니다. 해시만 같아도 실화면·보안의 완전성이 보장되지는 않는다.
