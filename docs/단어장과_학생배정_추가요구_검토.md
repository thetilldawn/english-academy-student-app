# 단어장과 학생 배정 추가 요구 검토

2026-09-21 · 사용자 추가 요구와 현재 코드 대조 · 구현 전 검토

입력은 단어장 개편 뒤 받은 두 차례 피드백과 현재 앱 코드다. 기존 배포 결과는 보존하고, 이번에 추가한 요구와 확인된 오류 경로를 구분한다. 이 문서는 실행 코드 수정, 실제 학생 오류의 원인 확정, 운영 반영 완료를 뜻하지 않는다. 상태와 작업 순서는 루트 작업 대장이 기준이다.

## 1. 사용자가 요청한 결과

| 번호 | 요구 | 완료 판단 |
|---|---|---|
| R1 | 학생에게 단어를 배정할 때 학교·학년·학기 조건을 먼저 선택해 두기 | 학생에서 배정 창을 열면 학생 조건이 표시되고 자료 찾기와 새 범위 구성에 전달된다. 다른 조건을 직접 선택할 수 있다. |
| R2 | 학생 이름·학교·학년 필수 입력 | 신규 등록과 정보 저장 모두 화면과 서버에서 검사한다. 부족한 항목 바로 아래에 안내하고 테두리로 표시한다. |
| R3 | 내역의 오답 단어 목록은 기본 접힘, 최신순 10개씩 더보기 | 접혀 있으면 오답 상세 목록을 요청하지 않는다. 펼칠 때 첫 10개, 더보기마다 다음 10개만 받는다. |
| R4 | 오답 시험이 막히는 문제 확인과 보완 | 사용자가 겪은 오류와 코드에서 확인한 차단 조건을 구분한다. 일부 출제 불가 항목 때문에 가능한 항목까지 이유 없이 막히지 않는다. |
| R5 | 나중에 학생이 본인 페이지에서 오답 목록 보기 | 목록의 자료 모양과 표시를 재사용할 수 있게 설계한다. 학생용 조회는 로그인한 본인으로 한정한다. 이번에 학생용 새 화면까지 임의로 만들지 않는다. |
| R6 | 전체 자료를 받지 않고 필요한 자료만 조회 | 템플릿 목록, 조건에 맞는 범위, 펼친 단어 목록을 각각 조회한다. 첫 목록에 모든 단어와 과거 버전을 넣지 않는다. |
| R7 | 템플릿을 저장한 필터 조건으로 관리하고 삭제 가능하게 하기 | 조건을 저장·수정·삭제할 수 있다. 시험을 만들 때 실제 범위와 순서를 확정하며 과거 시험은 그대로 남는다. |
| R8 | 출제 순서를 오름차순·내림차순·무작위로 선택 | 배정·미리보기·저장·시험에서 같은 순서가 적용되고 다시 열어도 선택값이 보존된다. 정렬 기준에 관한 기존 질문의 답변은 별도 확인한다. |
| R9 | 필요한 수능 유형을 실제로 등록 | 원본 보유, 사전 연결, 앱 등록, 출제 가능 여부를 각각 확인한다. 화면의 ‘미등록’ 안내만으로 자료 추가 요청을 완료 처리하지 않는다. |

## 2. 학생 조건을 적용하는 방법

### 확인된 현재 동작

- 학교·학년은 배정 준비 단계까지 이미 전달된다. 자료 선택 창은 이 정보를 받지 않고 열 때 전체 조건으로 초기화한다.
- 학생 등록과 정보 수정은 이름만 필수다. 학교·학년은 빈 값으로 저장할 수 있다.
- 학기는 현재 학생 프로필의 필드가 아니다. 학교 일정의 개별 시험과 자료 분류에는 학기가 있다.
- 학교 필터는 공통자료를 함께 보여주지만, ‘직전 대비’ 자료 종류를 선택하면 공통자료를 제외하는 예외가 있다. 학년·학기 조건도 정확히 일치하는 자료만 남긴다. 그대로 자동 적용하면 분류 없는 공통자료까지 숨길 수 있다.

### 수정 지시와 권장 기본값

1. 한 학생에서 시작하면 그 학생의 학교·학년을 기본 선택한다. 자동 선택된 조건을 화면에서 확인하고 변경할 수 있어야 한다.
2. 선택한 대비 시험에 학기가 있으면 그 학기를 사용한다. 시험을 지정하지 않은 경우에는 현재 학기를 제안하는 방안을 권장한다. 학생 프로필에서 학기를 받아왔다고 표시하지 않는다. 날짜로 학기를 정하는 정확한 기준은 구현 전 확정한다.
3. 학교·학년·학기는 학습 대상의 조건이며 원자료의 시행 연도·문제 학년과 구별한다. 고2 학생의 직전 대비에 고3 기출을 넣을 수 있어야 한다. 자료 종류에 의미 없는 학기 조건을 일괄 적용하지 않는다.
4. 공통자료와 해당 학교 자료를 함께 찾을 수 있게 한다. 범위의 분류 누락을 특정 학기나 학년으로 추정하지 않는다.
5. 같은 학생의 창을 다시 열 때 선생님이 바꾼 선택을 매번 덮어쓰지 않는다. 학생이 바뀌면 이전 학생의 조건과 늦게 도착한 응답을 적용하지 않는다.
6. 여러 학생을 함께 배정할 때는 모두 같은 학교·학년인 항목만 자동 선택하는 방안을 권장한다. 서로 다르면 해당 조건은 ‘전체’로 둔다. 기존 학년 불일치 포함·제외 확인은 유지한다.
7. 이름·학교·학년 필수 검사는 신규 등록과 프로필 저장에 함께 적용한다. 예: ‘이름을 입력해 주세요’, ‘학교를 입력해 주세요’, ‘학년을 선택해 주세요’. 기존 학교 검색과 학교급별 학년 선택을 재사용한다.
8. 기존 학생 중 학교·학년이 없는 경우에는 누락 안내와 정보 보완 진입을 제공하는 방안을 권장한다. 값을 임의로 채우지 않는다. 기존 학생의 배정까지 막을지는 신규 등록 필수화와 다른 결정이며 아직 정하지 않았다.

## 3. 오답 목록과 시험을 구별해서 보완

### 확인된 현재 동작

| 현재 동작 | 사용자에게 미치는 영향 | 근거 |
|---|---|---|
| 학생 내역 진입과 동시에 오답 조회 활성화 | 목록을 펼치지 않아도 조회 비용 발생 | [내역 패널](../src/features/students/ui/panels/student-history-panel.tsx:58) |
| 오답·대기열을 500개씩 끝까지 조회하고 관련 배정 상태도 조회 | 표시할 분량과 무관하게 전체 자료를 읽음 | [오답 조회](../src/lib/services/wrong-word-query.ts:141) |
| 필터 결과 전체를 표시 | 내역이 길어지고 10개 더보기가 없음 | [오답 패널](../src/features/students/ui/panels/student-wrong-word-panel.tsx:407) |
| 미해결 → 반복 오답 → 최근 오답 순서 | 사용자가 기대한 최신순과 다름 | [정렬 계산](../src/lib/admin/wrong-word-history.ts:393) |
| ‘다음 시험에 추가’는 대기열에만 추가 | 버튼을 눌러도 독립된 오답 시험은 생성되지 않음 | [오답 명령](../src/lib/services/wrong-word-command.ts:30) |
| 일부 후보의 출제 연결 또는 필요한 방향이 없으면 선택 전체 거절 | 정상 후보도 함께 시험 준비가 막힐 수 있음 | [시험 준비 검사](../src/lib/services/direct-review-preparation-service.ts:113) |

기존 가짜 자료 검사에서 정상 후보 2개와 필요한 방향이 빠진 후보 1개가 함께 있을 때 전체가 거절되는 사례를 확인했다. 관련 기존 3파일 16검사가 통과했다. 검사 파일: [출제 후보 검증](../src/lib/services/reviewed-direct-review-selection.test.ts:23).

이것만으로 실제 학생의 오류 원인이 과거 오답의 혼합이라고 확정할 수 없다. 현재 독립 오답 후보 조회에도 해결한 단어와 진행 중 배정의 겹침을 제외하는 규칙이 있다. 실제 오류 학생과 버튼·안내 문구는 사용자에게 질문해 둔 상태다.

### 수정 지시

1. 학생 내역의 오답 **단어 목록만** 기본 접힘으로 둔다. 접힌 상태에서는 단어 본문을 가져오지 않는다. 전체 오답 수가 필요하다면 목록 전체 대신 집계만 조회한다.
2. 펼치면 최근에 틀린 시각 기준 10개를 조회한다. 마지막 시각이 같은 항목도 안정적으로 이어지도록 고유 식별자를 함께 사용한다.
3. ‘10개 더보기’는 다음 묶음을 서버에서 받는다. 전부 내려받아 화면에서 10개만 자르는 방식으로 바꾸지 않는다.
4. 동일 단어의 반복 기록은 기존 식별 기준으로 계산한 뒤 페이지를 나눈다. 표제어가 같다는 이유로 다른 뜻·출처를 합치거나 페이지별로 오답 횟수를 계산하지 않는다.
5. 단어·뜻·최근 오답일·오답 횟수·현재 상태와 필요한 출처를 간단히 표시한다. 대기 중, 시험 배정됨, 해결됨을 구별하고 조회 결과를 실제 출제 가능 목록과 동일시하지 않는다.
6. 조건 또는 학생 변경 시 이전 페이지와 더보기 기준을 버린다. 더보기 실패는 기존 표시를 보존하고 그 요청만 다시 시도한다. 인증이 거절되면 개인 자료를 숨긴다.
7. 출제 가능한 단어와 불가능한 단어의 이유·개수를 미리 보여주는 방안을 권장한다. 제외될 항목을 숨기지 않고, 사용할 범위를 선생님이 확인한 뒤 출제한다. 자동으로 정상 후보만 골라 다른 시험을 만들어 버리지 않는다.
8. 필요한 출제 방향·선택지 수·동시 배정 겹침 등의 검사는 유지한다. 연결되지 않은 옛 단어를 임의의 사전 항목으로 붙이지 않는다. 저장 직전에 다시 검사하고 미리보기와 달라졌으면 재확인을 안내한다.
9. ‘다음 시험에 추가’와 ‘오답 시험 배정’은 실제 행동이 구별되는 문구와 결과 안내를 사용한다. 대기열 추가를 시험 생성 완료로 표시하지 않는다.
10. 학생용 후속 화면은 같은 목록 자료 모양과 표시를 사용하되, 본인 로그인에서 학생 대상을 결정하는 별도 조회 경로를 둔다. 현재 관리자 API를 학생에게 그대로 열지 않는다.

## 4. 앞선 단어장 요구도 함께 보존

### 필요한 자료만 조회

현재 단어장 창은 `list_vocabulary_library_v1`으로 전체 범위의 단어 정보와 템플릿의 과거 버전을 함께 받는다. 클라이언트에서 필터링하므로 응답을 나눠 전송하는 것만으로는 필요한 자료만 조회하는 방식이 되지 않는다.

- 첫 화면: 템플릿 이름·자동 태그·조건 요약만 한 페이지.
- 조건 선택: 맞는 범위의 요약·개수만 조회.
- 단어 목록 펼침: 해당 범위의 단어를 한 페이지씩 조회.
- 템플릿 열기: 선택한 템플릿의 현재 조건만 조회. 과거 버전은 요청할 때 조회.
- 시험 만들기: 서버가 조건을 해석해 실제 포함 범위·단어·순서를 확정하고 저장.

근거: [전체 목록 조회](../src/features/wordbook-compositions/server/queries/library-catalog.ts), [응답 계약](../src/features/wordbook-compositions/contracts/library.ts), [전체 조회 함수](../supabase/migrations/20260919212837_add_vocabulary_library_templates.sql:417).

### 필터로 저장하는 템플릿과 삭제

템플릿의 본체는 다시 사용할 조건이다. 실제 시험은 생성 시점의 범위를 보관한다. 따라서 자료가 추가돼도 과거에 배정한 시험이 자동으로 바뀌면 안 된다.

삭제는 템플릿 목록에서 해당 구성을 제거하는 행동으로 설계한다. 원자료·사전·이미 만든 단어장·학생 시험을 함께 삭제하지 않는다. 저장된 조건이 아닌 직접 지정 범위와 제외 단어가 있는 기존 템플릿은 정확한 범위를 보존해 호환한다. 과거 필터만 읽어 기존 선택을 임의로 재구성하지 않는다.

### 출제 순서

내부에는 오름차순·내림차순·무작위 값이 있지만, 현재 화면은 ‘순서대로·무작위’만 표시한다. 비무작위 선택을 오름차순으로 바꾸는 경로도 있어 내림차순을 제대로 유지하지 못한다.

근거: [출제 설정](../src/lib/admin/assignment-settings.ts:1), [화면 선택](../src/features/assignments/ui/exam-condition-fields.tsx:25), [설정 전달](../src/features/assignments/ui/assignment-settings-fields.tsx:102).

원자료의 단어·문제 순서를 정방향/역방향으로 사용할지, 영어 A→Z/Z→A를 사용할지는 앞서 질문한 답변을 확인한다. 두 의미를 같은 옵션으로 혼용하지 않는다.

### 수능 자료 추가

직전 운영 확인에서 수능은 2025년 시행·2026학년도 장문 2범위, 포함 104개였다. 전체 유형 등록은 끝나지 않았다. 로컬에는 2024년 시행 후보 886행/25묶음과 2025년 시행 후보 827행/25묶음이 있으며, 이는 고유 단어 수나 출제 가능 수가 아니다.

기존 후보와 검토 기록에서 필요한 유형의 원문·뜻·품사·사전 연결·실제 등록을 이어 확인해야 한다. 이번 화면 분석을 위해 전체 원자료를 다시 추출하지 않는다. 2026년 시행으로 표시된 후보는 실제 시행 전 자료이므로 내용을 확인하기 전 공식 수능으로 등록하지 않는다.

근거: [앞선 수능 원자료 대조](verification/APP-20260921-01.md:68), 운영 수치는 직전 반영 때의 확인값이며 이번 검토에서 운영 DB를 재조회하지 않았다.

## 5. 검사와 실행 단계

| 검사 | 기대 결과 |
|---|---|
| T1 학생별 기본 조건 | 한 학생의 학교·학년 자동 선택, 직접 변경, 재열기 보존, 학생 전환 시 이전 조건 제거. 확정한 학기 기준·시험 미지정·학기 정보 없음, 같은 학교/학년의 일괄배정과 서로 다른 학생의 일괄배정 대조 |
| T2 자료 혼합 | 공통자료와 대상 학교 자료 검색 가능, 다른 학년 기출 직접 선택 가능, 자료 종류에 불필요한 학기 조건 미적용 |
| T3 필수 입력 | 신규·수정의 이름·학교·학년 누락을 각각 화면/서버에서 차단, 해당 입력의 안내와 오류 표시 확인 |
| T4 실제 조회 분량 | 오답 목록 접힘 0회, 펼침 첫 10개, 더보기 다음 10개, 목록용 전체 순회 없음 |
| T5 페이지 정확성 | 최근 오답순, 동일 시각·반복 오답·마지막 페이지·0건·조회 실패·학생 변경·늦은 응답을 구별 |
| T6 오답 시험 | 정상 후보만 있는 경우, 정상+불가 혼합, 모두 불가, 해결/진행 중 겹침을 구분. 사용자 확인 범위와 실제 저장 범위 일치 |
| T7 템플릿 | 조건 변경 즉시 반영, 목록과 상세 별도 조회, 삭제 뒤 기존 시험/단어장 보존, 과거 직접 선택 범위 호환 |
| T8 출제 순서 | 선택한 정렬을 일반·일괄·오답·기존 설정 불러오기에서 보존하고 실제 문항 순서와 대조 |
| T9 학생용 후속 계약 | 관리자와 본인 조회 권한 분리, 다른 학생 조회 차단, 개인 목록의 공유 캐시 사용 없음 |
| T10 수능 등록 | 필요한 연도·유형별 실제 범위, 보류 사유, 사전 연결과 출제 가능 수 대조. 원행 수를 단어 수로 보고하지 않음 |

기존 분석 두 건과 문서 대조를 읽기 전용으로 병행했다. 독립 검토에서 직전 대비의 공통자료 제외 예외와 학기·일괄배정 검사 누락을 찾아 문서에 반영했다. 파일 작성은 메인 담당자가 수행했다. 확인한 범위는 현재 코드와 기존 가짜 검사이며, 이번 운영 조회·학생 기록 변경·실제 배정·시험 시작·배포는 없다.

실행 작업은 결과별로 학생 조건/필수 정보, 오답 조회/출제, 단어장 조회/템플릿/정렬, 수능 자료 등록을 구분해 지시한다. 이전 완료 결과를 다시 진행 중으로 바꾸거나 자료 등록 요구를 UI 작업의 부가 안내로 처리하지 않는다.

구현 전에 남은 판단은 정렬 기준, 학기 기본값의 기준, 기존 학생 정보 누락 시 배정 제한 여부, 출제 불가 후보를 확인하고 제외하는 동작이다. 이 중 사용자가 이미 명시한 이름·학교·학년 필수, 자동 필터, 기본 접힘, 최신순 10개 더보기는 재질문 대상이 아니다. 정확한 오류 문구가 없다는 이유로 목록 구조의 확인된 문제까지 미확인으로 돌리지 않는다.

후속 작업은 이 검토에서 필요한 결정만 정리한 뒤 각 작업의 요구·결정·검사 번호를 정식 구현 기록에 연결한다. 이번 문서를 구현 완료 근거로 사용하지 않는다.
