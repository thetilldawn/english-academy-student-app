# R3 관리자 개요·내역 읽기 모델

## 1. 목적과 범위

관리자 개요와 전체 내역이 시험 배정·응시·숨김 자료를 끝까지 읽은 뒤 화면에서 10개씩 자르는
구조를 목적형 읽기 모델로 바꾼다. 첫 화면은 한 DB 문장에서 공통 기준 시각, 상태별 전체 개수,
상태별 최대 11건만 받고, 화면에는 10건만 표시한다. 11번째 행은 다음 페이지 존재 여부 확인에만
사용한다.

이번 범위는 다음 세 경로다.

- 관리자 개요 `/admin`
- 관리자 전체 내역 `/admin/results`
- 관리자 내역 상세 `/admin/results/[entryKey]`와 가로채기 상세

학생 관리·배정 준비·수정 자료가 아직 사용하는 기존 전체 이력 묶음은 R4·R5 전환 전까지 보존한다.
시험 수정 창 전체 자료의 지연 로딩도 R5 범위이며 이번 작업에 섞지 않는다. Production과 실제 학생은
대상이 아니다.

## 2. Next.js 경계

- 첫 자료는 Server Component가 기능 전용 서버 조회를 직접 호출한다. 자체 Route Handler로
  HTTP 요청하지 않는다.
- 브라우저 Route Handler는 사용자가 검색·상태를 바꾸거나 `10개 더보기`를 누른 뒤의 읽기에만
  사용한다.
- Client Component에는 화면에 표시할 10건, 전체 개수, 다음 커서만 전달한다. 전체 이력 배열은
  전달하지 않는다.
- 검색·상태 선택·접기·더보기만 작은 Client 영역이 소유한다. 상태 판정·검색·개수·페이지 경계는
  서버와 DB가 소유한다.
- 개인 시험 이력은 요청 사이 공유 캐시, `use cache`, 태그 캐시를 사용하지 않는다. 기존 React
  `cache()`는 같은 RSC 요청 안의 인증 중복 제거에만 쓴다.
- `cookies()`를 읽는 보호 구역은 이미 동적 렌더링된다. `force-dynamic`을 중복 선언하지 않는다.
- Cache Components는 공개 단어장·범위 자료가 개인 자료와 물리적으로 분리된 뒤 R8 canary에서만
  켠다.

## 3. 읽기 모델 계약

첫 읽기 RPC 한 번이 공통 원본을 한 번만 결합해 다음을 반환한다.

- DB `statement_timestamp()` 기준 시각
- 개요: `응시 전 / 확인 필요 / 완료`의 개수와 각 최대 11건
- 전체 내역: `응시 전 / 확인 필요 / 완료 / 취소·삭제`의 개수와 각 최대 11건
- 상태 필터를 고른 경우: 해당 필터의 전체 개수와 최신 최대 11건

기본 구역과 상태 필터는 서로 다른 축으로 유지한다. 예를 들어 재시험 후 미통과는 기본 구역에서는
`확인 필요`, 상태 필터에서는 `재시험`이다. SQL이 화면 문구를 직접 소유하지 않고 표준 상태·구역을
반환하며 화면 조합부가 한국어 제목을 고른다.

다음 페이지는 다음 복합 커서를 사용한다.

```text
version + snapshotAt + current/all 범위 + 구역 + 검색조건 지문
+ effectiveAt + 고유 entryKey
```

- 정렬은 `effectiveAt 내림차순 + entryKey 오름차순`이다.
- 다음 조건은 기준 시각보다 과거이거나, 같은 시각에서 entryKey가 더 큰 행이다.
- 커서는 base64url JSON으로 감추고 검색어 원문은 넣지 않는다.
- 검색어·상태·현재/전체 범위·구역이 달라지면 지문 불일치로 커서를 거부한다.
- 커서는 페이지 연결 계약이지 권한 토큰이 아니다. 활성 관리자 권한은 매 요청에서 다시 확인한다. 현재
  커서는 HMAC 서명을 하지 않으므로 관리자가 값을 임의 변경하면 요청 거부 또는 페이지 중복·누락은
  가능하지만, 다른 사용자 자료나 추가 권한을 얻을 수는 없다.
- 새 배정과 새 응시는 원본 생성 시각이 `snapshotAt` 이후면 제외한다.
- 마감·완료·취소·삭제·숨김의 상태 판정도 가능한 범위에서 같은 `snapshotAt`을 기준으로 한다.

현재 표에는 학생 이름·학교·학년·시험 제목·마감·단원 편집값의 시간별 원본을 따로 남기지 않는다.
따라서 배정·응시 생명주기와 상태 경계는 고정되지만, 조회 도중 관리자가 표시값을 수정하면 다음
페이지에는 최신 문구가 보일 수 있다. 특히 검색 중 학생 이름·학교·학년이 바뀌면 검색 결과 행이
들어오거나 빠질 수 있다. 완전한 과거 화면 복제와 검색 결과 고정은 별도 감사 이력 표가 필요한 후속
범위이며, 이번 R3에서 거짓 스냅샷 자료를 만들지 않는다.

`현재 내역`은 숨김 처리된 행을 먼저 제외한 뒤 남은 응시 중 최신 한 건을 고른다. 따라서 최신 응시를
숨기면 같은 학생·시험의 이전에 보이던 응시가 다시 나타난다. 숨김은 학생·시험 전체를 감추는 기능이
아니라 선택한 내역 한 건만 관리자 목록에서 감추는 기능으로 고정한다.

상세 읽기는 `attempt ID` 또는 `(assignment ID, student ID)`를 직접 조건으로 사용한다. 오래된 배정
주소에 이미 응시가 생겼다면 최신 보이는 응시 한 건과 표준 주소를 반환해 redirect한다. 상세 요약
조회 함수는 전체 이력 묶음을 호출하지 않는다.
상세 요약과 응시·포인트 상세는 서로 다른 읽기에서 조합되므로, 조회 사이에 시험이 완료되면 아주 짧은
시간 동안 요약과 현재 상세 상태가 다를 수 있다. 상세는 현재값을 우선하고 다음 새로고침에서 요약을
맞춘다. 한 시각의 감사용 상세 화면은 이번 R3 범위가 아니다.

## 4. DB와 권한

- 물리 projection 표와 동기화 trigger는 만들지 않는다. 현재 규모에서는 한 문장 SQL projection이
  자료 중복·동기화 실패 위험이 더 작다.
- 공개 읽기 RPC는 `SECURITY INVOKER`, 빈 `search_path`, 활성 관리자 선확인, PUBLIC·anon 실행권한
  회수를 적용한다.
- core table RLS를 그대로 통과하는 로그인 사용자 client를 사용한다. 새 목록 읽기에 service-role을
  사용하지 않는다.
- 검색은 동적 SQL 없이 정규화한 인자를 `strpos(lower(search_text), lower(query))`로 비교한다.
- 첫 읽기에서만 exact count를 계산하고, 더보기에서는 count를 다시 계산하지 않는다.
- 인덱스는 함수 모양을 고정한 뒤 Preview 실행 계획으로 필요성이 확인될 때만 추가한다. 추측으로 큰
  covering index나 GIN을 넣지 않는다.
- 다음 페이지는 네트워크로 11건만 반환하지만 현재 projection은 후보 이력을 다시 분류한다. Preview의
  `EXPLAIN (ANALYZE, BUFFERS)`로 실제 비용을 확인하기 전에는 DB 비용까지 일정하다고 주장하지 않는다.

시간 제한 없는 응시 4건은 DB 만료 계산을 위해 `deadline_at='infinity'`를 정상 저장하고 있었고, 현재
개요 25건 중 1건이 `deadlineAt: "infinity"`로 반환됐다. 새 서버 계약이 이를 ISO 시각으로만 검사해
응답 전체를 거부한 것이 원인이었다. DB 원본과 만료 의미는 바꾸지 않고 기능 서버의 행 변환 경계에서
`infinity / -infinity`만 `마감 없음(null)`으로 정규화했다. 일반 ISO 시각과 `null` 검사는 그대로
유지한다. 목록·상세 전용 회귀검사 2건을 추가했고, 전체 317파일·1,717테스트, lint, typecheck,
구조 검사, Preview 설정 Next.js 16.2.12 build가 통과했다. 보정 코드 배포 뒤 같은 고정 Preview에서
개요·내역·더보기·검색·상태 필터·상세와 브라우저 오류를 다시 확인한다.
