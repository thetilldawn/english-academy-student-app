  기존 검색 적용 `0a43ba7`(원 기능 `2e710e3`)이다.

## 준비 상태 오류 보완

기존 문구는 유형이 허용 목록에 없으면 이유에 관계없이 `검토 중`이었다. 해당 서버 조회는
검토 진행 상황이 아니라 단어장 전체의 활성·승인 문항 수만 반환한다. 단어장 미선택도 같은
문구로 보였고, 자료가 있으면 사용할 수 있는 운영 유형에도 `Preview 전용`이 남아 있었다.

| 실제 상태 | 표시·동작 |
| --- | --- |
| 단어장 미선택 | 단어장 선택 안내; 영어 유형 선택 불가 |
| 선택 후 준비 정보 누락 | 정보 확인 실패와 다시 여는 방법 안내; 0개로 위장하지 않음 |
| 정상 조회·해당 유형 없음 | 배정 가능한 문항 없음 안내; 해당 유형만 선택 불가 |
| 활성·승인 문항 있음 | 해당 유형 선택 가능; 선택한 DAY의 실제 수량은 이후 미리보기에서 검증 |

- 기본 교재 뜻으로 되돌리는 안전 규칙·배정 계약·시험일 없는 1회 제한은 유지한다.
- 원자료 승인 상태를 바꾸거나 모든 문항을 임의 활성화하지 않는다. 새 정제·추출·문항 생성도 없다.

## 로컬 검증

- 실제 학생 행 클릭, 일괄 선택 후 준비, 학생 지정 주소의 세 진입에서 공용 검색창을 확인한다.
  HTTP와 Next.js 지연 모듈 로더만 가짜로 바꾸며 실제 controller·검색창·범위 UI는 사용한다.
- 검색 중 추가 조회 0, 확정한 단어장과 두 영어 유형 선택, 실제 준비 요청의 학생 ID를 검사한다.
- 서버 준비 조회는 단일·일괄에 같은 유형 정보를 전달하고 읽기 실패를 0개로 반환하지 않는다.
- 기존 SQL을 메모리 안 PostgreSQL에서 재실행해 심석 여섯 묶음 활성과 교정판 재실행을 검사한다.
  원격 DB·실제 학생·기존 배정에는 접근하지 않는다.
