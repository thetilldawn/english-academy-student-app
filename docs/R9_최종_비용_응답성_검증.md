DB 실행만으로 15~30초 지연을 설명할 수 없다. 현재 우선 조사 경로는 다음과 같다.

1. 모든 관리자 화면·API를 거치는 Proxy 인증과 `getClaims()` 대기 시간 계측
2. 보호 layout의 반복 인증과 RSC 화면 전송 구간을 request ID로 분리 계측
3. Supabase 네트워크 호출에 5~8초 종료 기준과 재시도 UI 추가
4. 내역·학생 상세의 큰 조회를 프로필/요약과 이력/오답 패널로 나눠 독립 표시
