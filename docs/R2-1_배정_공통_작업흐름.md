# R2-1 배정 공통 작업 흐름

- 작업일: 2026-08-28
- 첫 적용 흐름: 독립 오답 시험 배정
- 적용 환경: 로컬 코드·Preview DB·Vercel Preview
- 제외: 일반 범위 배정 전환, 기존 mixed 생성 복구, 시험 수정 정책, UI 재디자인, Production

## 1. 결과

독립 오답 시험의 입력 계산과 저장에서 중복되던 요청 수명주기를 `application` 계층으로 옮겼다.
화면 controller는 입력 상태와 화면 표시를 맡고, 요청 생성·응답 해석·의미 fingerprint·멱등키·
최신 Preview 판정·중복 저장 차단·오류 변환은 화면 밖에서 처리한다. 여러 흐름을 한 만능 hook으로
합치지 않았으며, 독립 오답은 자기 요청·응답 adapter를 사용한다.

현재 화면에서 사용하지 않는 일반·mixed 생성 경로는 이 작업으로 되살리지 않았다. 기존 일반
단일·일괄 배정과 수정 경로의 동작도 바꾸지 않았다.

## 2. 코드 경계

| 경계 | 책임 |
|---|---|
| domain | 제출 순간의 업무 검증, 의미가 같은 조건의 정규화 |
| flow adapter | 독립 오답 Preview·저장 요청 생성, 응답 해석, 409 복구 선언 |
| application | 최신 요청만 반영, 취소, 중복 저장 차단, 멱등키 예약, 오류 표준화 |
| controller | 입력 상태, 계산 중·오류·완료 상태, 충돌 뒤 화면 자료 갱신 |
| UI | 구간 표시, 오류 입력으로 이동, 버튼과 진행 상태 |
| server | 명령 시각 1회 확정, 완료 요청 재생, 현재 후보 재검증, DB 명령 호출 |
| DB | 새 요청의 생성 전·후 마감 최종 검사와 전체 거래 되돌리기 |

`src/features/assignments/application`은 React, JSX, 브라우저 전역, API 주소를 가져오지 못하도록 구조
검사로 잠갔다. 독립 오답 controller도 API 주소, 원시 `JSON.stringify(draft)`, 창을 연 시각을 직접
사용하지 못한다.

## 3. 요청 수명과 멱등성

- Preview는 입력 의미 fingerprint, 요청 ID, revision을 함께 비교해 가장 최근 응답만 반영한다.
- 타이머 정리와 `AbortController` 취소를 모두 수행한다. 서버가 취소 신호를 무시해도 이전 응답은
  화면에 반영하지 않는다.
- 저장은 한 제출 세션에서 한 요청만 실행한다. 같은 의미의 실패 재시도는 같은 멱등키를 쓰고,
  통과 점수·문제 순서 같은 실제 조건이 바뀌면 새 키를 만든다.
- 제출 세션은 controller의 `clock`이나 `transport`가 리렌더 중 바뀌어도 유지된다. 실행 객체가
  다시 만들어져도 동시 저장 잠금과 기존 멱등키 예약은 사라지지 않는다.
- 성공 응답을 client application에 별도로 캐시하지 않는다. 완료 결과 재생의 최종 기준은 서버·DB의
  멱등 기록이다.

## 4. 마감 시각 계약

1. 화면의 남은 상태 표시는 분 단위로 갱신한다.
2. 저장 버튼을 누르면 application 흐름이 그 순간의 시각으로 다시 검증한다.
3. Route Handler는 인증과 입력 해석 뒤 `Date.now()`를 정확히 한 번 읽어 명령 시각으로 전달한다.
4. 서버는 같은 멱등키의 완료 결과를 먼저 조회한다. 완료된 요청은 마감 뒤 재시도해도 기존 시험 ID를
   돌려준다.
5. 새 요청만 명령 시각으로 마감을 검사하고 현재 오답 후보를 다시 만든다.
6. DB는 완료 결과 재생 뒤, 실제 생성 전과 생성 후에 각각 `clock_timestamp()`로 마감을 검사한다.
   실패하면 요청 기록·오답 큐·시험·감사 기록을 모두 되돌린다.

Preview DB에는 `harden_current_wrong_review_deadline` migration을 한 파일로 적용했다. 로컬 파일은
`20260828174000`, Preview 이력은 `20260828084722`이며 파일 SHA-256은
`AC41BEE4E7E75A39EBA15DD215959973C91724AB8766528E50ECD3BC03EA3DA6`이다. 전체 `db push`는
사용하지 않았다.

원격 함수 readback은 완료 결과 반환이 마감 검사보다 앞이고, 새 요청 검사가 학생·큐 변경보다 앞이며,
생성 뒤 검사도 존재함을 확인했다. 함수는 `SECURITY DEFINER`, 빈 `search_path`, authenticated 실행,
anon 실행 금지 상태를 그대로 유지한다.

## 5. 충돌과 오류 표시

- Preview 또는 저장이 현재 오답 변경으로 409를 받으면 오답 요약과 Preview를 함께 다시 읽는다.
- 같은 Preview fingerprint의 자동 복구는 한 번만 실행해 반복 409가 무한 요청으로 이어지지 않는다.
- 서버 도착 사이에 마감된 422는 `fieldPath: "deadline"`을 보존한다. 화면은 짧은 `마감 확인` 표시와
  전체 안내 문구를 함께 보여 주고 실제 마감 입력으로 이동한다.
- 입력 위치가 없는 일시 오류는 이전 렌더의 오래된 입력으로 잘못 이동하지 않는다.
- Zod 내부 문구와 네트워크 예외 상세는 화면에 노출하지 않고 공통 오류 형식으로 바꾼다.

## 6. 검증

- R2-1 집중 검사: 7파일 57테스트 통과
- DB 최종 스키마 통합 검사: 1파일 31테스트 통과
- 전체 회귀: 297파일 1,581테스트 통과
- 구조 검사: 4파일 46테스트 통과
- lint, typecheck, Preview ref를 명시한 Next.js 16.2.12 build 통과
- Preview DB 적용 뒤 함수 순서·보안 속성·실행 권한 readback 통과
- 보안 advisor: ERROR 0, 기존 의도된 `SECURITY DEFINER` 안내 포함 INFO 44 / WARN 22
- 성능 advisor: ERROR 0 / INFO 70

화면 배치나 시각 디자인을 바꾼 작업이 아니므로 브라우저 시각 검사는 생략했고 인앱 브라우저는 열지
않았다. 가짜 학생·시험·응시 자료 쓰기도 없다. Production 앱·DB와 실제 학생은 변경하지 않았다.

## 7. 다음 시작점

R2-2에서 일반·예전 mixed·exact 오답 시험의 수정 가능 필드를 한 순수 정책표로 만든다. 특히 미래
공개 시험의 원래 공개 시각과 mixed 시험의 원래 scope·문제 snapshot·오답 queue ID를 보존한 채,
reducer·controller·UI·server가 같은 정책을 사용하도록 전환한다.
