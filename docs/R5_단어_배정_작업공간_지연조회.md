## 1. 이번 배치에서 분리한 경계

- 첫 화면: 기본 진입은 학생 첫 묶음만 Server Component에서 읽는다. `reviewDraft` 복구 주소로
  들어온 경우에만 해당 초안 요약 한 건을 추가로 읽는다.
- 학생 찾기: 검색·필터·다음 묶음은 학생 기능의 공개 Client 진입점과 `private, no-store` 조회를
  사용한다.
- 선택 바구니: 현재 페이지와 분리된 최소 학생 요약을 보존하고 최대 210명 경계를 적용한다.
- 필터 전체 선택: 보이는 행이 아니라 서버가 같은 필터의 전체 대상을 다시 확정한다.
- 배정 창: 창을 연 뒤에만 학생별 준비 자료를 읽는다.
- 단어장·범위: 단어장 목록과 선택 단어장의 범위 단위를 필요한 시점에 따로 읽는다.
- 최근 시험: 학생 한 명과 단어장 한 개의 정확한 조합만 읽고, 완료된 조합 결과만 요청 키별로
  재사용한다. 학생이나 단어장이 바뀌면 진행 중 요청은 취소한다.
- 독립 오답: 오답 탭에서만 summary와 preview를 준비하며 같은 입력의 결과를 요청 안에서 재사용한다.
- 수정: 학생·배정 한 건의 edit context와 단일 편집기를 사용한다.
- 서버 저장: 일괄 배정의 조회·계획·저장 조합을 `features/assignments/server`가 소유한다.

## 2. 제거하거나 잠근 경로

- 구 전체 작업공간 로더와 구 관리자 일괄 배정 계약을 제거했다.
- 사용되지 않던 별도 일괄 편집기와 겹침 결정 UI·domain을 제거했다.
- 같은 날짜의 기존 시험은 별도 건너뜀·이동 결정을 만들지 않고 배정 자체를 허용한다.
- exact 오답 수정은 기존 문항 snapshot과 출제 방향을 유지한다.
- 학생 단어장 이력 계약은 students 공개 계약으로 옮겼다.

전용 migration 호출은 두 번 응답이 끝나지 않았고 사후 확인에서 이력·함수 모두 0건이라 부분 적용이
없었다. 이후 같은 SQL 원문과 해당 버전의 migration 이력 기록을 한 트랜잭션으로 묶어 파일별로
직접 실행했다. 다섯 이력은 각각 SQL 원문 한 건을 보존한다.

적용 전후 지문은 학생 35명, 시험 125개, 학생 배정 124개, 문항 4,790개, 오답 배정 요청 1개,
일괄 series 요청 38개로 모두 같다. 세부 readback은 다음과 같다.

- 필터 전체 선택은 활성 학생 29명을 중복 없이 29명 반환했다.
- 오답 공개 시각 열은 nullable이며 기존 요청 1개는 `NULL`로 보존됐다. 64자리 소문자 SHA-256
  제약은 검증 완료 상태다.
- 즉시 일괄 v10은 private 함수의 외부 실행 권한이 0이고, 기존 회차 시각 증가 검사와 v7 delivery
  호출을 유지한 채 날짜 없는 1회 배정만 허용한다.
- 최근 시험 조회는 앱 관리자 역할에서 학생·단어장 한 조합에 일반 시험 1건만 반환했다.
- exact 오답은 v6가 v7으로 이어지고 v6/v7의 소유자·권한 모드·검색 경로가 같다. 기존 선택지
  snapshot 4,790건은 모두 4개 선택지를 유지했다.

보안 권고는 74건에서 77건으로 늘었다. 추가 3건은 공개 관리자 명령
`create_current_wrong_review_assignment_v2`, `create_bulk_vocab_assignments_v10`,
`replace_student_assignment_v7`이 `authenticated`에서 실행 가능한 `SECURITY DEFINER`라는 경고다.
세 함수는 앱의 관리자 세션으로 직접 호출해야 하므로 의도된 허용 목록이며, 모두 빈 `search_path`,
활성 관리자 검사, 익명·PUBLIC 실행 차단을 확인했다. 성능 권고는 68건으로 변하지 않았다.

## 5. 복구 경계

- 코드 배포 전에는 새 DB 함수가 사용되지 않으므로 앱은 직전 Preview와 계속 호환된다.
- 코드 배포 뒤 문제가 생기면 먼저 직전 코드로 되돌린다. v6 호환 wrapper와 기존 공개 writer가
  남아 있어 즉시 DB 삭제는 필요하지 않다.
- 완전한 DB 되돌리기는 새 forward migration으로만 수행한다. 앱이 이전 writer를 사용함을 확인한 뒤
  새 읽기 함수·v2/v10/v7과 보조 private 함수를 역순으로 제거하고, nullable 열은 값이 모두 `NULL`인지
  확인한 뒤에만 제약·열을 제거한다. 검증 없이 migration 이력이나 함수를 직접 삭제하지 않는다.
