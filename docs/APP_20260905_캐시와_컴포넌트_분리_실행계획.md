## 1. 결론과 범위

기존 구조를 전면 교체하지 않는다. 이미 공용화한 단어장 검색·영어 선택지·발음·모달은 보존하고,
전체 배정 상태에 의존하는 화면 부품을 작게 나눈다. 불필요한 조회부터 제거한 뒤, 남은 반복 조회에만
짧은 사용자별 브라우저 캐시를 시험 적용한다. 서버 공용 캐시는 별도의 조건부 실험으로 둔다.

완료의 의미는 파일이 나뉘거나 캐시 설정이 생기는 것이 아니다.

1. 같은 부품을 단일·일괄·오답 배정에서 독립적으로 검사할 수 있다.
2. 기존 범위·회차·날짜·잠금·요청 내용이 분리 전후 동일하다.
3. 목록 재방문 때 실제 목록 조회가 줄고, 최초 진입은 허용 범위 이상 느려지지 않는다.
4. 저장·삭제·로그아웃·권한 변경 때 오래된 자료가 잘못 복원되지 않는다.
5. 측정하지 못한 항목과 조건부 미채택 항목을 완료로 포장하지 않는다.

학생 시험 진행·타이머·현재 포인트·최종 배정 가능 여부의 최신성은 유지한다. 단어 정제, 자료 재생성,
영영풀이·예문의 배정 제한 확대, 포인트 규칙 변경, DB 구조 변경은 이 계획에 섞지 않는다.

## 3. 컴포넌트는 이렇게 나눈다

### 역할과 의존 방향

    경로·서버 화면: 권한 확인, 화면 조합
        ├─ 서버 조회·저장: 현재 데이터 확인, 권한·최종 규칙 검증
        └─ 화면 연결부: 입력 상태, 요청 수명, 캐시, 부품 연결
              ├─ 순수 계산: 범위·회차·반복·검증 규칙
              ├─ 표시값 변환: 계산 결과를 제목·문구·표시 상태로 변환
              └─ 화면 부품: 값 표시, 사용자 동작 전달
                    └─ 공용 UI: 버튼·입력·탭·모달·움직임·접근성

- 화면 연결부는 전체 상태를 알아도 된다. 재사용할 범위·일정·조건 부품은 전체 상태를 몰라야 한다.
- 예: 범위 부품에는 선택한 단원, 선택 가능 범위, 오류, 선택 변경 함수를 전달한다.
  일정 부품에는 날짜 사용 여부, 선택 날짜, 회차별 표시값, 오류, 날짜 변경 함수를 전달한다.
- controller 전체, hook의 ReturnType, 이름만 바꾼 전체 상태 객체, 객체 펼치기로 우회하지 않는다.
- 화면 부품에서 fetch, 인증, 캐시 폐기, 회차 계산을 하지 않는다. 작은 예제 값만으로 단독 렌더가 가능해야 한다.
- 순수 계산은 React·Next.js·DB를 몰라야 한다. 서버는 저장 직전 현재 자료로 다시 검증한다.
- 기본 입력·모달을 업무 규칙과 합친 만능 부품으로 만들지 않는다. 수정 화면의 잠금과 오답 시험의
  전용 흐름은 유지하고, 정말 같은 입력·표시만 공유한다.
- 단순히 파일 길이나 파일 개수를 기준으로 분리하지 않는다. 독립 변경·독립 검사가 가능한지가 기준이다.

### 우선 분리 대상

아래 파일은 현재 경로다. 새 파일명은 구현 단계에서 정하되 역할과 완료 기준을 먼저 고정한다.

| 현재 대상 | 분리할 책임 | 그대로 보존할 동작 |
|---|---|---|
| [범위 화면](../src/features/assignments/ui/vocab-range-fields.tsx) | 범위 표시/선택 부품과 상태 연결부 | 단원 순서, 역방향 범위 선택, 취소·재선택 |
| [일정 화면](../src/features/assignments/ui/vocab-schedule-fields.tsx) | 날짜 제어, 회차별 시간, 요약 표시. 회차 수 계산은 공통 계산으로 이동 | 날짜 없는 분할, 범위 반복의 초과·축소, 마감 정렬 |
| [일괄 시험 조건](../src/features/assignments/ui/bulk-exam-fields.tsx) | 유형·출제 조건 부품과 일괄 요청 연결부 | 단일/일괄의 같은 조건 의미와 제출 내용 |
| [오답 배정](../src/features/assignments/ui/direct-review-assignment-sections.tsx) | 재사용 입력·요약과 오답 전용 연결부 | 오답 범위, 기존 잠금, 복구 흐름 |

영영풀이·예문 지원 여부, 준비 상태, 일정 제한은 하나의 순수 정책 결과로 전달한다. 화면 안내는
그 결과를 한국어로 바꾸고 서버 검증도 동일한 계약을 사용한다. “검토 중”과 “준비 정보 없음”을
혼용하지 않는다. 검색·선택지·발음·단어장 모달의 기존 공용 구현을 이 과정에서 복제하지 않는다.

기능 간 타입은 public-contracts 경계로 점진 이동한다. 타입만 연결된 것을 곧바로 실행 코드나
성능 문제로 단정하지 않는다. 경로 이동 시 기능 소유권 지도와 가까운 지침을 같은 변경에 갱신한다.
일부 파일명만 검사하거나 controller라는 단어만 금지하지 않고, 재사용 UI 분류 전체의 실제 import와
타입 의존을 검사한다. 연결부 예외는 역할·사유가 있는 목록으로 관리한다.

## 4. 캐시 설계 결정 — 제안

### 선택한 방향과 대안

| 방법 | 장점·한계 | 결정 |
|---|---|---|
| 기존 서버 첫 조회 유지 + 불필요한 준비 조회 제거 | 변경이 작고 첫 목록의 서버 표시를 보존. 화면 왕복 재조회는 남을 수 있음 | 먼저 적용·재측정 |
| 필요한 관리자 목록만 사용자별 브라우저 메모리에 보관 | 짧은 왕복에서 같은 목록을 재사용. 최초 진입·인증·폐기 설계 필요 | 중복 조회가 남을 때 학생 목록 한 곳에서 시험 |
| 전역 페이지 캐시 시간 확대 | 설정은 작지만 개인 목록·포인트·권한까지 영향이 넓음 | 이번 기본안에서 제외 |
| 서버 공용 자료 캐시 | 반복 자료 조회를 줄일 가능성. 권한·자료 변경 연결이 선행 조건 | 조건부 후속 실험 |

목록 캐시를 도입하게 되면 TanStack Query v5를 우선 평가한다. 요청 합치기·취소·갱신 기능을
직접 다시 만드는 비용과 추가 JavaScript 비용을 함께 비교한다. 현재 설치되어 있지 않으며 이번에는
추가하지 않는다. 기존 버전 호환, 허용 라이선스, 잠금 파일, 최초 표시 측정을 통과한 경우에만 채택한다.
Next.js는 서버 화면과 필요한 부분의 클라이언트 자료 조회를 함께 사용할 수 있다.
전체 앱을 클라이언트 전용으로 바꾸는 제안은 아니다. [공식 혼합 구성 안내](https://nextjs.org/docs/app/guides/single-page-applications).

### 반드시 함께 바꿔야 할 조회 경로

브라우저 캐시만 추가하고 page에서 초기 목록을 매번 조회하면 DB 비용은 그대로다.
따라서 시험 대상 목록에서는 서버의 무조건 초기 목록 조회를 제거하고, 인증된 화면 안의 작은 목록
연결부가 기존 비공개 조회 API를 캐시 미보유·만료·변경 시에만 호출하도록 함께 바꾼다.

- 경로·레이아웃·서버 권한 검사와 Next.js Link는 보존한다. 내부 RSC 헤더를 검사하는 편법이나 새 라우터는 만들지 않는다.
- 기존 학생 목록 읽기 API는 POST 방식이다. 읽기라는 이유로 무조건 GET으로 바꾸거나 HTTP 공개 캐시를 켜지 않는다.
- API의 현재 인증·행별 접근 제한·private, no-store 응답은 유지한다. 서버와 브라우저 캐시는 별개다.
- 이 방식은 해당 목록의 최초 서버 렌더 데이터를 포기하고 첫 자료 요청이 뒤로 밀릴 수 있다.
  최초 표시와 JavaScript 증가를 측정하고 손해가 크면 채택하지 않는다. 학생 목록 외에는 먼저 확장하지 않는다.
- 기존 초기 snapshot 전달 방식과 새 Query 저장소가 같은 목록을 이중 소유하지 않도록 한 번에 전환한다.

### 자료별 보관·갱신·폐기 규칙

아래 시간은 실측 전의 보수적인 설계 제안값이다. 적용된 수치나 사용자 확정 요구사항이 아니다.

| 자료 | 보관 위치·사용 범위 | 갱신·폐기 |
|---|---|---|
| 인증·권한 | 서버에서 검증. 목록 캐시는 인증 근거가 아님 | 각 API, 화면 진입·복원·탭 복귀에서 현재 권한 확인 |
| 관리자 학생/배정/내역 목록 | 사용자·로그인 세대·검색/필터·정렬·조회 범위별 브라우저 메모리 | 성공 조회 후 15초까지 새 조회 없이 사용. 이후 진입/복귀 시 1회 갱신. 변경은 시간과 무관하게 무효화 |
| 갱신 중인 기존 목록 | 마지막 성공 조회 후 최대 60초까지만 명시적으로 오래된 상태로 표시 | 60초가 넘으면 숨기고 갱신 또는 오류·재시도 표시. 활동 없는 항목은 120초 후 메모리에서 제거 |
| 단어장 찾기 목록·단원 | 기존 화면/배정창의 메모리 재사용 우선 | 승인 상태·개수 등이 섞인 전체 준비 응답을 서버 공용 캐시에 넣지 않음. 서버는 제출 때 재검증 |
| 응시 진행·타이머·현재 포인트·최종 배정 가능 여부 | 기존 최신 조회·응답 흐름 | 첫 화면 캐시 시험 대상에서 제외 |

15초는 새 조회 생략 시간, 60초는 표시 허용 상한, 120초는 사용하지 않는 메모리 보관 시간이다.
staleTime/gcTime만 설정해서 세 규칙이 모두 구현됐다고 판단하지 않는다. 마지막 성공 시각 기준의
표시 제어를 따로 검사한다. 창을 계속 열어 둔 경우도 표시 만료용 단발 타이머로 오래된 자료를
숨기고 다시 확인할 버튼을 제공한다. 이 타이머는 조회를 발생시키지 않는다. 오류·오프라인으로
60초를 넘긴 자료를 계속 표시하지 않는다. 주기적 네트워크 polling은 넣지 않는다.
자동 재시도는 우선 끄고, 활성 화면의 만료·탭 복귀·재연결·명시적 재시도만 요청을 합쳐 처리한다.
이는 라이브러리 기본값과 다르므로 명시 설정이 필요하다. [공식 기본값 설명](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults).

### 개인 자료 보호 — 속도와 별개의 필수 관문

- 캐시 저장소는 관리자 공통 레이아웃 아래의 작은 Client Provider가 소유한다. 레이아웃 전체를
  Client Component로 바꾸지 않으며 localStorage·IndexedDB·서비스워커에 개인 목록을 저장하지 않는다.
- 레이아웃은 매 이동마다 새 인증을 보장하지 않는다. 서버 데이터 접근과 API에서 권한을 검사하고,
  화면 진입·뒤로/앞으로 복원·탭 복귀 시 현재 로그인과 권한이 확인되기 전에는 저장된 개인 목록을 숨긴다.
  이미 수행한 현재 진입의 인증 결과는 중복 사용하되, 오래된 사전 로딩 결과를 새 인증으로 취급하지 않는다.
- 복원 경로에 현재 인증 결과가 없다면 기존 인증 조회를 재사용한다. 없다면 최소 권한 확인 경계를
  구현 단계에서 추가한다. 콜드 목록 응답의 인증과 중복 요청하지 않도록 요청 소유자를 하나로 둔다.
  이 인증 요청/조회는 목록 조회와 따로 측정하며, “모든 요청 0·항상 즉시 이동”을 약속하지 않는다.
- 로그아웃 시작·401/403·계정 변경·권한 상실 시 즉시 진행 요청 취소, 캐시 폐기, 로그인 세대 증가,
  개인 화면 숨김을 함께 수행한다. 로그아웃 통신 실패도 옛 목록을 복구할 이유가 되지 않는다.
- 늦게 도착한 이전 응답은 이전 세대나 변경 이전 버전이면 버린다. 다른 탭에는 로그인 변경·폐기
  신호만 전달하고 이름·성적·토큰을 전달하지 않는다. 복원/백그라운드 복귀도 동일 검사에 포함한다.
- 서버 권한 검사와 부품 숨김은 서로 대체할 수 없다. [Next.js 인증 경계 설명](https://nextjs.org/docs/app/guides/authentication#layouts-and-auth-checks).

### 저장 후 갱신 영향표

| 성공한 변경 | 갱신 또는 무효화할 범위 | 하지 않을 일 |
|---|---|---|
| 학생 등록·수정·삭제·접근 상태 변경 | 해당 상세, 학생 목록/필터 개수, 배정 대상 목록, 영향을 받는 이름·개요·내역 | 무관한 학생의 모든 상세 재조회 |
| 시험 배정·수정·취소·숨김 | 해당 학생의 배정/요약, 배정 목록, 개요 수치, 관련 내역 | 모든 관리자 탭과 전체 과거 페이지 즉시 재조회 |
| 단어장 승인·수정·교체 | 해당 자료의 찾기 목록·단원·배정 준비 정보 | 사용자 개인 응답을 공용 자료 캐시에 합치기 |
| 다른 화면·다른 탭의 변경 통지 | 관련 캐시만 무효화. 활성 목록은 합친 1회 갱신 | 숨은 화면까지 연쇄 조회 |
| 로그아웃·권한 상실 | 해당 로그인 세대 전체 폐기 | 오래된 자료로 인증 오류 대체 |

저장 응답으로 확실히 고칠 수 있는 행은 즉시 반영하되 필터 포함 여부·정렬·총개수가 달라질 수 있으면
첫 페이지를 다시 확인한다. 실패한 저장으로 정상 캐시를 바꾸지 않고, 진행 중 옛 조회가 새 저장 결과를 덮지 못하게 한다.
첫 페이지를 새로 받으면 이전 snapshot의 더보기 페이지와 커서를 함께 폐기한다. 옛 페이지를 새 첫
페이지에 붙이거나 과거에 열었던 모든 페이지를 자동 재조회하지 않는다. 화면 위치 복원과 자료 복원은 구분한다.

## 5. 적용 순서와 단계별 통과 조건

### 0단계 — 기존 동작과 비용 기준 고정

- 가짜 학생·고정 자료로 단일/일괄/오답/수정의 요청 내용, 범위 순서, 회차, 잠금, 취소·재선택을 기록한다.
- 로컬 배포형 빌드에서 최초 진입, 실제 Link 왕복, 뒤로/앞으로, 모달 열기·닫기, 필터 변경을 같은 조건으로 측정한다.
- RSC 요청, 목록 API, 인증 조회, 목록 DB/RPC, 전송량, JavaScript, 첫 유효 목록 표시 시간을 분리한다.
  사전 로딩으로 앞당겨진 요청도 합산한다. 강제 새로고침만으로 재방문 캐시 효과를 판단하지 않는다.
- 조건별 준비 실행 뒤 최소 10회 반복하고 중앙값·상위 95% 시간 및 실행 환경을 남긴다.
- 통과: 비교 가능한 기록과 동작 보존 검사가 있어야 다음 단계 착수. 실데이터·운영 계정은 쓰지 않는다.

### 1단계 — 계산과 화면 부품 분리

- 3절의 네 대상에서 한 번에 한 흐름씩 분리하고 모든 실제 소비 화면을 연결한다.
- 일정 수치 계산과 시험 유형 지원 정책을 공통 계약으로 모으고 남은 Preview 안내를 실제 제한 설명으로 교체한다.
- 분리마다 0단계의 제출 내용·범위·회차·잠금 검사를 비교한다. 최종 단계까지 동작 검사를 미루지 않는다.
- 통과: 재사용 부품 단독 검사, 전체 대상의 의존 경계 검사, 기존 요청 동일성, 새/옛 계산 중복 0.

### 2단계 — 불필요한 조회와 로딩 표시 정리

- 접힌 학생 등록 준비 자료는 실제 열 때 읽도록 한다. 이미 받은 검색 목록·범위의 중복 읽기는 제거한다.
- 첫 자료가 없을 때는 해당 영역의 뼈대 화면, 기존 자료 갱신은 작은 진행 표시, 실패는 원인과 재시도를 보여준다.
  실패를 빈 목록·0건으로 바꾸지 않는다. 권한 오류는 개인 자료를 숨긴다.
- 현재 화면을 작은 갱신 때문에 통째로 비우지 않는다. 탭/부품의 빠른 표시 애니메이션과 감소 모션 설정은 보존한다.
- JS 선로딩은 현재 흐름에서 실제 사용 의도가 확인된 부품만 검토한다. 모든 페이지의 데이터를 미리 읽지 않는다.
- 통과: 접힌 영역 준비 조회 0, 초기 중복 조회 0, 강제 최소 대기 0, 오류·키보드·로딩 동작 유지.
- 같은 Link 왕복을 재측정한다. 이 조치로 해결된 화면에는 새 캐시 계층을 추가하지 않는다.

### 3단계 — 남은 목록 조회에만 작은 캐시 시험

- 선행 조건: 2단계 뒤에도 반복 조회가 남고, 4절의 사용자 격리·폐기·갱신 규칙 검사부터 작성되어야 한다.
- 학생 목록 하나에서 조회 소유권과 저장소를 함께 전환한다. 조건을 통과한 뒤 배정 목록, 내역 순으로 별도 확대한다.
- 목록 캐시 유효 시간 내 동일 조건 왕복은 목록 API·목록 DB 조회 0을 목표로 한다. 인증 관련 비용은 따로 공개한다.
- 만료·저장 후 변경·동시 소비자에는 한 갱신 사건당 목록 요청 1회. 더보기는 같은 snapshot으로만 연결한다.
- 통과 목표: 권한 확인 후 캐시 목록 표시는 100ms 이내, 전체 왕복 중앙값은 기준보다 30% 이상 개선,
  최초 유효 목록의 중앙값·상위 95% 시간은 10% 넘게 악화되지 않음. 이는 로컬 비교용 제안 관문이며
  0단계에서 측정 오차·환경을 기록해 고정한다. 수치만 맞추려고 인증 검사나 오류 표시를 생략하지 않는다.
- 안전 관문 실패 또는 의미 있는 비용/응답 개선이 없으면 확대하지 않고 해당 목록의 기존 서버 조회 경로로 복귀한다.

### 4단계 — 서버 공용 자료 캐시는 조건부

- 브라우저 최적화 후에도 큰 공용 조회가 남을 때만 별도 실험한다. 이 단계의 기각은 개인 목록 실험 결과와 구분한다.
- 공유 가능한 최소 필드, 사용자별 접근 차이, 자료 버전, 모든 수정·가져오기 경로를 먼저 확인한다.
- 서비스 역할 키로 권한을 우회하지 않는다. 권한에 따라 다른 자료는 공용으로 취급하지 않는다.
- 실제 변경 경로에 갱신을 연결하지 못하거나 읽기 권한을 보장할 수 없으면 적용하지 않는다.
  시험 적용 시에는 자료별 버전 키와 태그/만료를 선택하고 변경 성공 뒤에만 폐기한다.
- 전역 Cache Components 설정이 필요하면 보호 화면 전체의 호환·인증·부분 표시 영향도 별도로 검증한다.
- 통과: 같은 버전 반복 조회 감소, 서로 다른 두 관리자 권한 격리, 변경 직후 새 자료, 변경 실패 시 기존 자료,
  갱신 누락·오류 경로 검사. 기각된 R8 설정을 단순 복원하지 않는다.

### 5단계 — 회귀 검사와 인계

- 단계별 좁은 검사 후 최종 통합 지점에서 전체 테스트·타입·lint·구조·요청 캐시·build를 실행한다.
- 자동 로컬 검사를 먼저 통과한 뒤 앱 브라우저에서는 실제 화면·모달·포커스·정렬·오류 표시만 최종 확인한다.
  숫자 계산과 타이밍 규칙을 브라우저에서 반복 추측하지 않는다.
- 최초 진입·짧은 왕복·만료·저장·삭제·계정 전환·오프라인의 전후 기록과 채택/기각 결론을 남긴다.
- 코드·설정·의존성·서버·DB·캐시·검사의 변경 여부, 커밋, 검사 수치, 금지사항, 다음 진입점을 인계한다.
- 최종 로컬 통과는 배포 승인이 아니다. Preview·Production·원격 DB는 새 요청 없이는 변경하지 않는다.

## 6. 검사표

| 검사 층 | 필수 사례 | 실패 시 |
|---|---|---|
| 순수 계산 | 날짜 없는 5회 분할, 반복 2회 초과/축소, 순서 보존, 최대 배정 수 | 분리 단계 진행 중단 |
| 부품 | 전체 controller 없이 렌더, 오류/준비 상태, 단일·일괄 공용 검색, 키보드 | 실제 화면 연결 전 보완 |
| 요청·저장 계약 | 같은 입력의 제출 내용 동일, 중복 저장 방지, 늦은 응답 무시, 실패 복구 | 캐시 확대 금지 |
| 시간 규칙 | 15/60/120초 경계, 갱신 실패, 열린 채 만료, 오프라인, 자동 재시도 폭증 없음 | 해당 캐시 채택 금지 |
| 인증·격리 | 관리자 A/B, 계정 전환, 로그아웃 실패, 401/403, 다른 탭, 복원, 늦은 응답 | 속도와 무관하게 채택 금지 |
| 목록 정합성 | 필터별 분리, 수정·삭제 뒤 반영, snapshot 교체, 커서 폐기, 중복/누락 0 | 해당 목록 복귀 |
| 실측·화면 | 실제 Link 왕복, prefetch 포함 요청 수, 최초 JS 비용, 360/768/1280 폭, 모달 복원 | 실측하지 않은 항목은 미검증 |

모의 요청 검사는 로직·횟수 계약을 증명하지만 실제 DB 비용을 증명하지 않는다. DB 조회 감소 판정에는
로컬 DB/RPC 계측이 필요하다. 로컬 DB 준비가 없으면 자동 대역 검사까지 수행한 범위만 기록하고,
운영 DB로 대체 측정하거나 비용 감소를 완료로 판정하지 않는다. 검사 도구도 외부 fixture 생성·정리
스크립트를 그대로 실행하지 않도록 로컬 목적지 차단 검사를 선행한다.

## 7. 진행·복구·문서 기준

- 각 단계는 독립적으로 되돌릴 수 있는 작은 변경으로 끝낸다. 관계없는 기능 커밋을 섞지 않는다.
- 대체 경로를 검증하기 전에 기존 경로를 지우지 않되, 단계 완료 시 실제 실행의 이중 상태/이중 조회를 없앤다.
- 실제 학생·원자료·DB 규칙을 건드릴 필요가 생기면 범위를 확장하지 말고 이유와 선택지를 보고한다.
- 별도 결제가 필요한 도구·외부 서비스는 도입하지 않는다. 의존성 추가는 채택 근거와 부하 측정을 기록한다.
- 이번에는 코드 측정이나 전체 검사를 새로 실행한 것으로 기록하지 않는다. 계획 안전성·분리 순서는
  읽기 전용 독립 리뷰 두 건을 받아 인증 복원, 표시 만료, 페이지 묶음 폐기, 단계별 동작 보존 관문에 반영했다.
- 다음 구현 시작점: 루트 대장 → 이 계획 → 0단계 기준값/동작 고정. 기존 완료 문서를 다시 실행하지 않는다.
