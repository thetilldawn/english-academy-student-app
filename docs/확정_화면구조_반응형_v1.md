# 확정 화면구조·반응형 배치 v1

- 확정일: 2026-07-29
- 상태: 모바일·태블릿·PC 확정 구조 구현 및 로컬 검증 완료
- 기준: 기능과 정보 배치만 다루며 세부 UI 디자인은 포함하지 않음
- 이전 선택지: [페이지별 ASCII 레이아웃 시안](페이지별_ASCII_레이아웃_시안.md)

## 1. 사용자 선택과 해석

| 번호 | 경로 | 선택 | 확정 내용 |
|---:|---|:---:|---|
| 1 | `/` | C | 첫 화면에서 학생 코드를 바로 입력하고 버튼명은 `인증` |
| 2 | `/code` | C→통합 | 별도 화면을 없애고 `/`로 연결하는 호환 주소만 유지 |
| 3 | `/student` | C | 지금 해야 할 시험을 가장 크게 표시 |
| 4 | `/student/attempt/[id]` | C | 문제와 네 보기를 한 화면에 둔 속도형 |
| 5 | `/student/result/[id]` | C | 다시 볼 단어를 결과의 첫 내용으로 표시 |
| 6 | `/admin/login` | A | 독립된 중앙 단일 로그인 폼 |
| 7 | `/admin` | C | 최근 운영 흐름을 중심으로 표시 |
| 8 | `/admin/students` | C | 학교·학년별로 학생을 묶어 표시 |
| 9 | `/admin/assignments` | B | 배정 조건을 순서대로 입력 |
| 10 | `/admin/results` | A | 전체 결과 표 |
| 11 | `/admin/results/[id]` | C | 첫 선택→재풀이→최종 상태 흐름 |

### 인증 경로

```text
학생
  /  ── 코드 입력 ── [인증] ──> /student
  /code ── 호환 이동 ─────────> /

관리자
  / 의 작은 [관리자 페이지] 링크 ──> /admin/login
  /admin/login ── 이메일·비밀번호 ──> /admin
```

- 첫 화면에는 관리자 로그인 폼을 넣지 않는다.
- `/admin/login`은 완전히 분리된 관리자 로그인 페이지다.
- 첫 화면의 `관리자 페이지`는 별도 페이지로 이동하는 작은 링크일 뿐이다.
- `[오류 발생 시 표시]`는 평상시 보이는 안내문이나 빈 공간이 아니다.
- 잘못된 코드·잘못된 비밀번호·실제 연결 실패가 발생한 뒤에만 해당
  입력폼 안에 오류문을 만든다.

## 2. 반응형 공통 기준

| 구간 | 기준 폭 | 기본 배치 |
|---|---:|---|
| 모바일 | 0~767px | 1열, 주요 실행 버튼 전체폭 |
| 태블릿 | 768~1199px | 1~2열, 상단 관리자 메뉴 |
| PC | 1200px 이상 | 관리자 좌측 메뉴+넓은 작업영역 |

- 모바일·태블릿·PC용 페이지를 따로 복제하지 않는다.
- 같은 경로·데이터·동작을 유지하고 화면 폭에 따라 배치만 바꾼다.
- 학생 인증·시험·결과는 PC에서도 지나치게 넓히지 않고 중앙 작업면을
  약 480~900px 안에 둔다.
- 관리자 화면만 PC에서 좌측 메뉴와 2~3열 작업공간을 사용한다.
- 모바일 관리자 메뉴는 화면 아래의 4개 메뉴로 유지해 현재처럼 메뉴가
  사라지지 않게 한다.

### 학생 공통 셸

`/student`와 `/student/result/[id]`에 적용한다. 시험 집중을 위해
`/student/attempt/[id]`만 공통 상단바를 숨기는 전체화면 예외로 둔다.

```text
모바일
+--------------------------------+
| 영어 학습실   학생·학년  접속종료 |
+--------------------------------+
|           중앙 작업면            |
+--------------------------------+

태블릿·PC
+--------------------------------------------------+
| 영어 학습실              학생·학년 · 접속 종료    |
+--------------------------------------------------+
|        [폭을 제한한 중앙 학생 작업면]             |
+--------------------------------------------------+
```

### 관리자 공통 셸

```text
모바일
+--------------------------------+
| 현재 페이지       관리자 · 종료  |
+--------------------------------+
|            작업 내용             |
+--------------------------------+
| 현황 | 학생 | 배정 | 결과         |
+--------------------------------+

태블릿
+--------------------------------------------------+
| 관리 | 현황 | 학생·코드 | 시험 배정 | 결과 | 종료 |
+--------------------------------------------------+
|                    작업 내용                     |
+--------------------------------------------------+

PC
+-------------+------------------------------------+
| 영어 학습실  |                                    |
| 현황         |             작업 내용              |
| 학생·코드    |                                    |
| 시험 배정    |                                    |
| 결과         |                                    |
|-------------|                                    |
| 관리자·종료  |                                    |
+-------------+------------------------------------+
```

## 4. 호환 주소 `/code` · 별도 화면 없음

```text
모바일·태블릿·PC 공통

/code 요청 ── 임시 리다이렉트 ──> /
                                |
                                +─ 학생 코드 인증
```

학생 로그아웃과 인증이 필요한 학생 페이지의 무세션 이동도 `/`로
통일한다.

## 12. 시험 결과 목록 `/admin/results` · A 확정

### 모바일

선택한 전체 표 구조를 유지한다. 학생과 시험 열은 왼쪽에 고정하고 나머지
열은 좌우로 밀어 확인한다.

```text
+--------------------------------+
| 시험 결과          관리자 · 종료 |
+--------------------------------+
| 학생 | 시험 | 회차 | 상태 | ...  |
| 김   | A > | 1   | 완료 | ...  |
| 이   | A > | 1   | 진행 | ...  | -->
| 박   | B > | 2   | 종료 | ...  |
+--------------------------------+
| 현황 | 학생 | 배정 | 결과         |
+--------------------------------+

가로 이동 영역:
첫 점수 | 재풀이 후 | 통과 | 시작시각
```

### 태블릿

```text
+-----------------------------------------------------------+
| 관리 | 현황 | 학생·코드 | 시험 배정 | 결과 | 종료          |
+-----------------------------------------------------------+
| 학생 | 시험 | 회차 | 상태 | 첫점수 | 최종 | 통과 | 시작      |
| 김   | A > | 1   | 완료 | 85    | 95   | O   | 10:20    |
| 이   | A > | 1   | 진행 | -     | -    | -   | 10:15    |
+-----------------------------------------------------------+
```

폭이 부족할 때는 시작시각까지 표 안에서 가로 이동한다.


## 14. 구현 전에 유지할 규칙

1. PC 대응은 별도 페이지 복제가 아니라 같은 컴포넌트의 반응형 재배치로
   구현한다.
2. 학생 인증과 관리자 인증은 서로 다른 경로와 세션을 유지한다.
3. `/code`는 기존 링크 호환용 이동 경로만 남긴다.
4. 모바일 시험의 네 보기는 작은 화면에서도 2×2를 우선 유지하되, 긴
   보기 문구는 줄바꿈으로 높이를 늘린다.
5. 모바일 관리자 메뉴를 숨기기만 하지 않고 하단 메뉴로 대체한다.
6. 결과 표는 정보를 삭제하지 않고 폭에 따라 가로 이동을 허용한다.
7. 오류·경고는 평상시 표시하지 않고 실제 실패나 위험 동작 시점에만
   표시한다.
