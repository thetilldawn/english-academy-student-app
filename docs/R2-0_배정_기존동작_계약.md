# R2-0 배정 기존 동작과 목표 계약

- 기준일: 2026-08-28
- 기준 커밋: `f6babbd`
- 적용 범위: 단어 시험의 단일·일괄 배정, 독립 오답 시험, 기존 시험 수정
- 제외 범위: 학생 성취 화면, 학부모 PDF, 학생 자율 시험, Production
- 문서 목적: 현재 정상 동작과 바로잡아야 할 결함을 분리해 R2-1 이후 구조 변경의 기준으로 사용한다.

## 1. 용어를 먼저 분리한다

현재 코드의 `assignmentMode`는 서로 다른 두 뜻으로 사용된다.

| 구분 | 현재 값 | 이 문서의 이름 |
|---|---|---|
| 배정 대상 선택 | `single`, `bulk` | 대상 방식 |
| 범위를 회차에 넣는 방법 | `all_sessions`, `per_session`, `word_count` | 회차 배정 방식 |

R2 구현에서는 변수·함수 이름도 이 뜻을 구분한다. 한 이름으로 두 결정을 표현하지 않는다.

## 2. 현재 실행 경로

| 흐름 | 현재 화면 경로 | 미리보기·저장 | 제출 시각 | 중복 저장 방지 | 현재 상태 |
|---|---|---|---|---|---|
| 일반 단어 배정 1명 | 단어 배정 화면 | `/api/admin/bulk-assignments/preview` → `/api/admin/bulk-assignments` | 클릭 순간 브라우저 시각으로 사전 검사하고 서버가 별도 현재 시각으로 재검사 | 의미 입력 fingerprint별 UUID와 Preview 계획 서명 | 정상. 대상이 1명일 뿐 일괄과 같은 엔진이다. |
| 일반 단어 배정 여러 명 | 단어 배정 화면 | 1명 배정과 동일 | 위와 동일 | 위와 동일 | 정상. 학생 수만 다르다. |
| 독립 오답 시험 | 오답 시험 탭 | `/api/admin/exact-review-assignments/preview` → `/api/admin/exact-review-assignments` | 브라우저는 창을 연 시각으로 검사하고, 서버·DB는 저장 시각으로 재검사 | draft fingerprint별 UUID, 서버 SHA-256, DB 멱등 원장 | 저장 안전성은 있으나 브라우저 오류 안내 시점이 잘못됐다. |
| 예전 일반·오답 포함 생성 | 현재 새 배정 화면에서는 사용하지 않음 | `/api/admin/assignments`, `/api/admin/mixed-assignments` | 제출 직전 브라우저 시각, 서버는 별도 현재 시각 | 일반·혼합 생성은 멱등키 없음 | 호환 경로. 새 공통 흐름의 기준으로 사용하지 않는다. |
| 기존 시험 수정 | 이력의 수정 화면 | `GET/POST/PUT /api/admin/assignments/{시험}/students/{학생}` | 제출 직전 브라우저 시각, 서버·DB 저장 시각 재검사 | 의미 입력 fingerprint별 UUID, 서버 SHA-256, DB 멱등 원장 | 기존 시험 취소 후 교체본을 만드는 방식이다. |

일반 단어 배정의 `단일/일괄`은 별도 업무가 아니다. 같은 준비 화면·계획·검증·저장을 쓰고 대상 학생
수가 1명인지 여러 명인지만 다르다. 앞으로도 이 경계를 유지한다.

## 3. 회차 배정 방식의 현재 의미

| 화면 값 | 내부 계약 | 실제 저장 시점 |
|---|---|---|
| 전체 회차 | `repeat + question_count` | 선택한 모든 회차를 즉시 만든다. 각 회차는 같은 범위를 쓴다. |
| 회차별 | `split + range_unit` | 첫 시험만 만들고, 완료되면 다음 범위 시험을 큐에서 만든다. |
| 단어 수 | `split + question_count` | 첫 시험만 만들고, 완료되면 다음 문제 묶음을 큐에서 만든다. |

시험일을 사용하지 않으면 `회차별`은 전체 범위 1회 배정으로 정규화된다. 독립 오답 시험과 기존 시험
한 건 수정에는 이 세 가지 연속 배정 방식을 억지로 적용하지 않는다.

## 4. 수정 가능 필드

`열림`은 화면과 서버가 모두 변경을 허용한다는 뜻이다. `서버만`은 서버 능력은 있으나 현재 화면에
입력이 없다는 뜻이다. `잠금`은 원래 문제와 오답 출처를 보존해야 한다는 뜻이다.

| 필드 | 일반 시험 | 예전 오답 포함 시험 | 독립 오답 시험 | R2 목표 |
|---|---|---|---|---|
| 제목 | 서버만 | 서버만 | 서버만 | 자동 제목을 보존하고 이번 범위에서는 직접 입력을 추가하지 않는다. |
| 단어장·범위 | 열림 | 잠금 | 잠금 | 현행 유지 |
| 단어 수 | 열림 | 잠금 | 잠금 | 현행 유지 |
| 출제 방향 | 열림 | 잠금 | 열림 | 현행 유지 |
| 문제 순서 | 열림 | 열림 | 열림 | 현행 유지 |
| 시간 제한 | 열림 | 열림 | 열림 | 현행 유지 |
| 최초·재시험 통과 점수 | 열림 | 열림 | 열림 | 현행 유지 |
| 공개 시작 시각 | 계약 없음 | 계약 없음 | 계약 없음 | 세 종류 모두 원래 값을 보존하고 수정도 가능하게 한다. |
| 마감 시각 | 열림 | 열림 | 열림 | 현행 유지 |
| 오답 범위·단계 | 화면에서 종류 전환 불가 | 잠금 | 잠금 | 예전 시험은 원래 scope와 단계를 정확히 보존한다. |
| 요일·이어 배정 규칙 | 계약 없음 | 해당 없음 | 해당 없음 | 한 시험 수정에서는 바꾸지 않고 원래 series 자료를 보존한다. |

수정 UI와 서버 정책은 R2-2에서 한 순수 정책표를 함께 사용한다. 현재처럼 reducer, controller, UI,
서버가 각자 잠금 조건을 만들지 않는다.

## 5. 요청 fingerprint와 시각 계약

### 5.1 유지할 규칙

- Preview fingerprint는 실제 대상·범위·일정이 바뀌면 달라진다.
- 저장 fingerprint는 학생·오답 단계처럼 집합인 값의 순서 차이를 무시한다.
- 저장 fingerprint는 시험 조건과 Preview 계획 서명을 포함한다.
- 같은 의미의 재시도는 같은 멱등키를 쓰고, 의미가 바뀌면 새 키를 쓴다.
- 서버는 Preview 계획을 다시 계산해 서명과 학생별 실제 대상을 확인한다.
- 독립 오답과 수정은 서버·DB에서도 현재 후보, 원래 문제 snapshot, queue ID를 다시 확인한다.

### 5.2 바로잡을 규칙

- 브라우저는 버튼을 누른 순간의 시각으로 다시 검사한다. 창을 연 시각은 제출 판단에 쓰지 않는다.
- 서버 Route Handler는 인증 뒤 `commandNow`를 한 번 확정하고 검증·서비스·DB 명령 전체에 전달한다.
- 브라우저가 보낸 시각은 권한·마감 판단의 기준으로 신뢰하지 않는다. 서버 시각이 최종 기준이다.
- 모든 생성·교체 명령은 멱등키와 정규화된 의미 fingerprint를 사용한다.
- endpoint 문자열, fingerprint 생성, 오류 변환은 controller가 아니라 흐름별 adapter가 맡는다.

## 6. 요일별 단위 수 계약

현재 하위 계산기와 서버 요청은 가변 단위 수를 처리할 수 있지만 실제 화면 연결은 끊겨 있다.

```text
현재 화면 상태
  └─ 모든 선택 날짜를 1단위로 고정
       └─ commonPlan.rangeUnitCounts
            └─ Preview·저장 요청
                 └─ 서버 재계산·큐 저장
```

R2-3의 목표 흐름은 다음과 같다.

```text
동일/요일별 선택 + 공통 단위 수 + 요일별 단위 수
  └─ planner state와 action
       └─ 원래 반복 요일 기준 순수 계산
            └─ 배정 규칙 + 실제 회차별 범위
                 └─ Preview·저장 요청
                      └─ 서버 동일 계산·변조 거부
                           └─ 큐에 원래 규칙과 실제 회차를 함께 보존
```

대표 계약은 월요일 2단위·수요일 3단위, 총 8단위다.

```text
월 [1, 2] → 수 [3, 4, 5] → 다음 월 [6, 7] → 다음 수 [8]
```

회차 날짜를 예외적으로 옮겨도 단위 수는 옮긴 날짜의 요일이 아니라 원래 반복 회차의 월·수 규칙을
따른다. `same/by_weekday`, 공통 단위 수, 요일별 단위 수는 조건 복사와 큐 상태 설명에 필요하므로
실제 `unitIds`만 남기지 않고 series 원 규칙도 저장한다.

## 8. R2 회귀 검사 기준

기존 도메인·controller·adapter의 관련 검사 91개는 모두 통과하지만, 도메인의 요일별 `[2, 3]`과
controller의 고정 `[1, 1]`이 각각 통과해 계층 단절을 숨긴다. 따라서 단순 전체 테스트 성공만으로
요일별 기능 완료를 판정하지 않는다.

R2-1 이후에는 다음을 흐름별로 검증한다.

1. 입력 지연, 이전 요청 취소, 늦게 도착한 응답 무시
2. 같은 입력 연속 제출 한 번만 저장, 응답 유실 재시도 동일 결과
3. 버튼 클릭 뒤 마감 경과 시 브라우저와 서버 모두 거부
4. 서버 오류 코드가 같은 필드와 같은 문구로 변환
5. 독립 오답은 exact 경로만 사용하고 mixed는 반드시 일반 범위를 포함

R2-3 이후에는 다음을 한 테스트에서 끝까지 검증한다.

1. UI action → planner state → `commonPlan`
2. 월 2·수 3 → `[2, 3]`과 `[1,2] / [3,4,5] / [6,7] / [8]`
3. Preview body와 저장 body의 배정 규칙·회차 범위 완전 일치
4. 서버의 조작된 회차 거부
5. 첫 시험과 큐 저장, 완료 뒤 다음 시험 생성
6. 학생 1명과 여러 명의 회차 패턴 동일
