# 외부 연결 검증

- 검증일: 2026-07-29
- 검증 방식: 설치된 앱 커넥터의 읽기 전용 도구를 실제 호출
- 이 문서의 최초 연결 검증 단계 외부 쓰기: 0건
- 후속 현재 상태: 서울 Supabase 적용 완료, GitHub 비공개 저장소 생성 완료

## 결론

GitHub·Supabase·Vercel의 인증과 연결은 모두 정상이다. 앞서 도구를 찾지
못한 원인은 인증 실패가 아니라, 이 작업에서 지연 로딩되는 앱 도구를
`codex_apps`와 구체 도구명으로 검색하지 않은 도구 발견 질의 문제였다.

같은 작업에서 정확한 앱 도구를 불러온 뒤 세 서비스 모두 실제 호출에
성공했으므로 재인증·재연결·재부팅은 더 필요하지 않다.

## 현재 상태

| 서비스 | 읽기 전용 실호출 | 현재 외부 상태 |
|---|---|---|
| GitHub | 로그인 사용자 조회 성공 | `thetilldawn/english-academy-student-app` 비공개 저장소 생성, 첫 푸시 준비 |
| Supabase | 조직·프로젝트·테이블·마이그레이션 조회 성공 | `ap-northeast-2` 운영 프로젝트, 테이블 13개, 마이그레이션 2개 |
| Vercel | 팀·프로젝트 조회 성공 | 팀 1개, 프로젝트 0개 |

최초 검증 때 발견한 `ap-south-1` 빈 프로젝트는 운영 기준본으로 쓰지
않았다. 한국 학생용 운영 프로젝트는 `ap-northeast-2`에 새로 만들고
마이그레이션과 보안 검증까지 완료했다.

GitHub 앱 커넥터의 설치 저장소 접근 범위는 여전히 0개지만, 로컬 Git
자격증명은 정상이다. 따라서 앱 전용 비공개 저장소는 로컬 Git 경로로
생성했으며 첫 커밋과 푸시를 진행한다.

Vercel 연결 자체는 정상이지만 연결·배포된 프로젝트가 아직 없다.

## 재발 시 확인 순서

1. 인증을 반복하지 말고 `codex_apps`의 서비스별 구체 도구를 검색한다.
2. GitHub는 로그인 조회, Supabase는 프로젝트 목록, Vercel은 팀 목록을
   읽기 전용으로 실제 호출한다.
3. 호출이 성공하면 연결 문제로 취급하지 않고 저장소·프로젝트 유무와
   접근 범위를 확인한다.
4. 호출이 인증 오류를 반환할 때만 재인증한다.
