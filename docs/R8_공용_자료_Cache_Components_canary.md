# R8 공용 자료 Cache Components canary

- 상태: canary 기각, 롤백 Exact Preview 확인 완료(`rejected`)
- 활성화: `b3377fd`
- 요청 경계 보완: `e2472a1`
- canary 구조 관문: `727d593`
- 롤백: `a789d7d`
- DB migration: 없음

## 판정

Cache Components는 유지하지 않는다. 실제 따뜻한 요청의 DB 재조회 감소가 측정되지 않았고, 최초 공용 경로가 서비스 역할 키를 사용했으며, 재검증 Route도 실제 자료 변경 흐름과 연결되지 않았다. 실행지시서의 중단 조건에 따라 설정과 런타임 캐시 경로를 제거했다.

## canary 실측

- 같은 관리자 세션에서 `/admin`과 `/admin/students`를 정상 이동한 7회 모두 `vocab_datasets`와 `vocab_dataset_catalog`를 다시 읽었다.
- Supabase 확인 시각: UTC 2026-08-31 19:48:26~19:48:27.
- 따뜻한 요청 DB 재조회 감소: 0회. 즉, 7회 중 7회 재조회했다.
- Preview 활성 관리자는 한 명뿐이어서 관리자 2명 교차 격리는 실환경에서 확인할 수 없었다.

## 롤백 내용

- `next.config.ts`의 `cacheComponents: true` 제거
- `"use cache"` 공용 자료 모듈 제거
- 서비스 역할 키 기반 공유 자료 조회 제거
- 연결되지 않은 `/api/admin/material-cache/revalidate` 제거
- 관리자 인증 뒤 현재 세션의 Supabase Client와 RLS를 사용하도록 복귀
- React `cache()`는 같은 RSC 요청 안의 중복 자료 조회에만 사용하고 요청 사이에는 공유하지 않음

태그 갱신과 실패 변경의 캐시 선반영 조건은 장기 캐시 자체를 제거했으므로 해당 없음이다. 개인 시험·응시·오답·포인트는 계속 요청 사이 캐시 금지다.

## 자동검증

- 실제 RSC 렌더 검사에서 같은 요청의 같은 키는 1회 조회, 새 요청은 다시 조회해 누적 2회가 됐다.
- 인증 실패 시 DB Client와 자료 조회가 모두 0회인 계약을 검사한다.
- 전체 341파일·1,788테스트와 구조 65테스트, lint·typecheck·build가 통과했다.

## 롤백 Preview 확인과 측정 한계

- 최종 `3634192` Exact Preview에서 관리자 배정·학생 로그인·시험 시작·답 저장·시간 종료 결과와
  관리자 반영을 확인해 롤백 상태의 핵심 흐름이 정상임을 확인했다.
- 전용 fixture 정리 뒤 세션 회수와 비대상 보호 지문 7/7 일치를 확인했다.

- DB 변경이 없으므로 rollback SQL은 없다.
