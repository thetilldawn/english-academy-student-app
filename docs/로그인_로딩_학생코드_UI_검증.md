# 로그인 로딩·학생코드 UI 검증

- 검증일: 2026-07-29
- 범위: 관리자 로그인 진행 상태, 학생 접속코드 입력
- 실제 학생정보: 사용하지 않음

## 반영 내용

- 관리자 로그인 성공 뒤 `/admin` 화면이 열릴 때까지 버튼의 `로그인 중…`
  상태를 유지한다.
- 처리 중에는 이메일·비밀번호·로그인 버튼을 비활성화하고 빠른 중복
  제출을 차단한다.
- 실패 응답이나 연결 오류가 발생한 경우에만 입력과 버튼을 다시
  활성화한다.
- 학생 접속코드는 실제 입력 한 개와 시각 셀 12개를 결합한
  `4칸-4칸-4칸` 구조로 바꿨다.
- 하이픈·공백이 포함된 전체 코드 붙여넣기, 소문자 자동 대문자 변환,
  모바일 일회용 코드 자동완성, 백스페이스와 좌우 이동을 단일 입력의
  기본 동작으로 유지한다.
- 발급에 사용하지 않는 `I`, `O`, `0`, `1`은 입력값에서 제외한다.
- 12자리가 채워지지 않으면 네트워크 요청 전에 안내한다.

## 검증 결과

- `npm run lint`: 통과
- `npm run typecheck`: 통과
- `npm run test`: 7개 파일·27개 검사 통과
- `npm run build`: 통과
- `abcd-efgh-2345` 붙여넣기:
  `ABCDEFGH2345`, 시각 셀 12개 채움, 완료 상태 확인
- 혼동문자가 포함된 불완전 코드 제출:
  API 요청 전 `접속코드 12자리를 모두 입력해주세요.` 표시
- 관리자 로그인 제출 직후:
  입력 2개와 버튼 비활성화, `로그인 중…`, 실시간 상태 안내 확인
- 실패 응답 뒤:
  오류 표시와 입력·버튼 재활성화 확인
- 브라우저 오류·경고: 0건
- 기본 PC 폭에서 시각 셀 12개, 카드 480px, 최소 셀 약 23px,
  가로 넘침 0
- 320px 전용 CSS에서 카드 폭과 여백을 축소하고 세 그룹을
  `minmax(0, 1fr)`로 배치해 가로 넘침 없이 유지

## 서버 키 확인

- 로컬 `SUPABASE_SECRET_KEY`는 서버 요청 방식으로 Supabase 응답 200을
  확인했다.
- 같은 키를 브라우저 계열 User-Agent로 직접 호출하면 Supabase의
  서버키 브라우저 사용 방지 때문에 401이 반환된다. 이는 키 불일치가
  아니다.
- 키 값은 이 문서와 Git에 기록하지 않는다.
- Vercel Production에는 사용자가 직접 민감 변수로 등록한 뒤 새
  배포에서 적용 여부를 확인한다.
