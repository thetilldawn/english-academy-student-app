선택된 date-fns 4.4.0만 정확 버전으로 추가했다. 직접 런타임 의존성과 peer 의존성은 각각 0개다. package.json 1줄 추가, lockfile 12줄 추가/1줄 삭제다. 이 중 jsdom과 vitest의 peer 표시 재계산이 각각 1곳이며 다른 기존 패키지 버전은 바뀌지 않았다. Node 24.19.0에서 검사했다. 설치 출력의 기존 앱 전체 취약점 안내를 date-fns의 문제나 이번 작업에서 해결한 결과로 해석하지 않는다.

## 운영 반영 전 남은 단계

적용 준비된 migration은 `20260913092302_add_school_schedule_and_student_school_key.sql`이다. 파일 SHA-256은 `185bee54b1280c010722539a80a2eaa9b765e86f25df58deb36abb927163f8e6`이다. 적용 이력을 먼저 읽어 이미 실행한 버전을 중복 적용하지 않는다.

1. 검증된 앱 코드와 신규 migration을 승인된 Preview/운영 순서로 반영하고 권한을 다시 확인한다.
2. 앱 밖 검토 자료 `앱전달_검토본.json`을 자료 버전·원문 해시와 함께 등록한다. 일정 수량·대상 학교·확인된 날짜는 별도 비공개 운영 기록에서 대조한다.
3. 승인된 대상 학생의 공식 학교 선택을 확인해 프로필 버전 검사로 연결한다. 이름 문자열만으로 마이그레이션에서 일괄 채우지 않는다. 테스트/학교 미등록 학생은 별도다.
4. 실제 관리자 화면과 학생 본인 조회를 읽기 검증한다. 기존 점수·배정·진행 응시와 원천 자료의 보존을 별도 확인한다.

현재 운영 반영 0회, 실제 학생 쓰기 0회다. 수행평가의 정확한 날짜, 영어 실제 시험일·교시, 선택과목 수강 여부는 학교의 후속 공식 안내가 필요하다. 지시서 갱신은 자동 수집기나 예약 실행을 만든다는 뜻이 아니다.
