# 시험 답 선택과 정오답 표시 검증

## 반영 내용

- 마지막 선택 후 **20ms**에 한 번만 전송한다. 선택 강조는 즉시 표시하고, 정오답은 서버가 확인한 뒤 표시한다.
- 정오답은 **200ms** 보여준 뒤 자동 진행한다. 그동안의 클릭·터치·키보드 입력으로 표시를 건너뛰거나 다음 답을 제출하지 않는다.
- 답을 고른 뒤 자동으로 영어를 다시 읽는 동작과 화면 전체 음성 건너뛰기 버튼을 제거했다. 문제 음성과 직접 누르는 스피커는 유지하며 답 선택 시 재생 중인 소리는 멈춘다.
- 다음 문제 준비가 늦으면 이미 선택한 답을 유지한다. 저장 응답만 유실된 경우에는 서버에서 같은 문항·단계·저장답을 확인한 경우에만 정오답을 복원한다. 확인되지 않은 결과는 만들지 않는다.
- 구형 서버가 예약한 대기시간이 남아 있으면 다음 문제의 제한시간을 먼저 소모하지 않는다. 5·8·10초 및 전체시간·제한없음 정책은 바꾸지 않았다.

## 확인된 원인과 한계

기존 음성 건너뛰기 동작은 정오답 대기까지 0으로 만들 수 있었다. 답이 저장됐지만 응답을 받지 못한 복구에서는 정오답 표시 없이 다음 문항/결과로 넘어가는 경로도 있었다. 두 경로를 코드와 재현 검사로 확인하고 수정했다. 특정 학생의 당시 사건이 이 원인 하나 때문이었다고 단정하지 않는다.

기존 요청의 2초 제한, 마지막 문항 뒤 대기배정 처리, 보수적인 서버시각 동기화는 유지했다. 네트워크 대기 자체가 20ms가 되는 것은 아니다. 이번에는 서버·DB·점수·포인트·권한을 변경하지 않았다.

### 실제 브라우저 — 가짜 자료만 사용

격리된 `127.0.0.1:3037`에서 실제 앱 빌드와 가짜 서버로 검사했다. 뜻 고르기 첫 시험 3답, 영영풀이 첫 시험 2답, 예문 재시험 1답을 제출했다. 답 요청 6회 모두 200, 다음 문항 준비 5회 모두 200, 중복 저장 0이었다. 연속 클릭은 한 문항만 진행했고, 오답과 Enter 입력도 자동 진행됐다. 영영풀이 답 선택 뒤 음성 이벤트 수는 증가하지 않았고 수동 스피커의 재생은 관찰됐다. 운영 학생에게 제출한 답은 0개다.

정확한 20/200ms 경계는 자동검사로 확인했다. 실제 화면은 자동 진행·중복 입력·음성 분리를 확인한 것이며 사람이 200ms를 계측한 것은 아니다. 화면 빌드 뒤 추가한 구형 서버 대기시간 보완은 최종 5/8/10초 검사와 재빌드로 검증했다.

가짜 서버가 지원하지 않는 학생 대시보드·결과 상세 조회에서 오류 화면이 나왔다. 마지막 답 뒤 **결과 경로로 이동**은 확인했지만 이 가짜 환경의 결과 점수 화면을 통과로 기록하지 않는다. 실기기 터치/운영 학생 응시는 하지 않았다. 검사 서버는 정상 종료했다.
