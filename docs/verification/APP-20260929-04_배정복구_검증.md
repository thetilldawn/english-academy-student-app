# 배정 저장 결과 확인 보완

F04는 서버 저장 뒤 응답이 끊긴 상태를 일반 실패로 취급하여 변경된 요청·새 식별키로 다시 저장할 수 있던 문제다. 운영에서 중복 발생을 확인한 것은 아니며 가짜 저장 영수증으로 재현했다.

범위 배정에만 최초 완성 요청·식별키·미리보기 서명·원래 결과 검증기를 보관한다. network/5xx/잘못된 성공본문/취소는 미확정 상태로 두며, 이후 4xx도 첫 요청이 저장되지 않았다는 증거로 쓰지 않는다. 명시적인 '저장 결과 다시 확인'만 원요청을 재전송한다. 날짜/학년 확인/예상 개수를 새로 계산하지 않는다.

확인 전에는 초안·별도 일정·학생 제외/복원·목적 전환·닫기·폐기를 잠근다. 기존 이탈 보호로 내부 이동/뒤로가기를 막고 새로고침/종료 경고를 제공한다. 단일 범위와 제외 후 1명인 일괄도 같은 경로이며 기존 독립 오답/수정의 기본 흐름은 변경하지 않았다.

## 검증

- 전체 배정 기능과 이탈 보호 104파일946검사 통과. 마지막 경합 보완 후 UI+보호 54검사와 최종 관련4파일103검사를 재통과했다.
- 모의 저장 후 응답 유실, 503, 본문 형식 오류, 취소, 미확정 뒤400/401/403/404/409/422, 변경 입력/마감 경과, flow 재생성, 복구 이중 클릭을 검사했다. 원래 요청/키 동일·모의 영수증1개를 확인했다.
- 기존 날짜/미리보기/학년 확인/단일·일괄 구분·실제 인증 시 개인정보 제거 회귀를 유지했다. 실제 401/403은 상위 작성창을 제거한다는 독립 검토를 반영했다.
- 독립 리뷰에서 찾은 두 경합을 추가 수정했다: 제거된 화면의 늦은 성공은 history.back/닫기/성공 통지0, succeeded 렌더가 await보다 빨라도 성공/닫기/보호용 뒤로가기 각1회. 독립 재검토에서 차단 지적 없음. 리뷰어의 코드 검토와 메인의 테스트 실행을 구별한다.
- 타입/lint·기능지도·화면구조·설계 검사를 통과했다. 최신 입력 확인값과 완료 관문은 같은 번호 기록에 있다.

## 한계

동일한 인증 화면이 살아 있는 동안만 최초 요청 복구를 보장한다. 강제 종료·실제 인증 상실 뒤 보존하려면 별도 서버 인증 복구 설계가 필요하므로 완료로 주장하지 않는다. 개인정보를 localStorage에 저장하지 않았다. 이 작업의 새 브라우저 운영 저장은 하지 않았으며 실제 부품/이탈보호 검사를 사용했다. 운영·실학생 쓰기/DB변경/새 배포0. 전체 빌드는 순차 수리 통합판에서 다시 확인한다.

다음 입력은 F05 검토 문항 후보의 페이지 조회 누락이다. 상태·순서는 루트 대장만 따른다.
