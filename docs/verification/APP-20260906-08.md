- 요구 R1~R4, 결정 D1~D6, 검사 T1~T7은 같은 번호의 지시서/작업 기록과 연결한다.

## 성능 비교 T5

동일 조건 준비 실행 1회는 별도 보존한 뒤 최초 진입 10회, 실제 Link 왕복 10회를 비교했다. DOM의 유효 목록 표시 후 두 프레임까지 측정했다. 사전 로딩·RSC·API와 데이터 조회 횟수를 원본 JSON에 함께 보존했다.

| 항목 | OFF 중앙값 / p95 | 최종 ON 중앙값 / p95 |
|---|---|---|
| 최초 학생 목록 | 51.75 / 339.80ms | 49.45 / 61.90ms |
| 학생 목록 재방문 | 321.60 / 329.40ms | 69.55 / 79.60ms |
| 배정 화면 재방문 | 323.50 / 330.80ms | 320.70 / 331.30ms |

- 학생 재방문 약 78.4% 개선, 최초 표시 악화 없음. 30% 개선 / 최초 10% 악화 제한을 그대로 통과했다.
- 최종 ON 왕복은 준비용 첫 문서 1회를 포함하여 인증 21, 프로필 21, 전체 학생 목록 조회 11, 현재 포인트 조회 10이다. 전체 목록 11 = 첫 문서 1 + 배정 화면 10. **학생 재방문 10회의 전체 목록 조회는 0**이다. 현재 인증/포인트 요청까지 0이라고 표현하지 않는다.
- 최초 준비 실행도 OFF 493.3ms / ON 498.5ms로 약 1.05% 차이였다. 최초 인증/목록 각 1회, 중복 Client 조회 0.
- 1차 Client 전용 진입은 약 103ms로 최초 진입 기준을 실패했다. 기준을 낮추지 않고 D6의 최초 서버 렌더 자료 인계로 수정했다. 1차 측정도 삭제하지 않았다.
- 배정 화면은 아직 학생 캐시가 연결되지 않아 개선되지 않았다. 이 작업으로 관리자 전체 캐시 완료를 주장하지 않는다.
- 실제 DB 쿼리 실행 비용·운영망 성능·요금 감소는 미측정이다. 대역 DB/API 요청 횟수와 실제 로컬 브라우저 표시 시간만 검증했다.

## 자동 검사와 독립 검토 T1~T4/T6/T7

- 최종 전체 단위/부품/계약: 406파일 / 2,479검사 통과 (2026-09-06 09:40 KST 시작).
- 타입, lint, 구조/변경 기록 연결, 요청 내 React cache(calls=2), 새 Next 배포형 빌드 통과. 구조 전용 4파일 71검사.
- 이후 완료 관문에서 기존 공용 부품 테스트의 소유 연결 누락을 발견해 D7/T8로 보완했다. 관련 작업 기록 검사 112개와 lint/구조·격리 새 빌드를 다시 통과했다. 전체 2,479는 이 메타 검사 3개 추가 전 실행임을 구분한다.
- 환경을 주입하지 않은 직접 build는 APP_ORIGIN 누락으로 실패했다. 실제 환경을 복사하지 않고 대역 전용 환경의 격리 빌드를 재실행해 33경로를 통과했다.
- 15/60/120초 경계, 포인트 비보관·현재 조회, 동시 요청 합침, 취소된 옛 인증 실패 무시, 인증 세대/계정 전환·로그아웃 실패 폐기, 탭 복원·변경 무효화, 필터/더보기 폐기를 검증했다.
- SSR renderToString → hydrateRoot 인계 및 첫 조회 중복 0을 검사했고 Client 재진입에서 옛 서버 인계 자료를 인증 근거로 재사용하지 못하게 했다.
- 정상 0명과 조회 실패·권한 실패·60초 만료를 구분한다. 실제 로컬 화면에서 정상 목록과 만료 시 “최신 학생 목록을 다시 확인해 주세요.” 및 다시 확인 동작을 확인했다.
- 읽기 전용 코드/서버 독립 리뷰의 취소 응답, 세션 전달, 포인트 값 형식, 계층 import 보완 후 재검토에서 미해결 P1/P2 없음.
- 저장/삭제는 가짜 단위 검사로 검증했으며 실제 학생 대상으로 실행하지 않았다.

## 과정 중 문제와 복구

첫 대역 서버 종료 시 Windows 제한으로 하위 프로세스 정리가 실패했다. 대상 명령/부모 관계를 별도 읽기로 확인한 뒤 이 검사의 프로세스 2개만 종료했다. 기존 .next를 복구했고 실패 시험 빌드는 임시 구역에 보존했다. 후속 OFF 검사는 승인된 프로세스 환경에서 정상 종료했다. 앱 기능 오류나 테스트 통과로 혼동하지 않는다.
