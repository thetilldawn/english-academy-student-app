모든 HTTP 성공·오류에 `private, no-store`를 확인했다. API는 인증을 한 번 한 뒤 검증된 서버 세션을 조회 함수에 전달한다. 서버 컴포넌트가 직접 호출할 때는 조회 함수 내부에서 인증한다. React cache가 Route Handler의 중복 인증을 합쳐 준다고 가정하지 않는다.

기존 관리자 `uniqueWordCount`는 미해결 단어 수로 보존했다. 학생 `wordCount`는 해결 여부와 관계없이 과거에 틀린 전체 단어 수다. 책 조건은 해당 출처가 있는 단어를 고르는 것이며 횟수는 그 단어의 전체 누적이다. 과거 답안을 다시 채점하거나 사전·발음을 생성하지 않았다.

SQL은 추가 읽기 함수뿐이다. 관리자 v2는 기존 관리자 인증을 거치고 학생용 함수는 서비스 계정만 실행한다. 공유 집계는 호출자 권한으로 실행하며 순수 단어 식별 helper 외 일반 사용자 권한을 넓히지 않았다. 현재 모든 migration을 적용한 가짜 최종 DB에서도 실제 서비스 계정의 읽기·관리자 기존 결과 일치를 확인했다.

## 실패 이력과 보완

1. 독립 검토에서 201자 검색어의 조건키 계산이 렌더 예외를 낼 수 있음을 발견했다. 초안 키 계산은 검증 예외를 내지 않게 하고 전송 경계에서 안전한 입력 오류로 거절했다. 수정 후200자 복구까지 검사했다.
2. HTTP 인증 후 조회가 재인증하는 불필요한 호출을 발견했다. 검증된 전체 서버 세션만 전달하도록 보완하고 본인 식별자/인증 횟수 검사를 추가했다.
3. 중간 전체 실행은 동시 부하에 따른 시간 초과와 코드 수정 중 실행이 겹쳐 중단했다. 그 결과를 최종 근거로 재사용하지 않고 코드를 고정한 뒤 worker4·검사 제한시간을 명시해 전체를 다시 통과했다. 앱의 시험 시간 설정은 바꾸지 않았다.
4. 첫 로컬 Webpack 빌드는 컴파일·타입 검사 뒤 `APP_ORIGIN` 누락으로 사전 페이지 처리에 실패했다. 프로세스에만 로컬 주소를 지정해 전체 빌드를 다시 통과했다. 환경 파일·운영 설정 변경은 없다. 기본 Turbopack의 기존 로컬 폴더 연결 제약을 해결했다고 표시하지 않는다.
5. 작업 기록 변경 연결에서 공통 진입점의 간접 배정 흐름·기존 학생 목록·옛 SQL 검토 범위가 빠진 것을 발견했다. 이후 완료 검사에서 일부 경로에 관련 없는 학생 흐름까지 적혀 있음을 확인했다. 실제 지도와 정확히 일치하도록 이번 기록의 연결만 보완했고 원 코드와 옛 SQL 변경은 없다.
6. 검사 작성 중 가짜 SQL 자료의 식별자 충돌과 테스트 행의 타입 선언 오류를 고쳤다. 최종 SQL15개·전체4196개·타입/빌드 결과는 수정 후 실행이다.

독립 검토의 후속 설계 보완도 전체 계획에 반영했다. 본인 오답임을 확인한 뒤 기존 발음/음원 조회를 연결하고, 여러 책의 원출처·뜻을 유지하며, 교사 시험의 포인트0을 서버 저장·채점 정책으로 강제한다. 기존 단일 책 미해결 복습 후보를 전체 누적 오답으로 대체 사용하지 않는다.
