# 모고 발음 연결과 운영 반영

## 요청과 보완 이력

사용자는 2024·2025 모고 전체의 사전 발음 우선 연결과 미보유 표기의 상위모델 검토, 운영 반영을 요청했다. 원사전·원음·학생 시험 기록은 보존한다. 사용자 화면 확인은 사용자가 한다.

첫 Preview 거래는 29항목의 품사 비교에서 중단되어 전부 롤백됐다. 27항목은 복합어/숙어의 음원 분류가 other이고 시험 자료에는 실제 품사가 있다. equivalent/gourmet 2항목은 품사 간 같은 발음을 공유함을 사전 근거와 상위모델로 확인했다. 따라서 데이터만 등록하면 끝난다는 최초 판단을 보완한다. 이번 연결 오류에 필요한 DB 필드·조회 조건 한 곳만 수정하며 화면·프런트엔드 배포는 하지 않는다.

## 요구·결정·검사

- R1: 사전와 신규 검토값 253개를 정확 연결하고 기존25개 보호. T1/T2/T3/T5.
- R2: 원음·identity·시험 원문·배정·응시·답안 보존, 구판 새 배정만 숨김. T1/T4/T5/T6.
- D1 사용자 확정: 두 예시에 한정하지 않고 전체 점검·상위모델 검토 후 운영 연결. 새 학생 시험 생성이나 청음 완료 주장은 하지 않음.
- D2 내부 결정: identity_lexical_pos가 NULL이면 기존 품사 일치 경로 그대로. 명시값은 원음 품사와 일치해야 하고 검토된 시험 분기에서만 허용. 시험 자료 품사는 기존 lexical_pos와 별도로 일치시킨다. 29개만 명시, 224개·과거 행은 NULL.
- D3 내부 결정: 같은 연결 오류의 소규모 보완이다. 원음 identity나 검토된 시험 payload를 다시 쓰지 않는다. 앱 재배포 없이 DB migration 한 건 + 정확253행 거래만 실행한다.

## 영향과 복구

입력은 해시가 고정된 교정자료·원음 품사 근거이고 출력은 기존과 같은 발음 조회 응답이다. 일반 발음 binding, occurrence, registry의 판정은 그대로다. 익명/학생 직접 실행 금지와 서버 조회 권한, 최대400행, 빈 search_path, 사용자 승인 우선, 기존 캐시 정책을 유지한다. UI·경로·상태·학생 입력은 변경하지 않는다.

실패하면 한 거래로253행과 구판 표시를 되돌린다. 새 NULL 열은 과거 행의 의미를 바꾸지 않는다. DB 구조 되돌리기가 필요하면 이번 명시 품사 행 제거 후 기존 조회 정의를 복구한다. 확인 없이 다른 배정/원음/학생 자료를 복구 대상으로 잡지 않는다.

## 검사 계획

후속 확인: 음원 이름이 settle on/upon, 시험 이름이 settle on[upon]인 정확1개도 분리 증명이 필요했다. 두 대안을 모두 읽는 원래 음원 계획과 상위모델 검토를 재사용한다. nullable identity_headword를 두 번째 migration으로 추가하고, 이름 또는 품사 명시값이 있으면 일반 경로를 차단한다. 시험 표제어·원음 표제어를 각각 정확 비교하며 별칭 추측·정규화는 하지 않는다. 278개 실제 근거에서 명시 이름1개·명시 품사29개만 허용한다.

T1 기존 최종 DB 스키마의 세 경로·권한·잘못된 품사·명시값 일반 경로 우회 차단.
T2 검토된 시험에서 두 품사 별도 증명·없는/틀린 명시값·변경 payload·승인값 보호.
T3 기존 실제 공통 선택기·단어보기의 표시/음원/실패 처리 검사.
T4 형식→설계 기록 검사와 변경 파일 정적검사.
T5 Preview→운영 253개 실제 조회와 보호28영역 전후 비교. 과거 교정표는 새 nullable 열을 제외한 기존 값 비교와 모든 과거행 NULL을 함께 검증한다.
T6 독립 코드/실제 행 검토. 전수 청음·사용자 브라우저 검사를 완료로 처리하지 않음.
