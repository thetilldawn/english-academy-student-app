# 검토 증거 공유·복구 검증 결과

검토 근거에 반복되는 같은 객체를 한 번만 저장하고, 기존 조회에서는 원래 내용을 돌려주는 도구를 구현했다. 구현 커밋은 `5cbf95c`다. 구현·격리 검토 DB 검증 범위의 결과이며 운영 DB·배포·실제 학생 쓰기·물리 용량 회수는 모두 0이다.

## 변경과 확인

대상은 `private.reviewed_mock_source_resources_v1.payload` 안에서 명시한 증거 위치뿐이다. 단어·뜻·발음·선택값과 임의 중첩 필드는 변경하지 않는다. 숫자 `1/1.0`도 서로 다른 원형으로 보존하며, 배열의 순서·중복·추가 필드·null을 유지한다. 같은 증거는 자료판을 넘어 공유한다.

기존 자원 조회 함수 한 곳만 복원 읽기를 연결했다. 함수 식별자·실행 권한·안정성·설정과 최대400개 제한을 보존했고, 종료된 자료도 기존처럼 조회됐다. 자료 등록기는 들어오는 새 입력을 검증하고 같은 등록 요청을 재사용하므로 저장된 payload를 읽지 않는다. 기존 직접 UPDATE/DELETE 금지는 유지하고 정상 INSERT와 내부 일회 변경을 구별했다.

명시100행 이내를 준비하고, Git 밖 파일 저장·디스크 확정·재읽기 후 전환한다. 준비 단계는 증거 본문을 DB에 복제하지 않는다. 참조·명세·새 공용 객체 비용까지 포함해 작아지는 묶음만 허용한다. 일부 행 전환이 손해가 되면 전체 취소하며, 같은 요청은 이후 상태와 관계없이 최초 응답을 재사용한다. 복구는 지정 payload만 되돌리고 공용 증거·학생 기록은 유지한다.

## 한계와 수정한 검사 오류

검토 DB의 물리량은 819,039,379→819,793,043B였다. 가짜 자료와 검증용 표가 추가된 결과로, 실제 용량 절감 측정값이 아니다. 운영 대상 수·제외 비용·공유 후 공간은 통합 명세에서 따로 계산한다.

로컬 SQL 별칭 충돌, 절감 최소비용보다 작은 숫자 보존 예제, 가짜 입력 파일명, 점수100/100.00을 문자열로 비교한 검사 오류를 수정했다. 점수 검사 때문에 취소된 두 거래는 반영되지 않았으며 숫자 비교로 다시 성공했다. 읽기 전용 열 이름 오기와 제한시간 종료도 근거에 구분했다. 수정 후 위 최종 검사 결과를 사용한다.
