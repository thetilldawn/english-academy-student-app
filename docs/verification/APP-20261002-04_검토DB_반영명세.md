# 임시 자료 정리 기능 — 검토용 DB 반영 명세

APP-20261002-04 / M06. 승인된 24시간 기준과 기존 D12 보관기간의 구현 검증이다. 실제 운영 기록의 최초 정리·정기 실행 활성화·Production 배포는 이 반영에 포함하지 않는다.

## 반영 대상과 파일

- 대상: Preview `wojxpruvbjzbhrpmsbuy`만. Production `xdxhswjgksukjmpbzqgz` 제외.
- 파일: `supabase/migrations/20261002140634_retain_operational_logs_and_preparations.sql`
- SHA-256: `af3db832a99b36327586ef11ca66a0675045613dc285de477bbe6de4c94e5453`
- 기준 커밋: `4611b9d1b00c2980542454b5e9b650588125aadf`.
- 원격 DDL은 Supabase apply_migration으로 적용한다. 실제 정리 함수는 migration 중 호출하지 않는다.

## 변경 내용과 보존

private 정책·허용 작업·보존 표시·분류별 최신 실행 상태·준비 만료 확인·구형 본문 복원 확인 표 6개를 추가한다. 정책 한 행과 현재 SQL/소유자/DB가 정확히 일치하는 기존 예약 작업 허용 목록만 초기화한다. 기존 cron 일정은 수정하거나 추가하지 않는다.

운영자 postgres만 미리보기·보존 설정·제한량 정리를 실행할 수 있다. 익명/학생/일반 로그인/service_role에는 이 운영 기능을 공개하지 않는다. 기존 학생 시작 함수 7개는 서명·OID·소유자·권한·SECURITY 설정을 유지하며, 정리된 준비를 다시 시작하지 않도록 작은 만료 확인표 검사를 추가한다. 이 보호 함수만 기존 시작 경로에 필요한 service_role 권한을 부여한다.

실제 학생·배정·응시·문항·답·결과·오답·포인트·M05 기기 제출 복구·공용 내용은 삭제하지 않는다. 미시작 준비를 지울 때도 학생/준비 잠금과 실제 응시 대조 뒤 ID/요청/만료 확인을 보존한다. 이미 시작된 새 참조 형식은 정리하지 않는다. 구형 본문은 기존 실제 문항 참조로 완전히 복원되는지 확인하고 24시간 뒤 다시 대조하여 바꾼다.

## 적용 전 검사

로컬 새 DB 검사 21개 통과. 전체 실행 중 기존 가상 cron 구조가 빠진 7개 검사 파일을 수정했고 재실행 101개 통과. 나머지 609파일의 4,871개 통과와 합쳐 616파일 / 4,972개 통과, 기존 제외 1개다. 타입·변경 파일 lint·기능 지도·화면 구조·설계 기록·React 요청 캐시·Webpack 빌드와 공개 오프라인 자산 25개 검사 통과. DB/복구 두 서브에이전트가 읽기 검토를 마쳤다.

첫 구조 검사 실행에는 React 서버 실행 조건을 빠뜨려 검사 명령이 실패했으며, 정해진 `--conditions react-server` 명령으로 재실행하여 통과했다. 앱 코드를 바꿔 이 검사 실패를 숨기지 않았다.

## 적용 후 검사와 경계

변경 전후 기존 표의 행 수/내용 확인값과 기존 시작 함수 7개의 권한·OID를 비교한다. 검토용 DB의 실제 이전 로그를 삭제하지 않고, 별도 가짜 학생/자료와 고정 과거 기준으로만 정리·재요청·잠금 충돌을 검사한다. 동시성은 두 연결의 PID·겹친 시각·잠금 대기 또는 skip/busy 결과가 있을 때만 통과로 기록한다.

MCP SQL 요청 두 개는 순차 실행됨을 확인했다. 실제 동시성은 SQL과 별도 HTTP 요청을 사용한다. 운영 정리 기능을 HTTP로 검증할 필요가 생기면 Preview에서만 제한된 임시 검사 함수를 설치하고, 정확한 허용 가짜 후보 검사와 service_role 제한을 둔 뒤 검사가 끝나면 제거한다. 이 검사 도구의 설치/제거 SQL과 해시는 실제 적용 전에 별도 부록으로 기록한다.

## Preview 임시 동시성 검사 도구 명세

운영자 MCP SQL은 직렬 실행되므로 SQL 연결과 HTTP 연결을 함께 검사한다. 실제 앱 시작·갱신 함수의 HTTP 호출과, 고정된 가짜 자료만 허용하는 임시 `public.m06_preview_retention_probe_v1(text)`를 사용한다. 이 함수는 임의 SQL·학생·기준시각·개수를 받지 않고 정해진 검사 종류만 받는다. postgres 소유/빈 search_path/실제 service_role 확인, PUBLIC·anon·authenticated 실행권한 없음, service_role만 허용한다.

정리 기준은 2000-01-20의 사례별 고정 초이며, 후보 전부가 가짜 식별자 목록인지와 hasMore=false를 확인한 뒤 실제 private 정리 함수를 호출한다. 중복 실행/cron 잠금 검사는 실제 정리 함수의 55P03만 성공 근거로 받고, 뜻밖에 성공하면 검사 거래 전체를 취소한다. 조사 보존 검사도 삭제된 가짜 한 건만 대상으로 한다.

설치 SQL: `.codex-tmp/m06-helper-install.sql`, SHA-256 `d0a2120073c2e05b1317696d29aa5f1d816c0689dd74b630b1001a1bab84e1b7`. 제거 SQL: `.codex-tmp/m06-helper-remove.sql`, SHA-256 `13eed4ec53ac29f8a0b64bc1ed9017ab8f3b2c77538d92a31c0ca677ff3818a0`. 설치 직전 내용을 다시 대조하고, 검사 후 exact signature로 권한 철회·DROP·스키마 갱신 및 존재0을 확인한다. 운영 migration에는 이 검사 함수를 넣지 않는다.

가짜 자료는 관리자1명·학생3명·단어4개·배정2개·만료 준비2개와 실제 시작용 준비1개·세션2개·예약 실행 상세1개다. 모두 `M06-a608` 소유 표식을 확인하며, 기존 기록/운영 일정은 변경하지 않는다. 필요한 가짜 실제 응시·작은 불변 확인은 종료 표시로 보존하며 트리거를 해제하지 않는다.

### 실제 권한 확인 뒤 후속 반영

첫 SQL의 cron.job 행 잠금은 실제 Supabase의 SELECT 전용 권한에서 42501로 거절됐다. 기존 표 권한은 확대하지 않는다. 후속 파일 `supabase/migrations/20261002151801_validate_cron_retention_with_read_permissions.sql`, SHA-256 `6f37cf30c870bcb820df4c65cd6629a9c9bfbe1b39cac37a5dea7f3e0b938461`은 운영 정리 함수 한 개만 교체한다. 테이블·일정·권한·기존 행은 바꾸지 않는다.

실제 상세행만 잠그고 각 DELETE에서 현재/과거 작업, 허용 목록, 종료 기간, 보존 표시, 상세 전체 확인값을 다시 대조한다. READ COMMITTED를 강제하며 실제 삭제 행 수만 합산한다. 이 조건은 DELETE 시작 당시 확정된 설정을 뜻한다. 그 뒤 확정된 설정 변경은 다음 DELETE에서 반영된다. 상세 삭제 후 같은 거래 안의 가짜 트리거로 설정을 바꾸는 회귀는 이후 DELETE의 재대조를 확인하며, 다른 연결의 변경 확정까지 직접 재현한 검사라고 주장하지 않는다.

보완 로컬 검사23개 통과, 타입/변경lint 통과. PGlite는 실제 Supabase의 비최고관리자 권한을 그대로 재현할 수 없어 SELECT-only 검증은 원격 권한 조회와 42501 재현, 후속 반영 뒤 가짜 상세 삭제 성공으로 확인한다. 실패한 cron 잠금 경합 사례는 폐기하고 완료 근거에 포함하지 않는다. 설치한 임시 검사 함수의 cron_locked 모드는 더 이상 호출하지 않고 나머지 가짜 자료 검사 후 도구 전체를 제거한다.

## 복구

정리 실행을 멈추면 후속 삭제가 없다. 아직 스케줄을 추가하지 않았으므로 일정 해제 작업도 없다. 정리한 운영 로그 복구가 필요한 경우 확인된 해당 로그만 복원하고 학생 DB 전체를 되돌리지 않는다. 만료 확인표를 사용하는 기존 시작 함수는 표만 먼저 제거하지 않는다. 가짜 검사 도구는 이 기능의 운영 코드와 별도로 제거한다.

반영 결과·원격 버전·보존 검사·실제 경합 근거는 후속 검증 결과 문서에 기록하며, 이 명세 자체를 원격 적용 완료로 보지 않는다.
