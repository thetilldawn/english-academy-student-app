## 확인한 현재 구조

- M01 공용 사용값은 구현·검토 DB 검증을 마쳤다. 기존 범위·단어장판은 읽고 신규 참조 형식과 비교할 수 있다.
- 학생별 배정 문항, 응시 문항, 시험 출현의 발음/보기 부속 기록, 준비 계획, 자율연습 문항에 본문 사본이 있다.
- 앱 직접 조회는 7개 파일 8곳이다. 본문을 사용하는 5경로와 식별자/진행만 사용하는 3경로를 구분한다. 채점·시간·답 저장은 작은 개인 열만 읽으므로 본문 복원을 넣지 않는다.
- 기존 준비 확인값은 배정/AQ 전체 행을, 현재 오답 검토 서명은 QQ 전체 행을 해시한다. 참조 열 추가 전 원래 행 모양을 고정해야 한다.
- 일반 생성은 base INSERT 다음 v2 UPDATE를 한다. 정확한 오답 생성은 마지막에 보기 ID를 확정한다. 개인 오답 AQ는 생성 후 UPDATE가 금지된다.

## D2 저장과 불변성

기존 사전·문제은행의 승인/생성 기능을 추가하지 않는다. 이미 선택된 내용을 한 번 보관하는 private 저장 표와 기존 불변 문항의 참조만 추가한다. 이 표에 있다는 이유로 출제 승인되지는 않는다.

1. 공용 저장 키는 형식, 대상/보기의 자료 범위, 원문항의 전체 FK 묶음, 대상 단어·방향·보기 순서·정답 위치, 생성/검토 규칙판, 고정 사용값의 확인값으로 만든다. 해시 충돌 시 JSON/길이도 비교하며 INSERT ON CONFLICT DO NOTHING 다음 별도 SELECT로 동시 등록 결과를 읽는다.
2. 구성/검토/canonical 문항은 기존 문항 FK로 질문·보기·발음을 복원한다. 이미 그 문항에 있는 본문을 새 공용 표로 복사하지 않는다. 당시 표제어·뜻·추가 근거처럼 기존 문항에서 정확히 복원할 수 없는 값만 별도로 한 번 고정한다. 최신 vocab_entries 값으로 과거 값을 바꾸지 않는다. 독립 검토에서 canonical/reviewed 원행의 불변 보호가 불충분함을 확인했다. 실제 기존 쓰기는 INSERT뿐이므로 이 두 원표의 내용 UPDATE를 거절하는 보호를 추가하고, 공용 값이 참조한 원행 삭제는 FK로 막는다. 자료판 활성/숨김 상태 변경은 별도 release 표이므로 그대로 유지한다. 참조 존재 여부만 읽는 조건부 보호는 동시 등록과 오래된 거래 스냅샷에서 빠질 수 있으므로 사용하지 않는다. 수정은 새 문항/판으로 등록한다.
3. 일반/개인 오답/구형 범위에서 최종 생성한 질문·보기는 최초 검증한 그대로 고정한다. 개인 오답의 학생 ID, 원응시/원문항/오답 사건, sourceHash, 날짜·순서는 공용 본문이나 재사용 키에 넣지 않는다. 원본 notebook_source_snapshot의 study만 분리한다. 사건·순서가 섞인 기존 question_content_sha256도 개인 행에 그대로 남기며 공용 해시로 재사용하지 않는다.
4. AQ/QQ의 기존 ID/FK/작은 출처키, 순서, 정답 위치, 답안·시각·정오·오답 횟수는 현재 열에 남긴다. content_version_id가 있는 신규 행의 긴 본문만 null로 저장한다. 기존 행을 일괄 갱신하거나 지우지 않는다.
5. 원문항 FK·복합 고유 제약은 유지한다. 본문 관련 기존 CHECK와 NOT NULL은 복원한 동일 행에 같은 SQL 조건으로 적용한다. 단순히 참조가 있다는 이유로 검증을 생략하지 않는다. 존재/해시뿐 아니라 대상·방향·보기 ID 순서·정답·원문항 전체 FK 묶음의 일치도 검사한다.
6. 공용 내용과 개인 문항의 참조는 생성 후 불변이다. QQ 답안·시각 등 개인 진행 열은 기존 경로로 갱신한다. 정답 판정 시 공용 본문 조회를 추가하지 않는다.
7. 원자료가 비활성/숨김 상태가 되어도 기존 시험 복원은 고정 참조로 가능해야 한다. 신규 배정의 현재 사용 가능 여부는 기존 생성 검사에서 확인한다.

## D3 쓰기 경계

배정의 본문은 기존 검증을 모두 통과한 다음 같은 거래에서 공용 참조로 바꾼다. 중간 단계에서 압축하여 후속 검사를 우회하지 않는다.

| 최종 함수 | 마무리 위치 |
|---|---|
| 일반 exam-use dispatch | 일반/시험 출현 결과 반환 2곳 |
| system dispatch | 예약용 일반/시험 출현 결과 반환 2곳 |
| exact dispatch | persist_exact_review_question_plan_v1 다음 반환 1곳 |
| reviewed bank | canonical 분기/일반 검토판 반환 2곳 |
| composition bank | 보기 충돌/개수/판 확정 다음 반환 1곳 |
| canonical preview | 원본 최종 반환 1곳 |
| notebook | INSERT의 기존 출처·보기 검사를 한 뒤 저장 직전 공용 참조 생성 |

원본/복제 base·v2·v3를 중복 패치하지 않는다. 실제 최종 함수의 치환 기대 수를 검사하여 예상과 다르면 적용을 중단한다. AQ의 완료 공통 함수는 시험 출현 부속 본문도 함께 처리한다. 개인 오답은 UPDATE로 압축하지 않는다.

QQ 신규 INSERT는 연결된 AQ와 내용/정답이 일치하는지 확인하고 같은 공용 참조를 쓴다. AQ가 없는 구형 범위 계획도 고정 본문 참조를 등록한다. 응시 기록을 최신 단어로 재생성하지 않는다.

## D4 준비·연습

- 새 준비 plan은 명시적 v2 형식과 문항 참조·고정 ID·순서만 저장한다. 기존 v1 plan은 그대로 읽는다. get의 서비스 전용 응답에서는 기존 raw plan을 복원하여 TS 계약을 보존한다. 준비 때의 random 순서를 조회/시작 때 다시 추첨하지 않는다.
- 기존 준비/오답 확인값은 복원한 구형 전체 행에서 새 참조 열을 제외하여 계산한다. 이전 준비와 서명이 바뀌지 않았다는 실제 전후 검사를 한다. 원래 확인값을 무시하거나 다시 서명하지 않는다.
- 자율연습 prepare는 아직 출처/보기 검증 전이다. 저장된 값은 승인 자료로 취급하지 않으며 begin→기존 start의 전체 검증을 그대로 통과해야 한다. 개인 선택 wordKey 등은 개별 계획에 남기고 표시값만 공유한다.
- 연습 문항은 기존 body에 wordKey와 correctChoiceIndex 및 필요한 개인 연결만 남긴다. 공용 값과 정답 위치의 일치를 생성 때 검사하며 답 저장/재전송은 이 작은 정답 값으로 판정한다. 조회만 복원하므로 M11 완료 확정·정답 가림·시각·영수증을 바꾸지 않는다.

## D5 읽기·권한

SQL 본문 소비자는 좁은 복원 함수/내부 뷰를 사용한다. FOR UPDATE/SHARE, 채점, 진행 갱신, 개수·ID 조회를 일괄 치환하지 않는다. v1 행만 기존 본문을 직접 읽으며 참조가 있는데 깨진 경우 현재 사전/빈 값으로 우회하지 않는다.

서버 전용 복원 모듈은 quiz-player/server/queries에 두고 실행 중 시험, 준비, 결과·관리자 상세가 공유한다. 결과는 기존 변환 함수를 계속 거쳐 정답/발음 공개 시점을 유지한다. 학습 예문과 관리자 오답 이력도 당시 표시값을 복원한다. 식별자만 읽는 배정 수정/중복 검사/시작 직후 조회는 유지한다.

공개 RPC에는 공용 내용 ID를 직접 받는 조회를 만들지 않는다. 학생 응시/준비/학습 또는 관리자 응시/학생 이력 문맥과 개인 문항 ID를 받아 같은 응시·배정·준비 계획 소속인지 DB에서 다시 검사한다. 최대 200개씩 묶는다. 기존 active admin/student, service-role 경계를 유지한다. private 표의 직접 조회 권한은 열지 않는다. 기존 invoker 함수의 private 접근은 서비스 검사를 가진 명시적 함수 경계로 해결한다.

## 흐름과 화면

생성/배정은 기존 관리자 검증 후 같은 거래에서 참조를 완성한다. 응시 시작은 기존 시각/잠금/멱등키를 유지한다. 조회는 현재 권한과 고정 내용을 결합한다. 검색/페이지 분할은 현재 기준을 유지하며, 원템플릿 변경은 새 판으로만 반영한다. 템플릿 숨김과 참조 중 자료의 물리 삭제를 구분한다. 결과·점수·로그의 보존은 기존 정책이며 축약/삭제는 M03/M04/M06/M08의 별도 범위다.

새 메뉴·스타일·모달·URL 변경은 없다. 서버 결과와 준비 화면 연결이 달라지므로 실제 PC/모바일 준비→시작→복구→결과 대표 확인은 필요하다. 실패 시 기존 진행/오류 영역을 사용하고 준비 선택과 서버의 시작 시각을 보존한다. 내부 SQL/정답/키를 사용자 문구에 넣지 않는다. 정상 0건·없는 시험·권한 실패·자료 연결 오류를 같은 빈 목록으로 취급하지 않는다. 구체적 상태/문구/부품은 정식 R/D/T 기록에 연결한다.

캐시는 이번에 추가하지 않는다. 서버 요청 내 참조 조회만 묶으며 개인 진행·정답을 공유 캐시에 넣지 않는다. 새로운 브라우저 재시험 캐시는 M05 결정 후 별도 수행한다.

### 조회 사이 준비가 바뀌는 경우

첫 준비 조회와 본문 조회 사이 다른 탭이 시작하면 같은 영수증을 다시 읽어 기존 응시로 연결한다. 이때 새 시작 명령은 보내지 않는다. 준비 만료로 재조회가 null이면 준비 변경 오류로 분류한다. 학생 시험·연습 페이지는 이 예상 가능한 오류만 기존 PanelLoadFailure로 표시하고 시험 목록·내 단어장으로 돌아갈 수 있게 한다. 참조 손상·권한 오류는 이 경로로 숨기지 않는다. 본문 RPC 자체에는 정답 위치·개인 답안·진행 시각·공용 참조 ID를 넣지 않는다.
