# 사전 사용값을 공유하기 위한 구현 전 설계

입력: 전체 유지보수의 M01/M02 지시와 읽기 전용 서브에이전트 두 명의 최신 SQL·자료형 조사. 이 문서는 설계 초안이며 구현·DB 적용·자료 이전 완료가 아니다. 현재 작업 상태는 루트 작업 대장만 따른다.

## 확인된 문제와 저장 원칙

- 기존 로컬 등록 묶음48개/61,880,440바이트/19,596행을 값 전문 없이 형태로 조사했다. dictionary가 있는9,132행의 sense_id는 모두null이고8,716행의canonical_approved는false다. 이는 로컬 원고 조사이며 운영 전수 집계로 확대하지 않는다.
- 같은 표시값을 한 번 저장하는 `private.vocabulary_learning_value_versions`와 출처/선택 근거를 연결하는 `private.vocabulary_learning_value_bindings`를 분리한다. 원출현 ID·원문 SHA를 표시값 해시에 섞으면 출현마다 본문이 생겨 절감 효과를 잃는다.
- 새 내부 UUID는 저장 참조일 뿐 새 영어 사전 ID가 아니다. 기존 문자열 사전 ID·옛 UUID·앱 bigint·원출현·sense ID를 역할별로 그대로 보존한다. 앱 bigint는 문자열로 전달해 숫자 정밀도 손실을 막는다.
- `entryValues`는 headword/headword_normalized/pronunciation_ko/meanings/primary_meaning/english_definition/example_en/example_ko/entry_type을 가진다. 기존 문자열의 공백·대소문자·강세·meanings의 순서와 null 요소를 바꾸지 않는다. source_ref는 출처 연결에 둔다.
- `selectedFields`는 선택된 pronunciation/lexicalPos/definitionEn/exampleEn/exampleKo다. entry의 선택값과 다를 수 있으므로 서로 덮어쓰지 않는다. 발음은 기존 엄격한 계약을 재사용하고 음원 본체/base64는 허용하지 않는다.
- 출처 연결은 source(kind,datasetId,unitId,releaseId,version,fileHash,locator,sourceRow,occurrenceKey,state), entryLink(id,datasetId,unitId,sourceRow,rowHash,sourceRef), 원 entry/occurrence/selected/dictionary 전체 SHA, 최소 사전 식별자, 기존 ID 대응, proof 위치/해시/상태, 학습 의미 키를 포함한다. 원문·검토 전문·proof.value는 저장하지 않는다.
- proof 키는 audio/definition/dictionary_entry/dictionary_sense/example_en/example_ko/lexical_pos/pronunciation_ko/pronunciation_pos/pronunciation_variant/stress/source.headword/source.meaning/source.pos/source.display_headword/source.display_meaning 16개로 닫는다.
- 표시값과 연결은 자체 SHA·JSON 전체 동등성을 확인해 중복 등록한다. ON CONFLICT DO NOTHING 뒤 기존 본문 대조; DO UPDATE 금지. 두 표 모두 불변 트리거/RLS/직접 권한 취소, (selection_id,selection_sha256) 외래키를 가진다.

## 참조와 구형 호환

```text
resources.selected = {schemaVersion: vocabulary-resource-ref-v2, selectionId, selectionHash}
resources.selectionBinding = {schemaVersion: vocabulary-source-binding-ref-v1, bindingId, bindingHash}
resources.entryHash / linkRecordHash 또는 linkRecordHashes는 기존 계약 유지
```

등록 helper는 기존 entry/occurrence/resources/source를 받아 strict 투영 뒤 두 참조를 반환한다. 새로운 읽기는 `vocabulary-resource-selected-v2`를 반환하며 기존 v1과 명시적 union으로 구별한다. proofs.value=null을 지어 v1인 것처럼 반환하지 않는다. 깨진 ID/해시/연결은 실패시키고 최신 사전/빈 뜻/v1 우회로 채우지 않는다.

- 필요한 helper: project_vocabulary_learning_value_v1(immutable), project_vocabulary_learning_binding_v1(stable), register_vocabulary_learning_resources_v1(volatile), resolve_vocabulary_learning_value_v1(stable), resolve_vocabulary_learning_binding_v1(stable).
- 기존 vocabulary_composition_resource_v1은 DB 참조 읽기가 생겨 IMMUTABLE에서STABLE로 바꾼다. 고정search_path와 직접 실행 금지를 유지한다.
- 같은 SQL문에서 register를 호출한 직후 STABLE resolver로 새 행을 다시 읽지 않는다. 등록 결과를 사용하거나 다음 SQL문에서 조회한다.
- 승인 의미 연결은 mock_wordbook_identity_review의 출처판/원행ID/행SHA/검토 표제어/뜻까지 맞을 때 기존 의미 키를 재사용한다. senseId 존재나 dictionary.canonical_approved 입력 또는 vocab_entry_link.mapping_status만으로 의미 승인을 만들지 않는다.
- 미승인 학습 키는 원출현+원자료판+primary_meaning 필드+뜻/품사 확인값이다. 표시판 전체 SHA를 섞지 않아 발음/예문만 수정됐을 때 학습 의미가 갈라지지 않게 한다.

## 필수 검사와 M02 경계

같은 입력 재등록/동시등록, 같은 표시값의 출처2개, 같은 철자의 다른 뜻/발음, v1/v2 중복 범위, 원본문서만 변경, 승인 근거 불일치, ID/해시/FK 오류, 전문/임의키/base64거절, 음원·강세 전수 보존을 확인한다. 이전migration 전500/501행 준비중 자료의 재개, 신규501행 마지막배치 실패 뒤 재개, reviewed 범위 밖 보기와4발음, 보기 제외, 학생학습/오답/개인단어장 재배정도 검사한다. 기존 학생/배정/응시/사전 원본은 전후 확인값 동일해야 한다. PGlite 순차 중복 검사는 실제 두 연결 경합 검사를 대신하지 않는다.

M02는 개인 배정/응시 문항의 본문 제거를 맡는다. 기존 assignment_questions/quiz_questions의 ID/FK, 정답 위치 SQL 채점, 고정 보기 순서와 준비 영수증을 보존해야 한다. 원래 질문을 작은 공용판으로 읽는 SQL/TS 양쪽 resolver가 필요하다. whole-row 준비/오답 지문은 열 추가만으로도 바뀌므로 옛 지문 분기를 먼저 고정한다. 개인 단어장 스냅샷의 학생/원질문ID는 공용 자료에 섞지 않는다. 새 참조가 생긴 뒤 되돌릴 앱도 그 참조를 읽을 수 있어야 한다.

원자료/학생 행 이전·삭제는 이 설계로 자동 승인된 것이 아니다. 승인된 유지보수의 단계별 검증과 M08 회수 조건에 따라 진행한다.

## 구형 입력 경계 추가 검토

과거 SQL 읽기 함수는 선택 항목 일부가 없는 최소 v1도 읽었지만 앱 계약과 원고 가져오기 검사는 처음부터 전체 선택 항목을 요구했다. 기존 최소 v1 읽기·같은 원행 비교·이미 시작한 판 재개는 보존한다. 이 최소 자료를 새 참조로 만드는 경우에는 누락값을 만들지 않고 명시적인 오류로 중단한다. 새 입력 검사를 낮추거나 최신 사전으로 채우지 않는다. Preview 기존 범위 22,324행에서 10개 필수 키 누락0·다른 형식0을 읽기 집계했다. 운영 같은 집계는 연결 시간 초과2회로 미확인이며 실제 운영 적용 전에 확인한다. 로컬48개 원고와 Preview 집계를 운영 전수 확인으로 확대하지 않는다.
