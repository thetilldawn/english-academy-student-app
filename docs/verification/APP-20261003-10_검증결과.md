# 배정의 공용 확인값 공유 검증

신규 구성 배정의 원행·출제 적격 확인값 두 개를 기존 공용 문항판에서 읽도록 바꿨다. 학생·문항·배정 키와 원래 정답·보기·출처·뜻 검사는 유지한다. 기존 행은 바꾸지 않고, 새 INSERT 직후부터 두 중복 열만 비운다. 운영 DB와 실제 학생 자료는 변경하지 않았다.

## 로컬 근거

- 전체630파일·5,112검사 통과/기존 제외1, 표준 작업자4·368.63초.
- 핵심30검사: 신규8·앞선 저장 보완6·역사 자료 이전/복구16. 적용 전 준비를 원기기로 시작하고 새 시험의 최초·재시험·재접수·75점/미통과·오답 재배정의 원행 확인값 연결을 확인했다.
- 100배정×50문항: 공용50·배정/응시 각5,000·INSERT5,000·UPDATE0·인라인본문0·확인값중복0·확인값복원5,000·뜻연결5,000·응시/배정본문 차이0. 순차 저장 예시이며 동시 운영 가능 인원 검사가 아니다.
- 기존 행·준비·함수OID/소유/권한/설정·뷰열·FK/UNIQUE 보존. 한쪽 확인값 누락, 다른 내용판, 남은 식별자/정답/보기 변조와 새 축약행의 과거 이전 진입을 거절한다. 후반 실패는 공용 등록까지 전부 취소한다.
- M08 적용 전 준비 명세를 메모리에 직렬화해 APP10 적용 뒤 같은 명세로 일부 이전·일부 복구했다. 별도의 기존 검사가 실제 파일 저장/재읽기/복구를 수행한다. 이를 적용 전 실제 파일을 재읽은 하나의 검사로 합쳐 주장하지 않는다. 보존 비교는 검사에 지정한 학생 기록 묶음이다.
- 타입·변경4파일 lint·기능지도·108기록 형식·설계·UI 구조 통과. 격리된 Webpack53페이지·공개 오프라인 자산25개 검증, 이전 로컬 빌드 복구.
- 정확한 검토 준비·생성·정리 SQL을 별도 최종 PGlite에서 검사했다. 독립 설계/제품 SQL/검사 검토의 차단사항0이며 검토 실행 명세 재검토를 이어간다.

처음 변조 검사에서 존재하지 않는 열 이름이 무시되는 검사 도구 오류를 고쳤고, 모든 변조 키의 실제 열 존재를 먼저 검사한다. 새 축약행의 금지된 본문 수정은 기존 선행 검사에서 `question_content_binding_mismatch`로 더 일찍 거절된다. 원형 행의 `question_content_reference_immutable`과 나눠 정확한 오류를 고정했다. 시험 미통과의 결과 상태는 원래 계약인 `failed`로 확인했다. 제품 검사를 약하게 하거나 시간 제한을 늘리지 않았다.
