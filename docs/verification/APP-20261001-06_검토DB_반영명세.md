## 변경과 보호

공용 표시값, 출처 연결, 새 구성의 저장 형식 표 3개를 추가한다. 선택값·출처 검증/투영/불변 등록/조회 함수를 추가하고 등록·단어장 구성·자료 변경 감지·학생 학습/오답 읽기 경로를 연결한다. 학생·배정·응시·기존 사전/원행을 일괄 갱신하거나 삭제하지 않는다. 이전 preparing/ready 구성은 기존 저장 형식을 유지한다. 실제 단어 행의 호환용 9개 표시 열은 아직 남으며 개인 문항 압축은 M02다.

최종 함수 본문에서 치환 위치와 횟수를 확인하고 다르면 같은 거래 전체를 취소한다. 기존 읽기 함수 OID `60775`, 권한·보호 래퍼·보기 제외 규칙을 적용 뒤 다시 확인한다. 새 표는 RLS와 불변 트리거를 적용하고 모든 앱 역할의 직접 접근을 막는다. 새 helper의 직접 실행 권한도 허용하지 않는다.

적용 직전 기존 44표 162,821행의 개수/행 내용 확인값과 관련 함수 95개의 정의·OID·권한을 로컬 검사 자료에 보관했다. 이 수는 여러 표 합계이며 학생 수나 단어 수가 아니다. 적용 뒤와 검사 종료 뒤 동일 44표를 다시 대조한다. 검사 자료만 명시적 접두사와 FK로 제외하며 학생 자료는 제외하지 않는다.

## 실제 두 연결 검사

가짜 dataset/unit/entry 각 1개, 범위/승인 각 3개만 사용한다. 학생·관리자·배정·응시를 만들지 않는다. 범위 키는 `m01-qa-c1011001-`, 승인 번호는 `M01-QA-c1011001-`로 고정한다. 실제 학습 자료는 입력으로 쓰지 않는다.

1. 같은 등록 입력: MCP A가 core 등록 뒤 거래를 유지하고 숨김 Node B가 기존 공개 RPC로 같은 입력을 보낸다. 승인 행 잠금에서 대기한 뒤 동일 범위를 반환하는지 확인한다. 이것을 공용 값 UNIQUE 경합의 근거로 확대하지 않는다.
2. 새 표시값: A는 승인/공용 등록 잠금 없이 private 등록 helper만 실행한다. B 공개 RPC가 새 표시값 UNIQUE에서 실제 대기하는지 관측하고 A를 커밋한다. B가 저장한 참조를 A의 두 참조와 비교한다.
3. 새 출처 연결: 2번의 표시값을 그대로 사용하고 출처만 바꾼다. 이미 저장된 값은 재사용하고 새 연결 UNIQUE에서 실제 대기하는지 확인한다.

각 사례에서 서로 다른 PID, `pg_blocking_pids`의 직접 차단 관계, Lock/transactionid를 확인한 즉시 커밋한다. 시간만 기다린 실행이나 PGlite Promise 병렬을 실제 경합으로 세지 않는다. Windows 오류를 낸 `.codex-tmp/m11-postgres-runtime/pgsql/bin/` 실행 파일은 사용하지 않는다.

예상 잔여물은 값 2, 연결 3, 범위 3, 범위행 3, 지문 3, 승인 3이다. 모두 불변 검증 이력으로 남기고 가짜 dataset은 비활성/retired, catalog는 is_assignable=false로 닫는다. 트리거 해제·물리 삭제는 하지 않는다. 실제 남은 수·참조·용량을 별도 근거에 기록한다.

## 중단과 복구

적용 전 또는 거래 내부 오류는 롤백하고 실제 migration history를 다시 읽는다. 새 참조가 저장된 뒤에는 옛 읽기 함수만 복원하지 않는다. 신규 등록/구성을 중지하고 v1/v2 읽기를 유지한 채 별도 복구 migration으로 수정한다. 기존 학생 기록을 DB 전체 복원으로 되돌리지 않는다. 보관한 함수 정의는 비교 근거이며 자동 복원 스크립트가 아니다.

새 앱은 SQL 반영 뒤 배포해야 한다. 구형 앱의 관리자 준비 응답 검사는 v2를 지원하지 않으므로 새 형식의 실사용 개시는 같은 환경의 앱 배포와 관리자 검증까지 연결한다. 이번 가짜 범위는 검증 후 퇴역시킨다. 이 문서는 적용 전 명세이며 실제 성공은 migration readback과 실행 근거로 판정한다.
