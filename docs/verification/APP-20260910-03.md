## 반영한 내용

- 단일 배정은 학생과 단어장의 학년이 달라도 그대로 허용한다.
- 일괄 배정은 학년이 다른 학생 이름·학년·단어장 학년을 보여주고 `포함하기 / 제외하기 / 돌아가기`를 제공한다. 1명만 선택했거나 제외 뒤 1명만 남아도 일괄이다.
- 포함은 선택한 단어장을 유지한다. 제외는 이번 창의 대상만 바꾸고 범위·시간·점수는 보존한다. 되돌리기를 제공하고 0명 저장은 막는다.
- 대상/단어장 변경은 앞선 확인을 지운다. 서버도 저장 직전에 현재 학년과 대상을 다시 읽어, 확인 이후 바뀐 요청을 거절한다.
- 빈 학년이나 불명확한 `1학년` 표기는 다른 학년으로 단정하지 않는다. 조회 실패도 정상 결과로 바꾸지 않는다.
- 기존 요청·중복 요청 재조회·인증·개인 응답 캐시 규칙을 보존했다. 기존 배정·응시·답안·점수·교재·사전·DB 구조를 변경하지 않았다.

## 실제 화면에서 확인한 것과 남은 것

- 실제 계정이나 환경 파일을 쓰지 않는 앱 내부 격리 사본에서 검사했다. 가짜 고1/고2 학생과 고1 단어장만 사용했다. 검사 서버는 저장 API와 외부 연결을 차단한다.
- 1280×720와 390×844에서 학년 확인창의 글·목록·세 버튼이 잘리지 않는 것을 보았다. 첫 초점은 `돌아가기`였다.
- 2명 중 고2만 확인 대상으로 표시됐다. 제외 후 새 배정 대상은 1명이 되고 일괄 표시는 유지됐다. 입력한 통과 점수85와 범위를 보존했으며 되돌리면 2명이 됐다.
- 제외 직후 키보드 초점이 빠지는 것을 발견해 되돌리기 버튼으로 옮기도록 수정했다. 부품 검사29와 재빌드는 통과했다.
- 재빌드 후 일괄1명 → 확인창 → 0명 제외/복구 및 포함 버튼의 마지막 화면 검사는 도구 안전장치가 배정 클릭을 거절해 중단했다. 서버의 저장 차단 근거를 확인해 제시했으나 거절이 유지되어 더 우회하지 않았다.
- 실제 DB 저장 성공·운영 반영은 검사하지 않았다. 전원 제외·단일 허용·포함 전달·실패 후 재시도·낡은 확인 차단은 자동 검사 근거와 구분한다.

남은 확인을 이어갈 때 필요한 사용자 승인: **실제 저장이 차단된 로컬 가짜 학생 화면에서 배정 버튼과 포함·제외까지 눌러 검사할지**. 운영 학생에게 시험을 만드는 승인이 아니다.
