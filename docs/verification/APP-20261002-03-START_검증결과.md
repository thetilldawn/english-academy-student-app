# 새 시험 시작만 잠시 중지하는 기능 검증

구현 c2376fb의 로컬 검사와 검토 DB 적용을 마쳤다. 배포 중 **새로 시작하는 배정 시험만** 잠깐 막을 수 있으며, 이미 시작한 시험의 재시험·답 접수·늦은 제출은 계속 처리된다. 운영 DB와 운영 앱에는 아직 반영하지 않았다. 작업 상태와 순서는 루트 대장이 기준이다.

## 운영 방법

운영자는 설정행만 UPDATE하는 **짧은 별도 거래를 먼저 확정**한다. 이 잠금을 잡은 채 배포·학생 검사·다른 자료 수정을 하지 않는다. true는 새 시작 중지, false는 정상 재개다. 설정행이 없으면 새 시작을 거절한다. 기존 시작 재접수·재시험·답 제출과 자율연습은 이 중지 대상이 아니다.

앱 안내: “점검 중이라 새 시험을 시작할 수 없습니다. 잠시 후 다시 시도해 주세요. 진행 중인 시험은 계속할 수 있습니다.” 새 시계를 만들거나 기기에 보관된 답을 지우지 않고 같은 준비로 다시 시도한다.

첫 MCP 동시 호출은 직렬 처리돼 겹치지 않았고, HTTP 준비 지연/관찰 방식의 시간 초과도 있었다. 실패 로그는 보존하고 성공 근거에 합산하지 않았다. HTTP를 먼저 준비하고 실제 잠금 관찰로 바꾼 뒤 두 방향을 확인했다. 검사 숫자 비교의 문자열/숫자 차이로 한 번 되돌린 거래도 성공에 포함하지 않았다. 첫 빌드는 로컬 APP_ORIGIN 미설정으로 실패했고, 비밀값 없는 가짜 환경을 명시한 전체 빌드가 통과했다.

private 설정표에 정책이 없다는 정보성 권고는 모든 앱 역할 접근을 막는 의도된 설정이다. [Supabase 권고 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)을 함께 검토했다. 프로젝트 기존 권고를 전부 해결했다는 의미는 아니다.

실제 관리자 로그인→배정→학생 응시, 같은 주소의 앱 교체/호환 복귀, 운영 적용은 M10에서 이어서 확인한다. 이번 기록의 보존 주장은 지정 표·함수 범위이며 전체 DB의 모든 객체를 비교했다는 뜻이 아니다. 운영 쓰기·운영 배포·공간 회수는 모두 0이다.
