# 인증 갱신·로그아웃 오류 보완

입력: 58af62c와 전체점검 F08/F09, 현재 사용자 증상. 로컬 구현·검증이며 운영 반영 기록이 아니다.

## 원인과 수정

- 관리자 만료 토큰 갱신에서 요청 취소를 가짜 HTTP408로 바꾸던 코드가 실제 Auth SDK의 세션 삭제를 유발했다. 표준 취소와 재시도 가능한 인증 장애로 유지하고, 이미 취소된 요청의 추가 실제 전송은 차단했다.
- 관리자 인증 조회와 학생 세션 DB 조회가 실패해도 정상 세션이 없다는 뜻의 null로 처리했다. 일시 장애는 503/오류 경계, 실제 무효·철회·차단만401/로그인 이동으로 구분했다. 인증을 쓰는 기존 API52파일에 동일한 경계를 적용했다.
- 로그인 직후 프로필 조회 실패 때문에 강제 로그아웃하던 흐름, 철회 실패를 로그아웃 성공으로 응답하던 흐름을 보완했다. 원격 로그아웃 실패 때는 쿠키를 남겨 재시도하고, 확정된 무효 세션은 정상 정리한다.
- 학생 갱신은 응답 본문까지7초 제한을 적용한다. 학생60일·24시간 갱신 정책과 기존 권한·개인 no-store는 바꾸지 않았다.

## 검증과 한계

- 설치된 Supabase SDK에 가짜 만료 세션을 넣어 시간초과/408/429/5xx/무효 refresh token과 재시도를 검증했다. 취소 뒤 실제 네트워크 전송은1회이고 쿠키는 보존된다. SDK 내부 지연 재시도 자체를 임의로 패치하지 않았다.
- 최종 전체 검사521파일: 3,963통과·실패0·기존1건너뜀. 원결과 `.codex-tmp/APP-20260929-01_전체검사_최종.json`. 기존 건너뜀은 학교 발음 전체 스키마 통합검사이며 이번 수정으로 통과했다고 계산하지 않는다.
- 타입·lint·기능지도·화면구조·요청내 캐시·설계/변경연결69기록·40페이지 빌드 통과. 추가한 구 배정 API2경로를 실제 상세 흐름에 등록했다.
- 첫 전체 검사에서 이동 중인 검사 파일1개와 옛 export 문법만 검사하는 정적 주장1개가 실패했다. 파일 이동 완료와 주장 보완 뒤 위 최종 전체 검사를 새로 실행했다. 첫 빌드의 APP_ORIGIN 누락은 로컬 환경 오류였으며 localhost 값을 명시한 새 빌드가 통과했다.
- 독립 읽기 전용 검토에서 무효 refresh token의 로그아웃 복구를 추가 보완했다. 현대/구형 SDK 응답 형식 검사도 통과했다.
- 운영 데이터·배포·실학생 응시0. 사용자가 겪은 각각의 사건을 운영 로그로 확정한 것은 아니며, 확인한 코드 원인과 실제 SDK 재현을 구분한다.
