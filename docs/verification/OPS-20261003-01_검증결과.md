# 기존 자료 이전·복구 검증 결과

M08-A의 가짜 과거 자료 이전·복구 연습과 운영 읽기 조사를 마쳤다. 제품 기준은 `e57f399`이며, 이전 도구 6종의 구현은 APP-20261003-02~07에 있다. 운영 DB 적용·실제 학생 쓰기·운영 사본 확보·물리 용량 회수는 수행하지 않았다. 현재 작업 상태와 순서는 루트 작업 대장만 따른다.

## 확인한 결과

- 기존 SQL 적용 전 넣은 가짜 문항·자료에 새 참조를 연결하고, 원래 질문·보기·정답·발음·뜻·출처를 복원했다. 기존 ID와 학생 기록 관계를 유지했다.
- 중단·재실행·늦은 확정·현재 행 변경 감지·보호 대상 거절은 각 APP의 실제 함수 검사와 두 연결 검사로 확인했다. 최대 사건 번호만으로 이전 완료를 판정하지 않는다.
- 사본 파일을 실제로 다시 읽어 지정 본문만 복구했다. 복구 뒤에 생긴 학생 답·점수·현재 오답 상태를 과거 상태로 되돌리지 않았다.
- 개인 오답 문제지 1항목을 만든 뒤 8문항 본문 축약→새 시험 정답 4개와 오답 해결→8문항 본문 복구를 직접 결합했다. 문제지 출력과 최신 학생 상태가 같았다.
- 공간 계측을 붙인 기존 검사 **6파일 73개**, 결합 문제지 검사 **1개**가 통과했다. 제품 함수의 매개변수나 보호 조건을 바꾸지 않고 전후 크기만 읽었다.

원출현은 같은 24개 필드를 재사용한 참조 표현이 3,763,256B여서 해당 열의 텍스트 차이는 29,022,517B다. 이 값에 보관 기록·인덱스 비용은 포함되지 않는다. 검토 자원은 100행씩 169묶음을 각각 빈 공유표 조건에서 계산했을 때 25묶음·2,500행만 묶음 전체의 비용 조건을 통과했다. 통과한 원래 본문 14,719,865B도 절감량이 아니다. 실패 묶음까지 더한 비용 차이를 회수 예상량으로 사용하지 않는다.

**본문 텍스트의 합계를 DB 크기에서 빼서 500MB 달성이라고 판정할 수 없다.** PostgreSQL은 긴 값을 압축하며, 변경 뒤 빈 페이지를 재사용할 수 있어도 파일 크기가 바로 줄지는 않는다. 운영의 검토 묶음 표는 본문 텍스트 약129MB와 달리 표·인덱스 합계가 약40.98MB다. 실제 운영 회수는 M08-B에서 따로 검증한다.

## 공간 계측의 범위

[계측 JSON](OPS-20261003-01_공간계측.json), [전후 CSV](OPS-20261003-01_공간계측.csv), [재현 실행기](OPS-20261003-01_계측/reproduce.mjs)에 원본 검사 SHA와 관측을 연결했다. 관측280개 중 전후가 모두 있는 같은 호출은106개다. 실패해서 이후 관측이 없는62개는 증가량 계산에서 제외했다. 106쌍 모두 DB 크기 차이와 추적34표의 전체 관계 크기 차이가 같았다.

작은 가짜 자료에서는 참조·복구 기록 추가 때문에 파일 할당이 늘었다. 위 값은 호출문 완료 경계에서 잰 값이며 뒤에 거래를 되돌린 검사도 있다. 여섯 DB의 최고값을 더하거나, 이를 클라우드 전체 이전의 최고 공간/WAL/파일 회수량으로 환산하지 않는다. `pg_table_size`는 TOAST를 포함하며 인덱스만 한 번 더한다. 본문 행 JSON은 별도 지표다.
