# APP-20260929-08 시험 목록 표시와 10개 더보기

## 요청과 결정
- R1: 학생/관리자 목록의 긴 범위는 두 줄 말줄임. 같은 교재·범위 제목을 반복하지 않는다. 전체 범위는 학생 펼침/관리자 상세에서 확인한다.
- R2: 학생 공개예정·응시가능·확인필요·마감·완료 모두 처음 10개, 버튼으로 10개씩 더 본다. 개수는 전체 개수다.
- R3: 완료·미통과·시간초과는 실제 종료 최신순. 마감이 빠르다고 예전 미통과를 먼저 두지 않는다. 더보기 경계의 같은 시각은 식별자로 고정한다.
- D1 사용자: 위 요청은 현재 화면 수정의 보완이며 별도 기능 선택 대기 없음. 로그아웃은 APP-20260929-09에서 이어서 수정.
- D2 개발: 기존 완료 v2 커서/읽기는 보존. v3 초기 조회와 네 구역 페이지를 추가하며 이전 v1로 자동 폴백하지 않는다.
- D3 개발: 공개예정은 빠른 공개시각, 진행 중은 기존 마감 우선, 끝난 내역은 최신 종료. 목록 데이터·점수·응시를 쓰지 않는다.
- D4 제외: 내 단어장은 수리 후 구상만. 미결정된 새 기능은 구현하지 않는다.

## 근거와 설계
학생 카드 scope는 무제한이며 자동 제목은 160자에서 잘려 범위 중복 제거를 통과한다. 초기 SQL은 완료만11행, 다른구역 전량이다. review_pending의 공용 정렬이 마감을 우선해 9/10 완료가9/29보다 먼저 나오는 가짜 자료 재현이 있다. 관리자 전체내역 SQL 최신순은 이미 맞으며 학생상세의 재정렬만 제거한다.
서버 현재 학생 세션 → v3 초기 읽기(구역별11행·전체개수) → 첫10개와 학생/구역/스냅샷/정렬키 커서 → UI. 더보기는 controller→transport→동일출처 POST→현재세션→구역 페이지 RPC. 완료 경로는 기존 유지. 모든 개인 응답 private,no-store; 브라우저 공유캐시 없음. 공개예정 미래시각은 정상이며 완료커서의 과거시각 제한과 분리한다.
구역별 SQL 정렬을 화면에서 재정렬하지 않는다. 회귀검사는 같은 최종DB와 lifecycle로 분류를 대조한다. 기존 read_rows_v2의 공개/학생필터를 재사용하고 새 읽기 함수는 service_role만 실행한다.
범위 원문/등록 제목은 수정하지 않는다. 자동생성 원문과 정확히 일치하는 제목만 표시에서 제거하고 사용자 자유제목은 보존한다. 목록은 말줄임, 학생은 native details로 원문 펼침(추가 HTTP 없음), 관리자 링크 내부에 새 버튼을 넣지 않는다.

## 검사 R/D/T
- T1: 긴 모고/짧은 DAY/사용자 제목/160자 자동제목/중복문구; 학생 및 관리자 목록·상세.
- T2: 최종 가짜DB에서 구역 0/10/11/21·공개대기 미래시각·동시종료·새 학생/취소/권한·조회 전후 불변.
- T3: 요청취소·연속클릭·더보기 실패재시도·401/403/409 숨김·커서 위조/학생변경·same-origin/no-store.
- T4: PC/좁은화면 카드와 구역별 더보기, 실패와 빈 결과 구분. 기존 시험 버튼 유지.
- T5: 타입/lint/기능지도/작업기록/빌드, 독립 읽기검토. 새SQL 검토 환경 적용·재조회는 운영 반영 단계에 별도 기록.
- 운영 반영은 기존 사용자의 같은 화면 수리 배포 지시에 따라 검토환경 통과 뒤 같은 코드/SQL만 적용; 실제학생 시험시작/답안쓰기 금지.

## 상태·복구
초기 로딩은 기존 보호경계, 정상0건은 빈목록 안내. 다음페이지 실패는 기존10개/커서를 보존하고 같은버튼 재시도. 인증거절은 즉시 자료숨김과 접속화면 이동. 없는주소/예상밖예외는 기존 경로경계. 선택·저장 없는 읽기이므로 새 입력/저장오류 없음.
복구는 앱 이전커밋으로 되돌리면 v2를 계속 사용한다. 새SQL은 기존함수/표를 교체하거나 삭제하지 않는다.

## 로컬 확인 결과

- 처음 10개만 보내는 v3 읽기와 구역별 다음 페이지를 구현했다. 완료는 기존 v2를 유지한다. 공개 예정은 공개 시각, 종료된 시험은 종료 시각을 기준으로 이어지며 화면에서 순서를 다시 섞지 않는다.
- 가짜 최종 DB 9검사: 구역마다 21건을 10→20→21로 읽기, 전체 개수, 동시 종료·마이크로초·미래 공개, 학생 분리와 실행 권한 확인. 별도 독립 검사에서는 132건을 빠짐·중복 없이 읽었다. 0/1/10/11/21 경계와 null 응답 거절은 서버 query 검사로 보강했다.
- 독립 변경분 검토 8파일 87검사 통과. v1/v2의 예전 응답 검사는 전용 스키마로 분리해 기존 호환성을 계속 확인한다.
- 실제 브라우저의 가짜 화면: PC 및 390×844에서 긴 범위 두 줄, 전체 보기 펼침, 버튼 노출 확인. 공개 예정 10→20→21과 다른 구역 10개 유지 확인. 실제 글꼴을 적용한 최종 화면의 콘솔 오류 0건.
- 전체 검사 두 번째 실행은 531파일 중 530파일 통과, 4,142통과·기존 건너뜀1·시간 초과1이었다. 시간 초과가 난 기존 자료 조합 검사 파일을 단독 재실행하여 22검사 전부 통과했다. 검사를 삭제하거나 제한 시간을 늘리지 않았다.
- 타입·전체 lint·기능 지도·화면 구조 통과. 로컬 APP_ORIGIN을 지정한 Webpack 빌드 41/41 통과. 첫 빌드의 APP_ORIGIN 누락은 로컬 실행 설정 문제로 별도 기록하며 운영 설정 변경은 하지 않았다.

검토 DB 반영과 배포 응답은 [별도 배포 기록](DEPLOY-20260929-02_배포결과.md)에 남긴다. 위 가짜 자료 확인을 인증된 운영 학생 화면 확인이라고 부르지 않는다.
