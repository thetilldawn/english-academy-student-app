# 종료 시험 기록 — 구현 전 설계

입력: M04, M03 구현2736600 및 마지막2파일28검사, 읽기 전용 독립 설계2건. 적용한 공통 결정은D05/D08/D10/D11이며 새 업무 결정은 없다. 최신 사용자 전송 지시는 M05에서 구현하며 본 설계는 브라우저 호출 수를 늘리지 않는다.

## 확정 경계와 보존

공용 문항은 M02의 `quiz_questions.id → content_version_id`로 복원한다. M03의 문항/단계 접수에는 뜻·구간·출처 키가 있으므로 새 요약에 전체 단어나 보기, 발음, 답안 응답 JSON을 다시 넣지 않는다. 새 정책표는 응시당 짧은 한 행, 단계표는 최초/재시험별 한 행이다. 이 단계에서 기존 표의 크기를 줄였다고 보고하지 않는다.

새 응시는 `summary_and_mistakes_v1` 정책을 고정하고 기존 응시·진행 중 응시는 `legacy_answers_preserved`로 읽는다. 기존 행이나 모든 정답 선택값을 지우지 않는다. 신규 결과의 장기 상세 제공 범위는 최초 오답/미응답이며 맞은 문항 선택의 새 장기 화면은 만들지 않는다. 원래 없는 과거 시각·선택을 추정해 채우지 않는다. 기존 결과는 저장값과 읽기 집계를 구별하고 대량 보관 정책 전환 도구와 실제 실행은 M08에 남긴다.

최초 단계 완료는 재시험 대기(`in_progress/review`)일 수 있다. 최초 요약은 고정하고 재시험 시작/완료 때 다시 쓰지 않는다. 최종 확정은 서버의 완료/만료와 필요한 단계 기록이 모두 갖춰진 상태다. 날짜가 오래됐다고 재시험 대기를 정리하지 않는다. 미응시 만료는 기존 배정 기록이며 가짜 응시나 재시험0점 행을 만들지 않는다.

요약 집계는 `정답+실제 오답+미응답=대상 수`이다. 문항 시간초과는 인위적인 오답 선택 위치가 있을 수 있으므로 `timed_out`을 먼저 검사한다. 공식 재시험 점수는 현행 `(최초 정답+재시험 정답)/최초 문항수`를 유지한다. 50개 중40개 최초 정답·재시험10개 중8개 정답은 최종96점이며 재시험 정답률80점으로 바꾸지 않는다. 최종 통과도 v4의 보정 결과를 사용한다.

## 저장 연결

| 경로 | 시점 | 보호 |
|---|---|---|
| 새 응시 | INSERT 뒤 정책만 등록 | 질문 생성 전에 요약하지 않음; 기존 응시는 소급 변경0 |
| 정상 최초/재시험 | M03 `submit_vocabulary_answer_v1`의 accept와 reopen 뒤 | v4 최종 passed 보정·마지막 접수보다 앞서 만들지 않음 |
| 자동/수동 만료 | M03 `finalize_vocabulary_expiry_v1`의 남은 접수 전체와 reopen 뒤 | 모든 미응답 반영 후 단계/종료 확정 |
| 학생 삭제 중단 | `abandon_student_attempt_v1`의 기존 종료 UPDATE 뒤 | 중단 사유만 기록; 오답 접수·뜻 사건·포인트 생성0 |
| 동일 요청 재전송 | 기존 완료 응답 재사용 | 요약/사건/포인트 증가0; 다른 확정 값 덮기 거절 |

정책/단계 표는 private 영역, 직접 앱 역할 접근 금지다. 서버 조회 함수는 service role에서 학생 본인 또는 활성 관리자를 확인한다. 함수의 기존 소유자·권한·설정·OID는 유지하고 본문에 정확한 호출 지점만 추가한다. 새 함수는 권한을 명시한다. 오류를 빈 결과로 바꾸지 않는다. SQL 적용 전 원격의 현재 정의와 확인값·복구를 따로 기록한다.

## 조회와 화면

구현 중 독립 검토 보완: 만료가 제출 내부 채점에서 발생한 경우에만 private 함수의 명시적 인수로 요약을 지연하고 바깥 최종 통과 보정 뒤 확정한다. 공개/작업 만료는 항상 즉시 확정하며 호출자 설정값으로 저장을 건너뛰지 않는다. 결과 조회는 같은 SQL 시점의 응시 상태·점수·날짜와 단계 기록을 함께 반환한다. 두 번의 조회 사이 재시험이 끝나도 오래된 상태를 새 단계와 혼합하지 않는다. 구형 재시험 답이 남아 있으나 시작/최초 종료 시각이 없으면 최종 종료 시각을 최초 종료로 대입하지 않는다.

학생 결과/관리자 상세는 보관 정책·결과판·단계 결과·최종 확정·상세 범위를 명시한다. 새 결과는 처음 맞힌 문항의 본문을 읽지 않고 오답/미응답만 M02로 복원한다. 기존 자료는 원래 상세를 유지한다. 요약이 없는 구형 자료의 기존 정답·점수 집계는 전체 문항 기준을 유지한다. 작은 오답 배열로 기존 점수의 분모를 계산하지 않는다.

공용 결과 표시 부품에서 최초/재시험 대상·정답·오답·미응답 및 실제 날짜를 보여준다. 신규 정책은 “이 시험은 결과와 오답 기록을 보관합니다.”, 상세 미보관은 “결과 요약만 보관된 시험입니다.”, 조회 실패는 “시험 결과를 불러오지 못했습니다.”로 구별한다. 실제 오답0은 정상 빈 결과로 표시하되 요약만 있는 결과에 모두 정답 안내를 띄우지 않는다. 권한 실패·없는 응시는 기존 인증/404 경계를 유지한다.

## 검사와 복구

실제 화면 검토에서 발견한 R2 보완: 관리자 상세의 배정 메타정보는 유지하되 응시 상태·점수·날짜·재시험 시작·무제한 마감은 같은 결과 RPC의 응시 값으로 통일한다. 무한대 마감은 null로 반환한다. 상세 점수 표시는 확정된 단계와 공식 통과값을 사용하고, 재시험 대기는 최종 미통과와 구별한다. 기존 목록 분류·커서·정렬 규칙은 변경하지 않는다.

T1 최초 통과/재시험 통과/양쪽 미통과, T2 별도 오답 배정·재응시, T3 진행·대기·미응시 만료·중단, T4 기존 전체 행 보존, T5 공용 원판 복원, T6 가짜100종료 시험 비용, T7 검색·전체 수·권한·요약/상세, T8 중복·지연·경합·원자 실패와 UI 상태를 연결한다. 가짜100명은 20명씩 최초 통과/재시험 통과/양쪽 미통과/최초 만료/재시험 만료, 단계 요약160행이 기본이다. 요약·개인 문항 키·접수·오답 상세·공용 본문·인덱스 비용은 분리한다.

T7은 기존 최종 스키마의 0/1/10/11/21 검색·동일 시각·커서·총수와 목록/커서 서버 검사를 함께 실행한다. T8의 DB 원자성·재전송은 실제 SQL 검사, 문구·보관 분기는 결과 화면 검사, PC/390px는 실제 브라우저 근거로 나눠 기록한다. 하나의 화면 검사로 DB 경합까지 입증했다고 하지 않는다. 오답 상세 응답은 공용 본문과 기존 문항에서 복원하므로 별도 DB 저장비용으로 중복 합산하지 않는다.

복구는 추가 표를 지우지 않고 호환 읽기 코드로 전환한다. 기존 답안과 공용 판을 보존하므로 새 선택 답을 지어낼 필요가 없다. 실제 운영 배포·기존 기록 이전·용량 회수는 수행하지 않는다. 차단된 Windows PostgreSQL 대신 PGlite와 승인된 검토 DB를 사용한다.
