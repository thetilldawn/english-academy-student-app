# 공용 범위·완료 구성의 이전과 부분 복구 결과

승인된 M01/M08 보완을 구현하고 검토 DB에서 확인했다. 공용 범위와 완료 구성에 중복 저장된 과거 본문을 당시 학습값·출처 참조로 바꾸고, 외부 사본에서 지정한 본문만 복구할 수 있다. 기존 판 번호·원문 확인값·문항·뜻 정체성과 학생 기록을 보존한다. 운영 적용·실제 자료 정리·용량 회수는 아직 하지 않았다.

## 구현과 독립 검토

- SQL: `supabase/migrations/20261002192000_migrate_historical_learning_sources.sql`, SHA-256 `1782965a78c2a933c73722d823c230188724ff115a0c95c5304ff5a6dd5207ba`.
- 범위 행의 `entry_snapshot/occurrence_snapshot/resources`, 완료 구성 행의 `source_snapshot/resources`만 허용한다. 자동 이전은 없다. 운영자가 외부 파일을 저장·재읽기한 뒤 지정 키와 원행 확인값으로 최대100행을 처리한다.
- 과거 값 등록은 현재 사전 연결·새 검토 결과를 읽지 않는다. 원래 문서 확인값과 전환된 문서 확인값을 작은 이전 기록으로 연결하여 기존 고정판 검사를 유지한다.
- 나중에 새 단어장을 만들 때는 기존 신규 생성 정책대로 현재 연결을 확인한다. 과거 범위/구성의 뜻을 소급 변경하지 않는다. 실제 옛 단어장과 별도 검토된 모의고사 뜻의 신규 생성→배정 결과를 각각 비교했다.
- 같은 요청은 처음 접수를 그대로 반환한다. 직접 UPDATE나 세션 설정으로 불변 보호를 우회할 수 없고, 일회 허용은 현재 거래·정확한 행·변경 전후 확인값에만 적용된다.
- 독립 검토에서 재요청 확인 순서, 다중 출처 배정 보호, 신규 생성의 사전 연결 유지, 모든 Git 저장소의 사본 저장 금지를 보완했다. 최종 확인된 결함은 없다.

전체623파일 **5,039통과, 실패0, 기존 제외1**. 타입 검사, 변경 파일 린트, 기능 지도·화면 구조·설계 관문,53페이지 앱 빌드가 통과했다. 관련 독립 회귀검사에서 CRLF 함수 정의의 정확한 치환을 보완했고 최종31검사가 통과했다. 병렬 실행 중 기존 대형 검사의 기본5초 제한 초과는30초 제한으로 재검사했다. 최종 전체 검사는 같은 최종 SQL을 사용했다. 화면 변경이 없어 추가 UI 검사는 해당하지 않는다.

완료 관문은16개 범위·1,224개 입력·7개 필수 검사로 통과했다. 확인값은 `5aec82a9e720e294c39a8f6012012c74acc840f2ef9b9e170f8e2a88231fb594`다. 실제 검사 로그 확인값은 동시 실행·복구 근거에 연결했다.

## 실행 중 발견한 검사 도구 문제와 사본 위치

임시 검사 함수의 열/변수 이름 충돌을 수정하고 새로운 가짜 낮은 키로 성공 사례를 다시 확보했다. 이미 축약된 행은 원문 준비를 다시 요구하지 않고 기존 외부 파일을 사용했다. 시험 답 시각은 기존100ms 화면 전환 규칙에 맞췄다. 거절된 제출 거래에는 답이 기록되지 않았다. 이들은 검사용 입력/도구 보완이며 앱 데이터 보호 검사를 완화하지 않았다.

루트에 기존 `.git`이 있어 사본 도구가 하위 자료 폴더를 거절했다. Git 자체는 변경하지 않았다. **가짜 연습 사본만** `C:/Users/임성열/AppData/Local/Temp/english-app-private-rehearsal/APP-20261003-03/`에 보관했다. 실제 사용자·작업 계정·SYSTEM·Administrators만 접근하도록 상속을 차단했다. 파일명·바이트 수·SHA-256은 근거 JSON에 있다. 임시 사본은 운영 백업이 아니며 실제 운영 사본은 별도 영구 경로와 공간 예산을 확정해야 한다.
