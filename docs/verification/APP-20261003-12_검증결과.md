# 시험 시작과 학생 알림 동시 요청 수리 결과

학생 알림 함수의 잠금 순서를 시험 시작과 맞췄다. 기존 알림 조건·응답·권한·학생 기록은 보존했다. 운영은 아직 미반영이며 실제 검토 앱 재검사는 M10에서 이어간다. 현재 상태·우선순위는 루트 대장만 따른다.

- 로컬: 3파일23검사, 타입·변경 lint·기능 지도·설계 관문, 같은 보존 거래의 PGlite 실행 통과. 기존 두 CTE 81줄/2,875자는 동일하다는 독립 검토를 받았다.
- Preview: 이력20261003144923, 대상 함수 OID20548 유지. prosrc/prolang 외 메타 동일·비대상826함수 거래 내 보존. 48표19,875행은 적용 전후 개수와 전체 행 확인값 차이0이다. 알림 수신표를 포함하고 정기 작업/접근 로그는 보존 목록 밖이다.
- 알림 먼저: 서로 다른 연결101275/101280과 실제 Lock/transactionid 대기를 관찰. 알림(신규1/마감1) 뒤 시험 시작200.
- 시작 먼저: 연결101328/101341의 같은 실제 대기를 관찰. 시험 시작 확정 뒤 기다리던 서비스 역할 알림이200/(0,0), 해당 배정 학생 수신행0이었다.

## 검사 중 보완과 한계

처음 경합 도구는 두 요청이 겹치지 않아 실패로 기록했다. 두 번째 방향의 첫 SQL 연결은 서비스 역할 식별값이 없어 거절됐으며 새 가짜 배정으로 다시 검사했다. 위 두 성공만 경합 근거로 센다. 일반 기능 검사 준비 중 SQL 생성기 구분자와 수신표 정렬 열의 도구 오류도 수정 후23개를 다시 통과했다.

기존 관리자 알림/배정 알림 기록 경로의 모든 교착이 해결됐다는 뜻은 아니다. 이번에는 실제 장애로 확인된 학생 알림만 수리했다. 알림은 같은 학생의 먼저 시작한 거래가 끝날 때까지 기다릴 수 있다. 제품 클라이언트·시험 중 요청·기기 답·캐시 정책 변경0, 운영 DB/배포/실제학생쓰기0이다.
