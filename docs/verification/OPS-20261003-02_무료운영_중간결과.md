## 2. 학생 등록과 시험 누적을 구분한 수치

100명 등록의 물리 증가는 학생 표73,728B, 가짜 관리자·인증32,768B, 합계106,496B였다. 학생 등록만으로 수백MB가 생긴 것이 아니다. 실제 로그인·세션은 표본에 포함하지 않았다.

| 구간 | 새 행 | 행 표현 | 표·TOAST·인덱스 합계 | 그중 인덱스 | 전체 DB |
|---|---:|---:|---:|---:|---:|
| 6회 정리 후→16회 정리 후 | 2,990 | 1,151,690B | 2,572,288B | 933,888B | 3,170,304B |
| 16회 정리 후→32회 정리 후 | 4,784 | 1,841,984B | 4,112,384B | 1,556,480B | 4,194,304B |
| 마지막16회 평균 | 299 | 115,124B | 257,024B | 97,280B | 262,144B |

‘행 표현’은 `sum(pg_column_size(row))`다. 긴 행의 압축·외부 저장과 물리 페이지/색인은 별개이므로 물리 용량이나 최소 필요 공간으로 해석하지 않는다. 마지막16회 행 JSON 텍스트는4,576,226B로 별도다. 표 크기는 기본표·TOAST·관련 색인을 한 번만 더했다. 전체 DB에는 조사 대상 밖 시스템 표 등이 포함되므로 표 합계와 같다고 주장하지 않는다. 해당 구간 차이598,016B/81,920B의 세부 시스템 원인은 분해하지 않았다.

32회째 정리만 보면 조사 표는49,152B 줄었지만 전체 DB는32,768B 늘었다. 정리 작업 자체도 보조 정보와 통계를 바꾸며, 삭제/축약 바이트가 곧바로 물리 회수 바이트는 아니다. 일반 VACUUM은 재사용 공간을 만들고 FULL은 별도 잠금·재작성 비용이 든다. [Supabase DB 용량 안내](https://supabase.com/docs/guides/platform/database-size)

## 4. 인원 계산의 현재 결론

관리자마다 별도 무료 학생 할당량은 없다. 같은 프로젝트의 공용 자료·학생 기록·전송 한도를 함께 사용한다. F02 관리자 분리는 아직 구현 전이므로 여러 관리자 권한 검증 완료나 지원 인원을 약속하지 않는다.

아래는 **같은 책 반복의 마지막16회 평균을 곱한 표본 외삽**이다. 월20개 시험(별도 오답 시험 포함), 최초50+재시험10문항,6개월 보존을 가정한다. 운영 전체 예측·최대 인원 보장이 아니다.

| 학생 | 시험 수 | 조사 표의 물리 증가 가정 | 12개월이면 |
|---|---:|---:|---:|
| 1명 | 120 | 30.84MB | 61.69MB |

100명·6개월에서 행 표현만1,381,488,000B이고, 조사 표 합계3,084,288,000B 중 색인1,167,360,000B다. 실제 단가는 정리 주기·색인 분할·자료 다양성에 따라 달라진다. 새 공용 자료, 새 학생별 단어 상태, 로그인, 배정 요청 보관, 진행 중 최고 점유량, 복구 여유는 추가 비용이다. [전체 인원/기간 CSV](OPS-20261003-02_계측/인원별_저장가정.csv)

계획 산식은 `학생 예산 = 한도 − 현재 물리 사용량 − 새 공용 자료 − 별도 운영 기록 − 작업/복구 여유`다. 학생당은 `초기 등록·신규 단어 상태 + 월 시험 수 × 기간 × 계획 단가`다. 관측보다 여유를 둔 임시 단가0.40MB/시험은 학생당6개월48MB이며 검증된 상한이 아니다. 모든 다른 비용을 이미 제외한 잔여50/100/200MB의 산술 예시는1/2/4명이다. 실제 잔여가 확인되기 전 운영 가능 인원으로 쓰지 않는다.

현재 운영 DB는779,914,387B로 무료 목표500MB를 넘는다. 따라서 **현재 상태에서 추가 학생을6개월 보관할 무료 용량을 보장할 수 없다.** 현재 접속 가능한 학생이0명이라는 뜻이 아니다. 이미 구현된 자료 공유·보관 도구의 운영 적용/회수도 아직 하지 않았으며, 이를 완료한 공간으로 미리 빼지 않는다.

## 6. 전송·성능의 확인 범위

로컬 RPC5개(준비·최초 시작·최초 제출·재시험 시작·재시험 제출)의 응답 JSON 합계는 시험당40,697~40,848B, 평균40,798.31B였다. 100명×월20회이면 이5개 응답만 약81.60MB/월이라는 산술값이다. 인증·대기열·목록·HTTP 포장·브라우저 자료/음원·캐시 실패와 재전송은 제외했다. 실제 Supabase/Vercel 월 전송량으로 주장하지 않는다. 검사에서 추가한2회 재전송과 기기 클릭 수는 정상 시험의 요청 수에 포함하지 않는다.

공용 표시48시간 재사용과 시험 중 호출0은 M05의 기능 검증 근거를 따른다. 응시마다 필요한 시작/제출 응답까지48시간 캐시로 없어지는 것은 아니다. 음원은 기존CDN과 일반 브라우저 캐시이며 음원 품질 추가 검사는 사용자 지시에 따라 하지 않는다.

로컬 최초 제출32개의SQL 구간 p95는523.34ms, 재시험 제출 p95는378.23ms다. 브라우저·인증·통신·클라우드 대기를 포함하지 않아 서버 응답시간 합격으로 바꿀 수 없다. 등록100명과 동시100명도 다르다. 현재 한도 초과 상태에서 원 지시의 중단 규칙에 따라 검토 DB의100명×6개월 대량 입력 및10/30명+관리자1/3명 부하는 수행하지 않았다.

| T2 가짜 수량·결과 | 로컬32회 통과.100명 모두의6개월 이력은 미생성 |
| T3 공용/개인/색인 | 분리 계측 완료. 물리 회수·클라우드 최대 임시 공간 미검증 |
| T4 응답/전송 | 로컬 RPC 바이트만 확인. HTTP 전체와48시간 실제 재사용 월량 미검증 |
| T5 관리자 동시 배정 | 미실행. 한도 초과 상태에서 부하를 늘리지 않음 |
| T6 오류 뒤 저장·권한 | 기존 기능 검증과 즉시 재접수만 확인. 부하 후 교차 관리자 검증 미실행 |
| T7 인원 판단 | 기존 모형 정정과 가정 표 작성. 실제 최대 지원 인원은 미확정 |
| T8 지연/유실/회복 | M05 기존 개별 검증과 구분. 새 부하 분포·공식 결과 시간 미측정 |

[독립 검토](OPS-20261003-02_독립검토.json)에서 위 수치와 최신 일괄 배정 경로를 대조했다. 재현기 SQL 파일 목록 검사, 세부 비용2곳, 짝수 표본 중앙값을 수정한 뒤 추가 지적0건을 확인했다. 기능 완료를 위해서는 다음 저장 보완 뒤 같은 측정을 다시 해야 한다.

1. 회차 접수의 반복 accepted 배열을 개별 접수에서 복원한다. 최초 결과는 당시 값으로 보존하여 재시험 후에도 최초 응답을 그대로 돌려준다.
2. 준비·단계 계획은 고정 문항 참조와 순서를 공유한다. 시작/재개·늦은 답·기기 제한은 유지한다.
3. 배정 문항을 본문으로 먼저 쓰고 다시 비우는 과정을 줄이고, 공용 문항판에 이미 있는 반복 메타를 작은 참조로 전환한다. 기존 문항ID/FK·뜻/발음은 보존한다.
4. 개별 접수·포인트의 삭제나 거래 합산 없이 반복 표현만 줄인다. 전체행을 읽는 구형 소비자는 호환 조회로 먼저 연결한다.

이 보완은 승인된 중복 저장 축소·학생 기록 보존 요구의 누락을 메우는 작업이다. 제품 변경은 별도 APP 기록으로 묶고, M09는 최종 인원 검증을 미완료로 유지한다. M10 운영 반영·M08-B 운영 회수와 F01/F02 구현은 아직 완료하지 않았다.

Supabase의 GitHub 로그인 연결은 자동 승인 심사가 해당 계정 접근 승인이 없다는 이유로 거절했다. 우회하지 않았고 사용자 직접 로그인을 요청했다. Vercel 로그인은 정상이며 이 제한과 관계없다. 운영 DB 쓰기·실제 학생 변경·유료 전환·새 배포는 이번 측정에서0이다.

## 8. 재현과 다음 비교

앱 저장소에서 [reproduce.mjs](OPS-20261003-02_계측/reproduce.mjs)를 Node로 실행한다. `--check-only`는1,909입력과6증거의 확인값만 검사하며 이번에 통과했다. 인자 없이 실행하면 약4~5분의 격리 PGlite 검사 후 `.codex-tmp/m09-model/`에 새 결과를 쓴다. 네이티브 initdb나 클라우드 쓰기를 사용하지 않는다.

기준 결과의 제품 스키마는e57f399, 포장 시 문서 HEAD는a0c7f42다. 이후 제품 변경 시 원 입력 확인값 검사가 멈추는 것이 정상이다. 변경 후 측정은 별도 결과 이름/명세로 보관하여 기준32회를 덮어쓰거나 개선 후 수치로 바꾸지 않는다. 보호 검사 우회·학생 기록 삭제·서버 접수 미확인 기기 답 자동 정리는 금지한다.
