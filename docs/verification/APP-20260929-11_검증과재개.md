## APP12 독립 설계 검토 메모

아래는 구현을 시작한 것이 아니라 다음 단계에서 다시 전부 탐색하지 않기 위한 읽기 전용 조사 결과다. 실제 설계 관문은 APP12 요구/결정/검사 기록에서 진행한다.

- 정규 응시 저장 함수를 재사용하지 않는다. 연습 회차/문항 2표와 서비스 전용 시작·읽기·답·전환·만료·결과 명령을 별도로 둔다. 정규 배정·응시·오답·복습 큐·포인트는 전후 불변을 검사한다.
- 기존 순수 출제 함수는1~500문항, 방향0/50/100, 전체 시간30~10800초·문제당5~600초를 지원한다. 현행 문제당 설정에도 전체10800초 상한이 함께 있으므로 무제한으로 바꿨다고 가정하지 않는다. 교사 직접 오답 배정의400개 제한과 혼동하지 않는다.
- 전체 조건 선택을 화면의10개나 RPC 첫501개로 대체하지 않는다. 미리보기와 저장의 원천/설정을 확인값으로 묶고 바뀌면 재확인시킨다. 성공한 시작 요청 재전송은 원천 재검사보다 기존 결과 확인이 먼저다.
- `createTargetedQuizQuestions`는 대상 본문 대신 보기 후보에서 같은 ID를 다시 찾는다. 대상과 보기 후보 모두 동일한 과거 표제어·뜻을 사용하고, 같은 원행의 다른 과거 뜻에는 내부 임시 식별자를 부여한다. 검토된 보기 제외 근거가 정확한 표제어·뜻에 해당하는지도 확인한다.
- `QuizFrame` 표시를 재사용한다. 현재 controller에 박힌 정규 API/결과 주소는 `use-quiz-submission`, `resolve-quiz-feedback-transition`, `use-quiz-recovery`, `use-quiz-player-controller`에서 통신 객체·결과 이동 함수만 주입 가능하게 분리한다. 정규 경로는 기존을 기본값으로 보존한다. 마지막 선택100ms와 복구/전환 경쟁 처리 전체를 복제하지 않는다.
- 가변 전환 계약의7초 예약·0~750ms 전환 확인·미사용 예약 회수, 서버 기준 제한시간·소유권·멱등 답 처리를 함께 검증한다. 미응답 정답은 클라이언트에 보내지 않는다.
- 실제 학생을 시험에 배정하거나 응시/답안 제출하는 것을 확인 수단으로 쓰지 않는다.
