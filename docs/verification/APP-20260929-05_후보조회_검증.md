# 배정 후보 전체 조회 보완

F05는 기존 예문·영영풀이/검토 문항을 한 번만 읽어 서버 반환 상한 뒤의 후보가 빠지는 문제다. 명시적 정렬과 페이지 조회로 바꾸고 실제 반환 행 수만큼 이동한다. 1,000개보다 짧은 페이지도 끝으로 추측하지 않는다.

선택 범위·방향·필수 값·중복·역순·출제판 일치를 확인한다. 빈 페이지까지 받은 뒤 첫 행을 재확인하여 더 짧은 출제판으로의 교체·삭제를 거절한다. 구성 단어장 분기, 최종 저장 검증, 회차당500 상한과 기존 배정 계산은 보존했다. 검사 응답도 실제 정렬·페이지 계약을 따라가도록 보완했다.

## 검증과 한계

- 관련4파일88검사 통과. 독립 검토자가 같은88개를 재실행했고 차단 지적 없음.
- 기존1001행·검토1002행·서버300행 상한, 중간 오류/중복/역순/다른 범위/출제판 변경, 마지막 첫 행 재확인, 실제 최종 스키마의 예문/날짜 없는 연속시험을 검사했다.
- 타입/lint·기능지도·설계 검사를 통과했다. 최신 입력 확인값과 완료 관문은 같은 번호 기록에 있다.
- 정상 조회에 종료 빈 페이지와 첫 행 확인 요청2회가 추가된다. 실제 서버 지연은 미측정이며 여러 요청이 동일 DB 시점이라는 보장은 하지 않는다. 불변 출제판·최종 저장 검증을 함께 사용한다.
- 새 브라우저 저장/운영 DB/실학생 쓰기·배포0. 최종 전체 빌드는 모든 수리 통합판에서 재검사한다.

다음 입력은 F06 포인트 응답 계약이다. 현재 상태·순서는 루트 대장만 따른다.
