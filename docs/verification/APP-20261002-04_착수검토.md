## 준비 정보라는 말의 정확한 대상

시작 버튼을 누른 뒤 실제 응시를 만들기 전에 학생/배정 번호, 문항 번호·순서·방향·최소 채점 정보와 내용판 참조, 준비 만료시각을 확정하는 작은 기록이다. 실제 응시가 생기면 그 번호를 연결해 재요청 때 같은 시험을 반환한다. 준비하다 창을 닫아 실제 시작하지 않은 만료 정보와, 실제 시험·답/결과는 다르다. 준비15분은 시험 제한시간이 아니다.

20261001145444_share_vocabulary_question_content.sql의 compact_initial_quiz_plan_v2는 prompt/choices를 제거하고 content_version_id를 남긴다. 20261002060000_submit_local_quiz_phase_batches.sql의 최신 prepare_quiz_attempt_v1도 이 함수를 호출한다. 신규 준비에서 본문을 반복 저장한다고 설명하면 부정확하다. 구형 배열 본문이 실제 남아 있는지·더 필요한지 확인한 뒤 정리 대상으로 삼고 작은 참조 전체를 삭제 대상으로 해석하지 않는다. 같은 준비의 기존 응시 연결·확정 만료 확인과 M05 늦은 답 접수는 보호한다. 이번 확인은 로컬 코드 읽기이며 현재 원격 준비 용량을 새로 측정하지 않았다.

음원 내용·발음은 사용자가 학생들에게 확인시키겠다고 했으므로 추가 검수하지 않는다. 기존 음성 중단 보완은 유지한다.

## 현재 코드에서 필요한 보호

1. 주 대상은 완료된 해당 앱의 예약 작업 상세다. 현재 저장소에는 cron.job_run_details의 기간 정리가 없다. 실제 원격 작업 ID·소유자·SQL을 구현 직전에 읽어 허용 목록을 고정하고 실행 중·다른 서비스·조사 보존 건을 제외한다. private.student_app_maintenance_state는 현재 상태, retry_state는 재시도 제어이므로 로그와 함께 지우지 않는다.
2. 세션은 발급일 대신 실제 사용 불가 확정 시각을 기준으로 한다. 활성60일/일별 갱신과 최근15분 실패 제한을 보존하고, 삭제 직전 조건을 다시 검사한다. 로그인 시도 표에는 성공도 있어 실패 보관기간을 모든 행에 일괄 적용하지 않는다.
3. 준비의 begun_id만 확인하면 안 된다. 같은 ID의 실제 응시와 자율연습 요청 연결을 함께 검사하고, 시작과 같은 학생→준비 잠금 순서를 따른다. 실제 응시가 있는데 시작 표시가 누락된 경우에도 복구 연결을 보존한다. 본문을 줄여도 같은 요청의 기존 응시 또는 확정 만료 응답은 남긴다.
4. M05의 local_quiz_runs/phase_plans/phase_receipts, 답 접수·결과와 기기 runs는 기간 정리 대상에서 제외한다. 마감시각이 지나도 기한 내 기기 답은 늦게 접수할 수 있으므로 deadline/expires 값만으로 관련 확인 자료를 지우지 않는다. 진행·재시험·미접수 원판도 보호한다.
5. 읽기 미리보기와 실행을 분리하고 UTC 상한, 제한량, 재개 위치와 중복 작업 잠금을 고정한다. 기록은 대상/삭제/제외 수·정책판·오류·처리시간만 남긴다. 원문을 다른 로그에 옮겨 저장하지 않는다. 최초 운영 정리와 VACUUM FULL 등 물리 회수는 별도 작업이다.
