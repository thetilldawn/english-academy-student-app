**2026-09-29 재점검: "이전에 되던 연결 정보가 갑자기 누락됐다"는 원인 설명은 확인되지 않았다.** 오류 문구를 실제 삭제 원인으로 확대하고, 과거 배포 성공과 MCP 프로젝트 조회 성공을 혼동했던 판단을 정정한다. Vercel 웹사이트 재로그인이나 새 OAuth 승인을 현재 재개 필수 조건으로 요구하지 않는다. 연결된 앱 도구의 팀 조회와 GitHub 전송·검토 배포 자체는 성공했지만, 프로젝트 조회와 보호된 검토 화면 확인은 별개다.

- 프로젝트 `.codex/config.toml` 수정 시각은 2026-09-01 13:23:21 KST다. 파일 시각만으로 내용 이력 전체를 증명할 수는 없지만, 오늘 설정이 삭제됐다고 볼 근거는 없다.

- [OpenAI 공식 변경 기록](https://learn.chatgpt.com/docs/changelog)은 9월 17일 CLI 0.155.0의 만료된 MCP 인증·갱신 실패 안내 개선을 설명한다. [공식 MCP 문서](https://learn.chatgpt.com/docs/extend/mcp)는 인증 서버 식별자 검증을 설명한다. 그러나 현재 설치된 alpha 버전의 저장 형식 변경이나 이번 오류의 직접 원인을 설명하는 근거는 찾지 못했다. "업데이트가 기존 인증을 깨뜨렸다"는 결론도 내리지 않는다.
- 인증 갱신 시점에 필요한 정보가 없어서 오류가 드러났을 가능성은 있으나, 최초 저장 때부터 없었는지·읽기 방식이 달라졌는지·언제부터 실패했는지는 미확인이다.

### 이번에 확인한 두 연결의 차이

- 연결된 Vercel 앱 도구: 현행 [프로젝트 도구](https://vercel.com/docs/agent-resources/vercel-mcp/tools/projects)는 `idOrName`, [배포 기록 도구](https://vercel.com/docs/agent-resources/vercel-mcp/tools/deployments)는 `list_deployment_events`를 사용한다. 현재 세션의 노출 도구는 이전 `projectId`·`get_deployment_build_logs` 규격이다. 규격 차이는 공식 문서·독립 검토로 확인했으며 내부 전달 코드의 정확한 결함 위치는 미확정이다. 프로젝트 목록 0개·배포 403의 원인까지 이 차이 하나로 단정하지 않는다.
- 프로젝트 전용 MCP: 루트 `.codex/config.toml`에 `enabled = true`, URL `https://mcp.vercel.com/thetilldawn-3859s-projects/english-academy-student-app`로 등록되어 있다. `list_mcp_resources(server="vercel")`가 **`OAuth refresh credentials for server vercel are missing an authorization server issuer`**로 시작에 실패했다. Codex가 갱신용 인증에서 필요한 서버 식별자를 얻지 못했다는 오류는 확인했다. 실제 저장값 삭제·누락 시점·변경 주체를 확인한 것은 아니며, Vercel 브라우저 로그인 상태나 앱 코드 문제와 구분한다. 인증 저장소는 읽지 않았다.

### 앞서 시작한 인증 준비의 종료

[OpenAI 공식 MCP 지침](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)과 설치된 `codex-cli 0.155.0-alpha.9.2` 도움말의 OAuth 명령을 확인했다. 일반 명령은 프로젝트 설정을 찾지 못해, **이미 등록된 동일 URL을 해당 실행에만 지정**하고 `mcp login vercel --no-browser`를 시작했다. 네트워크 허용 후 정상 승인 URL과 숨김 입력 대기까지 도달했다. 설정 파일 수정·저장된 인증값 추출·브라우저 자동 조작은 하지 않았다.

해당 실행 세션 `81122`는 **`timed out waiting for OAuth callback` / `deadline has elapsed`로 종료 코드 1을 반환했다.** 사용자 승인·인증 완료는 확인되지 않았고, 더 이상 대기 중인 터미널이 아니다. "사용자 인증 대기"와 "준비된 세션이 끝나면 다시 인증부터 시작"이라는 이전 지시는 철회한다. 이번 재점검에서는 새 인증 실행·설정 변경을 하지 않았다. 승인 URL·state·반환 코드는 보고서나 Git에 저장하지 않는다.

기존 MCP를 통한 읽기 전용 재확인 결과는 다음과 같다. 이는 MCP 미연결이나 사용자 브라우저 로그인 만료와 구별한다.

- 팀 조회: 정상, 대상 팀 1개.
- 같은 팀의 프로젝트 목록: 정상 응답이지만 0개.
- 지정 배포 목록: 403 `You don't have permission to list the deployment`.
- 지정 배포 상세: 404 `Deployment not found`.
- 프로젝트 상세: 연결 도구는 `projectId`를 받지만 서버는 `idOrName` 누락 오류를 반환한다. 두 필드를 함께 전달해도 같은 오류다.
- 빌드 기록: `Tool get_deployment_build_logs not found`.

따라서 연결된 앱 도구에서는 **대상 프로젝트/배포 조회 거절과 호출 규격 차이**, 별도 프로젝트 MCP에서는 **인증 서버 식별자를 얻지 못하는 시작 오류**를 확인했다. 두 오류의 근본 원인과 복구는 미확인이다. 같은 실패 호출을 반복하거나 사용자에게 일반 조회 허용을 다시 요구하지 않는다. 웹사이트 재로그인만으로 두 문제를 해결할 수 있다고 주장하지 않는다.

저장된 CLI 인증값을 직접 읽어 조회하려는 시도는 자동 안전 검토가 거절했다. 자격 증명 노출·우회 위험 때문에 실행하지 않았으며 다른 방식으로 해당 인증값을 꺼내지 않았다. 관련 임시 실행 파일은 제거했다. **거절된 인증값 직접 읽기와 우회 재시도는 금지한다.** 정상 연결 도구의 보호 페이지 조회도 프로젝트 접근 불가를 반환했다. 공개 GitHub 조회에는 인증값을 사용하지 않았다.

이전 브라우저 재확인 자체가 자동 안전 검토에서 거절된 사실은 유지한다. 새 화면을 읽거나 로그인·권한 변경을 실행한 것은 아니다. 거절된 브라우저 접근은 우회하지 않되, **이를 이미 연결된 MCP 읽기 전용 조회의 추가 승인 요건으로 확대하지 않는다.** 이번 재확인에서는 브라우저·인증값·보안 설정을 건드리지 않았다.

검토 배포 성공 표시만으로 보호된 화면·현재 환경 결속까지 검사했다고 기록하지 않는다. 빌드 로그는 이번 재개에서 확인했지만 보호된 앱 응답 확인이 남아 있어 운영 반영을 진행하지 않았다. 인증 보호를 끄거나 공유용 우회 URL을 만들지 않는다.

## 다음 시작점

1. 위 공식 CLI 재개 결과부터 읽는다. 이미 정상 조회한 CLI를 사용하고, 실패 중인 MCP를 반복하거나 종료된 OAuth 절차부터 다시 시작하지 않는다. 저장된 인증값을 직접 꺼내거나 거절된 브라우저 접근을 우회하지 않는다.
2. 코드·빌드·환경 분리 사전 검사 확인은 끝났다. 위 자동 검사 접근키 생성/폐기 범위의 명시적 승인 후, 보호된 검토 주소의 `/api/preview-identity`와 비로그인 보호 응답을 읽고 새 키를 즉시 폐기한다. 가능한 관리자 읽기 전용 화면은 앱 로그인 확보 여부와 별도로 기록한다. 기존 검토 DB SQL은 이미 적용했으므로 재실행하지 않는다.
3. 원격 main과 운영 알림 함수 MD5 `11d028084bddf0a0eec52f7b81142d24`, 공개 판정 함수와 대량배정 55초 설정을 재대조한다. 달라졌으면 새 변경을 보존하는 검토부터 한다.
4. 검토가 통과하면 `.codex-tmp/DEPLOY-20260929-01/apply-guarded.sql`을 **운영 프로젝트 xdxhswjgksukjmpbzqgz 한 곳**에 적용하고 정의·권한·보존을 다시 읽는다. 읽기/반영 도구를 혼동하지 않고 이번 한 건만 적용한다.
5. 같은 `02a2d65`를 기존 main에 정상 전송한다. 강제 전송이나 검토 빌드의 운영 승격은 금지한다. 같은 코드의 운영용 별도 빌드·대표 주소·가능한 관리자 화면과 15분 오류/지연 관찰을 완료한다.
6. 복구가 필요하면 현재 함수가 이번 배포본과 같은지 확인하는 `production-guarded-rollback.sql`만 사용한다. 이 파일의 자동 방어는 함수 정의만 비교하므로, **실행 전 현재 함수 실행 권한도 `{postgres=X/postgres,service_role=X/postgres}`와 대조하고 다르면 중단한다.** 다른 새 수정이나 학생 행을 덮어쓰지 않는다. 가짜 DB 재현용의 가드 없는 이전 정의 파일은 운영 복구에 사용하지 않는다.

현재 상태와 우선순위는 루트 대장만 관리한다. 배포 준비/검토 반영/운영 반영/실사용 검증은 각각 별개다.
