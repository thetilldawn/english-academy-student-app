# 출제 보기 보완 반영 명세

APP02~05의 로컬 구현에 이어 적용할 APP06 변경이다. 원고의 검토 근거를 조회·출제·저장까지 보존한다. 원문·단어 목록·학생의 과거 문항·점수는 바꾸지 않는다. 실제 수능 원고와 템플릿 등록은 이 명세에 포함하지 않는다.

기존 [APP04 통합 명세](APP-20260921-04_반영명세.md)의 SQL5건, [APP05 명세](APP-20260921-05_반영명세.md)의 060000, 이번 `20260921070000_preserve_reviewed_choice_conflicts.sql`까지 총7건을 순서대로 적용한 뒤 같은 검증 앱 판을 배포한다. 적용 대상 Preview는 `wojxpruvbjzbhrpmsbuy`, Production은 `xdxhswjgksukjmpbzqgz`이며 환경별 적용·배포·확인을 따로 기록한다. 전체 밀어넣기는 사용하지 않는다.

이번 SQL SHA-256은 `1F82C114080511967F02C60BCE19866DF1AED60BD5F01A5F714B16FE66AEF70C`이다. 함수·트리거만 추가/교체하며 기존 학생/자료 행 갱신과 새 데이터 등록은 없다. 관리자 전용 커서 조회는 항목 ID와 nullable 검토 정보만 반환한다. 학생·익명·일반 서비스의 직접 접근은 거절한다. 새 수능 원출현에는 검토 정보를 필수로 검증하고, 새 배정 및 조합 문항의 발문·정답·제외 보기와 구성을 최종 검사한다.

적용 뒤 migration 이력, 관리자 조회 권한, 원출현/배정/구성의 새 트리거3개, 두 구성 준비 함수와 완전 계획 검증 함수를 읽어 대조한다. 실제 시험 시작·학생 답안 제출을 점검용으로 사용하지 않는다. APP02의 이름·학교·학년 필수값은 기존 학생에 값을 추측해 넣지 않으며 실제 다음 저장/배정에서 보완하도록 한다.

복구 시 검토 근거를 가진 새 수능 자료의 등록과 새 출제를 먼저 중단한다. 저장된 원출현·단어·학생 기록은 지우지 않고, 승인된 이전 앱 배포로 되돌릴지 판단한다. SQL 방어를 임의 제거하거나 새 수능을 이전 출제기로 생성하지 않는다. 실제 적용 전에 이 문서·파일 SHA·대상·이전 배포를 함께 확인한다.

현재는 로컬 구현 결과이며 외부 DB·배포에 적용하지 않았다.
