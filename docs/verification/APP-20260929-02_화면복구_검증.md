# 화면 이동·내역 오류 보완 결과

## 수정과 원인

- 완료 내역의 실제 인증 거절(401/403), 다른 학생의 예전 커서(409), 일시 조회 실패를 구별했다. 앞의 두 경우만 이전 학생 목록을 버리고 새 문서로 이동하며, 일반 조회 실패에는 기존 목록과 더보기 위치를 보존한다.
- 결과 조회의 DB 오류를 `없는 결과`로 바꾸던 코드를 수정했다. 실제 없는/다른 학생 결과는 기존 404, 조회 장애는 해당 영역에서 안전한 안내와 재시도를 제공한다. 응답 본문이 멈춰도 완료 목록 요청은 7초 내 종료한다.
- 관리자 모달 슬롯의 빈 루트 경로에 null page를 추가했다. [Next 병렬 경로 문서](https://nextjs.org/docs/app/api-reference/file-conventions/parallel-routes)의 catch-all과 빈 경로 차이에 맞춘 보강이며, 이 누락이 사용자가 겪은 모든 사건의 원인이었다고 단정하지 않는다.
- 오류 버튼은 설치된 Next 16.2.12의 `unstable_retry`를 전달해 서버 재조회까지 실행한다. 해당 설치본 error-boundary 구현과 타입을 확인했으며, 현재 공식 안내에 없는 이름을 공식 문서의 권장으로 포장하지 않는다. `reset` 호환은 유지하고 정상 모달 닫기에는 재조회하지 않는다.

## 검증

- 관련 50파일 321검사 통과. 학생 변경·커서 및 최종 제목 계층 보완 후 4파일 14검사 재통과. 독립 검토 8파일 36검사 통과, 남은 차단 지적 없음.
- 타입·변경 코드 lint·기능 지도(24 page/30 special/53 API)·화면 구조 검사, 최종 40페이지 생산용 빌드 통과.
- 완료 관문에서 기존 결과 조회 테스트의 소유 연결 누락을 발견했다. 원래 테스트 위치를 유지하고 유일한 동명 등록 서비스의 테스트 소유를 연결했다. 원본 없음/다른 위치/동명 원본 중복은 미연결, 명시 등록은 우선하도록 보호했다. 관련 118검사·지도·lint 재통과.
- 변경 기록 연결 70건 검사는 통과했다. 그 검사는 마지막 학생 커서 보완 전에 시작했으므로 최신 파일 전체 연결은 후속 통합 검사에서 다시 확인한다. 이 작업의 완료 관문은 최신 파일 해시로 별도 확인한다.
- 로컬 가짜 자료 브라우저에서 내역→학생 상세→학교 입력 모달→역순 닫기→개요, 앞으로 이동, 직접 URL/새로고침을 확인했다. 정상 모달 왕복 동안 최초 내역 목록 조회는 1회 그대로였다. 일정 등 다른 화면의 별도 자료 조회까지 0회라는 뜻은 아니다.
- 가짜 DB가 의도적으로 결과 요청을 거절하는 상황에서 404 대신 안전한 오류가 표시됐다. 다시 시도를 누르면 실제 결과 조회가 1회→2회로 늘었다. 계속 거절하는 시험 장치이므로 이후 정상 응답 복구까지 확인한 것은 아니다.
- 브라우저에서 발견한 결과 오류 제목 중복은 h2로 수정하고 컴포넌트 검사·최종 빌드로 확인했다. 요청 기록: `.codex-tmp/APP-20260929-02_가짜화면_요청기록.json`.
- 초기 검사에서 잘못 놓인 hook 호출로 실패한 항목은 위치를 고친 뒤 재검사했다. 이를 통과 결과에서 숨기지 않는다.

## 범위와 다음 입력

실제 학생·운영 DB 쓰기, 외부 전송/새 배포는 0이다. 세션 60일/갱신 정책·소유자 검사·개인 응답 no-store·정상 닫기 캐시는 유지했다. 다른 탭의 학생 변경을 실시간 감시하는 새 기능은 추가하지 않았으며, 변경이 서버 응답으로 확인된 경우를 고쳤다.

가짜 서버와 탭을 종료했고 기존 빌드를 복원한 뒤 최종 빌드를 다시 생성했다. 변경 범위/검사별 확인값은 `architecture/work-records/records/APP-20260929-02.json`을 따른다. 다음 입력은 F01 및 APP-20260929-03 시험 응답 본문 대기 재현이다. 상태·순서는 루트 대장만 따른다.
