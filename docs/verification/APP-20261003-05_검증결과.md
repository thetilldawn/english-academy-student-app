# 자료판의 중복 단어 목록 공유와 복구 검증

이미 원출현에 있는 단어 내용을 자료판에 다시 저장하던 부분을 줄였다. 검토 승인 자료의 단어 목록은 원출현 키와 원래 배열 순서로 다시 조립하고, 원래 본문 확인값과 정확히 같을 때만 사용한다. 구현 커밋은 `6e0ba8a`다. **검토 DB에서 가짜 자료만 전환·복구했으며 운영 DB·배포·실제 학생 쓰기·물리 공간 회수는 모두 0**이다.

[요구·결정·검사](../work-orders/APP-20261003-05.md), [검토 DB 실행 명세](APP-20261003-05_검토DB_실행명세.md), [수치·확인값·두 연결 근거](APP-20261003-05_검토DB_근거.json)를 함께 보관한다.

## 바뀐 내용과 경계

- 검토 승인 자료의 `package_json.entries`만 줄인다. 원출현의 `package_entry_json/audio_json`과 원자료 검토 본문, 학생 기록은 이번 전환 대상이 아니다.
- 헤더는 자료판에 남기고 원래 단어 순서·본문 확인값을 작은 명세로 기록한다. 누락/null, 제외 항목, 추가 필드를 버리지 않는다. 원문을 같은 크기의 다른 DB 표로 복사하지 않는다.
- 원본 재등록 비교와 오답 준비 확인 함수 2곳의 읽기만 바꿨다. 기존 함수 6개의 OID·권한·설정을 보존했고, 2개 정의는 명세의 정확한 치환과 일치한다. 나머지 4개 정의는 동일하다.
- 한 번에 자료판 1건, 원행 16MiB/파일 32MiB, 거래 30초/잠금 1초, READ COMMITTED로 제한한다. 현재 자료·등록기 잠금·행/원출현 잠금을 잡은 뒤 다시 대조한다.
- 복구는 사본의 본문만 되돌린다. 새로 쌓인 답이나 현재 자료의 종료 상태를 과거로 돌리지 않는다. 준비 응답이 유실돼도 본문이 남은 상태라면 최초 사본과 같은 응답을 재발급한다.
- 직접 수정 가능한 옛 자료·파생 자료·특수 g12 목록은 이 도구에서 제외한다. 공용 단어 48시간, 미사용 준비 24시간, 미접수 답 보존 기준은 그대로다.

## 로컬과 실제 흐름 검사

전체 **625파일 5,060검사 통과, 기존 제외 1개**다. 최종 검사 강화 뒤 대상 12개도 통과했다. 타입·변경 파일 린트·기능 지도·UI 구조·53페이지 빌드를 확인했다. 제품 화면 변경이 없는 내부 자료 처리 도구라 추가 화면 시나리오는 없다.

로컬은 새 SQL 직전에 실제 기존 등록기로 월별 6항목과 수능 100항목을 등록했다. 배열 순서 [3,1,6,2,5,4], 제외 항목, 추가 필드, 한글·큰 정수, 잘못된 환경/크기/파일/현재 행, 원출현 변조·삭제 보호, 복구 취소를 검사했다. APP04의 비교 검사도 이후 추가된 빈 표는 0행인지 검사하되 기존 표의 내용 비교에서는 분리하도록 보완했다.

검토 DB 적용 이름/시각은 근거 JSON의 migrations에 기록했다. 본 SQL은 `20261002234601`로 적용됐다. 비공개 3표/8함수의 앱 역할 권한은 0이고 불변 보호는 유지된다.

| 확인 | 실제 검토 DB 결과 |

| 전환 전후 기존 조회 | 자원 11개·범위 4개·자료판 2개의 원래 내용 확인값 동일 |

실제 MCP SQL 연결과 별도 HTTP 연결에서 6사례를 검사했다. 두 연결의 PID를 맞춰 보고 대기는 `pg_blocking_pids`, 즉시 포기는 `55P03`으로 확인했다.

1. 등록기 실행 중 운영자 전환은 잠금 충돌로 포기.
2. 운영자가 전환하는 동안 실제 등록기는 기다렸다가 기존 결과 반환.
3. 같은 전환 요청은 거래 중 포기하고 확정 뒤 최초 응답 재반환.
4. 전환 전 오답 준비의 **첫 저장**이 release를 잡고 있으면 운영자 전환 포기.
5. 정상 자료 종료 중 전환 포기; 이후 사본 복구는 최신 종료 상태 유지.
6. 처리한 키보다 작은 새 release는 확정 전 후보에 없고 확정 후 새 조회에 포함. 이는 후보 가시성 검사이며 행 잠금 검사로 주장하지 않는다.

## 기록 보존과 종료

적용 전과 최종 대조에서 **기존 179표 252,453행의 수량·전체 행 확인값 차이는 0**이었다. 각각 35개의 짧은 읽기 거래로 나눴으므로 같은 순간의 단일 스냅샷은 아니다. 정기 관리 상태 3행은 애초 이 비교에서 제외하고 현재 상태를 따로 기록했다.

새로 생긴 **47표 257행**은 모두 가짜 관리자·승인·자료·학생에 연결됐다. 245행은 새 행의 실제 외래키 연결로, 나머지 감사 기록 12행은 별도 확인한 가짜 인증 사용자 연결로 확인했다. 가짜 인증 사용자 1행은 이 수에 포함하지 않는다. 실제 자료 본문을 보고서로 복제하지 않고 키와 개수/확인값으로 검사했다.

가짜 학생 2명은 차단/삭제 상태, 배정 3개는 종료, 자료 3개와 관리자는 비활성이다. 두 시험의 접수 10개와 기록은 유지했다. 임시 검사 함수는 제거했고 일회 허용 잔여 0, 사본 명세 3개/전환·복구 접수 6개다.

검사용 호출 두 개를 처음 병렬 실행했을 때 도구 실행 시점이 겹치지 않아 양쪽 거래가 제한 시간 내 취소됐다. 숨김 HTTP 연결을 먼저 시작해 최종 6사례를 다시 검사했다. 점수 확인문의 정수 변환 오류 1회도 전체 거래가 취소된 뒤 수치 비교를 수정해 재검사했다. 후보 검사 함수의 키 연결 오류는 임시 검사 코드에서만 고쳤다. 이들을 제품 장애나 학생 기록 손실로 분류하지 않는다.

## 사본과 남은 단계

접근 상속을 차단한 모든 Git 밖 TEMP 폴더에 가짜 사본 3개를 저장/fsync/재읽기했다. 총 37,767바이트이며 각 SHA-256/경로는 근거 JSON에 있다. 접근 주체는 사용자·작업 계정·SYSTEM·Administrators다. 실제 운영 자료의 영구 사본은 별도 M08-B 절차가 필요하다.

운영 읽기 집계에서 자료판 27개의 entries는 원출현과 일치했다. 이번 대상인 검토 승인 20개의 entries JSON text는 **32,819,561바이트**다. 이는 회수한 물리 공간이 아니다. 원출현의 두 본문, 검토 자원, 구성 문항의 출처 근거와 미대상 7개 자료판은 후속 소비자 검토가 필요하다. M09 인원 산정·M10 배포·M08-B 운영 정리는 아직 완료되지 않았다.

최종 독립 근거 검토에서 완료를 막는 불일치·과장은 0건이었다. 합산·전후 확인값·PID·기록 보존·시험/빌드 로그·SQL과 사본 해시를 별도로 재확인했다. 완료 관문은 11범위·655입력·6검사를 통과했고, 입력 지문은 `fecd163df26ff0811445f2861b5063721039b116daae889f7eb3fde103b273c2`다.
