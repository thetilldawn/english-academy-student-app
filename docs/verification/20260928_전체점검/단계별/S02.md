# S02 — 기존 자동검사 실행

## 입력

S01_검사범위.json, package.json, lockfile, 검사/빌드 설정과 관련 scripts.
앱에 지정된 Node/npm 버전과 기존 실행 프로세스·산출물 상태를 확인한다.

## 순서와 명령

각 하위 묶음을 별도 실행으로 나눌 수 있다. 명령은 앱 작업본에서 실행한다.

- S02-A 정적 검사: npm run typecheck, npm run lint를 각각 실행한다. 종료 코드와 최초 오류를 기록한다.
- S02-B 전체 기존 검사: npm run test. 전체 검사 전 외부 연결을 호출하는 setup/fixture가 없는지 확인한다.
  package의 maxWorkers=4를 넘기지 않으며 다른 대규모 DB 검사·빌드와 겹치지 않는다.
  전체 파일/사례/통과/실패/건너뜀 수를 저장한다. 중간 로그만 보고 통과로 기록하지 않는다.
- S02-C 구조·기록: npm run verify:feature-map,
  npm run verify:work-records -- --phase format,
  npm run verify:architecture:static,
  npm run verify:server-architecture,
  npm run verify:react-request-cache를 나누어 실행한다.
  전체 static 명령의 변경 기준과 소요가 큰 부분은 스크립트에서 확인하고 로그를 분리한다.
  지정하지 않은 모든 과거 완료 기록에 complete를 일괄 실행하지 않는다.
- S02-D 빌드: npm run build를 현재 지원 옵션으로 실행한다.
  이전 기록의 webpack 대안이 필요하면 로컬 명령 도움말과 적용 이유를 확인해 기록한다.
  기존 서버/산출물과 충돌하지 않는 출력 위치가 있는지 먼저 확인한다.
  기존 .next 등을 임의 삭제하거나 다른 세션의 서버를 종료하지 않는다. 안전한 실행이 안 되면 이유를 남긴다.

현재 package.json에는 전용 격리 build 명령이 없다. 일반 build의 prebuild에는 환경·지도·기록 형식 검사가 포함된다.
기존 package/next 설정을 감사 목적으로 고쳐 격리 옵션을 만들지 않는다. 필요한 안전한 검사 환경을 먼저 확보한다.
static 명령에 design/changed가 이미 포함되므로 같은 설계 검사를 중복 완료 수로 더하지 않는다.

## 기대 결과와 실패 처리

타입·lint·구조·기록·빌드 각각 종료 0인지, 전체 검사에서 fail/skipped가 있는지 별도로 판정한다.
시간 초과를 코드 결함으로 단정하지 않으며 최초 실패를 보존한 뒤 같은 입력으로 통제된 재실행만 한다.
실패한 검사 이름을 후속 기능 단계와 연결한다. 기존 테스트만 통과했다는 이유로 실제 화면/운영 검증 완료로 쓰지 않는다.
npm run verify 한 명령에 모든 결과를 묻지 않고 묶음별 근거를 남긴다.

## 종료 기준

모든 명령에 완료 결과 또는 실행 불가 사유가 있고, 후속 검토가 필요한 실패 목록이 있어야 한다.
