# S10 — 누락 재확인과 최종 보고

## 입력

S01_검사범위.json, 모든 S단계 결과의 요약/사례표, 진행 파일.
전체 소스를 다시 읽지 말고 미실행·문제·변경 영향이 있는 항목만 확인한다.

## 순서

- S10-A 범위: 현재 HEAD/변경 상태를 S01과 비교한다. 중간에 달라졌다면 영향받은 결과만 낡은 근거로 표시하고 재확인 범위를 지정한다.
- 기능·공용 영역·16흐름의 담당 사례와 판정을 모두 대조한다.
  누락 항목은 기존 담당 단계의 작은 하위 묶음으로 되돌려 확인한다. 안전상 실행 못 한 경우는 이유와 필요한 권한/환경을 남긴다.
- 전체 테스트, 부분 재실행, 임시 재현의 사례 ID를 대조해 같은 검사를 두 번 합산하지 않는다.
  자동검사 수/화면 확인 경로 수/실제 운영 읽기 확인/미실행은 각각 보고한다.
- S10-B 문제: 확인된 결함은 영향 큰 순으로 정리한다. 각 항목에 최소 재현·기대/실제·관련 파일/줄·근거·권장 수정 범위·재검사 방법을 붙인다.
  같은 원인의 여러 화면 증상은 묶되 독립 원인은 합치지 않는다. 가설/실행환경 문제/구조 개선과 구별한다.
- 중요한 문제와 미확인 경계는 새 읽기 전용 검토자에게 확인받고 메인이 결론을 확정한다.
- S10_검사결과.md에 한눈에 보는 결과, 문제별 상세, 미실행, 수정 권장 순서, 운영 기록 보존 여부를 작성한다.
- 모든 단계에 근거 또는 명시적 미실행 사유가 있고 누락 대조까지 끝났을 때만 감사 작업 완료를 대장에 기록한다.
  '검사 완료'와 '모든 기능 정상'은 다르다. 결함이 남아 있어도 보고 완료는 가능하나 고쳤다고 쓰지 않는다.

## 종료

진행 파일의 nextStep을 null, runningStep을 null로 하고 완료 보고 위치를 저장한다.
후속 실행 요청을 더 보내지 않는다. 삭제한 15분 예약을 재생성하지 않는다.
앱 수정·배포를 자동으로 시작하지 않고 발견한 문제와 권장 수정 순서를 사용자에게 보고한다.
