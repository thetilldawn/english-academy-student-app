# S05 — 배정·수정·이어지는 시험

## 입력

map:feature assignments, assignment-queue 및 map:owner shared-admin-command, database-contract.
배정 미리보기/저장/수정/대기열 흐름, 입력 계약, 순수 배분 계산과 관련 RPC 검사.
추가 55초 설정은 다른 작업의 별도 기록/SQL/검사를 읽고 본 작업에 합쳐졌다고 가정하지 않는다.

## 검사 순서와 기대 결과

- S05-A 조건: 의도한 단일 배정의 학년 차이는 허용하고, 일괄 배정의 차이는 포함/제외 확인이 필요한지 검사한다.
  제외 후 학생 1명이어도 audienceMode가 일괄로 유지되는지, 미상 학년을 잘못 확정하지 않는지 확인한다.
  DAY 정방향/역방향·양 끝 포함, 오름차순/내림차순/무작위, 요일/날짜 없음, 문제별/전체 시간, 미선택/빈 목록을 각각 검사한다.
  Preview와 save의 questionMode/commonPlan/distribution/selectedDateCount/sessions/timing/order 계약을 대조한다.
- S05-B 수량/저장: 0/1/199/200/201/400/401개와 사용 가능한 문항 부족을 가짜 자료로 검사한다.
  기본 경계 사례의 단위는 유효한 출제 문항 N개, 출제 방향은 단방향(가짜 원항목1개→문항1개), 회차당 제한은 설정값200개로 고정한다.
  2026-09-29 승인된 최소4문항 정책(APP-20260909-05 R3) 대조 후 기대값 정정:
  N=0/1 저장 거절, 199→[199], 200→[200], 201→[197,4], 400→[200,200], 401→[200,197,4]이다.
  양방향/혼합 출제는 별도 사례로 원출현 수·중복 제거 후 항목 수·생성 문항 수·출제 가능 문항 수를 구분하고 승인된 규칙으로 기대 회차/잔여/총문항 수를 먼저 계산한다.
  중복·누락 없는 회차 합계, 마지막 잔여, 미리보기와 저장 계획 일치, 유효하지 않은 요청 거절을 확인한다.
  저장 전 실패·응답 유실·재시도·중복 요청·입력 변경·취소를 모의 HTTP와 격리 DB로 재현한다.
  결과 불명확 상태에서 중복 배정하지 않고 기존 요청 식별자로 확인할 수 있어야 한다.
- S05-C 수정/다음 회차: 오답 선택·선택 안 한 오답·이미 해결된 오답, 배정 수정/취소, 앞 시험 완료와 재시험을 나눠 검사한다.
  다음 회차 해제는 정해진 선행 조건에서 한 번만 일어나며, 과거 응시/점수/답안은 보존되어야 한다.
  여러 탭 동시 수정·기간 경계·원본 단어장 변경도 격리 DB로 확인한다.

## 방법과 종료 기준

단위/계약/컴포넌트 검사와 PGlite 통합 검사를 우선한다. 실제 관리자 저장은 하지 않는다.
55초 설정은 함수 본문/권한/전역 제한을 바꾸지 않은 별도 설정인지 근거를 확인하고 현행 미보유 SQL을 구별한다.
각 경우에 입력 수·계획 수·저장 모의 결과 수와 기대 차이 0 여부를 남긴다.
