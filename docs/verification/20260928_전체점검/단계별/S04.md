# S04 — 관리자 학생·내역·상세 화면

## 입력

map:feature students, history와 map:owner shared-ui, 가까운 AGENTS.
학생 목록/상세 및 history API, @detail 가로채기 경로와 일반 상세 페이지.
기존 로컬 관리자 가짜 자료 도구의 지원 범위를 읽는다.

## 검사 순서와 기대 결과

- S04-A 학생 관리: 검색·학교/학년 조건·조건 없음·검색 0건·더보기 마지막 페이지를 검사한다.
  조건을 빠르게 바꾸어 늦은 이전 응답이 현재 목록을 덮지 않는지 확인한다.
  등록/수정/차단은 실제 저장하지 않고 가짜 API의 성공·검증 실패·401/403·503·응답 유실로 검사한다.
  일시 오류에서는 입력을 유지하고, 실제 권한 상실 시 개인정보를 보호해야 한다.
- S04-B 내역/모달: 목록→상세→닫기, 브라우저 뒤로/앞으로, 상세 직접 주소, 상세 새로고침을 각각 실행한다.
  닫기만으로 목록 새로고침·선택/필터 초기화가 없어야 한다. 요청 수와 목록 상태를 전후 비교한다.
  없는 내역, 목록보다 최신인 내역, 상세 실패/인증 만료는 잘못된 오류 종착 화면에 갇히지 않고 명확한 복구 경로가 있어야 한다.
  생성/수정/삭제 성공 후에는 해당 자료만 갱신되는지 모의 명령으로 확인한다. 사용자 요구 없는 새로고침 버튼을 전제로 삼지 않는다.
- S04-C 사용성: PC와 좁은 모바일 화면, 키보드 Tab/Escape/Enter, 모달 초점 복귀, 긴 이름/문구, 목록 빈 상태를 확인한다.
  버튼 중복 처리, 로딩 중 닫기/이동, 연결 실패 후 복구의 실제 문구를 기록한다.

## 방법과 종료 기준

관련 컴포넌트/요청 수명/Route 테스트와 실제 로컬 브라우저 이동을 함께 사용한다.
코드상 캐시 선언만으로 요청 0회 또는 UI 유지 판정을 내리지 않는다.
화면 지원이 없는 경로는 미실행 사유와 남은 확인 방법을 남긴다.
