# S03 — 학생 로그인·학습·시험·결과

## 입력과 출발점

map:feature의 session, student-dashboard, quiz-player, results 및 가까운 AGENTS.
src/app/api/student/session/route.ts, 학생 page/attempt/result 진입점,
답안 Route와 지도에 연결된 controller/domain/server/DB 검사.
S02 실패 목록과 기존 가짜 학생 화면 도구의 지원 범위를 먼저 확인한다.

## 검사 순서와 기대 결과

- S03-A 로그인/목록: 정상·잘못된 코드·차단/회전·만료·로그아웃·재진입을 로컬 모의 응답으로 검사한다.
  정상 사용자는 자기 배정/학습 자료만 보이고, 인증 실패에서는 이전 개인정보가 남지 않아야 한다.
  미배정 0건과 조회 실패를 다른 문구/복구로 보여야 한다.
- 학습 상세 열기/닫기, 뒤로가기, 직접 주소 접속을 검사한다. 닫기만으로 목록 상태·스크롤·선택이 사라지거나 불필요한 조회가 발생하는지 요청 횟수로 확인한다.
- S03-B 답 입력: 가짜 시계로 A→B→C를 100ms 안에 입력한다.
  99ms 이전 전송 0, 마지막 입력에서 100ms 후 최종 선택 1회인지 확인한다.
  타이머 만료 직전 입력, 중복 클릭, 다음 문제 전환 중 입력도 각각 검사한다. 별도 음성/결과 표시 대기는 무단 변경하지 않는다.
- 문제별 5/8/10초는 다음 문제마다 해당 문제 시간으로 시작해야 한다.
  전체4분은 풀이 예산이 문항마다 처음으로 다시 시작하지 않아야 한다. 2026-09-29 기준 대조 정정:
  승인된 APP-20260927-01은 실제 피드백 동안 풀이 시계를 멈추고 예약7초의 남은분을 회수한다.
  절대 마감시각 불변을 강제하지 말고 예약분이 풀이시간으로 잘못 표시되는지 검사한다. 근거는 S03 결과 참조.
  배경 탭·재진입·시계 경계는 가짜 시계로 재현하고 실제 브라우저 제한과 구분한다.
- S03-C 실패/결과: 답 저장 전 실패, 저장 후 응답 유실, 늦은 응답, 재시도, 두 탭 동시 답을 로컬 모의 API/격리 DB로 재현한다.
  같은 답이 두 번 저장되거나 문제를 두 번 넘기지 않고, 저장 여부 불명확하면 안전한 재조회/복구가 있어야 한다.
  완료 후 같은 응시 ID의 저장값과 결과 화면이 일치해야 한다. 오답·재시험은 승인된 대상 선정/횟수 규칙과 맞아야 하며, 재시험 점수가 달라져도 이전 응시/점수를 보존해야 한다. 학습 조회 자체는 응시를 만들지 않아야 한다.

## 방법과 근거

관련 단위/컴포넌트/Route/DB 테스트를 지도에서 선정해 실행하고, 없는 사례는 메인의 임시 재현 도구로 보완한다.
로컬 화면에서 실제 버튼/네트워크 횟수/표시를 확인한다. 도구가 지원하지 않으면 코드 확인과 화면 미실행을 분리한다.
개인정보 없는 캡처와 사례별 시간·요청 수를 남긴다. 실제 학생 시험 시작/답 제출은 하지 않는다.

## 종료 기준

위 사례마다 판정과 근거가 있고 100ms·문제별·전체 타이머를 각각 별개로 판단한다.
