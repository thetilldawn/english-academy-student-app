## 순서

- S01-A 버전: 주 작업본의 git status --short와 git rev-parse HEAD를 확인한다.
  운영 근거 c210257, 계획 당시 HEAD 58af62c, DB 보완 5cf29e6의 git diff --name-status를 대조한다.
  실행 코드·문서·DB 설정·검사 파일 차이를 분리한다. 무단 병합/checkout/pull은 하지 않는다.
- 운영 배포/DB 상태는 승인된 연결의 읽기 전용 확인이 가능하면 갱신한다. 로컬 migration 존재를 운영 반영 증거로 쓰지 않는다.
  연결이 없으면 '현재 직접 확인 미실행, 마지막 확인 기록의 날짜/버전'으로 기록한다.
- S01-B 범위: 지도 features와 specialOwners, crossLayerFlows에서 실제 ID 목록을 뽑는다.
  12기능·공용9범주·16흐름은 계획 당시 수치이며 현재 목록과 대조한다.
  페이지/Route/API/공개 진입점도 지도와 대조해 지도 밖 경로를 별도 후보로 남긴다.
- 각 기능/흐름마다 주 담당 S단계, 관련 테스트, 추가 예외 사례, 화면 확인 방법을 연결한 S01_검사범위.json을 만든다.
  모든 feature/owner/flow의 담당 단계가 있어야 한다. entrypoints가 빈 학교 일정도 호출자에서 찾아 포함한다.
- package scripts와 Vitest/Playwright 설정에서 대상 파일 수, 외부 쓰기 여부, 필요한 환경을 분리한다.
  파일 수는 검사 통과 수가 아니다. 다른 작업의 DB 추가 검사도 별도 항목에 둔다.
- 기능 지도 명령은 npm run map:feature -- <실제 ID>, map:owner, map:flow를 사용한다.
  지도와 다른 현재 경로를 추정으로 채우지 말고 근거를 기록한다.
