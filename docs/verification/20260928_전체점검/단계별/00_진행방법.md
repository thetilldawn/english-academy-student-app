# 단계별 검사 진행 방법

이 폴더는 실행 지시다. 결과는 상위 폴더의 S01_검사결과.md처럼 별도 파일에 쓴다.
현재 순서는 상위 01_진행상태.json, 전체 범위는 상위 00_전체계획.md를 따른다.
이 문서와 이번 단계 문서만 읽고 시작한다. 다른 단계 원문 전체를 매번 읽지 않는다.

## 완료한 뒤 바로 다음 묶음으로

- 15분 예약은 사용자 요청에 따라 삭제했다. 시간 간격을 두지 않는다.
- 한 실행에 한 단계 또는 단계 안의 하위 묶음 하나를 처리한다. 결과와 다음 시작점을 먼저 저장하고 다음 실행 요청을 한 건만 전달한다.
- 작고 자연스럽게 끝낼 수 있는 단계는 그 단계의 하위 묶음을 함께 완료한다. 하위 항목 수만큼 무조건 별도 실행을 만들지 않는다. 검사량이 크거나 결과 검수가 밀릴 때만 세션을 나눈다.
- 전달 대상은 같은 작업 01a08a0f-9b0f-7180-b721-1d819ca9b2e8다. 새 작업이나 정기 예약을 만들지 않는다.
- 다음 실행 요청에는 작업 번호, 진행 파일, 이번 완료 묶음, 다음 묶음, 금지사항만 적는다. 전체 검사 계획을 복제하지 않는다.
- 후속 요청 도구의 실제 응답으로 접수 여부를 확인하고 01_진행상태.json의 continuation에 기록한다. 성공 응답이 없으면 '예약 완료'라고 쓰지 않는다. 실패한 요청을 맹목적으로 중복 전달하지 않는다.
- 요청을 받은 실행은 nextStep/nextBatch와 요청 대상을 먼저 대조한다. 이미 처리한 요청이면 검사를 반복하거나 새 후속 요청을 만들지 않는다. 현재 요청을 소비한 사실을 남기고 runningStep을 지정한 뒤 진행한다.
- 요청의 단계/묶음이 현재 nextStep/nextBatch와 다르면 오래된 요청으로 판정해 실행도 후속 전달도 하지 않고 종료한다. 접수 결과가 불명확하면 작업 이력과 진행 파일을 확인하기 전에는 재전송하지 않는다.
- S10 최종 보고를 마치면 다음 요청을 보내지 않는다. 사용자가 중단·방향 변경을 요청하면 새 지시가 우선이다.
- 실행을 나눈다고 이 작업의 대화 맥락이 저절로 초기화되는 것은 아니다. 필요한 파일만 읽고, 조사별 새 서브에이전트에는 해당 범위만 전달해 맥락을 줄인다.

## 각 묶음 시작과 끝

1. 진행 파일과 직전 결과를 읽고 해당 묶음이 이미 끝났거나 실행 중인지 확인한다. 실행 중이면 남은 프로세스·로그부터 확인해 중복 실행을 피한다.
2. HEAD, 변경 파일, 운영 기준의 변경 여부를 좁게 대조한다. 다른 작업의 수정은 보존한다. 영향이 있는 기존 검사만 재확인 대상으로 기록한다.
   실행 전에 activeRun에 실행 식별자·현재 묶음·시작 시각·로그 위치를 쓰고 batchProgress의 해당 묶음을 running으로 바꾼다. 명령 시작 후 프로세스/실행 세션 ID도 저장한다. 중단 복구 때 PID 숫자만 믿지 말고 실제 명령·경로·시각과 일치하는지 확인한다.
3. 해당 기능 지도와 가장 가까운 AGENTS를 읽는다. 명령은 현재 package.json과 검사 스크립트에서 존재·부작용을 확인한 뒤 쓴다.
4. 조사·읽기 전용 리뷰는 필요한 범위만 나눠 맡긴다. CPU/메모리를 많이 쓰는 전체 검사·DB 검사·빌드는 겹치지 않게 실행한다.
5. 실제 검사 명령, 실행 버전·환경·시간, 종료 코드, 통과/실패/보류 수, 최소 재현 근거를 기록한다. 시작한 명령과 완료한 명령은 다르다.
6. 결과를 저장한 뒤 runningStep을 비우고 다음 하위 묶음 또는 다음 단계를 지정한다. 그 뒤 후속 요청 한 건을 전달한다.
   batchProgress에는 completed/partial/not_run과 남은 검사·결과 경로를 기록하고 activeRun을 비운다. partial은 같은 단계의 정확한 재개 위치를 nextBatch/resumeNote에 남긴다. 외부 권한 때문에 not_run이면 사유를 보존하고 가능한 다음 묶음으로 간다.

## 공통 검사 기준

- '검사 완료'는 문제가 없다는 뜻이 아니다. 계획한 사례 모두에 실제 판정 또는 미실행 사유가 있고 근거가 연결되어야 한다.
- 판정: 통과 / 재현된 문제 / 검토 필요 / 미실행 / 해당 없음. 코드만 읽은 결과, 로컬 가짜 화면, 실제 인증 화면 확인을 분리한다.
- 각 사례에 사례 ID, 요구 출처, 준비값, 행동 순서, 기대 결과, 실제 결과, 근거를 남긴다. 예상 결과를 정하지 않은 탐색만으로 통과 처리하지 않는다.
- 정상 흐름 외 미선택·정상 0건·없는 대상·권한 없음·지연/실패·연속 입력·늦은 응답을 해당 기능에 적용한다.
- 실패는 처음 로그를 보존한다. 환경 요인이 의심될 때만 이유를 남기고 통제된 재실행을 한 뒤 두 결과를 구분한다.
- 임시 재현 도구가 필요하면 메인만 .codex-tmp/전체점검_20260928/ 아래 작성한다. 기존 앱 코드·테스트·판정 기준을 고쳐 통과시키지 않는다.
- 운영/검토 DB 쓰기, 실제 학생 응시·답 제출·배정, 알림 발송, 배포, 외부 원자료 수정은 하지 않는다. 조회처럼 보이는 명령도 내부 쓰기 여부를 확인한다.
- 화면 검사는 로컬 가짜 자료가 우선이다. 실제 로그인/음원 청음/외부 장애를 확인할 수 없으면 그대로 미실행으로 남기며 다른 묶음은 계속한다.
- 기존 scripts/local-admin-baseline.mjs는 별도 전체 빌드와 로컬 서버를 실행하고 .next를 임시 이동/복원한다. 전용 격리 build 명령이 아니다. 가까운 guard를 읽고 .env* 유무(.env.example 제외), 3037/3038/3040 포트 점유, 기존 서버와 미복구 산출물을 먼저 확인한다. 실제 환경 파일을 옮기거나 비밀값을 바꿔 guard를 우회하지 않는다.
- 가짜 도구가 허용한 로컬 메모리 변경은 운영 쓰기와 다르지만, 실제 인증/DB/외부 연결을 검증한 것으로 보지 않는다. 기본 관리자 도구가 학생 시험 전체를 지원한다고 가정하지 말고 옵션/지원 경로를 먼저 확인한다.
- 접근 권한 부족이나 안전 경계는 우회하지 않는다. 별도 승인 없이는 할 수 없는 검사만 제외 사유와 함께 남긴다.

## 단계별 결과 형식

- 기준: 커밋, 변경 파일, 환경, 실행 일시.
- 범위: 기능/공용 영역/흐름 ID, 이번 하위 묶음, 직전 결과 참조.
- 사례 표: ID | 준비·행동 | 기대 | 실제 판정 | 근거.
- 문제: 영향, 최소 재현 순서, 관련 파일·줄, 원인 확정 여부, 누락된 기존 검사, 권장 수정과 재검사.
- 수치: 검사 파일 수와 사례 수를 구분하며 기존 S02 실행과 후속 재실행을 중복 합산하지 않는다.
- 종료: 완료한 사례, 미실행 이유, 다음 하위 묶음과 정확한 명령/출발 파일.
