# S08 — 권한·DB·캐시·외부 연결

## 입력

map:owner auth, shared-infra, database-contract, shared-contract 및 가까운 AGENTS.
학생/관리자 인증 경계, Supabase 생성부, RPC/RLS 검사, 응답 DTO와 캐시 관련 기존 검사를 읽는다.
DB를 확인할 때는 Supabase 스킬과 현재 환경 구분 지침을 먼저 적용한다.

## 검사 순서와 기대 결과

- S08-A 권한: 미인증/학생A/학생B/관리자를 격리 자료로 만들고 서로 다른 학생·배정·응시 ID를 대입한다.
  없는 ID와 남의 ID에서 정보 노출 없이 계약에 맞게 거절되어야 한다.
  코드 차단/회전/세션 만료와 늦게 돌아온 응답 후에도 이전 사용자 자료가 남지 않는지 확인한다.
- S08-B DB: 학생용/관리자용 RPC와 테이블 정책·실행 권한·함수 검색 경로·입력 검증을 계약 검사와 실제 적용 근거로 대조한다.
  중요한 저장의 원자성/중복 방지/보존 규칙을 PGlite 등 격리 환경에서 확인한다.
  운영에는 승인된 읽기 전용 조회만 하고 SQL 적용·역할 변경·테스트 행 삽입을 하지 않는다.
- S08-C 캐시: 요청 안의 재사용, 브라우저 화면 캐시, 서버의 요청 간 공용 캐시를 구분한다.
  A로그인→상세→로그아웃→B로그인, 탭 복귀, 모달 닫기, 저장 성공/실패 전후를 검사한다.
  읽기만 할 때 불필요한 갱신은 없어야 하고, 실제 변경 성공 후 필요한 자료는 갱신되며 개인정보가 공용 캐시로 새지 않아야 한다.
- S08-D 외부/오류: 401/403/404/429/500/503, 시간 초과, 취소, 뒤늦은 응답, 잘못된 JSON을 모의 응답으로 주입한다.
  오류를 정상 0건으로 숨기지 않는다. 시험 중 미응답 문항의 정답과 권한 밖 정답 정보, 비밀 인증값, 내부 오류 원문을 학생/브라우저 번들에 노출하지 않아야 한다. 승인된 피드백·결과·복습 화면의 정답 표시는 허용된 공개 시점/권한과 일치하는지 별도로 확인한다.
  운영/검토 연결 및 음원/알림 등 외부 연결의 확인 범위를 별도로 남긴다. 부하·공격성 운영 테스트는 하지 않는다.

## 종료 기준

역할×자료 대상 허용표, 캐시 수명/갱신표, 오류별 보존/복구표에 판정과 근거가 있다.
비밀정보는 출력하지 않으며 직접 확인 못 한 운영 권한/환경은 추정으로 통과시키지 않는다.
