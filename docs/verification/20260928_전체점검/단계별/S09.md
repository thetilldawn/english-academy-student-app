# S09 — 지침과 실제 코드 구조 대조

## 입력

루트/앱 AGENTS, docs/개발_지시서와_검증_기록.md,
docs/코드_길찾기_및_변경영향.md, 기능 지도와 가까운 안내서,
S01 범위표 및 S02~S08 결과, 현재 변경에 해당하는 작업 기록만 우선 읽는다.

## 검사 순서와 기대 결과

- S09-A 길찾기: 12기능/공용 영역/16흐름의 실제 경로, 공개 진입점, 문서 링크, 가까운 AGENTS를 대조한다.
  현재/목표 폴더와 채택/제안/폐기 규칙을 구별한다. 기능 표 10개와 지도 12개의 차이를 실제 누락 여부로 판단한다.
  새 에이전트가 기능 ID부터 UI→상태→서버→DB→검사를 찾을 수 있는지 경로를 따라 본다.
- S09-B 역할: UI의 fetch/DB/업무 계산, domain의 React/브라우저 전역/네트워크,
  다른 기능 내부 import, server 읽기 이름의 숨은 쓰기, 서비스/클라이언트 경계 혼합을 검사한다.
  검색 결과만 결함으로 세지 말고 실제 호출자·데이터 흐름·허용된 예외 근거를 확인한다.
  공용 UI/문구/업무 계산의 중복은 실제 사용자와 변경 영향이 같은 경우에만 공용화 후보로 보고한다.
- S09-C 기록: 현재 변경의 요구 R→결정 D→설계→검사 T→실행 근거를 실제 코드와 대조한다.
  미결정·미검사·과거 증거 재사용이 현재 완료 주장에 섞였는지 확인한다.
  예전 verified 기록의 현재 해시가 다른 것 자체를 제품 오류로 세지 않는다.
  현재 근거로 쓰려는 입력이 달라졌다면 해당 재검증 필요로 기록하며 해시만 갱신해 통과시키지 않는다.
- 각 기능에 12면 변경 영향표를 '확인만/해당 없음+이유'로 채운다.
  UI 상태(미선택/0건/실패/404/권한/저장불명확)의 실제 문구·복구·입력 보존과 T번호 연결을 확인한다.
  S08의 캐시/권한 판정을 다시 계산하지 말고 참조하고 누락만 보완한다.

## 방법과 종료 기준

기존 형식/구조 검사 결과와 수동 호출 경로 검토를 분리한다.
복잡한 위반 후보는 읽기 전용 독립 검토자에게 최소 관련 파일만 전달하고 메인이 재확인한다.
