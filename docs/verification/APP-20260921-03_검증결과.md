# 오답 목록과 오답 시험 보완 검증

2026-09-21 · 로컬 구현·검증 · 실제 운영 반영과 구분

학생 내역의 오답 목록을 기본 접힘으로 바꿨다. 펼칠 때 최신 10개를 읽고 ‘10개 더 보기’마다 다음 페이지를 서버에서 가져온다. 오답 시험은 전체 후보·출제 가능·제외 수와 단어별 사유를 보여 주며, 제외 확인 전에는 배정할 수 없다. 조건을 바꾸면 확인도 해제된다.

## 구현과 보존

- R1/T1: 첫 목록과 더보기의 자료 계약을 분리했다. 접힘 조회 0, 검색·필터·학생 변경 시 새 첫 페이지, 늦은 응답 폐기, 더보기 실패 때 읽은 목록 보존, 권한 거절 때 개인 자료 숨김을 검사했다. 30초 안에 재열면 이미 읽은 페이지를 재사용한다. 첫 페이지 갱신 실패 뒤 다른 조건을 왕복해도 폐기한 커서는 다시 쓰지 않는다.
- R2/T2: 최초 오답 사건 수, 단어의 출처·문항 당시 내용, 해결/대기/배정 상태를 기존 계산과 대조했다. 페이지 계산 전에 DB에서 단어별 집계·검색을 하고, 표시할 항목만 상세 자료로 만든다. 사건 상한과 최근 시각·식별키를 커서에 묶는다. 현재 해결/배정 상태까지 과거 시점으로 고정된다고 주장하지 않는다.
- R3/T3: 혼합·전체 가능·전체 불가를 구분한다. 실제 화면에서 대상 20/가능 19/제외 1을 확인했으며 확인 전 버튼 비활성, 확인 후 활성, 방향 변경 뒤 다시 비활성을 확인했다. 계산 전의 단어 수는 0개로 표시하지 않는다.
- R4/T4: 새 저장 경로는 전체 후보와 출제/제외의 정확한 분할·순서·자료 확인값을 다시 검사한다. 보기로 사용하지 않은 단어의 변경도 확인값을 바꿔 저장을 거절한다. 실패 시 생성·큐·요청 기록은 함께 취소되고, 제외한 오답은 미배정 후보로 남는다. 완료된 같은 요청은 학생 필수정보나 자료가 나중에 바뀌어도 원래 결과부터 반환한다. 구형 전체 출제 경로의 엄격한 비교는 유지한다.
- R5: 페이지 표시 계약은 후속 학생 화면에서 재사용할 수 있게 분리했다. 이번 조회 권한은 관리자만이며 학생용 새 화면·API는 추가하지 않았다.

## 검사 근거

검사 보고서의 이름·확인값과 합산 방식은 [검사 집계](APP-20260921-03_검사집계.json)에 있다. 전체 실행 3,727통과/6실패/기존 1보류 뒤, 실패 파일과 새 회귀검사를 포함한 5파일 125개를 재실행해 전부 통과했다. 전체 자료 확인값을 보강한 DB 2검사도 통과했다. 중복 검사명을 순번까지 구별해 합치면 **3,735통과·남은 실패 0·기존 보류 1**이다. 한 번의 전체 실행이 처음부터 전부 통과했다고 표시하지 않는다.

앞선 전체 검사에서 발견한 기존 학생정보 검사 자료도 보완했다. 학생 INSERT 8곳과 미리보기 학생 2곳에 가짜 학교·학년을 명시하고, 공통 자료 분류·프로필 갱신 구독·필수 이름 라벨의 검사 자료를 맞췄다. 실제 필수정보 검사나 학교 필터를 완화하지 않았다. 같은 작업에서 드러난 단계 번호 원형의 CSS 표현은 공용 허용값으로 바꿨고 모양은 같다.

타입, lint, 기능 지도, 화면 구조, 서버 요청 캐시 검사를 통과했다. 최종 코드로 38페이지 격리 빌드를 완료했고 최종 빌드의 내역 접힘/최신 10개를 다시 확인했다. PC 1440×1000와 모바일 390×844에서 더보기·필터·제외 확인을 실제 가짜 앱으로 확인했다. 모바일 본문 폭과 전체 폭은 모두 375px로 가로 넘침이 없었다. 기본 접힘 RPC 0, 첫 페이지·더보기·필터 변경은 각각 1회였고 짧은 접기/재열기의 추가 조회는 0회였다. 실제 저장 버튼 제출·학생 응시는 하지 않았다.

읽기 전용 독립 검토에서 실패한 캐시의 커서 복원 문제와 전체 보기 풀 검사의 빈틈을 찾아 보완했다. 보완 후 재검토와 해당 회귀검사를 통과했다. 로컬 서버는 종료하고 기존 빌드를 복구하며 화면 크기 임시 설정도 해제했다.

## 확인하지 않은 범위

- 운영/검토 DB 적용, 운영 배포, 실제 관리자 로그인 뒤 동작, 실제 학생 배정·응시는 미실시다.
- 실제 사용자에게 발생했던 특정 학생의 오류 응답은 제공되지 않아 그 원인을 확정하지 않았다. 확인된 전체 차단 경로를 보완한 것이다.
- 로컬 DB는 단일 연결이다. 실제 여러 연결의 잠금 대기·교착, 운영 크기의 속도를 검증했다고 주장하지 않는다. 검토/조합 자료의 누락 방향 복원과 비후보 문항 충돌 변화는 새 v3 경로에서 별도 통합 재현하지 않았다.
- 문항판 확인과 별도 발음 등록부의 후속 개정은 구분한다. 원사전·발음 값을 새로 승인하거나 바꾸지 않았다.
