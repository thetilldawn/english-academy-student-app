## 바뀐 저장 방식

새 배정·응시·준비·자율연습에서 같은 질문·보기·학습 표시·발음을 학생마다 다시 보관하지 않는다. 이미 고정된 원문항이 있으면 그 원문항을 사용하고, 추가 고정 표시값만 공용으로 저장한다. 학생별 기록은 문항 참조와 순서·답·정오·시각·배정 관계를 유지한다. 개인 오답 출처·학생·응시·배정 식별자는 공용 본문에 넣지 않는다.

같은 문항을 공유하는 조건에 자료 범위·출처판·생성 규칙·보기 순서·정답 위치를 포함했다. 새 공용 저장은 출제 승인 근거가 아니다. 기존 승인·방향·DAY·제외·출처 검사를 통과한 뒤 저장하며, 서버가 학생/관리자의 조회 관계를 확인한 다음 필요한 본문만 복원한다. 깨진 참조를 최신 사전이나 빈 문항으로 대체하지 않는다.

구형 참조 없는 행은 기존 본문을 그대로 읽는다. 기존 행 이전·삭제나 실제 용량 회수는 이번 단계에 포함하지 않았다. 새 참조를 모르는 구형 앱으로 그대로 되돌리면 안 된다.

## 실패와 수정 이력

초기 전체 검사에는 새 본문 분리와 맞지 않는 구형 가짜 자료, 준비 재조회 null 처리, 501개 자료 검사 5초 제한 초과가 있었다. 가짜 원문을 UPDATE하는 검사는 새 승인판 INSERT로 고쳐 원문의 변경 금지 조건을 유지했다. 준비 오류는 예상한 만료/변경만 안내하며 서버 장애를 숨기지 않는다. 15초 제한은 501개 처리 검사 한 건에만 적용했다. 수정 후 관련 26개와 최종 전체 검사를 다시 통과했다.

첫 원격 경합 검사는 관찰 거래의 통계 캐시 때문에 잠금을 읽지 못해 취소됐고 가짜 준비/공용 내용이 0임을 확인했다. 관찰 단계에 통계 새로고침을 추가한 재검에서 실제 차단 관계를 확보했다. 첫 실패를 동시성 통과 근거에 포함하지 않는다. 가짜 학생 정리는 삭제 상태 제약에 맞는 삭제자를 함께 기록한 거래에서 완료했다.

Windows가 차단했던 임시 PostgreSQL 실행 파일은 재실행하지 않았다. 로컬 SQL은 PGlite, 원격 동시성은 기존 MCP와 고정 Preview HTTP 연결로 확인했다. 격리 화면 서버를 종료하고 기존 빌드를 복원한 뒤 일반 빌드를 재검증했다.
