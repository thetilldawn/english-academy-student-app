# 오답 보완 반영 명세

이 문서는 반영할 변경과 확인 순서를 고정한 명세다. 운영 적용 완료나 새 반영 승인을 뜻하지 않는다.

## 대상과 순서

앱은 학생 조건·필수정보 APP-20260921-02의 `292d1cf`에 이어진 APP-20260921-03이다. DB는 APP02의 `20260921010000_require_student_profile_for_new_assignments.sql` 적용을 선행 조건으로 하고 다음 두 변경을 순서대로 적용한다.

1. `20260921020000_page_student_wrong_words.sql`: 관리자 오답 집계와 페이지 조회. 학생 자료나 기존 사건을 수정하지 않는다.
2. `20260921030000_confirm_partial_wrong_review.sql`: 전체 후보/제외 확인값, 자료 확인값, 새 v3 부분 오답 저장. 기존 v1/v2의 전체 후보 비교와 완료 요청 결과를 유지한다.

정확한 파일 확인값은 앱 내부 완료 기록에 포함한다. 후속 APP04를 합쳐 반영하면 이 명세를 참조하고 최종 앱 커밋과 전체 추가 SQL을 새 반영 명세에 고정한다.

## 적용 전후 확인

- 보호 범위: 학생·계정·배정·배정 문항·응시·답·오답 사건·큐·완료 요청, 원사전·자료·검토 문항·발음/음원 연결. 적용 전 읽기 전용 수량/확인값을 보관하고 적용 뒤 비교한다. 동시 실제 학습의 변화는 구조 변경에 의한 변화와 구분한다.
- 검토 환경부터 같은 SQL과 앱을 적용한다. 함수 본문·관리자 권한·개인 응답 no-store·미인증 거절을 확인한다. 실제 학생 시험 생성·응시를 검사 용도로 하지 않는다.
- 오답 목록을 접은 첫 진입에 상세 전체 조회가 없는지, 펼친 뒤 10개 페이지인지 확인한다. 서버에서 전체 목록을 받은 후 자르는 것으로 대신하지 않는다.
- 공개 계정/일반 학생의 새 관리자 함수 실행과 private helper 직접 실행은 허용되지 않아야 한다.
- 새 코드만 이전 앱으로 되돌리는 경우 새 함수/완료 요청 필드는 보존한다. 이미 저장한 요청이나 v3 생성 기록이 있으면 DB 구조를 삭제하는 방식으로 되돌리지 않는다.

실제 두 연결의 잠금 동작과 운영 자료량의 조회 비용은 운영 적용 전에 별도 관찰할 대상이다. 로컬 단일 연결 검사의 한계는 [검증 결과](APP-20260921-03_검증결과.md)에 기록했다. 현재 외부 DB·운영 배포·실제 학생 쓰기는 모두 0이다.
