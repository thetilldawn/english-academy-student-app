APP13은 첫 조회 전에 변경할3표의 잠금을 NOWAIT로 확보해 출처 보강 중 동시 배정을 막는다. 사용 중이면 기다리며 점유하지 않고 거래를 취소한다. 이는 [PostgreSQL 잠금 기준](https://www.postgresql.org/docs/current/sql-lock.html)에 따른 순서다. 잠금을 얻은 후 실제 변경 중에는 해당 표 접근에 짧은 대기가 생길 수 있으므로 ‘무중단0지연’이라고 주장하지 않는다.

기존12표의 **적용 전 열 목록** 전체로 전후 행 수·해시를 비교한다. 새 열은 별도로 기본값을 검사하므로 옛 값 비교를 생략하지 않는다. 변경 대상 기존 함수의 전 정의/권한과 변경 후 정의/권한을 정확히 확인하고 나머지 함수/옛 표 권한은 불변이어야 한다. 새 표/뷰의 비로그인·일반 로그인 권한/RLS도 명세와 일치해야 한다. APP13의 출처 관계는 기존 배정별 원책 하나와 정확히 같아야 한다.

MCP가 성공 여부만 반환하면 표별 해시를 수집했다고 주장하지 않는다. 적용 후 별도 조회로 환경별 이력·함수·표 상태를 확인한다.

## 배포와 검사

검토 DB4건 → 검토용 코드 빌드/환경·DB 일치/보호된 응답 → 같은 명세의 운영 DB4건 → 같은 코드의 운영 환경 별도 빌드 → 대표 주소·비로그인 보호·기본 응답·오류 확인 순서다. 검토 환경에서 빌드된 결과를 운영으로 승격하지 않는다. 기존 승인된 방식의 임시 검사 키는 정해진 검토 주소에만 쓰고 즉시 폐기하며 로그/파일에 값은 남기지 않는다.

## 복구 경계

새 생성 경로 실패·권한 누출·기존 응시 실패가 확인되면 새 기능의 생성 진입을 중단한다. 새 시험이 없으면 이전 배포 복귀가 가능하다. 새 시험이 생긴 뒤에는 현재 읽기 호환5파일을 유지한 중단 패치를 사용한다: attempt-query, attempt-result-query, question-snapshot, question-provenance, assignment-study-query. 직전 코드만 복귀하면 새 원문/발음 snapshot 대신 현재 사전으로 읽을 수 있다. 이 경계는 독립 대조했지만 구코드+새DB 전체 실행 검사와 동일하지 않다.

SQL 되돌리기로 학생·연습·배정·출처·영수증을 삭제하지 않는다. 기존 기록이 보존되는 추가 구조를 유지한다.
