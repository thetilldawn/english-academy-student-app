# 기존 사전 키 연결 수리 — 검증 및 반영 기록

사용자 지시대로 기존 사전·단어 키·태깅 관계를 보존하고, 선택 저장 시 원단어 본문을 추가 복제하던 경로와 그 복사본 번호를 전제한 배정/오답 조회를 수리한다. 새 사전이나 본문 저장소를 만들지 않는다. 과거 일괄 정리 OPS는 재개하지 않는다.

## 바뀌는 것

- 선택 이름·단원·출제 순서는 기존 관계에 둔다. 새 선택의 단어번호는 원단어 번호와 같다. 본문을 vocab_entries 또는 학습값 표에 새로 INSERT하지 않고 기존 범위/출현 키와 확인값을 저장한다.
- 배정 헤더에는 선택 목록을, 문항에는 실제 원자료 번호를 유지한다. 이미 있는 assignment_sources에 둘을 연결한다. 서버의 범위 단어 수는 선택 단원의 확인된 개수를 사용한다.
- A/B가 같은 원단어를 사용해도 오답의 실제 출제 출처를 각각 읽는다. 여러 원자료의 오답을 한 선택으로 재배정하고 다시 틀리는 경우도 같은 출처를 유지한다.
- 기존 문제 생성·문항 보관 경로는 재사용한다. 이번 수정이 기존 모든 문제 본문을 제거했다는 뜻은 아니다. 예전 선택/시험/응시/성적 행은 옮기거나 삭제하지 않는다.

## 필요한 검사

변경 흐름 4파일86검사 통과 후 마지막 M03 연결 수정에 해당하는 2파일33검사를 다시 통과했다. 범위는 원키·추가 본문0·A/B/학생2명·뜻/발음/순서·배정 수정·오답 재배정·실패 원복·기존행 보존·DB 준비/최초/재시험/재접수다. 500/501은 이미 있던 한 번의 처리 경계이며 용량/부하 실험이 아니다. 실제 브라우저 채점·캐시는 변경하지 않았고 이번 검사는 브라우저 직접 조작 검사가 아니다.

타입 검사 통과. 변경 파일 lint 통과(사용하지 않는 검사 변수를 정리). 읽기 전용 독립 검토 2건: 새 저장층/사용자 결정 충돌 없음, 원키/선택·원자료 관계 및 구형 읽기 호환의 추가 심각 결함 없음.

## 원격 적용 명세

대상 SQL: `supabase/migrations/20261004083102_reuse_original_vocabulary_keys_in_selections.sql`. 검토 DB에 먼저 적용하고 동일 SQL을 운영에 적용한다. 변경은 기존 관계 제약, 기존 함수의 확인된 조건, 새 내부 조회 보조 함수다. 기존 사전·학생행에 직접 UPDATE/DELETE/INSERT하는 일괄문은 없다. 문서의 최종 확인값과 전후 근거는 반영 완료 시 기록한다.

선행 확인: 운영 원단어30,073행·기존 선택 연결7,532행, 배정188·배정 문항17,990·응시89·응시 문항7,617·오답 사건1,901행. 적용 전후 원키/선택 관계 확인값과 학생 관련5표의 내용 확인값을 비교한다. 실제 학생 시험·답 제출은 하지 않는다.

되돌리기: 새 관계가 저장된 뒤 옛 전역 단어 PK나 옛 판독기만 되돌리면 안 된다. 원키·구형 읽기 호환을 유지한 채 문제가 있는 함수만 수리한다. 변경 전 함수 본문은 이번 작업의 로컬 점검 파일에 보관했다. 사전·학생 자료를 복구 사본으로 교체하는 절차는 없다.

검토 DB→운영 DB 순서로 동일 SQL 적용 완료. SQL SHA-256 `ad3a0dfbe12349822302e1be83b2a02619ec4da794f30651b790109177a3ea3c`. 양쪽의 적용 전후 원키·선택 관계·학생5표 확인값이 모두 같았다. 운영 학생 관련5표27,785행을 보존했고 실제 학생 시험·답 제출0이다. 기존 함수31개의 OID/소유자/실행권한/설정을 보존했다. 30개 함수 본문은 양쪽이 완전히 같고, 1개는 이전부터 검토 DB에 있던 내부 취소 사유 한글 깨짐만 다르다. 이 기존 차이를 운영에 옮기거나 별도 수정하지 않았다.
