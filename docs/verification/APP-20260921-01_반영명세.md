# 단어장 화면 보완 반영 명세

이 문서는 사전에 준비한 적용 범위다. 사용자 승인 뒤 2026-09-21 검토·운영에 적용했으며, 실제 결과와 미실시 검사는 [반영 기록](DEPLOY-20260921-01.md)을 따른다.

## 적용 대상

1. APP-20260921-01에서 검증한 앱 변경: 자료별 묶음 편집, 조건 변경 즉시 반영, 자동 태그/이름 제안, 저장 오류, 수능 안내, 초안 보호, 원본/조합 표시.
2. DB 변경 파일 한 개: `supabase/migrations/20260921000000_guard_vocabulary_library_templates.sql`.
   - 새 확정 버전을 저장할 때 범위 0개·포함 단어 0개를 거절한다.
   - 범위 새 버전과 제목/대상/태그를 함께 저장한다.
   - 기존 버전, 기존 완료 요청, 인증/권한, 55초 실행 제한을 유지한다.
   - 파일 확인값(SHA-256): `49f4433113e91790886525413a7efdb3b0d19116f989efff7b76caad27d5b2d1`.
3. 실제 원고·사전·발음·단어장/템플릿 데이터의 재작성이나 수능 추가 원고 등록은 이 명세에 포함하지 않는다.

## 확인 순서

1. 현재 운영 앱과 DB 변경 목록을 다시 확인하고 이번 작업 이후 다른 변경이 생겼는지 대조한다.
2. 기존 책·범위·버전·배정·응시·오답의 수량과 확인값을 기록한다. 개인 자료는 결과 문서에 출력하지 않는다.
3. 검토 환경에 DB 변경 1개를 적용하고 함수 정의·권한·실행 제한을 확인한다. 기존 데이터 확인값이 바뀌지 않아야 한다.
4. 같은 앱을 검토 환경에 배포한다. 빈 저장 거절, 혼합 범위 변경, 자동 태그와 과거판 유지, 인증 실패 후 복구를 확인한다. 실제 학생 쓰기는 하지 않는다.
5. 검토 통과 및 해당 운영 반영 범위의 승인 근거를 확인한 뒤 동일 변경만 운영에 적용한다. 보존 수량·확인값과 접근 권한을 다시 대조한다.
6. 운영 배포와 관리자 화면 확인을 구별해 보고한다. 관리자 화면을 실제로 조작하지 못했다면 그 검사는 미실시로 남긴다.

기존에 사용자가 저장한 빈 템플릿은 별도 원본이다. 화면을 열기만 해도 새판이 생기게 하지 않는다. 관리자가 저장된 조건으로 범위를 채우고 내용을 확인한 뒤 새 버전으로 저장한다.

## 복구와 추가 자료

화면 문제 발생 시 이전 앱으로 되돌릴 수 있다. 새 DB 계약은 기존 요청을 허용하며 기존 자료를 삭제하지 않는다. 오류를 이유로 학생 기록·버전·완료 요청을 지우지 않는다.

수능 전체 유형 추가는 별도의 자료 작업이다. 2024/2025년 시행 원본의 실제 문항·단어·뜻·품사와 사전 연결을 검수하고, 기존 장문과 중복되는 출처를 대응시킨 뒤 후보→등록→출제 가능 상태를 따로 확인한다. 2026년 시행이라고 표시된 미래 자료는 실제 내용 확인 전 공식 수능으로 취급하지 않는다.
