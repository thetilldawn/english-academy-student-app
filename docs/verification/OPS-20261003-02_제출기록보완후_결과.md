2026-10-03 / OPS-20261003-02(M09), 구현 f5eea58. APP-20261003-08의 신규 응답 중복 축소 뒤, 앞서 사용한 32회 조건으로 다시 측정했다. **시험 1회당 조사 표의 증가량은 257,024B에서 249,344B로 약 2.99% 줄었다. 무료 운영 문제가 해결됐다는 결과는 아니다.** 현재 상태·순서는 루트 대장만 따른다.

## 측정 조건과 보존

가짜 학생100명 등록·응시 학생2명·공용 책2개/100문항, 시험32회, 매회 최초50답 중10오답·재시험10답 중2오답·최종96점을 유지했다. 모든 RPC를 확정한 후 계측하고 6/16/32회 뒤 일반 VACUUM ANALYZE를 수행했다. 시간 조작·보호 해제·원격 입력·실제 학생 쓰기는 없다. 같은 요청의 즉시 재접수는 결과가 같고 행 수/행 표현/행 JSON 합계가 증가하지 않았다. 셀 전체의 암호학적 비교를 뜻하지 않는다.

검사1건 통과,259.88초. 원계측2026-10-03 06:15:14.934~06:19:31.237 UTC. 최종 응시32·배정문항1600·응시문항1600·개별접수1920·회차접수64·오답사건384·포인트1920이다. 이전 자료와 실행 도구는 덮어쓰지 않았다. 도구의 차이는 출력 폴더와 코드 기준 커밋뿐이다.

## 인원과 전송의 해석

월20시험·6개월·같은 책 반복을 가정하면100명은12,000시험이며 조사표 증가의 단순 외삽은 **2,992,128,000B(약2.99GB)** 다. 운영 최대인원이나 클라우드 상한이 아니다. 신규 공용자료·처음 만난 단어의 개인 상태·로그인·일괄배정 요청·동시 준비·작업/복구 공간은 별도다. 학생등록100명 자체의 학생표는73,728B로 앞선 실행과 같다.

5개 RPC 응답 JSON 합계는 시험당 평균40,799.3125B(40,699~40,848B)다. HTTP 헤더·인증·목록·음원/CDN과 Supabase 실사용 전송이 아니며 전송 청구량으로 환산하지 않는다. 실제 Vercel 조회와 DB 기준선은 [앞선 보고](OPS-20261003-02_무료운영_중간결과.md)를 따른다. Supabase 월 전송, 원격10/30명 동시 부하와 F02 관리자 분리는 여전히 미검증이다. 운영 DB·배포·회수는 이번에 변경하지 않았다.
