# 배정 저장 보완 후 저장량 재측정

2026-10-03 / OPS-20261003-02(M09), 구현 e6b98ab. APP-20261003-09가 구성 문항을 처음부터 공용 키로 저장하도록 바꾼 뒤, 같은32회 조건으로 측정했다. **마지막16회 조사 표 증가량은 회당249,344B에서207,872B로 약16.63% 적게 관측됐다. 최종 행 데이터는 줄어들지 않았다.** 무료 운영 가능 인원의 확정 결과가 아니다.

## 조건과 보존

가짜100명 등록 중 실제 응시는2명, 공용 책2개/100문항, 시험32회다. 매회 최초50답 중10오답, 재시험10답 중2오답, 최종96점이다. 모든 RPC를 확정한 뒤 측정하고6/16/32회 뒤 일반 VACUUM ANALYZE를 수행했다. 시간 조작·보호 해제·원격 입력·실제 학생 쓰기는 없다. 동시 학생 부하 검사도 아니다. 모델/설정/분석기는 직전과 출력 폴더·커밋 표기 외 동일하다.

검사1건 통과,249.49초. 최종 응시32·배정문항1600·응시문항1600·개별접수1920·회차접수64·오답사건384·포인트1920이다. 같은 요청64번의 재접수 응답은 같았고 행 수/행 표현/행 JSON 합계도 증가하지 않았다. 전체 셀 암호학적 비교를 뜻하지 않는다. 앞선 두 원계측과 도구는 덮어쓰지 않았다.

## 인원과 전송

같은 책을 월20시험씩6개월 반복하면100명은12,000시험이다. 이 구간의 조사 표 증가를 그대로 외삽하면 **2,494,464,000B(약2.49GB)** 다. 초기·공용자료·처음 만난 단어의 학생 상태·로그인·배정 요청/대기·동시 준비·시스템/복구 공간은 제외했고 보관 기간 경과에 따른 정리 작업을 반영하지 않았다. 이 숫자로 무료 운영 가능 인원을 확정하지 않는다. 학생등록100명 자체의 학생표는73,728B이며, 학생 프로필 텍스트가 용량의 주원인은 아니다.

5개 RPC 응답 JSON 합계는 시험당 평균40,798.6875B(40,698~40,848B)다. HTTP 헤더·인증·목록·음원/CDN을 포함한 Supabase 전송 청구량이 아니다. Vercel 사용량은 앞선 실조회 근거를 따르며 Supabase 월 전송과 원격10/30명 동시 부하, F02 관리자 분리는 아직 미검증이다. 운영 DB·배포·물리 회수는 이번 계측으로 변경하지 않았다.
