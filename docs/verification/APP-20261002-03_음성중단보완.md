# 답 선택·시간 종료의 음성 중단 보완

M05의 작은 오류 보완, 앱 기록 APP-20261002-03-AUDIO. 기준 e45e8839. 운영 DB·배포 변경0.

## 발견과 수정

기존 시험은 답 선택 경로에서 stopAudio를 호출했으나, 새 M05 화면은 재생 함수만 받아 사용했다. autoPlayEnabled=false는 예약만 취소하므로 이미 재생 중인 음원을 끊지 않았다. 실제 브라우저 재현에서는 답 선택126.5ms 후 다음 문항에서야 문제 음원이 중단됐다. 수동 선택지 음원은 다음 문항이 무음이면 더 오래 남을 수 있었다.

새 화면의 답 선택에서 기존 stopAudio를 즉시 호출하고, 저장 대기/채점/시간 종료 상태에서도 중단한다. 선택 확정 중 수동 재생 재시작을 차단했다. 선택확정20ms·기기 저장 완료 후 채점·정오답100ms, 기존 CDN 직접 재생·일반 캐시, 풀이 시험 API0은 유지한다. 공용 음성 재생기·SQL·CDN·학생 기록은 변경하지 않았다.

## 확인 근거

- [실제 브라우저 4사례](APP-20261002-03_음성중단검사.json): 자동 문제 음성+키보드 정답, 수동 선택지 음성+클릭 오답, 문제 음성/선택지 음성의 문항 시간 종료. 모든 중단은 원래 문항에서 발생했고 다음 문항에 재생 중인 이전 음성0, 풀이 API0이었다. 답 선택→중단은 로컬 관측0.5ms/0.1ms이며 실기기 성능 보장은 아니다.
- 시간 종료의 문제 음성은 기존3초 재생 제한과 구분하기 위해 문항 시작3.6초 뒤 발음 버튼으로 다시 재생한 뒤5초 문항 마감에 중단했다. 자동 문제 음성의 답 선택 검사는 별도 사례다.
- 합성8초 WAV와 실제 HTMLAudioElement를 사용하며 자동재생 허용 옵션을 켰다. 실제 CDN 가용성, 발음 내용, 스피커 출력이나 브라우저 기본 자동재생 허용을 증명하는 검사는 아니다.
- 관련4파일126검사, 타입·변경2파일lint·기능 지도·97기록 변경 연결, Webpack53페이지와 공용자산25개 확인. 최초 빌드는 로컬 APP_ORIGIN 환경 누락으로 실패했고 로컬 주소를 지정한 최종 빌드는 통과했다.
- 기존 전체4,951검사와 CDN2개 재생 종료는 e45e8839 시점 근거다. 이번 소규모 변경은 관련126검사와 새 빌드/실제 중단4사례로 확인했으며 전체 회귀를 다시 실행했다고 표시하지 않는다.
- 읽기 전용 독립 검토에서 신규 기능 결함을 발견하지 못했다. 완료 관문은 최종 기록에 별도 연결한다.

## 음성 정상 여부의 권장 판정

브라우저에서는 재생 시작과 실제 시간 진행, 자연 종료, 답 선택/이탈로 의도한 중단, 재생 오류를 구분한다. CDN 응답 성공만으로 정상 재생을 판정하지 않고, 의도한 중단을 실패로 세지 않는다. 자동재생 차단·네트워크 지연과 음원 자체 손상도 나눠야 한다. 이 상태 확인 때문에 시험 중 DB 호출이나 학생별 재생 로그를 추가할 필요는 없다.

실제 단어 고유키·발음 구분·음원 연결이 맞는지는 등록/교체 시 자료 대조와 청취 검수로 확인한다. 앞뒤 잘림·긴 무음·소리 크기도 그때 검사한다. 브라우저 재생 완료는 잘못 연결된 단어나 무음 파일을 걸러내지 못하며, 기기의 음소거·출력장치 상태까지 증명하지 않는다. 이 권장 판정의 새로운 UI/원격 기록 기능은 이번 보완에 포함하지 않았다.
