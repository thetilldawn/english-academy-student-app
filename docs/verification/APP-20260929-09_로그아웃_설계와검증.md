# APP-20260929-09 로그아웃 화면 전환

R1: 로그아웃 클릭 후 목록오류가 아니라 인덱스로 이동 — DELETE지연동안 개인정보/오류목록 노출없고 성공시 /로 문서이동1회·refresh0
R2: 요청 실패/취소/연속클릭에도 개인정보 즉시숨김과 서버로그아웃 확정구분 — 취소는쓰기0, 실패는재시도만·자료복원0, pending중 요청1회

## 원인과 결정
DELETE 전 개인정보 폐기 신호 → 캐시 lock → 보호목록이 인증실패로 표시되어 잠깐 오류가 보인다. 기존 Next16.2.12는 replace 뒤 refresh를 큐잉하므로 refresh만 원인이라고 단정하지 않는다.

- dataFlow: 이탈확인 승인 → 공용종료상태 pending → 기존개인캐시즉시삭제 + DELETE → 성공 / 문서이동1회, 실패 개인정보 숨김유지와재시도. 조회/응시/점수쓰기없음
- reuse: 기존 requestAdminLogout/requestStudentLogout, navigateDocument, 이탈확인 재사용. Next router refresh 제거
- cache: 로그아웃요청전에 현재 개인캐시삭제·다른탭신호 보존. 실패때원자료복원금지
- compatibility: 역할별 서버DELETE·쿠키보존/삭제판정 그대로. 버튼진입이탈확인취소시요청없음
- rollback: 해당UI경계/버튼/셸배치를되돌림; DB변경없음

D1: 바로 인덱스 /
D2: 기존즉시삭제 유지, 공용 보호셸 경계가 pending/failed동안개인자료를unmount. 성공시 document replace1회

## 검증
T1: 실제identity신호·캐시lock과지연DELETE, 성공/false/예외·반복클릭·학생/관리자 → 개인정보/중간오류숨김·목적지/1회·실패재시도·refresh0
T2: dirty이탈취소/승인·pending중재클릭·재시도 → 취소시DELETE/폐기0, 승인때1회, 실패개인자료복원없음
T3: 가짜학생/관리자 보호본문과모달에서느린로그아웃 → 중간목록오류없음·종료후인덱스·실학생쓰기없음
T4: 타입/lint/지도/구조/빌드·독립검토 → 현재입력에서통과;기존기록/다른기능보존

초기·갱신·0건·404·예상밖오류는기존경계. 로그아웃pending은오류가아님. 실패는종료실패와재시도만보이고 개인본문복원안함. 타학생/정답자료를새로조회하지않음.

## 구현과 확인 결과

관리자·학생의 보호된 화면 전체 바깥에 공통 종료 경계를 뒀다. 명시적 로그아웃 또는 이탈 확인 승인 때 본문·모달을 먼저 제거한 다음 기존 캐시 폐기와 서버 종료를 요청한다. 세션 기간·쿠키 판정·서버 인증 규칙은 바꾸지 않았다.

이탈 확인이 비동기로 이어질 때 단순한 상태 변경만으로는 제거가 늦는 것을 독립 검사에서 재현했다. 이 위치에서만 [React의 flushSync](https://react.dev/reference/react-dom/flushSync)를 사용해 요청 전에 화면과 정리 작업이 끝나게 했다. 일반 조회·렌더·effect에는 추가하지 않았다.

- 실제 종료 함수와 이탈 확인을 연결한 독립 3파일 25검사 통과. 요청 시작 시 본문/상세 모달 없음, 캐시 정리 완료, 반복 요청 하나, 성공 후 인덱스 이동 한 번을 확인했다.
- 종료 실패 뒤에도 개인정보와 이탈 방지 장치가 다시 등록되지 않으며 재시도가 가능하다. 사용자가 이탈을 취소하면 서버 요청과 캐시 폐기는 없다.
- 가짜 자료 실제 브라우저: 학생의 느린 종료 동안 종료 안내만 표시되고 접속 화면으로 이동. 관리자 종료 실패에서 개인정보 없이 재시도 안내, 재시도 성공 후 접속 화면 이동 확인.
- 전체 검사·타입·lint·41/41 빌드 결과는 APP08 기록과 같다. 구조와 R/D/T 설계 연결도 확인했다.

실제 학생의 세션이나 답안은 검사에 쓰지 않았다. 운영 반영과 보호 응답 검사는 별도 배포 기록에서 구분한다.
