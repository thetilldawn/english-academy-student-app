# 과거 문항의 안전한 이전·부분 복구 결과

2026-10-03. 종료된 구형 배정·응시·출처 문항을 공용 참조로 옮기고, 필요하면 파일 사본에서 당시 본문만 복구하는 도구를 구현·검증했다. 새 학생 답과 접수 기록을 덮어쓰지 않는다. 운영 DB 정리·배포·실제 학생 쓰기는 0이다.

## 구현 범위

- 준비 단계에서는 현재 문항과 당시 뜻을 비교하고 작은 참조·확인값만 기록한다. 원본문은 그대로 남긴다.
- 파일 저장 → 디스크 반영 → 재읽기 → 확인값 검사를 마친 묶음만 전환 인수로 전달한다. 최대100행·4MiB이며 지정한 실제 키와 현재 행의 확인값을 검사한다.
- 진행·재시험·시작 전 준비·새 기기 제출 규격·새 결과 정책·개인 오답 문항은 정리에서 제외한다.
- 복구는 같은 참조와 허용된 본문 열만 보충한다. 최근 답·결과·오답·포인트·정책·접수는 복구 파일에서 덮어쓰지 않는다.
- 일반 앱 역할에 새 실행 권한은 없다. 직접 수정, 임의 설정값, 참조 제거로 보호를 우회할 수 없다. 같은 요청은 처음 접수 결과를 그대로 반환한다.

## 로컬 결과

전체622파일 **5,026통과·기존 제외1**을 확인한 후 독립 검토에서 UUID 대소문자만 다른 중복 항목을 발견했다. 같은 행이 두 번 처리 건수에 잡히는 현상을 실제 재현한 뒤 UUID 기준으로 중복 검사하도록 수정했다. 수정 후 과거 문항 통합검사 **15개 전부 통과**했다. 전체 검사를 다시 실행했다고 주장하지 않는다.

검사 입력은 M02가 적용되기 전의 실제 구형 스키마에 먼저 만든 가짜 자료다. 과거 배정·응시·출처12행의 발음·선택 보기·뜻·ID/FK를 비교했다. 파일을 먼저 저장·재읽기한 뒤 본문을 줄이고, 새 답을 기록한 후 같은 파일에서12행을 복구했다. 복구 전후 새 답과 접수 결과, 원래 참조가 일치했다.

최종 타입·변경 파일 린트·전체 린트, 설계 연결 검사와 프로덕션 빌드53페이지를 확인했다. 공개 화면·브라우저 동작을 변경하지 않아 새 화면 검사는 해당 없음이다.

가짜 학생2명·배정3건을 기존 종료 절차로 처리하고 자료·관리자를 비활성화했다. 임시 공개 함수는 제거했으며 일회 허용 기록 잔여0이다. 가짜 추가분23표를 명시적으로 제외한 뒤 기존170표251,904행 확인값을 다시 대조하여 차이0을 확인했다. 주기적으로 바뀌는 유지보수 상태표1개는 전후 대조에서 제외했다.

가짜 복구 사본은 자료 구역 `영어/00_운영/학생앱_비공개검증/OPS-20261003-01_가짜이전복구/`에 있다. 로컬12행 사본21,617바이트의 SHA-256은 `5be41a70f25d238e23d455ab5001dd7e1a0493f542146783ee82941fb6ac6d0a`이다. 검토 DB의4행 사본2개는 각각7,233바이트이며 SHA-256은 `aa836a65d82543016bea88f1aeca399280d958622946158c7b2f3b9940889bd7`, `f721f4297a12ce7f4ecfb433943d1097c6a0d0510e15396956108f1569ad496a`이다.
