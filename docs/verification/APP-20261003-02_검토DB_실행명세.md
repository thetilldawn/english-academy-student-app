# 과거 문항 이전 도구 — 검토 DB 실행 명세

대상은 검토 DB `wojxpruvbjzbhrpmsbuy`뿐이다. 운영 DB 변경·운영 본문 정리·실제 학생의 시험 시작/답 제출은 없다. 승인된 유지보수 M02 보완 및 M08-A의 검토 적용이다.

## 1. 코드 적용

- SQL: `supabase/migrations/20261002190000_migrate_historical_question_bodies.sql`
- 최종 SHA-256: `64d6b57b9f001b53e549ababce192a9198992e51e0faa41ebaae953a8a04fd05`
- 최초 적용 SHA-256은 `8eeb2750389bd409b00e8a46b1d3c5220a392450c7f74c000580a87c552e6489`이다. 이후 독립 검토의 UUID 대소문자 중복 1건을 실제로 재현하고, 동일 UUID로 정규화하여 중복을 거절하도록 실행 함수만 보정한다. 이 보정까지 새 검사15개 통과. 기존 데이터 전환 전에 실시한다.
- 신규: private 내부 표 3개, 함수 12개. 원본문을 별도 표에 복사하지 않는다. 공개·익명·로그인·서비스 역할 실행 권한 없음.
- 기존 변경: 문항 보호 함수 3개의 정확한 일회 허용 경로와 저장 제약 3개. 함수 OID·소유자·권한·일반 저장 동작은 보존한다.
- 기존 행 수정 0. 자동 이전 0. 예약 작업 추가 0.
- 적용 전 기존 170개 표 251,904행의 수량·정렬된 행 확인값을 저장했다. 주기적으로 변하는 유지보수 상태표 하나는 제외했다. 적용 직후 같은 SQL로 대조한다.
- 적용 전 기존 검사 622파일, 5,026통과/기존 제외1. 과거 스키마의 가짜 자료를 사용하는 새 검사 14개 포함. 타입·린트·구조·설계 연결 검사 통과.

## 2. 실제 두 연결 검사

가짜 관리자 1명·가짜 학생 2명·가짜 4단어·작은 가짜 배정만 추가한다. 식별자 접두사는 `a8030000-0000-4000-8000-`이며 관리자 표시와 자료 표식까지 검사한다. 운영/기존 자료를 선택하는 조건은 사용하지 않는다.

필요한 일시 공개 검사 함수는 service_role만 실행 가능하고 인수·대상 가짜키를 고정한다. 실제 두 HTTP/SQL 연결에서 DB의 서로 다른 PID, 대기 잠금, 차단 PID를 관찰하여 겹침을 증명한다. 호출 종료시각만으로 동시 검사를 주장하지 않는다.

1. 준비→전환과 이미 준비된 전환이 겹쳐도 잠금 순서가 순환하지 않고 같은 요청의 결과가 유지된다.
2. 복구와 가짜 학생의 새 답이 겹쳐도 답/현재 접수 기록은 보존된다.
3. 낮은 키를 가진 늦은 거래가 확정된 후 전체 미연결 후보 재조회에서 빠지지 않는다.

가짜 문항 사본은 자료 구역의 접근 제한 폴더에 파일로 저장·재읽기한 후에만 전환한다. 앱 Git에는 확인값과 수량만 기록한다. 실제 과거 스키마 입력 검사는 로컬 14개 검사로 증명하며 최신 검토 DB의 가짜 행 삽입으로 대신 주장하지 않는다.

## 3. 마감과 실패 처리

각 짧은 거래가 실패하면 해당 거래만 취소한다. 본문 복원은 보관 파일과 원행·현재 참조를 대조한 허용 열만 수행한다. 답·점수·접수·오답·포인트를 과거 사본으로 덮어쓰지 않는다.

검사 뒤 가짜 학생/배정을 기존 삭제 절차로 종료하고 가짜 자료·관리자를 비활성화한다. 일시 공개 함수는 제거하고 실행 권한·일회 허용 잔여0을 확인한다. 기존 표 보존 검증과 가짜 추가분은 따로 기록한다. 이번 도구만으로 M08 전체 또는 운영 용량 회수를 완료 처리하지 않는다.
