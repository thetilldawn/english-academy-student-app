- 기준 브랜치: `codex/vocab-assignment-ux`

- 제외 범위: 시험 풀이 통신, 미리보기, 검색·더보기, 파일, 알림, Cache Components, Production

## 1. 이번 배치의 목적

정상 저장 뒤 화면 전체를 다시 그리지 않는다. 저장 명령이 바뀐 대상과 새 버전을 돌려주고, 화면은 그
결과만 반영한다. 다만 상태가 다른 구역으로 이동하거나 정렬·첫 10건 경계가 달라지는 목록은 서버를
최종 기준으로 삼아 해당 구역의 10건과 다음 항목 확인용 1건만 다시 읽는다.

## 2. 변경 흐름과 책임

| 흐름 | 변경 통로 | 성공 뒤 화면 반영 | 유지할 경계 |
|---|---|---|---|
| 학생 이름·학교·학년 저장 | 학생 기능의 얇은 Server Action | 상세의 학생 행 교체, 학생 목록 첫 구역 10+1 재조회 | 인증·입력 검증·감사 기록 |
| 학생 접속 차단·코드 교체 | 기존 Route Handler | 상세의 접속 상태만 교체, 학생 목록 첫 구역 10+1 재조회 | 401·403·503 |
| 시험 내역 숨김 | 이력 기능의 얇은 Server Action | 기존 행 제거 후 영향 구역 10+1 재조회 | 403·404·409·503 |
| 미응시 배정 취소 | 기존 Route Handler | 상태가 바뀔 수 있는 현재 표시 구역만 10+1 재조회 | 403·404·409·503 |
| 단일·일괄·오답 배정 | 기존 Route Handler | 배정 창을 닫고 현재 학생 목록 첫 구역 10+1 재조회 | 미리보기 fingerprint, 409·422·503, 멱등성 |
| 기존 시험 수정 | 기존 Route Handler | 반환된 새 배정 상세 주소로 교체 이동 | 409 충돌에서만 전체 복구 갱신 허용 |
| 배정된 시험 큐 처리 | 기존 Route Handler | 반환된 큐 한 건을 같은 `seriesId` 행에 교체 | 409와 큐 중복 생성 방지 |

읽기 요청은 Server Action으로 옮기지 않는다. 검색·필터·더보기·미리보기는 취소, 병렬 응답, HTTP 상태
계약이 필요하므로 계속 Route Handler를 사용한다.

## 3. 저장 응답 계약

정상 저장 응답은 다음 세 정보를 가진다.

- 변경 대상: 학생 ID, 이력 식별자, 배정 ID 또는 큐 `seriesId`
- 화면 변화: 교체할 작은 행 또는 다시 읽어야 할 구역
- 버전: 학생 프로필은 프로필 전용 DB 버전, 이력 숨김은 DB의 `hidden_at`, 취소는 DB의 취소 활동 시각,
  큐는 DB의 `updated_at`을 사용한다. 앱 서버에서 임의 시각을 만들지 않는다.

브라우저는 요청을 시작할 때의 대상과 응답 버전을 확인한다. 다른 학생으로 이동했거나 더 최신 응답을
이미 반영했다면 늦게 도착한 응답을 버린다. 저장 중 입력을 바꿀 수 있는 학생 정보 폼은 서버가 실제로
저장한 값을 기준선으로만 바꾸고, 저장 도중 사용자가 새로 고친 입력값은 미저장 상태로 남긴다.

## 4. 구역 10+1 재조회

- 학생 목록: 현재 검색·필터의 첫 10건과 다음 항목 확인용 1건만 다시 읽는다. 이전에 더보기를 여러 번
  눌렀더라도 저장 뒤 전체 보이는 행을 반복해서 다시 읽지 않는다.
- 관리자 내역: 숨김·취소 전후에 영향받은 구역만 새 스냅샷으로 읽는다. 구역 하나당 최대 11행이다.
- 학생 상세 내역: 해당 학생의 현재 필터 첫 10건과 다음 항목 확인용 1건만 다시 읽는다.
- 큐: 정상 처리에서는 `seriesId` 한 건만 교체한다. 409·503 또는 응답 유실처럼 커밋 여부를 모르는
  경우에만 최신 첫 페이지를 다시 읽고, 처리 명령 자체는 자동 반복하지 않는다.

## 5. `router.refresh()` 허용 목록

- 관리자·학생 로그인/로그아웃처럼 세션 자체가 바뀌는 경우
- 배정 수정 중 서버가 409 충돌을 반환해 원본과 편집 자료를 함께 복구해야 하는 경우
- 학생 시험의 시간 경계처럼 서버 화면 전체의 권한·유효 상태를 다시 확정해야 하는 기존 경계

학생 정보 저장, 배정 성공, 이력 숨김, 미응시 취소, 큐 처리의 정상 성공에는 사용하지 않는다.

## 6. 구현 순서

1. 저장 결과·구역 갱신 계약과 브라우저 사건 통로를 만든다.
2. 학생 정보 저장과 학생 상세의 로컬 교체를 연결한다.
3. 이력 숨김·미응시 취소와 관리자/학생 내역의 구역 재조회를 연결한다.
4. 배정 성공의 학생 목록 첫 구역 재조회, 수정 성공의 상세 교체 이동을 연결한다.
5. 큐 처리 결과 한 건 교체를 연결한다.
6. 기능 소유권 지도와 가까운 `AGENTS.md`를 갱신한다.
7. 구현을 모두 끝낸 뒤 관련 단위 검사, 전체 검사, 구조 검사, lint, typecheck, build를 한 묶음으로 실행한다.

## 7. 완료 검증

- 정상 성공 경로의 전체 `router.refresh()`는 0회다.
- 409·422·503과 멱등성·중복 클릭 방지가 기존과 같다.
- 학생 정보 저장 중 입력 변경, 늦은 응답, 연속 저장에서 화면이 과거 값으로 돌아가지 않는다.
- 이력 숨김·취소 뒤 개수, 행, 다음 커서가 서버의 새 10+1 결과와 같다.
- 큐 처리 뒤 같은 `seriesId`가 중복되지 않고 반환 행의 `updatedAt`과 화면 버전이 같다.
- 예전 오답 포함 시험 수정 뒤 문제 스냅샷·오답 큐 ID·변경 금지 필드가 R5 기준과 같다.

DB 문장 스냅샷에서 받는다. 저장 충돌 409는 최신 프로필을 기준선과 기준 버전으로만 반영하고 작성 중
초안은 그대로 둔다. 첫 페이지를 새로 읽기 시작하면 이전 스냅샷 커서를 즉시 폐기하므로 갱신 실패 뒤
오래된 더보기를 붙일 수 없다.

첫 적용 시도는 명시 승인 문구 부족으로 안전 검토에서 차단되어 DB 변경이 없었다. 그 뒤 독립 SQL 감사에서
학생 전체 행을 `UPDATE`하던 초기 백필이 기존 `updated_at` 트리거를 실행하고 삭제 학생 불변성 트리거와
충돌할 수 있음을 찾았다. Preview에는 삭제 학생이 실제 6명 있어 기존 SQL은 적용 시 전체가 되돌아갈
상태였다. 따라서 새 열은 `ALTER TABLE ... DEFAULT clock_timestamp() NOT NULL`로 추가해 기존
행의 다른 열이나 사용자 `UPDATE` 트리거를 건드리지 않도록 고쳤고 위 SHA-256을 새 기준으로 삼는다.
