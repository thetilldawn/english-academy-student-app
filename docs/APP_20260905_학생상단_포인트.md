# 학생 상단 포인트 표시

## 요청과 범위

- 학생 이름·학년 옆 `| 포인트 N`을 학생 공통 상단 우측에 표시한다.
- PC는 본문 최대 폭 900px에 맞추고 420px 이하에서는 정보와 조작 버튼을 두 줄로 나눈다.
- 학생 정보·포인트는 16px이며 긴 이름·숫자를 숨기거나 생략하지 않는다.
- 본문의 현재 포인트 카드와 해당 로딩 공간은 제거한다. 결과의 시험별 포인트 내역은 유지한다.
- 시험 중 집중 화면은 상단을 숨기며 포인트를 조회하지 않는다.
- 원장·지급·차감·학생 데이터·DB 구조는 변경하지 않는다. 별도 시안 페이지도 만들지 않는다.

## 연결과 갱신

- `@summary/page.tsx`와 `@summary/[...catchAll]/page.tsx`가 상단 내용을 서버에서 조합한다.
  layout에 초기 숫자를 고정하거나 Client 저장소에 합계를 복제하지 않는다.
- 상단은 독립적으로 학생 인증을 수행한다. 인증 redirect를 조회 실패로 삼키지 않는다.
- 결과 화면은 기존 결과 포인트 요약을 본문과 공유한다. 과거 요약이 없을 때만 현재 합계로 보완한다.
- 공유 읽기의 React `cache()`는 한 서버 요청 안에서만 중복 제거한다. 학생 간 공유 캐시가 아니다.
- 로딩은 `확인 중`, 읽기 실패는 `확인 불가`로 표시하여 실제 0과 구분한다.
- 일반 화면 이동에 전체 새로고침을 더하지 않는다. 뒤로/앞으로 복원은 경로가 바뀐 다음 한 번,
  브라우저 메모리 복원은 복원 사건에서만 갱신한다. 진행 중 시험은 제외한다.
- 단어장 모달을 닫을 때는 포인트 변화가 없으므로 갱신하지 않는다. 완료 내역의 더보기 상태를 보존한다.
- 줄바꿈으로 상단이 높아지면 실제 높이를 측정해 단어장 고정 제목·닫기 버튼이 가려지지 않게 한다.

## 로컬 검사와 리뷰

- 준비 과정 전체 검사 374파일·2,006테스트와 Next.js 16.2.12 build를 통과했다.
- 빌드에서 루트 page와 optional catch-all의 경로 충돌을 찾아 위의 두 경로로 분리했다.
  배포 전에 재빌드해 해결을 확인했다.
- 독립 코드 리뷰에서 단어장 닫기의 전체 갱신 위험을 발견해 제외 조건과 회귀 검사를 추가했다.
- 표시·인증·조회 오류·0·긴 문자열·결과 재사용·일반 이동/뒤로가기·모달 닫기·고정 높이를 검사한다.
- 사용자 요청대로 배치를 코드와 자동 검사로 검토한다. 실제 브라우저 픽셀 검증으로 주장하지 않는다.
- 위 수치는 준비 중간 검증이며, 최종 분리 브랜치의 전체 검사·커밋·배포 증거는 이후 항목에 기록한다.

## 배포 경계

- 운영 기준 `74e1a59`에서 포인트 변경만 분리한다. 이전 단어장 찾기 로컬 커밋은 보존한다.
- Preview와 Production은 각각 해당 환경의 빌드로 배포한다. Preview DB로 빌드한 것을 운영으로 승격하지 않는다.
- 직전 운영 기능은 `74e1a59`이며 복구 시 앱만 되돌린다. 학생 포인트·응시 기록을 되돌리지 않는다.
- 공개 GitHub 업로드가 안전검사에서 막히면 다른 도구로 우회하지 않고 명시 승인을 요청한다.
