# 2026-08-09 일괄 배정·해석 범위·시험 화면 작업 기록

> [!note] 역사 체크포인트
> 이 문서는 당시 한 배치에 섞였던 구현 근거만 보존한다. 현재 상태와 완료 조건은
> 루트 작업 대장의 `APP-20260807-04`, `APP-20260809-01`~`05`,
> `DRIVE-20260809-01`, `WORD-20260809-01`에서 각각 따로 관리한다.

## 입력

- 일괄 배정 오류 수정
- 학생별 수동 해석 시험지 범위 업데이트
- 단어 시험 선택지·발음 버튼의 고정 레이아웃
- 쉬운 오답 선택지 보완
- 공식 음원이 없는 단어의 합성 TTS 후보 분리
- 학생 결과 화면의 오답 횟수별 왼쪽 막대와 정답-only 표시

## 출력

- 앱 코드: `redesign` 브랜치
- DB: staging `wojxpruvbjzbhrpmsbuy`에만 신규 마이그레이션 3개 적용
- 자료 기준본의 합성 TTS 대기열은 앱 Git 밖 `영어/`에 보존

## 데이터 규칙

- 오답 횟수는 서로 다른 시험의 `initial` 오답만 센다.
- 같은 시험 재시험 오답은 이력은 남지만 횟수는 늘리지 않는다.
- 결과 카드의 1회는 노랑, 2회 이상은 빨강이다.
- 해석 범위 JSON은 학생 이름·학교·학년·선택 오답·현재 커리큘럼 단계만
  작업 입력으로 쓰고, 학생코드·세션·개별 답안·관리자 계정은 내보내지 않는다.
- Google Drive 실패와 앱 DB 저장 성공을 분리한다.
- 공식 MW 음원과 합성 TTS는 서로 다른 데이터층이며 자동 대체하지 않는다.

## 검증 수치

- Vitest: 91파일, 509테스트 통과
- lint, TypeScript, Next.js production build 통과
- PGlite 전체 마이그레이션 적용과 exam-use 저장기 통합 테스트 통과
- staging 함수 인자와 학생 reading-context 열 확인
- `quiz_questions.prior_wrong_count` 음수 0건

## 금지사항과 다음 시작점

- 운영 Supabase와 `main`에 바로 적용하지 않는다.
- Drive OAuth와 Preview 비공개 폴더가 준비되기 전에는
  `GOOGLE_DRIVE_ENABLED=true`로 바꾸지 않는다.
- 합성 TTS 후보를 생성·청취 검수 없이 앱 음원으로 연결하지 않는다.
- 다음 시작점은 Preview 배포 후 가짜 학생 한 명으로 일반 일괄 배정,
  틀린 단어 포함 일괄 배정, 결과 1회/2회 색, 해석 범위 DB 저장을 확인하는
  것이다. Drive 실제 파일 검증은 OAuth 연결 뒤 별도로 수행한다.
