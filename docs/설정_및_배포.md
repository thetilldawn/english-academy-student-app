# 설정 및 배포

## 1. Supabase 프로젝트

학생 앱 전용 `english-academy-student-app` 프로젝트를 서울
`ap-northeast-2` 리전에 만들었다. 기존 자료 폴더나 학생 원본과 합치지
않는다.

Supabase 관리화면의 Authentication 설정에서 다음을 확인한다.

- 공개 회원가입: 끔
- 이메일 회원가입: 끔
- 익명 로그인: 끔
- 관리자 계정: 관리자가 직접 만든 계정만 사용
- 비밀번호: 12자 이상 권장

로컬 설정 파일도 같은 원칙으로 공개 회원가입을 꺼두었다.

2026-07-29 공개 설정 API 검증에서는 `disable_signup=false`였으므로,
배포 전에 대시보드에서 `Allow new users to sign up`을 직접 꺼야 한다.

## 2. 데이터베이스 적용

원격에는 다음 두 마이그레이션을 적용했다.

1. `20260728134932_initial_student_app_mvp.sql`
2. `20260728170000_harden_admin_rpc_wrappers.sql`

적용 결과는 [Supabase 원격 적용 검증](Supabase_원격적용_검증.md)에
기록했다. 이후 새 마이그레이션만 순서대로 적용한다.

## 3. 관리자 계정 등록

1. Supabase 관리화면의 Authentication → Users에서 관리자 이메일·비밀번호 계정을 직접 만든다.
2. 계정의 이메일을 확인한 뒤 SQL Editor에서 [관리자 등록 예시](../supabase/bootstrap-admin.example.sql)의 이메일과 표시이름만 바꿔 실행한다.
3. 공개 회원가입이 계속 꺼져 있는지 다시 확인한다.

## 4. 환경변수

`.env.local`은 생성되어 있으며 Supabase Project URL, Publishable key와
서로 다른 앱 비밀값 네 개까지 구성했다. 비어 있는
`SUPABASE_SECRET_KEY`만 사용자가 대시보드에서 확인해 직접 넣는다.

새 환경에서 다시 만들 때만 서로 다른 32바이트 비밀값 네 개를 다음
명령으로 만든다.

```powershell
npm run secrets:generate
```

출력값은 `.env.local`과 Vercel 환경변수에만 넣는다. 채팅·Git·문서에 붙여 넣지 않는다.

운영 배포에서는 `APP_ORIGIN`을 실제 서비스 주소 하나로 정확히 지정한다.

```text
APP_ORIGIN=https://실제-서비스-주소
```

## 5. 능률보카 가져오기

현재 로컬에는 Git 제외 경로인 다음 검수본이 준비되어 있다.

```text
data/import/ability-voca-etymology-2025.json
```

먼저 쓰기 없는 검증을 다시 실행한다.

```powershell
npm run import:vocab -- --file data/import/ability-voca-etymology-2025.json
```

출력이 3,001행과 원본 SHA를 정확히 표시하는지 확인한 뒤에만 실제 프로젝트로 가져온다.

```powershell
npm run import:vocab -- --file data/import/ability-voca-etymology-2025.json --apply --mark-ready
```

- 같은 데이터셋 키에 다른 원본 SHA가 있으면 자동 교체하지 않고 중단한다.
- 기본 실행은 드라이런이며 데이터베이스 쓰기가 없다.
- `--mark-ready`가 없으면 시험에 쓰지 않는 검수 대기 상태로 남는다.

## 6. 로컬 실행

```powershell
npm install
npm run verify
npm run dev
```

기본 주소는 `http://localhost:3000`이다.

## 7. GitHub와 Vercel

- Git 루트는 이 `학생 앱` 폴더 하나다.
- 비공개 GitHub 저장소는 `thetilldawn/english-academy-student-app`이다.
- 이 앱 저장소에만 GitHub remote를 연결했고 `main` 첫 푸시를 완료했다.
- Vercel에는 해당 GitHub 저장소를 연결하고 위 환경변수를 등록한다.
- `SUPABASE_SECRET_KEY`와 네 비밀값은 반드시 Server-only 환경변수로 둔다.
- 배포 뒤 `APP_ORIGIN`을 실제 Vercel 도메인으로 바꾸고 재배포한다.

## 8. 아직 필요한 외부 연결

- Hosted Auth 공개 회원가입 비활성화 — 현재 켜짐
- Supabase Secret key와 로컬 비밀값 입력
- 관리자 계정 생성
- Vercel 프로젝트 연결·환경변수 입력

이 작업들은 사용자 계정 또는 채팅에 노출하면 안 되는 비밀값이 필요하다.
