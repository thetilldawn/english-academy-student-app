# R2-2 배정 수정 정책과 연결 보존

## 1. 목적

시험 수정 화면, reducer, controller, API, 저장 서비스와 DB가 서로 다른 기준으로 수정 가능 여부를
판단하던 구조를 한 정책으로 맞춘다. 수정은 기존 배정을 제자리에서 덮어쓰지 않고 새 배정으로
교체하되, 사용자가 바꾸지 않은 공개 시각·오답 범위·문제 묶음·오답 대기열·이어지는 배정 연결을
잃지 않아야 한다.

이 단계는 수정 흐름만 다룬다. 요일별 단위 수와 회차별 범위 계산은 R2-3에서 처리한다.

## 2. 한 곳에서 관리하는 수정 정책

기준 정책은 `src/lib/admin/assignment-edit-policy.ts`에 둔다. feature 계층은
`src/features/assignments/domain/assignment-edit-policy.ts`를 통해 이 정책을 사용한다.

이어지는 배정의 한 회차를 수정할 때는 단어장도 잠근다. 같은 단어장 안의 범위 변경은 허용하지만,
범위 변경 action 안에 다른 단어장 ID를 넣어 잠금을 우회할 수 없도록 reducer와 DB가 함께 막는다.

## 3. UI와 기능 분리

- 공개와 마감은 `AssignmentDateTimeToggleField` 공통 부품을 사용한다. 라벨·토글·날짜·시간·오류·
  열림 애니메이션을 한곳에서 관리하고, 실제 값을 바꾸는 함수는 controller가 제공한다.
- 화면은 정책 결과에 따라 항목을 숨기거나 잠그기만 한다. 무엇을 바꿀 수 있는지 직접 계산하지 않는다.
- controller의 변경 여부는 화면 상태 모양이 아니라 실제 PUT 요청 의미를 정규화해 비교한다. 예를 들어
  자동 단어 수와 같은 값의 직접 입력을 오가도 저장할 변경으로 잘못 표시하지 않는다.
- reducer는 잠긴 action을 받으면 같은 draft 객체를 반환한다. UI 밖의 재사용 경로에서도 정책을
  우회하지 못한다.

## 4. 교체 저장에서 보존하는 값

- `availableFrom`: 미래 공개 시험을 수정해도 즉시 공개 시험으로 바뀌지 않는다.
- `reviewScope`: 오답을 쓰지 않는 시험에서는 요청의 무의미한 scope를 원본 값으로 정규화한다.
- 문제 snapshot과 선택지 순서: 조건만 바꾸는 예전 오답 포함 시험은 기존 문제를 그대로 재사용한다.
  예전 자료의 선택지 ID 배열이 `NULL`이어도 문제 전체를 잃지 않는다.
- 선택된 오답 queue: 예전 오답 포함 시험의 오답 대기열을 그대로 보존한다.
- series item: 교체된 새 배정으로 회차 연결을 옮기고, 완료된 회차라면 다음 회차 생성 조건도 다시
  연결한다.
- 재시험 설정: 멱등 요청의 의미값에 포함해 같은 키로 다른 재시험 설정을 덮어쓰지 못한다.

완료 요청 재생과 롤링 배포를 위해 새 요청 원문 hash와 정규화된 hash를 구분해 저장한다. 구 앱의
복구 조회와 새 앱의 복구 조회가 같은 완료 결과를 찾되, 공개 시각이나 재시험 설정이 달라진 요청은
같은 요청으로 취급하지 않는다.

## 5. DB 변경

로컬 migration:

- `supabase/migrations/20260828193000_preserve_assignment_edit_metadata.sql`
- SHA-256: `E7C65ADF874B37C59B07D2ACC3EEA0DC0B19815B2ECD7CF9733FFA9295D6BA9C`

주요 변경은 `assignments.review_scope` 보존, 교체 요청 원문 hash 보존, v6 교체 writer, v2 완료 결과
조회, 이어지는 배정 문맥 조회와 회차 재연결이다. 구 writer의 불필요한 공개 실행 권한은 회수하고,
롤링 배포 중인 직전 앱이 쓸 v5 호환 wrapper만 유지한다.

Preview ref `wojxpruvbjzbhrpmsbuy`에는 이 migration 한 건만 개별 적용했고 원격 이력은
`20260828175502 preserve_assignment_edit_metadata`다. 적용 전·후 열, 함수 본문, 실행 권한,
기존 주요 행 수를 readback했다. 전체 migration을 한꺼번에 적용하는 `db push`는 사용하지 않았고,
Production ref `xdxhswjgksukjmpbzqgz`와 실제 학생은 조회·변경하지 않았다.

첫 Preview 브라우저 검증에서 다음 네 회귀를 추가로 발견했다.

- 1문항 독립 오답 시험 수정이 일반 시험의 최소 4문항 writer로 잘못 들어가 `422`가 됨
- 교체 저장 성공 뒤 `router.replace()`와 `router.refresh()`가 경쟁해 원본 상세가 남음
- 수정 화면의 `닫기`가 모달 전체가 아니라 편집 상태만 닫음
- 이어지는 배정의 `session.replaced` 시각을 원본 취소보다 먼저 잡아 이벤트 시각이 역전됨

이를 새 migration `supabase/migrations/20260829103000_fix_assignment_edit_preview_regressions.sql`로
보완했다. SHA-256은
`C0C2421BE9D4CF74C47296CE39D15B37D2ACECBAA9226139F3B6457087BA3B8C`이며, Preview 원격 이력은
`20260828182449 fix_assignment_edit_preview_regressions`다. 공용 일반 시험 writer와 공개 RPC를
바꾸지 않고 exact 오답 전용 저장 경로만 분리했다. 새 private 함수는 `SECURITY DEFINER`, 빈
`search_path`, 공개 실행 권한 없음으로 readback했고, 교체 이벤트 시각은 원본 취소가 성공한 뒤에만
잡도록 고쳤다. 적용 전·후 배정 120건, 배정 학생 119건, 교체 요청 1건, series 32건, item 84건,
event 103건은 같았다.
