# R2-2 배정 수정 정책과 연결 보존

## 1. 목적

시험 수정 화면, reducer, controller, API, 저장 서비스와 DB가 서로 다른 기준으로 수정 가능 여부를
판단하던 구조를 한 정책으로 맞춘다. 수정은 기존 배정을 제자리에서 덮어쓰지 않고 새 배정으로
교체하되, 사용자가 바꾸지 않은 공개 시각·오답 범위·문제 묶음·오답 대기열·이어지는 배정 연결을
잃지 않아야 한다.

이 단계는 수정 흐름만 다룬다. 요일별 단위 수와 회차별 범위 계산은 R2-3에서 처리한다.

## 2. 한 곳에서 관리하는 수정 정책

기준 정책은 `src/lib/admin/assignment-edit-policy.ts`에 둔다. feature 계층은
`src/features/assignments/domain/assignment-edit-policy.ts`를 통해 이 정책을 사용한다.

| 항목 | 일반 시험 | 예전 오답 포함 시험 | 독립 오답 시험 |
|---|---|---|---|
| 제목 | 화면에서 숨김 | 화면에서 숨김 | 화면에서 숨김 |
| 단어장 | 수정 가능 | 잠금 | 잠금 |
| 범위 | 수정 가능 | 잠금 | 잠금 |
| 단어 수 | 수정 가능 | 잠금 | 잠금 |
| 문제 방향 | 수정 가능 | 잠금 | 수정 가능 |
| 문제 순서 | 수정 가능 | 수정 가능 | 수정 가능 |
| 시간 제한 | 수정 가능 | 수정 가능 | 수정 가능 |
| 통과 점수·재시험 | 수정 가능 | 수정 가능 | 수정 가능 |
| 공개·마감 | 수정 가능 | 수정 가능 | 수정 가능 |

이어지는 배정의 한 회차를 수정할 때는 단어장도 잠근다. 같은 단어장 안의 범위 변경은 허용하지만,
범위 변경 action 안에 다른 단어장 ID를 넣어 잠금을 우회할 수 없도록 reducer와 DB가 함께 막는다.

## 3. UI와 기능 분리

- 공개와 마감은 `AssignmentDateTimeToggleField` 공통 부품을 사용한다. 라벨·토글·날짜·시간·오류·
  열림 애니메이션을 한곳에서 관리하고, 실제 값을 바꾸는 함수는 controller가 제공한다.
- 화면은 정책 결과에 따라 항목을 숨기거나 잠그기만 한다. 무엇을 바꿀 수 있는지 직접 계산하지 않는다.
- controller의 변경 여부는 화면 상태 모양이 아니라 실제 PUT 요청 의미를 정규화해 비교한다. 예를 들어
  자동 단어 수와 같은 값의 직접 입력을 오가도 저장할 변경으로 잘못 표시하지 않는다.
- reducer는 잠긴 action을 받으면 같은 draft 객체를 반환한다. UI 밖의 재사용 경로에서도 정책을
  우회하지 못한다.

## 4. 교체 저장에서 보존하는 값

- `availableFrom`: 미래 공개 시험을 수정해도 즉시 공개 시험으로 바뀌지 않는다.
- `reviewScope`: 오답을 쓰지 않는 시험에서는 요청의 무의미한 scope를 원본 값으로 정규화한다.
- 문제 snapshot과 선택지 순서: 조건만 바꾸는 예전 오답 포함 시험은 기존 문제를 그대로 재사용한다.
  예전 자료의 선택지 ID 배열이 `NULL`이어도 문제 전체를 잃지 않는다.
- 선택된 오답 queue: 예전 오답 포함 시험의 오답 대기열을 그대로 보존한다.
- series item: 교체된 새 배정으로 회차 연결을 옮기고, 완료된 회차라면 다음 회차 생성 조건도 다시
  연결한다.
- 재시험 설정: 멱등 요청의 의미값에 포함해 같은 키로 다른 재시험 설정을 덮어쓰지 못한다.

완료 요청 재생과 롤링 배포를 위해 새 요청 원문 hash와 정규화된 hash를 구분해 저장한다. 구 앱의
복구 조회와 새 앱의 복구 조회가 같은 완료 결과를 찾되, 공개 시각이나 재시험 설정이 달라진 요청은
같은 요청으로 취급하지 않는다.

## 7. Preview 반영 대기 순서

1. 사용자가 Preview ref의 위 migration 한 건 적용을 명시 승인한다.
2. migration 한 건만 적용하고 열·함수·실행 권한·기존 주요 행 수를 readback한다.
3. 현재 브랜치를 push해 자동 Preview 재배포를 시작한다.
4. 관리자 수정 화면에서 일반·예전 오답 포함·독립 오답의 잠금과 공개·마감 수정을 확인한다.
5. 이어지는 배정 연결과 브라우저 오류를 확인하고 브라우저를 닫는다.

이 다섯 단계가 끝나기 전에는 R2-2를 Preview 완료로 올리지 않는다. 완료 뒤 다음 시작점은 R2-3의
`같은 단위 수 / 요일별 단위 수` 연결이다.
