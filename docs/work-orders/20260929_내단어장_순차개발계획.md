## 3. 구조 판단과 공식 문서 적용

1. 첫 화면은 인증 후 Server Component가 기능의 서버 조회를 직접 호출한다. 같은 앱 API를 다시 HTTP로 호출하지 않는다. 필터·더보기처럼 브라우저에서 바뀌는 조회만 취소 가능한 전송 경계를 사용한다. [Next.js 서버 조회 안내](https://nextjs.org/docs/app/guides/backend-for-frontend).
2. 서버 전용 조회·명령이 권한과 최소 응답 자료를 책임진다. 학생은 현재 세션의 본인 자료만 받고 관리자 전용 필드·평가 정답을 전달받지 않는다. URL과 버튼을 숨기는 것을 권한 검사로 대신하지 않는다. [Next.js 자료 보안](https://nextjs.org/docs/app/guides/data-security).
3. `page/route`는 얇게 유지한다. `contracts`는 자료 형식, `client/controllers|flows|transport`는 입력과 요청 수명, `server/queries|commands`는 읽기·쓰기, `ui`는 표시를 맡는다. 현재 코드의 공개 진입점으로 연결하며 대규모 폴더 이동은 하지 않는다. [Server/Client 경계](https://nextjs.org/docs/app/getting-started/server-and-client-components).
4. ‘무조건 Server Action’으로 기존 HTTP 명령을 일괄 전환하지 않는다. 초 단위 응시·취소·멱등 처리와 이미 검증한 전송 계약은 유지하고, 새 폼 명령은 기존 기능의 계약과 맞춰 선택한다. 조회에 Server Action을 쓰면 요청이 순차 대기할 수 있으므로 조회 경로로 사용하지 않는다.
5. 자율연습은 별도 저장·명령으로 정규 시험과 격리하고 순수 계산·작은 표시 부품만 재사용하는 방향이다. 교사 배정은 기존 관리·응시 흐름에 출처와 포인트 제외 정책을 명시한다. 구체 SQL·경쟁 처리는 해당 단계의 R/D/T 설계 검토 뒤 확정한다.
6. 개인 자료에는 공유 캐시를 쓰지 않는다. 오류를 포함한 응답은 `private, no-store`. 같은 인증·조건의 현재 화면은 단순 시간 경과나 창 닫기로 지우지 않는다. 실제 저장 성공 때 관련 목록만 갱신하고 계정 변경·401/403 때 즉시 숨긴다.

공식 문서 확인일은 2026-09-29다. 웹 문서의 최신 버전 표시와 설치 버전은 다르므로 설치 버전에서 지원하는 방식만 사용한다. `cacheComponents`, `use cache`, 인증 체계 교체는 범위 밖이다. Supabase 변경 이력의 일반 PostgreSQL 보안 변경은 별도 참고이며 이 기능의 DB 업그레이드를 승인한 것으로 보지 않는다.

## 5. 놓치지 않을 경계 검사

독립 조사 반영: APP11의 듣기는 ‘본인 오답 단어 확인→검증된 발음/음원 조회→기존 표시·재생 부품’으로 별도 연결한다. APP10의 단어/출처 응답에 음원이 이미 있다고 가정하거나 배정별 읽기를 권한 없이 호출하지 않는다. APP13은 기존 독립 오답 후보의 ‘미해결·책 안 응시 횟수’가 아닌 여기의 전체 initial 집계를 쓴다. 여러 책도 제외하지 않으며 문항별 원출처·원뜻을 유지할 저장 설계를 먼저 검증한다. 교사 시험의 완료/미통과는 기존 판정을 유지하고 무포인트는 응시 생성의 불변 정책으로 전달한다. null 정책에 기존 포인트 기본값이 들어가는 현행 동작을 그대로 사용하지 않는다. 학생별 저장을 브라우저에서 반복 호출하지 않고 한 요청의 검증·중복 방지·전체 거래를 서버에서 보장한다.

- 자료: 시험 당시 검증 원문 우선순위, 같은 철자의 다른 뜻/출처, 보기·음원 없음, 출력에 정답/비밀/타인 자료 없음.
- 요청: 빠른 필터 전환·늦은 응답·중복 클릭·시간 초과·취소, 저장 성공 여부 불명 시 먼저 결과 조회. 임의 자동 재저장 금지.
- 화면: 초기 대기/미선택/정상0개/입력 오류/조회 실패/저장 실패/인증 실패/404/예외를 구분. 오류 원문 대신 짧은 한국어와 실제 복구 행동 제공.
- 보존: 자율연습 전후 정규 자료와 포인트가 동일. 새 교사 배정의 포인트0은 클라이언트 선택값만으로 결정하지 않음. 기존 정규 시험의 포인트 규칙은 유지.

## 6. 다음 세션의 시작점

루트 대장 → 이 계획 → 현재 단계의 `docs/work-orders/APP-번호.md` → `architecture/work-records/records/APP-번호.json` → 해당 검증 기록 순서로 읽는다. 이전 단계 원자료를 전부 다시 찾지 않는다. 각 검증 기록에 변경 파일, 실제 실행 수치, 미실행 항목, 다음 시작 파일을 남긴다. 서브에이전트는 독립 조사·검산·리뷰만 하고 파일/DB 쓰기는 메인이 맡는다.
