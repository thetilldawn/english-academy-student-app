# 학생 조건 자동 선택과 필수 정보

## 요구와 결정

- R1 / D1: 신규 등록과 정보 수정에서 이름·학교·학년 필수. 기존 학생도 새 배정 전에 보완한다. 기존 시험 조회·응시·성적·완료된 저장 결과 확인을 막지 않는다.
- R2 / D2: 선택 학생들의 공통 학교·학년을 자료 선택 기본값으로 사용한다. 서로 다르면 해당 조건 ‘전체’. 직접 고른 조건은 같은 창에서 보존하고 학생 변경 시 초기화한다.
- R3 / D3: 선택한 대비 시험의 학기가 있으면 우선한다. 별도 시험 선택 경로가 없는 현재 배정은 한국 날짜의 현재 학기(3~7월 1학기, 8~2월 2학기)를 제안하고 직접 바꿀 수 있게 한다. 학생 프로필에 영구 학기를 저장하지 않는다.
- R4 / D4: 학교와 학년은 기본 필터이며 다른 학년 기출을 직접 선택할 수 있다. 학기 분류가 없는 공통자료도 보여 주고, 새 범위 구성에는 대상 조건으로 전달한다. 기존 저장 템플릿의 범위를 학생 조건으로 임의 변경하지 않는다.
- D5: 사용자 ‘학생 정보 필수’와 후속 질문의 첫 제안에 대한 ‘ㄱㄱ’로 새 배정 전 보완을 채택한다. 내부 검증 함수를 재사용하되 저장 결과 확인은 보존하고 새 저장에만 적용한다.
- D6: 학교 직접 입력 시 중1~고3을 직접 선택할 수 있다. 학생 정보 저장 결과는 열린 배정의 학생 정보만 갱신한다. 검색어·수동 필터·작성 범위는 유지하고 직접 건드리지 않은 기본 조건만 새 정보에 맞춘다.

## 흐름과 소유

학생 생성/프로필 수정은 students, 배정 준비·미리보기·생성은 assignments, 새 구성 대상은 wordbook-compositions, 공통 검증은 shared-contract가 맡는다. 개인 조회는 현재 관리자 인증과 no-store를 유지한다. 과거 시험·학생 로그인·삭제·성적·원사전 변경은 해당 없음이다.

프로필의 입력값은 기존 버전 검사와 학교 검색을 거쳐 저장한다. 배정은 조회한 학생 정보로 기본 조건을 만들고, 저장 직전 서버가 최신 정보를 확인한다. 학생 식별자만 믿거나 브라우저 검사만으로 허용하지 않는다. 기존 학생 필드의 빈 값을 일괄 변환하지 않는다.

## 화면 상태와 검사

| 요구/검사 | 발생 조건 → 표시와 동작 | 보존과 복구 |
|---|---|---|
| R1/T1 | 이름/학교/학년 빈 값 → 해당 입력 아래 ‘이름을 입력해 주세요’/‘학교를 입력해 주세요’/‘학년을 선택해 주세요’, 오류 테두리와 저장 비활성 | 입력 보존, 해당 값을 채우면 오류 해제. 신규와 수정의 서버도 동일 거절 |
| R1/T2 | 새 배정 대상에 정보 누락 → ‘학생 정보에서 이름·학교·학년을 먼저 입력해 주세요’와 학생 정보 링크, 생성 비활성 | 다른 학생 자동 제외 금지. 작성 중 범위는 유지하고 정보 보완 후 다시 확인 |
| R2/T3 | 학생 선택/변경/같은 창 재열기 → 공통 조건 기본 선택 또는 ‘전체’ | 직접 선택은 같은 대상에서 보존. 이전 학생의 응답·조건을 새 학생에 적용하지 않음 |
| R3/R4/T4 | 학기 변경/공통자료/다른 학년 선택/새 구성 → 올바른 조건 및 자료 표시 | 저장 템플릿의 기존 대상·범위를 덮어쓰지 않음. 조회 실패를 0건으로 표시하지 않음 |
| R1~R4/T5 | 실제 PC·모바일 → 오류 입력, 자동 필터, 직접 변경, 정보 보완 안내 표시 | 키보드 초점, 초안 보호, 가로 넘침, 비동기 실패 확인 |
| R1~R4/T6 | 타입·관련 검사·구조·빌드·독립 검토 | 실제 외부 적용과 가짜 검사 결과 구분 |

학교 검색 실패·인증 거절·저장 충돌/결과 불명은 기존 전용 안내와 재시도를 유지한다. 개인 자료 공유 캐시는 만들지 않는다. 필수 정보 판정은 과거 완료 명령의 결과 재조회보다 뒤에 두어 응답 유실 복구를 방해하지 않는다.

## 구현·검증 경계

기존 계층/공용 FieldError·학교 검색·학년 코드 정규화·학생 상세 링크를 재사용한다. 새로운 학생 정보나 실제 학생 예시는 만들지 않는다. DB 제약이 필요하면 신규 변경 파일과 격리 검사로 확인하고, 운영 변경은 별도 명세에 기록한다. 검사 결과는 완료 후 검증 문서와 앱 인계서에 남긴다.
