# 기존 사전 키로 선택·배정 연결 수리

APP-20261004-04. 2026-10-04 사용자: 기존 연결이 유지됨을 확인하면 지금까지 구현한 기능과 검사를 재사용하여 필요한 부분만 보수한다. 기준은 [기존 사전 참조 계획](20261001_공용사전과학생기록_유지보수/16_기존사전기준_수정구조와작업계획.md)이며 현재 상태는 루트 대장만 따른다.

## 확인한 원인과 범위

운영 읽기 확인: 시험 사용 원자료18,479개·포함 범위행21,796개·기존 구성행7,532개의 원단어 참조가 남아 있다. 비어 있는528개 원자료 연결은 검토보류526/제외2이며 사용 대상의 연결 단절이 아니다. 옛 사전 매핑888개는 원래 unresolved 상태로, 임의 연결하거나 승인하지 않는다. 기존 구성 안의 원단어 키 중복0·원단어별 여러 출현 키0·생성 중 구성0이다. 원자료 전체의 문자 단위 동일성을 새로 검사했다는 뜻은 아니다.

오류는 기존 원단어 연결과 별개로 배정용 선택을 저장할 때 vocab_entries에 본문을 복제하는 데 있다. 기존 화면/API와 선택 목록의 이름·범위·단원 메타데이터는 유지하고, 선택한 단어·출처·순서 관계에서 원키를 사용한다. 새 사전·단어장 본문·문제은행 저장소를 만들지 않는다.

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 | 기존 선택 저장 경로가 원단어 키를 사용하고 vocab_entries 및 공용 학습값 본문을 추가 복제하지 않는다. | T1,T2 |
| R2 | 같은 원키를 A/B 선택과 두 학생에게 사용해도 출처·선택 뜻·발음·순서가 섞이지 않는다. 선택 단원과 원자료 단원은 각각 기존 관계에 둔다. | T1,T2,T3 |
| R3 | 기존 배정·응시·답·점수·오답 기록과 이미 작동하는 기기 채점·재시험·종료 제출을 유지한다. | T1,T3,T4 |
| R4 | 바뀐 연결의 오류·보존만 검증하고 전체 재작성·용량/부하 실험·기존 통과 검사 반복을 하지 않는다. | T1,T2,T3,T4 |

결정 D1 사용자: 원래 사전 키와 태깅을 재사용하고 실제 본문 중복을 없앤다. D2 내부: 기존 선택 관계 표의 식별 범위를 선택판+원단어로 바로잡고, 본문은 기존 범위 키를 통해 조회한다. 기존 선택 이름/단원 표는 본문 없는 목록 정보로 유지한다. D3 내부: 배정 문항의 원자료 소속은 이미 있는 assignment_sources로 연결하고 원단어 자체의 자료집·단원·행번호를 수정하지 않는다. D4 사용자: 과거 일괄 정리와 새 기능은 이 수리와 분리한다. 학생·사전·과거 구성의 기존 행을 옮기거나 삭제하지 않는다. D5 내부: 서로 다른 승인 내용이 같은 원키로 충돌하면 임의로 뜻을 합치거나 하나를 고르지 않고 저장을 거절한다. 미결정 없음.

## 구조와 변경 순서

1. 현재 키 참조와 변경 전 함수/제약을 확인하고 저장한다.
2. 기존 composition_entries의 전역 단어번호 제약을 선택판+단어 관계에 맞게 바꾼다. 원단어 FK와 문항의 선택판+단어 FK는 유지한다.
3. 기존 선택 처리의 본문 INSERT를 원키 연결 INSERT로 바꾼다. selected/resources에는 기존 scope/occurrence 키와 확인값만 둔다. 이미 저장된 구형/v2 내용은 기존 판독기를 유지한다. 본문판과 연결판을 새로 등록하지 않는다.
4. 목록·준비·단계 처리·배정은 기존 선택 위치를 읽고, 실제 단어 내용은 원자료를 읽는다. 단어번호만으로 어느 선택판인지 추측하던 조회는 전달된 선택판 키로 한정한다.
5. 배정의 기존 자료 관계에 원자료 소속을 등록한다. 원키 및 사전/뜻 식별, 포인트·권한·응시 정책은 유지한다.
6. 기존 소규모 검사를 보강하고 검토 환경부터 동일 SQL을 확인한다. 현재 운영의 학생에게 시험이나 답을 만들어 검사하지 않는다.

소유자: wordbook-compositions의 선택 저장·준비, assignments의 배정 자료 관계, database-contract의 연결 검사. 조회·검색·삭제의 공개 요청/응답과 화면 문구는 유지한다. 불완전 선택은 기존 오류/재시도 흐름으로 처리하며 오류를 빈 결과나 완료로 바꾸지 않는다. 저장 재전송은 기존 요청 키를 재사용하고 진행 중 단계는 기존 처리 위치를 보존한다. 권한·잠금·삭제 보호를 임의로 풀지 않는다.

캐시는 이미 구현한 공용 시험자료48시간, 사용하지 않는 준비자료24시간, 미접수 답 자동삭제 금지 기준을 유지한다. 시험 중 문항별 DB 호출과 음원 보관 정책은 변경하지 않는다. UI/CSS/라우팅을 바꾸지 않으므로 화면 전체 재검사는 하지 않으며 공개 응답 검증과 실제 배정/준비 경로를 확인한다.

서버의 선택 범위 단어 수 집계1곳도 복사된 단어 행의 개수 대신 기존 선택 단원의 확인된 개수를 사용한다. 직접 오답 재배정에서는 선택 목록의 헤더와 원자료 ID를 기존 출처 관계로 연결한다. DB 준비/제출 검사는 브라우저의 실제 채점 실행 검사와 구분해 기록한다.

T1: 기존6단어/겹치는 범위 검사에서 원단어 추가0·ID보존·선택 뜻/발음/순서·배정·오답/학습 조회 확인. T2: 기존500/501 처리 경계에서 연결행·진행 위치·실패 원복과 원자료 변경 거절 확인. 501은 처리 경계이며 부하 검사가 아니다. T3: 기존4문항 흐름으로 새 원키의 준비→기기 채점→최초/재시험 제출→재접수를 확인하고 A/B/학생2명 참조 및 옛 응시를 비교한다. T4: SQL 적용 전후 기존 행·함수 권한·제약 보존, 검토 환경 적용과 원키 연결을 확인한다.

복구: 새 선택 저장을 중지한 상태에서 변경 함수의 이전 본문을 보관한다. 새 원키 관계가 생긴 뒤 전역 단어 PK/옛 읽기로 단독 복귀하면 안 된다. 읽기 호환을 유지한 채 문제 함수만 수리한다. 기존 원단어·학생 기록을 이전하거나 되돌리는 절차는 없다. 운영 반영과 미검증 항목은 구현 완료와 별도로 기록한다.
