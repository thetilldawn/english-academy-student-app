# 배정에 반복 저장되는 내용 확인값 공유

승인된 유지보수 M02/M09와 OPS-20261003-02 D7의 같은 중복 저장 보완이다. APP09의 중간 쓰기 제거 뒤에도, 원행과 출제 적격 확인값 두 개가 공용 문항판과 학생별 배정 문항에 반복된다. 이번에는 신규 구성 배정의 두 열만 공용 문항판에서 복원한다. 상태와 순서는 루트 대장만 따른다.

## 요구와 완료 조건

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 확인값 한 곳 보관 | 새 구성 문항의 두 확인값을 원래 공용 binding에서 읽음, 최초 INSERT부터 중복0·후속 UPDATE0 | T1/T2 |
| R2 원래 의미 보존 | 기존/신규 복원 행·문항 순서·뜻·발음·오답/점수/포인트·준비 확인값 동일 | T1/T2/T4 |
| R3 원래 보호 보존 | 출처·본문·보관판 확인값·잘못된 참조·남아 있는 식별자 대조, 실패 전체취소 | T3/T4 |
| R4 과거와 복구 호환 | 기존 행/열/FK/UNIQUE·준비/보관 문서 확인값·M08 선택복구 유지 | T1/T4/T5 |
| R5 실제 효과 분리 | 개별/물리 저장량과 기존 기록·운영 상태를 분리, 같은 조건으로 후속 계측 | T6 |

## 결정

- D1 사용자: 공용 사전/출처 키를 공유하고 학생별 본문 중복을 없애며 배정·점수·최초/재시험·오답·포인트를 보존한다. 유지보수 완료·계속 진행 승인과 OPS02 D7을 적용한다.
- D2 사용자: 기기에서 채점·풀이 중 호출0·종료 제출·기한 안 기록한 답의 늦은 제출·원기기 재개·미확인 답 자동 삭제 금지와 공용48시간/미사용준비24시간은 유지한다.
- D3 내부: 신규 composition_verified_v1 문항의 entry_row_sha256_snapshot과 eligibility_input_hash_snapshot만 비운다. 두 값이 모두 NULL이고 이미 본문이 공용 참조인 엄격한 조합에서만 기존 binding으로 복원한다. 한 값만 빠졌거나 다른 출처형이면 원래 검증으로 거절한다. 다른 남은 식별자/정답/선택 키를 공용 값으로 덮지 않는다.
- D4 내부: 신규 열/표를 추가하지 않는다. 구성 복합 FK·배정 내 중복 방지 키·순서별 question_content_sha256·선택 키·분기/생성 규칙·학생/문항 ID는 그대로 둔다. 두 열 관련 최종 물리 CHECK는 NULL 또는 대문자16진64자이며 그대로 유지한다. 기존 원형 assert와 공용 원문 확인을 해제하지 않는다.
- D5 내부: 내부 메타 복원 함수를 만든 뒤 배정 판독기·응시 판독기의 raw bank 비교·시험용 binding과 배정 복원 뷰에 연결한다. 원래 binding 함수 자체는 순수 함수로 둔다. 새 BEFORE INSERT 트리거는 기존 출처·APP09 등록·zzz_freeze 보호 뒤에만 두 열을 비운다. 기존 freeze/M03/M08 특례를 임의 수정하지 않는다.
- D6 내부: 기존 행은 UPDATE/DELETE하지 않는다. 열 추가가 없으므로 전체 행에 기초한 과거 준비/보관 확인값을 유지한다. M08의 원래 자료 내보내기·선택 복구와 새 두 확인값 저장형의 관련 경계를 실제 검사한다. 실패 시 거래 전체취소이며 공용 등록·당시 뜻 고정을 함께 유지한다.
- D7 내부: 새 트리거를 제거하면 이후 신규 배정은 두 확인값을 다시 원형으로 쓴다. 이미 축약한 새 행을 읽는 호환 함수/뷰는 남겨야 한다. 학생 기록이나 새 참조를 삭제하지 않는다. 내부 직접 실행권한은 PUBLIC/anon/authenticated/service_role 모두0이다.
- D8 내부: 로컬 최종 PGlite→동일 SQL의 작은 가짜 검토 DB→보존/복구/필요 경합 검사→같은 계측 순서다. Windows initdb·원격 대량 부하·운영 DB 쓰기/배포·물리 재작성은 하지 않는다. 실제 절감량은 측정 전 확정하지 않는다.

## 데이터와 흐름

소유자는 assignments, 복원 소비자는 quiz-player, 검사는 database-contract다. 공용 문항의 원래 binding을 재사용하며 캐시나 두 번째 사전을 만들지 않는다. 생성·배정에서 기존 출처와 보기 검사를 마친 뒤 참조형으로 저장한다. 준비·응시·과거 결과·오답장은 기존 복원 계약을 통해 원래 두 값을 받는다. 검색·집계·수정 화면에는 새 상태나 필터가 없다. 삭제/정리는 새로 추가하지 않고 이전 복구 경계만 검사한다.

공개 요청/응답·학생/관리자 권한·학교 자료 원문·음원/CDN·진행 시험 정책은 같다. 두 열은 앱 TypeScript에서 직접 읽는 소비자가 없음을 검색했고 DB 함수의 직접 읽기·원형 대조는 모두 최종 스키마에서 추가 확인한다. 개인 정보·정답은 외부 근거에 보관하지 않고 가짜 자료와 집계/확인값만 사용한다.

| T2 | 신규 INSERT 직후 두 열 NULL·UPDATE0·복원 값/공용키/당시 뜻 동일, 다수 배정 공유 |

| T4 | 준비/시작/최초·재시험·재접수·오답장·M08 원파일 비교/선택 복구·후반 실패 전체취소 |
| T5 | 트리거 순서·내부권한0·기존 FK/UNIQUE·트리거만 제거한 이후 원형 쓰기와 축약형 읽기 |

UI/경로/스타일/문구는 바꾸지 않는다. 배정 실패는 기존 “단어 시험을 배정하지 못했습니다.”, 준비 실패는 기존 복구 안내로 표시하고 입력/미접수 답을 유지한다. 실패를 빈 목록이나 완료로 바꾸지 않는다. 기존 기기·인증·401/404·접수 대기 안내는 M05/M11 계약을 유지한다. 새 화면 검사는 해당 없음이며 공개 계약의 회귀 검사는 수행한다.

## 입력 근거와 산출물

최종 스키마 읽기, 독립 DB/소비자 조사, APP09 e6b98ab/595d9e1과 M09 3f414fb를 입력으로 한다. 실제 제품 SQL·검사·기록은 이 작업에만 묶고, 인원 계산은 별도 OPS02 증거로 보관한다. 단계별 코드 확인값·검사 수·검토/운영 구분과 다음 재개 지점을 인계서에 남긴다. 기존 미커밋 인계150줄과 과거 미등록 보고서는 섞지 않는다.

## 검사 중 확인한 내부 진단 경계

새 축약행의 금지된 본문 UPDATE는 기존 reviewed-choice 검사에서 먼저 복원하므로 `question_content_binding_mismatch`(55000)로 거절한다. 원형 행은 `question_content_reference_immutable`(55000)을 유지한다. 두 경로의 정확한 거절 검사를 각각 고정하며 공개 오류 문구·허용 쓰기·M08 permit은 바꾸지 않는다. M08은 APP10 직전 실제 준비 명세를 생성하고 적용 뒤 같은 명세로 부분 이전·부분 복구하여 검사한다.
