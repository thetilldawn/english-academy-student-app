# 내 단어장 조회와 메인 복귀 수리

입력: 2026-10-05 사용자의 단어장 조회 실패 및 메인 복귀 요청. 실제 운영 테스트 계정의 읽기와 기존 오답 구간 SQL을 대조했다.

- R1 / D1 / T1: DB의 기존 `md5(...)::uuid` 오답 구간키는 RFC UUID 버전 비트와 무관하다. 앱의 `z.uuid()`가 정상 응답을 거절했다. 구간키만 PostgreSQL의 8-4-4-4-12 형식을 받는 공용 계약으로 읽는다. 기존 키, 기록, 학생 ID 권한 검사는 유지한다. 조회·상세·더보기·배정 대상 계약이 같은 구간키를 사용한다.
- R2 / D2 / T2: 단어장 목록·상세·로딩·오류에서 상단 `메인으로`는 `/student`로 이동한다. 모바일 상세 모달 안에도 같은 링크를 제공한다. 기존 닫기와 목록 복귀는 그대로 둔다.
- R3 / D3 / T3: 기존 시험·사전·배정·오답을 수정하지 않는다. 관련 검사와 실제 화면 읽기만 실행한다. DB 변경이나 실제 학생 시험 생성 없이 검증한다.

상태: 첫 대기는 기존 로딩과 메인 링크, 빈 목록은 기존 빈 안내, 조회 실패는 기존 다시 시도와 메인 링크, 인증 실패는 기존 가림/재로그인이다. 실패를 빈 목록으로 대체하지 않는다. 서버 원문·학생 식별자·정답은 오류 문구에 넣지 않는다.

변경 영향: UI/계약/검사 변경, 라우팅 주소·DB·학생 권한·48시간 자료 재사용은 확인만. 자료 복제·이전·새 사전·실학생 쓰기는 제외한다. 복구는 앱 코드만 되돌리며 데이터 변경이 없다.

검사: T1 실제 응답 형식 대조와 가짜 구간키의 읽기/커서/배정 계약; T2 목록·모바일 상세·로딩/오류 메인 링크; T3 타입/lint/구조/빌드와 검토→운영 읽기. 과거 통과한 전체 검사·부하 실험을 반복하지 않는다.

독립 검토 보완: 연습 입력·연습 출제 자료·오답 문제 내보내기에도 같은 구간키 검사를 적용한다. 범위·뜻·정답·학생키 계약은 그대로다.
