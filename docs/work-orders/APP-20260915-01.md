# 검토한 발음 자산 추가 연결

기존 원문에 연결된 발음이 없더라도 검토한 공식/생성 음원과 한글 표기를 추가한다. 생성 음성 앞의 잡음·무음은 원본을 보존한 새 처리본으로 연결한다.

- R1/D1: 사용자2026-09-15 누락 발음의 한글·음성 생성/추가, 기존 음원 우선·Google 보충 승인. T1에서 승인 파일/범위/원문/POS/음원/표기 불일치를 거절한다.
- R2/D2: 기존 단어를 빌린 것처럼 가짜 출처를 만들지 않고 private 검토 자산을 연결한다. 기존 재사용 경로와 서비스 조회 유지. T1/T2에서 정상 추가·권한·재실행을 확인한다.
- R3/D3: 생성 음원 처리는 원음·내용·표기·품사를 보존하고 음원 자산만 새로 만든다. T1에서 원음 SHA·동일 발음 내용·처리 기록과 기존 연결판의 차이를 확인한다. 공식 음원은 처리하지 않는다.
- R4/D4: 학교 뜻·정의·사전·예문·문항·학생 자료를 보존한다. 전체 연결판의 변경 전후를 같은 거래 안에서 검사한 뒤 전환한다. T1/T2/T3에서 실패 롤백·구판 보존·현재 조회를 검사한다.

실행 흐름은 검토 입력→독립 검토/파일 확인값 승인→새 음원 업로드/확인→private 자산 등록→전체 연결판 보존 대조→같은 거래에서 전환→기존 발음 조회다. DB 허용 공급자는 기존 Merriam-Webster/Google을 유지한다. 학교 품사 미기재 원문을 임의로 채우지 않는다.

바꾸는 면은 발음 자료 수용·검사뿐이다. 경로/UI/브라우저 상태/시험 계산/HTTP/캐시/학생 인증은 확인만 한다. 원문 불변과 새로운 음원 주소로 기존 캐시·시험 기록을 보존한다. 예전 연결판 활성화로 복구하며 새/옛 음원 삭제는 하지 않는다.

T1 신규 검토 자산 통합검사, T2 기존 학교·원문 연결 통합검사, T3 타입/lint·설계/소유권·검토용과 운영 실제 조회/보존이다. UI는 기존 표시·재생 계약을 사용하며 DB 검사를 실제 청음으로 보고하지 않는다. 자동 재생 대기 변경은 원인이 확인되어 해당 구현 범위를 추가하기 전까지 이 변경에 섞지 않는다.
