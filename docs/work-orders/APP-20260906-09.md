# 배정 미리보기와 시간 입력의 좁은 재사용 경계

- [작업 기록](../../architecture/work-records/records/APP-20260906-09.json) R1/R2, D1/D2, T1~T5. 기존 계획의 하위 표시 부품 두 곳을 정리한다. 사용자 미결정 없음.
- 미리보기는 기존 응답의 items/commonPlanSummary와 진행/오류/학생 표시만 받는다. controller/요청/저장 메서드는 알지 못한다. 공통/개별/오류 중복/완료 연동 동작을 T1로 보존한다.
- 시간 입력은 enabled/timing과 개별 콜백만 받는다. 신규 단일/일괄, 독립 오답, 기존 수정의 실제 세 호출부에서 기존 timeLimitEnabled !== false 기본값을 적용한다. 입력 기억과 계산은 기존 controller 책임이다. T2/T3는 토글·모드·분초·오류 접근성과 실제 호출부를 검사한다.
- 역할 등록의 두 deferred를 pure/interaction으로 승격하되 검사와 단독 입력을 먼저 확인한다. 다른 편집6/선택4는 이번 네 우선 대상 외 후속 정리로 남기고 소스 지문을 보존한다. 완료된 재사용 부품으로 표현하지 않는다.
- UI/CSS·공용 탭·입력·오류·애니메이션은 기존 부품 재사용. 캐시, 인증, 요청 계약, 학생 데이터/점수/시험 규칙/DB/의존성은 변경하지 않는다. 캐시 계획 완료나 운영 배포 완료로 합치지 않는다.
- T4 관련검사→타입/lint/구조와 변경 연결, 최종 통합에서 전체/빌드 재확인. T5 독립 읽기 리뷰. 복구는 두 props와 실제 호출부/역할 등록을 함께 복구한다.
