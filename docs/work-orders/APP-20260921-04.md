# 단어장 필요 시 조회·조건 템플릿·삭제·출제 순서

사용자 추가 요구와 순차 진행 승인을 따른다. 입력은 APP03 `f86ace9`이며 원자료/학생 기록 변경과 운영 반영은 별도다.

## 요구와 확정 기준

- R1/D1: 첫 화면은 템플릿 요약 한 페이지다. 범위는 선택한 종류/조건에 맞는 요약 페이지만, 단어는 펼친 선택 범위의 한 페이지만 조회한다. 과거 버전도 열 때 조회한다. 모든 원행·과거 버전을 미리 가져와 화면에서 자르지 않는다. (T1,T2,T6,T7)
- R2/D2: 새 템플릿은 순서 있는 자료 묶음의 필터 조건을 저장한다. 실제 사용 시 현재 자료로 다시 계산하고 변경 범위가 있으면 확인 후 새 고정 버전으로 만든다. 예전 직접 선택 범위는 정확한 ID/버전/제외/순서를 유지하고 조건으로 임의 추정하지 않는다. (T1,T2,T3,T6)
- R3/D3: 삭제는 템플릿 목록에서 구성을 제거한다. 원자료·사전·이미 만든 단어장·배정·응시·답을 삭제하지 않는다. 삭제 전 이름과 보존 범위를 안내하고 확인받는 화면을 쓴다. 삭제 후 새 저장/복사/생성을 차단하되 과거 완료 요청과 이미 시작한 생성의 같은 요청 복구는 유지한다. (T3,T4,T6)
- R4/D4: 시험 문항 순서는 원자료 기준 오름차순·내림차순·무작위다. 알파벳 정렬을 추가하지 않는다. 일반/일괄/오답·이전 조건 복사·편집에서 같은 값을 보존한다. 기존 fixed만 오름차순으로 호환한다. (T5,T6)
- R5/D5: 기존 종류별 조건, 즉시 범위 갱신, 자동 이름/태그와 수동 이름 보존, 입력별 오류, 1→2→3 단계, 미확정 저장과 초안/미확정 요청 복구를 보존한다. 학생 자동 대상 조건도 유지한다. (T1,T3,T6)

## 데이터·요청·보존 설계

D6(내부): 조회 전용 POST `/api/admin/wordbook-library/query`를 쓴다. templates/versions/detail/facets/scopes/preview/words의 엄격한 구분과 관리자 권한·no-store를 적용한다. 목록 기본20, 범위30, 단어50의 제한과 다음 커서를 둔다. 커서는 검색/자료/정렬/선택 확인값에 묶고 조건이 바뀌면 첫 페이지로 돌아간다. 과거 범위 참조를 조회할 때 최신 ID로 대체하지 않는다.

DB는 범위 revision 상한과 조건·정렬·LIMIT 뒤 해당 페이지 상태/개수만 응답한다. 단어는 선택한 범위 또는 고정 판에서 occurrence key를 중복 정리하고 검색·정렬·페이지를 계산한다. 압축 참조와 옛 전체 고정판을 모두 지원하며 상세 원행 복원은 해당 페이지에 한정한다. 빈 조건 결과, 아직 계산 중, 자료 변경, 조회 실패는 별도 상태다.

D7(내부): 기존 4필드 recipe는 변경하지 않고 immutable 버전에 nullable criteria를 추가한다. criteria는 순서 있는 filter/fixed 묶음과 제외를 가진다. 조건식 묶음의 범위 제외는 scope_key로 보존한다. 전체 범위 순서를 직접 바꾸면 정확한 참조를 가진 fixed 묶음으로 전환한다. 과거 criteria=null은 명시한 고정 참조로 열며 상관관계나 정렬을 확대하지 않는다. 단어 제외가 더 이상 범위에 없으면 조용히 포함시키지 않고 확인 안내/정리 동작으로 해결한다.

미리보기는 서버가 recipe와 실제 포함/보류/제외 수·묶음별 참조·내용 확인값·이전 판과의 차이를 만든다. 자동 태그와 제안 이름은 포함된 범위 분류에서 계산한다. 클라이언트는 전체 단어/정답 위치/문항 자료를 받지 않는다. 템플릿 목록에는 includedKeys·모든 versions를 넣지 않는다. 저장/생성 응답도 현재 버전 요약만 반환하는 새 명령 경계를 사용하고 완료된 옛 응답 기록은 보존한다.

D8(내부): 새 v2 저장·삭제는 requestId/관리자/전체 요청 확인값에 묶고 같은 완료 요청을 먼저 반환한다. 저장할 때 미리보기 recipe와 내용 확인값을 현재 원판과 다시 대조한다. 삭제는 deleted_at과 revision만 바꾸며 생성 단어장 metadata 동기화를 호출하지 않는다. template 행 잠금으로 삭제/수정/새 생성 순서를 정한다. 기존 시작된 생성은 같은 템플릿·버전·requestId·확인값인 경우에만 복구한다.

클라이언트의 보관자는 현재 편집 창이다. 검색 250ms 대기, 요청 취소/순번으로 늦은 응답을 버리고 관리자 바뀜·권한 거절 때 숨긴다. 새 요청 시작 때 이전 결과를 새 조건의 0건으로 표시하지 않는다. 저장 불확실 시 같은 요청만 재확인하고, 성공 뒤 배정 화면 연결만 실패하면 완료 결과로 연결만 재시도한다. 공유 개인 캐시·주기 조회·학생 권한 확대는 없다.
