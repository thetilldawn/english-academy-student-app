# 최종 캐시·단어장 운영 반영

- 사용자 승인: 기존캐시·구조 마감→마지막 가리기→안전검증 후 Preview/Production. 기존 공개 GitHub 코드·개발문서 업로드 ㄱㄱ 승인. 새팀/유료/키공개/학생자료/원천/DB변경은 제외.
- R1/D2: APP08/10/12에서 로컬 채택한 개인 캐시의 기본값을 ON으로 연결한다. env의 한 해석을 Provider와 3화면이 재사용. 미설정·공백·1=ON,0·잘못된문자열=OFF; 학생OFF면배정OFF, 내역독립. 인증/15·60·120초/폐기/포인트 분리는 그대로다.
- R2/D3: 과거실험·해시는 보존한다. 이 배포의 현재 전체코드 검사와 원격환경 결과를 별도로 결속한다. 문법/자료/DB변경 없음. APP13은419파일2597검사·모바일/PC·현재 운영예문43/43 정렬까지 통과.
- R3/D4: 기존 기능브랜치push→정확 Preview 확인→main 비강제 fast-forward→Production 환경으로새빌드. Preview 산출물을 운영 DB에 연결된 것처럼 즉시 alias만 바꾸지 않는다. 모든 중간 커밋이 독립검증되었다고 표현하지 않고 최종 통합본을 출시 기준으로 삼는다.
- 고유 파일은 지시서별, 여러작업이누적된공유 연결은 책임을기록하여 통합 검토한다. 기존코드·기준·검증기록은유실없이보존. 공개 후보에서 비밀키·학생정보·원자료를재검사한다.
- T1 설정조합 및 ON/OFF 실패·redirect. T2 전체/타입/lint/구조/요청캐시/빌드/공개소스. T3 Preview/Production 정확SHA·로그인/읽기/캐시활성·환경분리. 미실행은통과로취급하지않는다.
- 복구: 해당CANARY=0와재배포 또는기본OFF 소스커밋. 전체문제는이전정확Production으로보통복구배포. force-push/DB역변경/배포보호해제없음.
- 공식근거: [Git 배포](https://vercel.com/docs/git), [환경별 재빌드](https://vercel.com/docs/deployments/promoting-a-deployment). 스킬 권장 promote는환경이같을때만적용, 이번은별도Production빌드.
