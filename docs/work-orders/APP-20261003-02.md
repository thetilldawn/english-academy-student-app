# 과거 문항의 안전한 참조 전환·부분 복구

M08-A에서 발견한 M02의 누락을 보완한다. 승인된 M08-R2/R3/R5의 실행 도구이며 학생 기능이나 업무 정책을 추가하지 않는다. 원 지시와 OPS-20261003-01의 읽기 기준선이 입력이다. 공용 범위/구성/검토자료 이전은 별도 보완과 명세로 이어가며 이 문항 도구로 완료를 대신하지 않는다.

## 요구와 검사

| 요구 | 합격 기준 | 검사 |
|---|---|---|
| R1 | 과거 배정·응시·출처 문항의 고유키·당시 표시값·선택 뜻을 보존하고 본문을 비우기 전에 참조 후보와 전수 비교 | T1/T2 |
| R2 | 파일 사본의 원행 확인값을 검사한 명시적 작은 배치만 전환. 중단/같은 요청 재실행/원행 변경을 구분 | T2/T3 |
| R3 | 복구는 같은 참조와 허용 본문 열만 보충. 이후 답·점수·접수·정책·오답·포인트를 덮어쓰지 않음 | T4/T5 |
| R4 | 진행·재시험·새 규격 미접수·개인 오답 자료는 제외. 학생→배정→응시→문항 잠금과 권한 유지 | T5/T6 |
| R5 | 실제 과거 스키마에서 만든 가짜 입력으로 파일 재읽기·공용 읽기·기존 답 재요청 검증. 운영 변경0 | T1/T4/T6 |

## 결정

- D1 사용자 확정: 기존 학생 기록과 출처/선택 뜻/발음을 보존하며 중복 본문만 줄인다. 유지보수 완료 지시와 M08-R1~R5가 근거다.
- D2 사용자 확정: 진행 시험은 원래 기기, 기한 내 저장한 답의 늦은 제출 허용, 접수 미확인 답 자동 삭제 금지. 이 도구는 새 규격 응시가 연결된 배정을 전부 제외한다.
- D3 내부 설계: 연결 준비는 작은 참조/확인값만 별도 표에 기록하고 원행은 그대로 둔다. 준비 단계에서 기존 finalize 함수를 호출하지 않고 개별 등록·해결 함수로 당시 내용을 비교한다. 뜻은 이전 직전의 기존 해석을 고정하고 새 자료의 뜻을 소급 채택하지 않는다.
- D4 내부 설계: 전환은 파일 사본을 다시 읽어 전달한 원본문의 DB 확인값, 준비된 원행/내용판, 현재 보호 상태를 모두 확인한 뒤 실시한다. 기본25/최대100행의 명시적 원행키 목록이며 최대ID를 커서로 사용하지 않는다. 반복 전체 후보 조회로 늦은 확정/변경행을 다시 찾는다.
- D5 내부 설계: 복구는 참조를 끊지 않고 검증된 당시 본문 열만 되살린다. 같은 참조의 읽기값과 정확히 같은 본문만 허용한다. 답 열을 포함한 전체행 복원·전체DB 복원·트리거 중지·세션 설정으로 보호 우회는 없다.
- D6 내부 설계: 운영자 전용 private 함수와 원행/현재거래/변경전후 확인값에 묶은 일회성 허용을 사용한다. 공개/학생/관리자/서버 역할은 실행 권한0, 새 공개 API/UI는 없다. 준비와 전환/복구는 모두 같은 운영 잠금을 학생 잠금보다 먼저 잡아 한 거래의 준비→전환과 다른 운영 거래 사이의 교착을 막는다. 중복 요청은 불변 완료 기록을 돌려주며 다른 내용의 같은 요청은 거절한다.
- D7 내부 설계: 배정이 닫힘/삭제됨/기한종료 상태이고 연결 학생의 진행/재시험/미시작 준비가 없으며 M04 결과정책과 M05 기기전송 응시가 없는 구형 배정만 문항 정리를 허용한다. 복구 또한 같은 잠금 순서를 따르되 이후 새 답을 사본에서 복원하거나 수정하지 않는다. 원래 새 기록이 진행된 상태라도 같은 내용의 본문 보충은 가능하다. 배정 잠금 뒤 학생 집합 변경은 재시도하고 이미 참조된 연결 응시의 참조도 후보와 대조한다.
- D8 내부 설계: 가짜 사본은 자료 구역의 접근 제한 폴더에서 파일로 저장/재읽기하고 Git에는 확인값·수량만 기록한다. 실제 운영 사본은 M08-B 실행 직전 별도 확보/대조하며 가짜 복구 결과로 실제 운영 사본 확보를 주장하지 않는다.

## 자료와 영향

자료 흐름: 종료 대상 확인 → 원문 사본 읽기 → 참조 후보 준비 → 원본문/새 읽기 비교 → 사본 확인값을 동반한 짧은 전환 → 현재 답 보존 비교 → 파일에서 당시 본문만 부분 복구.

변경: DB 내부 도구·보호 트리거의 정확한 허용 경로·저장 제약·가짜 통합검사. 확인만: 기존 문항 해결/학생 인증/결과·오답/전송·캐시. 해당 없음: 경로·UI·상태·CSS·새 문구·브라우저 네트워크. 운영 실패는 SQLSTATE와 작업 식별자로 구별하고 실제 원문/비밀을 앱 오류에 연결하지 않는다.

사본 도구 `scripts/historical-question-archive.ts`는 DB/통신 없이 저장소 밖 파일을 새로 저장하고 fsync→재읽기→SHA 대조가 끝난 자료만 전환 인수로 돌려준다. 실제 학생 자료는 이 파일에 내장하지 않는다. 기능 지도 입력의 변경으로 과거 검증 지문에 연결된 기존 배정 화면 검사·자료 목록 검사·학생 정보 규칙/검사 4개는 T6 전체 회귀로 다시 확인하며 제품 내용을 수정하지 않는다.

## 검사 상세

- T1: M02 적용 전 가짜 관리자1·학생2·4단어 및 종료/진행/재시험/미시작 자료. 새 SQL 후 원행·FK·당시 뜻·출처·학습/문항 응답 일치.
- T2: 준비 단계 본문 보존, 2행씩 제한 배치, 동일 참조 재사용, 잘못된 출처/본문 거절, 기존 개인 오답 문항 제외.
- T3: 파일 확인값·대상키·현재 원행 불일치, 중간 취소, 같은 요청/다른 요청, 늦게 확정된 낮은키 재탐색. 실제 두 연결은 OPS에서 별도 실행한다.
- T4: 파일 사본 실제 재읽기 후 지정 본문 복구, 다시 복구 동일, 참조 유지, 복구 직전 새 답/결과/오답/접수/포인트 전열 불변.
- T5: 진행/재시험/새 정책 응시/준비/다른 학생·변경판 거절. 직접 UPDATE/가짜 세션 설정/역참조 변경 거절, 일반 신규 저장의 본문 중복 제거 유지.
- T6: 익명/로그인/서비스 역할 실행 거절, 트리거/제약·기존 실패 의미 유지, 기존 SQL 회귀·타입·구조 검사. 동시 호출/실제 검토 DB 반영은 별도 명세 뒤 검증한다.

이 보완만으로 M08 전체 또는 운영 용량 회수를 완료 표시하지 않는다.
