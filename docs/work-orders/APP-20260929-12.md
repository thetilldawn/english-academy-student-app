# APP-20260929-12 — 학생 오답 자율연습

입력: 승인된 순차 계획, APP10 공통 집계, APP11 내 단어장. 미결정0. 로컬 구현 단계이며 외부 적용은 DEPLOY03에서 검토 환경→운영 순서로 진행한다.

## 요구·결정

- R1/D1: 선택 단어 또는 현재 조회 조건 전체를 서버에서 확인해 연습한다. 화면 첫10개를 전체로 취급하지 않는다. 기존 뜻 4지선다 출제 계산을 재사용한다. 문항1~500, 방향0/50/100, 전체30~10800초·문제당5~600초·무제한에서 선택한다. 부족/제외 이유와 실제 연습할 단어를 미리 보여준 뒤 시작한다.
- R2/D2: 연습 회차/문항을 private 별도2표에 저장한다. 정규 배정·응시·누적 오답·복습/배정 큐·포인트는 변경하지 않는다. 세션의 본인만 접근하며 비활성/삭제 학생·다른 학생 요청을 거절한다. 별도 연습 내역으로 진행 중 재개·결과·다시 연습을 제공한다.
- R3/D3: 과거 오답 원문·뜻·출처를 보존한다. 보기 후보는 대상 출처 책의 검토된 어휘에서 얻고 기존 의미 충돌 검사를 거친다. 현재 보기 검토 정책이 과거 뜻과 맞지 않으면 그 단어를 제외 이유로 표시하며 임의 정책 삭제/추론을 하지 않는다. 기존 발음/음원 조회만 재사용한다.
- R4/D4: 미리보기 확인값은 학생·원천·조건·설정·실제 문항을 묶는다. 시작의 동일 요청 재전송은 기존 결과부터 확인하고 같은 키의 다른 요청은 거절한다. 새 시작에서 원천 변경을 다시 확인해 다르면 미리보기로 돌아간다. 생성 문항과 정답은 브라우저 입력을 신뢰하지 않는다.
- R5/D5: 기존 QuizPlayer의 답 선택100ms·음성·복구를 복제하지 않고 읽기/답/전환/만료/결과 경로만 주입한다. 기본 정규 경로는 그대로 둔다. 연습은 첫 풀이만이며 정규 재시험 단계로 전환하지 않는다. 전체 시간은 문항 전환마다 초기화하지 않는다.
- R6/D6: 서버 시각·행 잠금·답 중복 보호. 7초 피드백 예약과0~750ms 조기 전환, 전체시간 미사용 예약 회수, 문제당 한도 및 전체3시간 상한을 유지한다. 무제한은 별도 무한 마감. 만료 전 강제 만료 거절, 동일 답 재전송은 같은 결과, 다른 답 덮어쓰기 금지. 미응답 정답/출처 뜻은 응시 응답에 넣지 않는다.

## 구조

`quiz-player`가 연습 계약·출제·저장·표시와 전송 교체를 소유한다. `students`의 공통 오답 집계/기존 발음 연결을 공개 서버 경계에서 재사용하고 `student-dashboard`에는 시작 폼 진입만 둔다. 새 업무 전체를 클라이언트로 옮기거나 기존 정규 명령을 조건문으로 분기하지 않는다. page/route는 인증·검증과 기능 호출만 한다. 개인 응답 전부 private/no-store. 생성·답·전환·만료는 same-origin 검사 및 서비스 전용 RPC, RLS·빈 search_path·PUBLIC/anon/authenticated 직접 실행/표 접근 금지다.

SQL은 추가 마이그레이션 `20260930034455_add_student_word_practice.sql` 한 건이다. 예전 정규 표·트리거·함수의 의미는 바꾸지 않는다. 지원 가능한 조회 한도를 넘으면 명시적 오류로 범위 축소를 안내하고 조용히 잘라내지 않는다. 연습 포기/삭제·포인트·새 채점 유형·정규 자동 배정은 범위 밖이다.

선택 조회는 공통 집계 v3의 단어 키 필터를 사용한다. 전체 누적이10,000개를 넘더라도 선택1~500개는 전체 페이지를 순회하지 않고 한 번에 읽는다. v2는 키 필터가 없는 v3로 위임하고 기존 전체 JSON 응답을 보존한다. 조건 전체 조회만10,000개 상한을 명시한다. 기존 코드를 고치지 않고 재사용하게 된 조회·발음·시험 부품도 이번 의존 범위에 등록하며 이전 검사 기록은 역사 근거로 유지한다.

연습 내역은 시작 시각/식별자 기준 최신순10개와 다음 페이지다. 커서는 학생 식별자를 포함하며 현재 세션과 다르면 DB를 읽기 전에409를 반환한다. 화면은401/403/409에서 옛 목록과 커서를 비우고 새 문서로 이동한다. 일시503은 기존 목록과 같은 재시도 요청을 유지한다. 시작 성공 여부가 불명확하면 새 요청키를 만들지 않는다.

## 화면 상태와 검사

- 로딩/다시조회: 해당 영역 대기와 입력 보존. 미선택/조건0개: 시작 불가. 검증 실패: 문항 수·출제 가능 수 표시. 원천 변경: 새 미리보기 요청. 저장 응답 유실: 같은 요청키 조회/재전송만 제공. 인증 실패: 개인자료 숨김·처음 이동. 없는 회차:404와내단어장 이동. 예상외 오류: 짧은 오류+실제 재시도. 설명을 상시 늘리지 않고 필요할 때만 이유를 보여준다.
- T1 순수계산/계약: 0/1/3/500/501, 홀수50%, 보기부족/정책불일치·과거뜻·결정적 문항/확인값·조건전체.
- T2 실제 최종 가짜DB: 본인/타인/비활성·실제SET ROLE, 시작중복/다른요청·원천변경·동일/다른답·중단/재개·시간/전환·정답비공개, 정규 관련표 전후불변.
- T3 HTTP/화면부품: 위조학생/불명필드/다른출처·오류no-store·same-origin, 전송객체4종/결과주소 주입과 정규 기본 회귀, 100ms 마지막입력·유실복구.
- T4 격리브라우저: 목록 선택→설정/미리보기→가짜연습→결과→다시연습, 조건전체/0개·중단재개, PC/모바일. 실제학생쓰기 금지.
- T5 전체타입/lint/검사/지도/빌드·독립검토. 실제 실행·한계·확인값을 별도 검증기록에 남긴 뒤 완료한다.

복구: 이전 코드로 복귀해 추가 연습 표를 사용하지 않는다. 새 연습 기록을 삭제하거나 정규 기록으로 변환하지 않는다. 외부 반영은 명세·권한·보존 대조를 별도 확인한다.
