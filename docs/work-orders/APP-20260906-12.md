# 내역 첫 페이지 캐시

- 기존 캐시 계획 3단계의 내역 확대다. 학생·배정 완료 근거는 APP08/10, 내역 중복 조회는 APP11에 보존한다.
- R1: 첫 목록만 15초 재사용/60초 표시상한/120초 비활동 폐기. 검색/상태별 분리하고 더보기는 저장하지 않는다.
- R2: 학생 캐시의 세션·취소·진입 수명만 공통화한다. session 기능의 브라우저 책임을 명시적으로 넓히되 서버 인증은 lib/auth, 내역 규칙은 history, 현재 포인트는 students가 소유한다. Client 이동에서는 오래된 SSR자료를 새 인증으로 쓰지 않는다.
- R3: 수정·숨김·취소 성공 시 공용 변경 신호를 한 번 낸다. 캐시 ON의 구역별 mutation 조회는 끄고 첫 목록 한 번으로 교체한다. 기존 DB 영수증 최소시각과 더보기/커서 폐기를 보존한다.
- D1: 사용자가 기존 캐시 먼저·단어 가리기 마지막으로 확정했다. D2~D4: 위 책임 분리/변경 소유/기본OFF 실험은 비용·업무·DB를 바꾸지 않는 내부 설계다. 미결정 없음.
- 초기 로딩은 해당 영역만, 정상0은 없음 안내, 조회실패는 실패/재시도, 인증실패는 개인 자료 숨김+로그인 안내다. 기존 쉬운 오류 카탈로그를 재사용하며 오류 원문을 표시하지 않는다.
- 생성/배정/응시/삭제 규칙·출제자료는 변경하지 않는다. 기존 변경 성공 지점만 읽기 무효화에 연결한다. 개인 내역은 공유 서버 캐시/브라우저 영구 저장에 넣지 않는다.
- T1 시간·세대·조건·공동취소/학생 회귀. T2 실제 부품·API·변경/권한/정답 노출. T3 전체·타입·lint·구조·빌드. T4 가짜 localhost 최초/실제 Link 각각10회 OFF/ON. 30% 왕복 개선·최초10%이내·인증뒤100ms 관문을 수치와 한계로 기록한다.
- 복구는 내역 스위치 OFF. 운영 반영은 최종 통합 검증과 별도 배포 단계에서 다룬다.
- D7: 최초 10회 편차 확인 뒤 OFF/ON 모두 준비 1회+측정 40회로 확장했다. Link 왕복은 준비 1회+측정 10회다. 예비·동시검사 부하·이상치를 전부 보존하고 최초 중앙/p95, 왕복 중앙, 현재 인증 뒤 표시 관문을 통과해 로컬 채택한다. 공용 서버 캐시는 큰 반복 공용조회 근거와 모든 변경 경로의 버전 연결이 없어 기존 계획 4단계에 따라 비채택한다.
- D5: 더보기400으로 거절된 커서는 캐시에서도 폐기하고 현재 진입표를 교체해 첫 목록을 한번 읽는다. 복구 성공/실패 뒤 왕복해도 옛 커서를 되살리지 않으며 표시 상한을 0으로 풀어둔 채 두지 않는다. 자동 저장/삭제 재실행은 없다.
- D6: 변경 알림 보내기/받기를 분리한다. DB쓰기 검사기가 로컬 Map.delete도 DB삭제로 판단하던 오탐은 실제 const native Map/Set 식별자 연결만 구분해 보완한다. 이름 예외/DB 호출 허용을 추가하지 않으며 DB·unknown·let·imported/동명이름가림의 탐지 유지 검사를 추가한다. 이 검사가 보안 완전성을 증명하지는 않는다.
- 공식 문서 근거: Next.js 인증 안내의 레이아웃 재사용과 데이터 접근 시 현재 권한 검사, Router Cache 설명을 확인했다. 최신 웹 문서는16.3.4이므로 새 API를 도입하지 않고 설치된16.2.12의 headers/서버데이터 직접읽기/기존 Client 수명만 사용한다.
