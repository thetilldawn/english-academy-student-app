## 자료와 요청

기존 level(all/once/repeated) 유지. all에서만 minWrongCount/maxWrongCount 선택, 양의 정수 최대2147483647, min<=max. 같으면 정확횟수, min만이면 이상. query 최대200. 학생 요청에 studentId 허용하지 않는다. cursor는 학생/전체 필터와 오답 이벤트 상한/정확 시각/키에 묶고 UI가 새로 학생 ID를 정하지 않는다.

공유 SQL은 현재 original 우선순위와 initial 사건 수를 유지한다. 관리자 v1 원문 보존, v2는 관리자 인증 wrapper. 학생은 기존 자체 세션에서 server가 ID를 결정하고 service_role 전용 읽기를 호출한다. private 집계는 invoker, 관리자 wrapper만 기존 관리자 정책상 definer가 필요하다. 순수 문자열 helper의 서비스 실행권한 외 일반 authenticated/anon 권한 확대 없음.

학생 응답은 key/headword/primaryMeaning/wrongCount/lastWrongAt와 학습 출처 최소값, 전체 누적 summary, 현재 totalCount/datasetOptions/nextCursor다. 기존 관리자 summary의 미해결 의미는 유지한다. 관리 초안/예약/배정 ID/응시·문항 ID는 제외한다. 서버 query는 server-only로 public-server, 공통 계약은 public-contracts로 공개한다.

초기/필터/더보기는 같은 쿼리. DB11행→화면10개, 최초에만 요약/전체수. 조건은 DB 전체에서 적용한다. eventUpperId는 이벤트 경계이며 해결 상태 전체의 완전한 고정 스냅샷으로 주장하지 않는다. SQL 추가→앱 적용 순서이며 외부 적용은 DEPLOY에서 별도 검증한다.

## 영향과 상태

화면/CSS/라우팅 페이지/쓰기/생성/배정/삭제는 이번 단계 없음. HTTP/공통 필터/기존 목록키/SQL 읽기만 변경. 신규 화면 상태를 구현하지 않으므로 UI 상태표·브라우저 검사는 APP11로 연결하고 여기서는 실제 HTTP 문구/기존 hook 회귀를 검사한다.

성공/오류 private,no-store. 서버 공유 캐시 없음. 기존 legacy 커서해시 보존, 확장 횟수는 공통키 포함. 정규 응시/포인트/학생행/사전은 읽기 전후 그대로여야 한다.

Route는 현재 세션을 한 번 확인하고 서버 전용 조회에 그 세션을 전달한다. RSC가 조회를 직접 쓸 때는 조회 내부가 인증한다. React cache가 Route Handler의 두 호출을 합친다고 가정하지 않는다. 전달 가능한 값은 서버가 검증한 전체 StudentSession이며 HTTP 요청의 학생 식별자는 거절한다. 검색 초안의 조건키 계산은 예외를 내지 않고, 잘못된201자 입력은 전송 경계에서 안전한 안내로 거절한다.
