# APP-20260908-02 학생 화면 정상화

## 확정 범위

[전체 검토안](../20260908_학생과_배정화면_개선_검토안.md)의 R01~R05. 사용자가 2026-09-08 후속 ㄱㄱ로 순서와 질문 답을 승인했다. 현재 상태/순서는 루트 대장만 소유한다. [R/D/T 검사 기록](../../architecture/work-records/records/APP-20260908-02.json)이 요구·설계·검사를 연결한다.

| 요구 | 완료 기준 | 검사 |
|---|---|---|
| R1 배경 목록 | 상세 왕복으로 DOM/필터/스크롤/요청 유지 | T1,T6,T7 |
| R2 상태 구분 | 로딩 위 옛 오류0, 실패/0건/404 구분 | T1,T3,T6,T7 |
| R3 프로필 저장 | 폼→Action 연결, 초안/충돌/결과불명 복구 | T2,T3,T4,T7 |
| R4 학교/학년 | 학생 상단·관리자 내역 최소 필드 연결 | T4,T5,T7 |
| R5 내역 연결 | 배정 이름→공용 내역, 체크 선택과 분리 | T4,T7 |

## 설계·결정

- D1 사용자 승인: 학생 화면→공용 입력/배정 표시→학교 검색/단어장 찾기. 실제 학생 변경과 새 운영 배포는 제외.
- D2 내부 결정: Next16.2.12 보호 layout의 children 슬롯을 안정적인 문자열로 비교한다. @detail 열기/닫기는 목록 이동이 아니다. ticket 생성과 요청 취소를 함께 수정하며 실제 이동/복귀/계정/저장 후 갱신은 유지한다. 로컬 화면 검사에서 60초 뒤 배경 목록을 제거하는 기존 설정도 확인했다. 배정과 학생 관리 모두 현재 인증 ticket의 마지막 성공 목록만 유지하고, 60초는 중립적인 신선도 안내/수동 갱신으로 분리한다. 15초 읽기 재사용·120초 미사용 제거·내역의 60초 표시 상한은 유지한다. 새 ticket에 옛 성공을 붙이거나 401/403 후 목록을 복원하지 않는다.
- D3 내부 결정: 서버 마이크로초 버전 문자열을 그대로 보존한다. 인증 장애503/미인증401 구분. 네트워크·잘못된 성공 응답은 결과불명 처리 후 먼저 읽어서 확인한다. 입력 보존, 자동 재전송 금지. 실제 운영 저장 실패 원인은 아직 미확정이며 시간 문제라고 단정하지 않는다.
- 기존 학교/학년만 최소 전달. 학생마다 상세 조회를 추가하지 않는다. 생성·시험·삭제·채점·공개 업무는 그대로이며 공용 내역/배정 진입만 연결한다.

## 상태·복구

입력 오류는 입력 부근, 조회 실패는 영역 안, 저장 안내는 모달 안에 남긴다. 재조회 중 옛 만료 오류를 숨긴다. 저장 결과불명은 “저장됐는지 확인하지 못했습니다. 입력은 유지했습니다. 저장 결과를 먼저 확인해 주세요.”와 확인 버튼을 사용한다. 401은 개인 자료 잠금/로그인, 없는 학생404, 성공0건은 빈 내역. 예상외 오류의 내부 원문 비노출.

## 검사·금지사항

관련검사→전체/구조/기록/타입/lint/빌드(T8)→필요한 로컬 실제화면(T7). 개인정보·정답·인증·캐시 보호 검토를 포함한다. 과거 결과를 현 코드 증거로 재사용하지 않는다. 김우용 등 실제 학생은 읽기만, 저장은 가짜/테스트 학생만. 새 배포 완료를 미리 선언하지 않는다. 복구는 APP02 변경만 선택 복구하며 자료 원본/실제 시험은 손대지 않는다.

## 목록용 학교 필드 변경 검토

새 migration은 기존 내역 함수의 목록 JSON에 이미 조회한 학교·학년 2개 필드만 추가한다. 학생 삭제 시 null 처리, 소유자·실행 권한·security invoker·빈 search_path를 보존하고 조건 불일치/중복 적용은 전체 중단한다. 학생별 추가 조회와 데이터 쓰기는 없다. 독립 Preview 정의 조회에서 교체 구간1·기존 열 존재·권한 보존 전제를 확인했다. 로컬 축약 함수 통합검사는 실제 전체 조회 함수 검사와 구분한다. 원래 함수 정의를 적용 전 근거로 보관한 뒤 선택 복구할 수 있으며 운영 적용은 별도 배포 판단이다.
