## 요구와 완료 조건

- R1: 범위별 수록 개수와 선택 합계를 즉시 표시한다. 실제 출제 가능 수는 현재 서버 계산만 사용하고 희망 회차당 입력과 구분한다. 미선택/대기/실패/정상0을 구분하며 미확정 칸의 focus만으로0/직접모드가 저장되지 않는다. T1/T2/T3/T5.
- R2: 모바일의 짧은 범위명은2열, 긴 범위명은1열 카드. 읽기 좋은 글자·44px이상 조작·선택체크/테두리·전체 이름·선택 요약을 사용한다. 모바일 세로 스크롤을 가로drag로 가로채지 않는다. T2/T5.
- R3: 단일·일괄·수정의 같은 범위 부품과 좁은 수량 부품을 보완한다. 순서/역방향/수량 상한/회차/저장·인증은 불변. 새요청/공유캐시0. T1/T2/T3/T4/T6.
- R4: 최종 로컬 검사→가짜 자료 실화면→같은 코드 Preview→Production 순서. 환경별 DB를 섞지 않고 실학생 응시/배정 저장없이 읽기 검증. T4/T5/T6/T7.

## 결정

D1 사용자가 위 개선안과 운영 반영 승인. D2 수록metadata와 현재preview의 역할 분리, 미확정focus 무동작/실제typing만 수량전환. D3 기존Button/Field/CSS의 모바일 카드, 실제 가로넘침이 없으면drag사용안함. D4 Git 기능브랜치 Preview와 main Production 재빌드를 사용하며 Preview DB환경을 운영주소로 승격하지 않는다. D2~4는 기존 업무를 바꾸지 않는 내부 결정이며 미결정0건이다.

## 실제 연결과 영향

- 기존 단위 조회 → AssignmentUnitRangePicker → DayRangeRail, 표시문구/수록 합계는 presentation/assignment-unit-range-label. 단일·일괄 VocabRangeFields와 기존 수정 AssignmentRangeFields가 재사용.
- VocabQuestionSection → vocabQuestionView(현재 bulk.preview + 미선택/대기/실패상태) → VocabQuestionFields/AssignmentWordCountField. 원시 state.preview.value의 과거 수치를 가져오지 않는다.
- UI/상태/비동기안내/스타일/검사 변경. 경로/서버/계약/DB/핵심계산/인증/캐시 확인만. 생성·배정·수정의 최종 저장계약은 그대로며 응시·조회API·검색·삭제·DB기록은 표시수정에 해당 없어 변경하지 않는다.
- 최초/갱신: “출제 가능 단어 수를 확인하는 중입니다.” 수록 합계와 입력 보존. 미선택: “시험 범위를 선택해 주세요.” 정상0: “출제 가능0개”. 실패: “출제 가능 단어 수를 확인하지 못했습니다. 다시 시도해 주세요.” 조건미완성은 별도 안내. 실제 FieldError/기존 재시도와 연결; 로그인실패는 기존자료숨김·404/저장오류/예외 경계는 유지한다.

## 검사와 복구

T5의 긴 카드 실화면 검사를 위해 기존 격리 가짜 자료의 마지막 범위 이름만 긴 예시로 바꾼다. 5범위/100개, 로컬 가짜 계정, 외부 연결·쓰기 거절은 유지하며 보호 검사에 이름/개수 확인을 추가한다. 실제 앱 자료는 변경하지 않는다.

기존 수정 화면 assignment-range-fields는 수록 합계 helper를 재사용하는 범위만 변경한다. 전체 제어기/초안 의존과 추천 계산은 아직 후속 분리 대상으로 유지하고, 역할을 승격하지 않는다. 의존 목록과 검토 소스 지문만 갱신한다.

로컬 T3에서 공통 배정 오류 변환이 503 응답의 내부 원문을 화면에 보내는 것을 재현했다. R1의 실패 안내 보완으로 5xx와 미분류 응답은 요청별 쉬운 기본 안내를 사용한다. 입력 검증(400/422), 권한·자료 없음·충돌의 기존 복구 분류는 유지한다. application/assignment-operation-error와 assignment-flow.test를 범위에 연결하고 T3의 실제 단일/일괄 재시도→정상 수량→늦은 응답 무시, T4 공통 흐름 검사로 확인한다. 업무 규칙이나 서버 계약을 바꾸지 않는 내부 안전 보완이다.

T1 표시/합계 단위검사, T2 좁은UI/카드/터치/미확정focus, T3 실제 단일/일괄 및 현재성·인증 회귀, T4 지도/역할/전체 및 독립검토, T5 로컬 모바일/PC, T6 타입/lint/최적화빌드, T7 Preview·운영 실제 읽기와15분후 확인. [R/D/T](../../architecture/work-records/records/APP-20260907-02.json)와 [실행기록](../verification/APP-20260907-02.md)에 결과·해시·한계를 연결한다.

정상 배정 작성/학생읽기가 실패하거나 현재학생 밖 자료가 보이면 운영 적용을 중단/복구한다. 앱 릴리스만 이전 검증 코드로 복구하며 DB/실제시험/팀/계정/요금은 건드리지 않는다. 기존 CI 사전 배포대조 실패는 숨기거나 보호조건을 완화하지 않고 실제 확인과 구분한다.
