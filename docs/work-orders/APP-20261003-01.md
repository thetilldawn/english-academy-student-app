## 결정

- D1 사용자 확정: 네 종류와 자유 설명 분리, 명확하지 않은 기존 자료는 분류 확인. 이름과 명시적 종류만 새 작성의 최소 필수이며 학교/학기/평가명은 기존 선택 조건 유지. D14 및 사용자 유지보수 지시가 근거다. M07에 미결정은 없다.
- D2 사용자 확정: 자료 혼합·과거 판·범위 미정 틀·학생 기록 보존. 종류만 바꿨다고 원자료 종류나 내용판을 바꾸지 않는다. M07-R2/R4와 기존 D10이 근거다.
- D3 내부 설계: 기존 metadata의 엄격한 8개 키와 purpose 문장은 유지한다. 템플릿에 nullable template_kind를 추가하고 새 저장 v3의 templateKind로 받는다. 네 값은 performance_assessment/exam_prep/mock_exam/other다. null을 기타로 치환하지 않는다. 기존 v1/v2 요청과 완료 영수증은 원형으로 보존하고 기존 편집이 새 공식 종류를 지우지 않게 한다.
- D4 내부 설계: 새 저장의 전체 요청(규격/공식 종류 포함) 확인값과 기존 동일 관리자/요청키 잠금·접수표를 사용한다. 같은 요청키의 다른 종류를 거절한다. 새 조회 v2·새 생성 요약 v3는 공식 종류를 필수 nullable로 응답한다. HTTP는 새 규격을 명시하여 구형 요청/응답을 계속 읽는다. 기존 materialize는 번호/내용판 멱등을 보존하되 표시정보는 현재 요약을 읽는 기존 계약이다. 저장 당시 표시정보 고정은 create/metadata/version/copy 완료 영수증에 적용한다.
- D5 내부 설계: 요약·종류 편집·범위 편집 상태를 분리한다. 종류 전환은 현재 이름을 고정하고 그룹/제외/순서/숨겨진 값을 보존한다. 실제 범위 변경 의도를 기록하고 명시적 이름/종류 수정은 저장판으로 처리한다. 미분류 자료의 변경 없는 사용과 기존 설명/범위 편집은 null을 보존해 허용한다. 새 만들기·복사엔 종류를 요구하며 이미 확정된 종류를 null로 지우지 않는다.
- D6 내부 설계: 목록 갱신 콜백과 실제 배정 선택 콜백을 분리한다. 표시 필드만 갱신하고 선택 단어장/문항 수/출제 방식/범위/열린 창을 유지한다. 저장 확정 뒤 목록 갱신만 실패하면 확정 결과로 콜백만 재시도한다. 개인 조회는 no-store, 관리자 변경·인증 실패·닫힌 화면의 늦은 응답을 버린다.
- D7 내부 설계: 현재 자동 분류 5본체(두 생성 내부 함수, metadata 동기화, 생성 요약 v1/v2)를 실제 최종 정의와 대조한다. M01 참조형과 삭제 보호 wrapper를 유지한다. 기존 생성 책의 표시 분류만 정확한 템플릿 연결로 동기화하고 원자료·문항·내용판·학생 기록은 변경하지 않는다. 순서대로 검토 DB에서 보존·권한·같은 요청/경합을 확인한다. Production 반영은 후속 M10이다.

## 흐름과 영향

소유 wordbook-compositions, assignments, shared-contract, database-contract, architecture-meta. 실행 흐름 mock-wordbook-compose와 assignment-workspace-planning을 중심으로 지도에서 실제 연결을 확인한다.

화면 → controller(초안/관리자/취소) → 엄격한 새 요청 → 관리자 인증·viewer 대조 → 새 SQL 거래/전체 요청 접수 → 새 요약 → 저장 목록과 배정 표시만 갱신. 원자료 범위 조회·M01 참조·기존 생성기·학생 배정/채점은 재사용한다.

변경: UI/state/domain/data/API/cache/asyncUi/styles/tests. 경로와 권한은 확인만: 기존 Route Handler·관리자 권한·private no-store를 유지하고 새 URL이나 교사별 공유 권한을 만들지 않는다. 학생별 운영 쓰기·본문 이전·음원 QA는 해당 없음이다.

## 검사 계획과 완료 기준

T1 네 종류 저장/새로고침/검색/배정 왕복. T2 자유 설명·null·구형 요청/완료 영수증 재전송과 create/copy의 종류 필수·기존 metadata/version의 null 보존. T3 직전대비 교과서+모의고사 혼합과 편집 중 연월만 노출. T4 탭 이동·이름/숨겨진 값/범위/순서 보존·수능 학년도. T5 20개 초과 서버 종류 검색과 커서/관리자 결합. T6 과거 판·빈 판·criteria=null·제외·범위 미정 틀 저장/재열기 가능과 실제 생성/학생 배정 불가. T7 저장 불명/충돌·취소/뒤로가기/계정 변경/늦은 응답·콜백 재시도. T8 표시정보만 바꿀 때 새 내용판 생성0·내용/문항/학생 결과 불변과 수량 의미. T9 PC/390px 가로 넘침0·키보드·닫기 후 포커스 복귀·reduced-motion·오류 위치/빈 결과/권한/404.

검증 단계: 설계 관문 → 관련 단위/DB/화면 검사 → 타입/lint/지도/화면 구조/전체 회귀/빌드 → 실제 화면 → 정확한 검토 DB 반영 명세/보존/권한 확인 → 독립 검토/완료 관문. 실제 결과가 없는 검사는 완료로 표시하지 않는다.

완료 증거에 네 종류 왕복 데이터, 옛 자료 변환 전후, 화면 예시와 분류 미확인 목록을 남긴다. 표시정보 편집은 기존 내용판을 읽는다는 뜻이며 내용판을 새로 만들지 않는다.

복구는 새 공식 종류 열과 저장 영수증을 유지한 호환 버전으로 한다. 구형 UI 표시 때문에 새 종류를 exam_prep으로 덮어쓰지 않는다. 운영 단어/학생 표 전체 복원이나 내용을 되돌리는 방식은 사용하지 않는다.

## 2026-10-03 검증 근거

[구현·검토 검증 결과](../verification/APP-20261003-01_검증결과.md)를 연결한다. 충돌 복구의 선택 판, 기존 수동 태그, 이름 다음 범위 편집, 표시한 저장 범위의 순서/제외, 저장 확정 뒤 콜백만 재시도까지 보완했다. 검토 DB의 정확한 변경/보존 범위와 실제 화면의 가짜 자료 경계는 결과 문서에 적었다. 운영 배포·자료 삭제·용량 회수를 완료했다는 뜻은 아니다. 상태·다음 우선순위는 루트 작업 대장만 따른다.
