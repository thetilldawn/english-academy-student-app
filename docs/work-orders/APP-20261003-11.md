# 시험 회차 목록의 중복 저장 축소

OPS-20261003-02 D7에 따른 같은 유지보수 보완이다. 최초 시험과 재시험의 고정 목록에 반복되는 문항 내용판 키·순서 객체를, 기존 응시 문항의 불변 키와 저장 순서로 복원한다. 준비 목록은 응시 문항이 생기기 전에도 필요하므로 이번 변경에 섞지 않는다. 상태와 순서는 루트 대장만 관리한다.

## 요구와 완료 조건

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 중복 목록 축소 | 신규 회차는 작은 표현을 쓸 때 문항 ID 목록만 저장하고 당시 내용판·순서를 정확히 복원 | T2 |
| R2 기존 시험 보존 | 기존 계획·준비·접수·답·점수·오답·포인트·함수 권한 유지 | T1/T4/T5 |
| R3 동일 응답과 원기기 재개 | 최초·재시험·늦은 제출·재접수·다른 시간대에서도 원래 내용/해시 유지 | T1/T2/T4 |
| R4 손상 거절 | 누락/중복/다른 응시 키·순서·내용판·시각·해시 변조와 잘못된 JSON을 거절 | T3/T4 |
| R5 실제 효과와 운영 구분 | 같은 보존 계약의 로컬/검토 DB 검증, 실제 측정 전 무료 인원 보장 금지 | T6 |

## 결정

- D1 사용자: 공용 키를 공유하고 배정·최초/재시험·오답·점수·포인트와 과거 기록을 보존한다. 유지보수 완료·계속 진행 승인과 OPS02 D7을 적용한다.
- D2 사용자: 풀이 중 서버 호출0, 종료 제출, 기한 안 기록한 답의 늦은 접수, 원래 기기 재개, 미확인 기기 답 자동 삭제 금지, 공용48시간/미사용 준비24시간을 유지한다.
- D3 내부: 신규 `plan`은 `storageVersion`, 순서대로 저장한 `questionIds`, 원래 서명에 들어간 `startedAt` JSON 문자열을 갖는다. 실제 `pg_column_size`가 원형 배열보다 작을 때만 이 형식을 쓴다. 기존 행은 변경하지 않는다.
- D4 내부: 새 내부 판독기는 기존 배열을 그대로 반환하고 새 객체만 엄격히 검사한다. 최대500개·정규 UUID·중복0·같은 응시·공용 내용판 존재를 확인하고 배열 순서로 원래 `id/order/contentId`를 재구성한다. 현재 오답 상태나 준비 행에서 재계산하지 않는다.
- D5 내부: 새 객체는 원래 `startedAt` 문자열의 절대시각이 `started_at`과 같고, 원래 규격/응시/회차/문항/시각/제한으로 계산한 전체 해시가 같아야 한다. 시간대별 문자열을 새로 만들지 않는다. 원래 문자열을 갖지 않은 구형 배열에는 이 새 해시 재계산을 소급하지 않는다.
- D6 내부: 기존 생성/읽기/신규 제출 검사/APP08 접수 복원 네 곳에 연결한다. 제출의 기존 원형 영수증 반환 순서는 유지하고 새 답 검사 직전에 계획을 복원한다. 저장 직전 원래 배열과 재복원 배열의 전체 JSON이 같아야 한다. 인증·학생→응시 잠금·시간/답 검사를 완화하지 않는다.
- D7 내부: 열·표·FK/UNIQUE·불변 트리거는 유지하고 plan 형식 CHECK만 두 저장판을 허용하도록 바꾼다. CASE와 최종 false 처리로 잘못된 타입이나 SQL NULL 우회가 없게 한다. 새 함수는 PUBLIC/anon/authenticated/service_role 직접 실행권한0이다. 쓰기를 되돌릴 때 생성기만 이전 원형 쓰기로 복구하고 두 형식의 판독기·CHECK를 유지한다.
- D8 내부: PGlite 최종 스키마·관련/전체 검사·기록 관문·작은 가짜 검토 DB를 검증한다. Windows initdb, 실제 학생 시험, 운영 DB 쓰기/배포/물리 재작성은 하지 않는다. 답 접수나 포인트를 삭제·합산하거나 보관기간을 바꾸지 않는다.

## 변경 영향과 데이터 흐름

기능 소유자는 quiz-player, DB 계약 검사는 database-contract다. 불변 응시 문항을 재사용하며 새 사전이나 두 번째 문항 저장소를 만들지 않는다. 회차 생성→원래 전체 배열·서명 계산→더 작은 저장판의 복원 검산→INSERT→읽기/최초·재시험 접수/옛 응답 복원으로 연결한다.

DB 저장·내부 판독/형식 검사만 변경한다. 경로·화면·스타일은 해당 없음이며 브라우저 상태·정답/순서 계산·공개 요청/응답·서버 인증·캐시·로딩/실패 안내는 확인만 한다. 생성·배정의 내용·뜻·발음과 검색·학생 삭제·기존 복구 도구는 유지한다. 준비 행이 교체·정리되어도 이미 끝난 시험 접수는 읽을 수 있어야 한다.

| 검사 | 실제 확인할 내용 |

새 화면은 없다. 실패 시 기존 “시험 자료를 준비하지 못했습니다. 연결 후 다시 열어 주세요. 저장한 답은 기기에 보관됩니다.”와 재확인 동작을 유지한다. 계정 확인·원기기 안내·접수 대기/완료 판정·401/404를 바꾸지 않으며 손상/조회 실패를 빈 시험이나 완료로 취급하지 않는다. 화면 문구와 각 R/T의 연결은 앱 기록에 고정한다.

## 근거와 분리

입력은 APP10 구현 be0c877/검증2f91000, 네 번째 M09 008dad5, 최종 스키마 직접 독자6개 중 본문 소비4개 조사와 독립 설계 검토다. 운영 결과나 무료 인원 확정은 별도 M09/M10/M08-B 근거를 따른다. 추가 발음 업무 WORD-20261003-01은 이 코드·커밋에 섞지 않는다.

2026-10-03 검사 실행 보완: 표준4작업자 전체 검사를 두 번 실행했으며, 기존 구성 자료 보존 검사 한 건이 기본5초 제한을 넘겼다. 이 사례는278단어/1,112원문문항 등록부터 구성·퇴역·배정까지 수행하며 APP11 변경 함수는 호출하지 않는다. 같은 파일24검사는 단독 재실행에서 변경 없이 통과했다. 대상631파일과 각 검사 제한시간을 그대로 두고2작업자 전체 검사로 자원 경합 여부를 확인한다. 검사 생략·제한시간 확대·제품 코드 변경은 하지 않는다.
