# 학교 일정 표시와 수동 입력

## 학생 상세 제목 배치 보완

R8 / D4 / T6: 배포 후 학생 상세에서 공통 모달 제목 행이 자식의 크기 격리 때문에 폭 0으로 줄어드는 문제를 발견했다. 제목 행과 제목 본체에 남는 가로 공간을 배정한다. 기존 이름 옆 시험 안내·좁은 화면의 위쪽 배치를 유지하며, 가상 학생 상세/일정 입력을 PC·태블릿·모바일과 두 테마에서 확인한다. 닫기·가로 넘침도 재확인한다. 데이터·API·업무 결정 변경은 없다. 이전 검증과 이후 보완 검증을 별도 기록한다.

## 요구와 결정

R1: 유형 태그를 왼쪽에 두고 대비를 높인다. 상단 학교 카드·미등록 수를 제거한다. 유형별 학생 수는 같은 학생이 여러 과제를 가지더라도 중복 계산하지 않는다.

R2: 기간이 겹치는 일정을 같은 날짜 묶음으로 나열한다. 가장 가까운 날짜 묶음만 펼쳐 강조하고 이후 일정은 펼쳐 볼 수 있다. 수행 초록·지필 노랑·수능 보라를 사용한다. 색 외에 유형 글자를 항상 표시한다. 이는 사용자의 '가장 가까운 하나'를 적용한 구현 기본값이며 후속 선택 답변을 반영한다.

R3: 수동입력과 날짜 확인 필요에서 같은 경로 모달을 열고 학교·학년별 등록 학생 수와 일정을 편집한다. 직접 주소·새로고침에는 동일한 편집기를 일반 페이지로 표시한다. 신규 일정과 날짜 미확인 일정 모두 처리한다.

R4: 수동 수정은 학교 원천과 분리하여 보존하고 최신 원천보다 우선한다. 다른 관리자나 원천 갱신과 충돌하면 초안을 유지하고 최신 기준을 다시 검토한다. 응답 유실 뒤 읽기로 저장 결과를 확인하며 자동 재저장하지 않는다.

R5: 학생 본인 일정과 관리자 개요·학생 정보가 같은 실제 표시값을 사용한다. 학생은 수동 입력 기능에 접근할 수 없고 관리자는 현재 활성 권한을 매 요청마다 확인한다.

R6: 학교 편제표에 따라 공통/지정 과목과 학생 선택 과목을 구분한다. 일괄 수강 확인 문구를 없애고 선택 과목만 태그로 설명한다. 특정 학교의 판단은 원천 데이터에서 적용한다.

R7: 교육부 공식 전국 수능 일정을 해당 달력 학년도의 고3에 제공한다. 시행연도와 수능 명칭의 학년도를 구별하고 확인하지 않은 다음 연도 날짜는 만들지 않는다. 가까운 시험 계산도 수능을 포함한다.

D1(사용자): 수행 초록·지필 노랑, 왼쪽 구분·태그, 겹친 날짜 한 칸, 수동입력 경로 모달, 수능 추가.
D2(구현 기본값): 가까운 날짜 묶음 하나 강조, 나머지는 펼침 목록. 수능은 별도 보라 태그.
D3(설계): 새 의존성 없음. Next.js 기존 경로 모달·RoutedDetailDialog·useRouteExitGuard·개인 캐시 변경 신호 재사용.
D4(설계): 원천은 불변, 수동 이력은 요청 ID·저장자·원천 기준 버전·수동 기준 버전·전체 일정값 보존. 같은 학교/연도/학기 잠금으로 저장과 원천 등록 직렬화. 수동본이 참조한 원천이 달라지면 관리자 편집기에 재확인 안내.
D5(설계): 원천 없는 학교도 학생의 공식 연결 학교키/학교급을 기준으로 수동 신규 입력. 학생 수·학교명은 서버에서 계산하며 브라우저의 표시값을 저장 권한 근거로 사용하지 않는다.

## 데이터와 경계

관리자 요청 → 인증 → 학교/학년 학생 수 조회 → 원천과 수동 이력의 실제 표시값 → 편집 초안 → 엄격한 검증 → 현재 관리자 확인 → 범위 잠금·버전 비교·요청 중복 확인 → 이력 저장 → 영수증. 학교 원문과 원문 해시는 수정하지 않는다. 학생 조회는 기존 본인 세션으로 같은 실제 표시값을 읽는다. 수능은 학교 원천과 분리한 공식 전국 공개 기준에서 고3에만 합성한다.

학교 원천·학생 식별자·실제 운영 수는 공개 코드에 넣지 않는다. 공개 검사는 가짜 학교와 학생을 사용한다. HTTP/서버 공유 개인 캐시를 추가하지 않는다. 저장 성공은 일정 화면 갱신 및 기존 학생 목록 개인 캐시 무효화로 전달한다. 입력 중 router.refresh로 초안을 덮지 않는다. 인증 실패 시 입력·학교 내용을 숨기고 로그인으로 연결한다.

## 화면 상태와 복구

처음에는 학교를 선택하고 기존 일정 또는 새 일정을 고른다. 일정 없음은 조회 성공일 때만 표시한다. 날짜 미확인·주차·월은 임의 날짜를 만들지 않는다. 불러오기 실패는 재시도, 입력 오류는 항목 안내, 저장 실패는 초안 보존, 충돌은 최신 기준 불러오기 후 재검토, 응답 유실은 저장 결과 확인으로 복구한다. 미저장 닫기·뒤로가기·다른 학교 선택은 기존 이탈 확인을 사용한다. 저장 중과 결과 불명 상태에는 중복 저장을 막는다.

## 검증 계획

T1 단위/컴포넌트: 겹친 기간·학생 중복 집계·가까운 묶음·초록/노랑 태그·학교 카드 제거·고3 수능·지난 일정/학년도 경계.
T2 DB 통합: 관리자만 저장, 원천 보존, 원천 없는 학교 신규, 동일 요청 재실행/다른 내용 거부, 버전 충돌, 새 원천 뒤 수동 우선, 직접 테이블 권한 금지.
T3 서버/클라이언트: 입력 검증·인증·충돌·저장 결과 읽기·초안 보존·학생 캐시 갱신·미저장 이탈.
T4 화면: 개요의 두 진입점, 모달 닫기/뒤로/앞으로, 직접 주소·새로고침, 좁은 화면과 가로 넘침.
T5 정적/빌드: 기능지도·설계 기록·경계·TypeScript·lint·빌드 및 독립 검토.

## 공식 참고

[Next.js 경로 가로채기](https://nextjs.org/docs/app/api-reference/file-conventions/intercepting-routes), [Supabase DB 함수 권한](https://supabase.com/docs/guides/database/functions), [PostgreSQL 잠금](https://www.postgresql.org/docs/current/explicit-locking.html)을 확인했다. 설치 버전은 바꾸지 않는다. Supabase 변경 이력의 markdown 주소 실패 후 공식 HTML에서 확인했으며 기존 함수 방식과 충돌하는 변경은 발견하지 않았다.

## 호환과 되돌리기

기존 학교 읽기 API 응답의 원천 묶음 구조를 유지한다. 새 수동 이력을 조합한 출력에도 원본 출처 해시를 수동 입력 해시라고 주장하지 않는다. 수능은 학교 등록 계약과 구분한 화면 계약으로 확장한다. 이전 앱은 새 수동 입력 화면을 사용하지 않으며 SQL 적용 전 앱 기능 활성화를 하지 않는다. 문제 시 이전 앱으로 되돌리고 수동 이력은 보존한다. 기존 학생·배정·시험 기록 변경은 없다.

## 저장 후 탐색 검토

실제 가상 화면에서 저장 후 개요는 갱신되지만 앞으로가기 편집기의 초기값이 남는 문제를 확인했다. 설치된 Next.js16.2.12에서 Server Action의 refresh()를 사용하여 성공 영수증 확인 뒤 탐색 보관값도 갱신한다. 실패·미확정 결과에는 적용하지 않는다. 공식 [refresh 안내](https://nextjs.org/docs/app/api-reference/functions/refresh)와 설치 코드를 대조했고 실제 뒤로/앞으로가기·직접 주소·새로고침을 검사한다. 색상은 공용 token/theme에 두고 밝은/어두운 모드에서 구분한다.
