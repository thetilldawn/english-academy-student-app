# 원출현의 중복 단어 본문 공유와 선택 복구

승인된 M08-A/OPS-20261003-01 D5 보완이다. 원출현 행에 이미 있는 단어·출처·뜻·음원 JSON과 같은 값을 `package_entry_json`에 다시 저장하는 중복을 줄인다. 상태와 순서는 루트 대장을 따른다.

## 요구와 검사

| 요구 | 합격 기준 | 검사 |
|---|---|---|
| R1 원형 보존 | 기존 고정 열과 같은 값만 참조하고 나머지 값·누락/null·공백·추가 필드·배열을 보존, 원행과 본문 확인값 동일 | T1,T2 |
| R2 소비자 보존 | APP05 패키지·범위판·M01 출처 상태·범위 등록·구형 구성·오답 준비의 기존 전체 문서 확인값 유지 | T2,T3 |
| R3 진행 작업 보존 | 적용 전 시작 시험/오답 준비의 첫 제출/저장·재시험·재접수 성공 | T4 |
| R4 제한 이전/복구 | 명시한 최대100행·실제 파일 재읽기·한 거래 전부 취소·재요청·같은 등록/생성 잠금·늦은 후보 보존 | T5,T6 |
| R5 운영 경계 | 불변 보호·앱 권한0·새 답 이후 일부 본문 복구·기존/신규 기록 검증·전체 회귀/독립 검토 | T6,T7 |

## 확정 결정

- D1 사용자: 승인된 공용 사전/키/태그 사용과 중복 본문 축소를 따른다. 배정·완료·점수·오답·미접수 답은 보존한다. 계속 진행 승인 범위다.
- D2 사용자: 운영은 읽기만 수행한다. 이 보완의 구현과 가짜 검토 DB 연습 뒤 M09/M10/M08-B의 승인된 순서를 따른다. 실제 운영 사본·적용·물리 회수는 별도로 검증한다.
- D3 내부: 기존 검토 승인 release에 연결되어 원출현 변경이 차단된 행만 대상으로 한다. 직접 수정 가능한 옛 자료·파생 구성은 제외한다. package_entry_json 한 열만 바꾸며 기존 audio_json은 재조립의 고정 입력으로 사용한다.
- D4 내부: 정해진 24개 필드의 원래 값과 기존 열 값이 PostgreSQL JSON text가 완전히 같을 때만 짧은 필드 번호 표시로 공유한다. 원래 unit/sequence_no/day, trim/nullif 전 표기, 누락/null, 추가 필드 등 나머지는 참조 옆 잔여로 둔다. 잔여4KiB 초과·참조가 더 커지는 행은 제외한다. 큰 본문을 다른 DB 표로 옮기지 않는다.
- D5 내부: 원출현 고정 열→단어 본문→전체 원행→APP05 패키지 순서로 복원한다. 하위 함수가 APP05 패키지나 최신 사전값을 역참조하지 않는다. 원행과 참조 확인값을 매 읽기에서 검사하며 누락/깨진 참조는 명시적으로 실패한다.
- D6 내부: 현재 소비자 7개 본체의 해당 원행 읽기만 정확한 치환으로 연결한다. OID/권한/설정과 M01/M02/APP03/APP05의 보완은 유지한다. 구형 구성의 original record도 복원해 새 release에 이전 표시를 복사하지 않는다.
- D7 내부: 명시된1~100행의 release/source_row 키를 중복 없이 정규화한다. 검토 등록기와 같은 dataset_key/9129, 자료/자료판/원출현 순서로 잠그며 충돌은 짧게 포기한다. READ COMMITTED·거래30초/잠금1초·원행1MiB/요청16MiB/파일32MiB를 요구한다. 후보는 매번 새 조회하며 마지막 키만 기준으로 건너뛰지 않는다.
- D8 내부: 모든 Git 밖 접근 제한 파일에 PostgreSQL 원행 문자열을 그대로 저장/fsync/재읽기한다. 준비 응답 유실은 원문이 남아 있을 때 같은 응답으로 재발급한다. 축약 상태에서는 원래 사본을 요구한다. 현재 원행과 외부 사본을 확인한 뒤 package_entry_json 한 열만 전환/복구한다.
- D9 내부: 같은 요청은 최초 응답을 반환하고 다른 용도 재사용은 거절한다. UPDATE 허용은 현재 연결/거래/키/전후 확인값에 묶인 한 번만 소비하며 기존 원출현 보호의 다른 동작은 유지한다. 원행을 삭제하거나 학생 기록을 과거로 복원하지 않는다.

## 근거와 검사 범위

운영 읽기에서 검토16,894행의 본문 JSON text32,785,773B 중 기존 열과 다른 잔여는1,552,265B, 최대110B였다. 참조/명세/인덱스 비용을 빼기 전 수치이며 물리 절감량이 아니다. 별도 음원 JSON은7,270,566B 중 잔여5,079,972B로, 이 단계의 별도 전환 대상으로 삼지 않는다. [읽기 집계](../verification/OPS-20261003-01_원출현_중복집계.json)를 근거로 쓴다.

T1 새 SQL 직전 실제 월별/수능·구형 범위/구성/시험 준비와 적용 후 원행 보존. T2 전체 원형·PostgreSQL 확인값·누락/null/공백/추가필드/큰정수·파일/환경/한도/다른판/잘못된 참조. T3 APP05/범위판/현재 출처 상태/새 범위 등록/구형 구성·기존 오답 전체 확인값. T4 전환 전 시험/오답 준비의 첫 처리·재시험·재접수. T5 묶음의 중간 오류 취소/준비 재발급/같은요청/새후보·실제 두 연결 등록/구성/오답 저장. T6 새 답 뒤 파일의 일부 원행 본문만 복구·비대상 전열 보존/보호/권한. T7 전체 회귀·정적 검사·빌드·검토 DB 보존/종료·독립 검토.

UI·경로·표시 문구를 바꾸지 않는 내부 도구다. 공용 단어48시간·미사용 준비24시간·미접수 답 자동 삭제 금지와 기존 음원 재생 정책을 유지한다.
