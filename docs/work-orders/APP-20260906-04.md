- [기록 v1](../../architecture/work-records/records/APP-20260906-04.json), [개발 기준](../개발_지시서와_검증_기록.md), [전체 계획](../APP_20260905_캐시와_컴포넌트_분리_실행계획.md)을 따른다.
- R1: 공통 조건 UI를 전체 controller 없이 재사용. 신규 단일/일괄·독립 오답 생성·기존 수정 사용처 연결과 기존 값/콜백/잠금 보존이 완료 조건이다. T1~T6.
- R2: 유형 지원과 제한을 같은 순수 정책으로 판단. 미선택/준비 정보 누락/정상 문항 없음 구분과 Preview 안내 교체, 기존 날짜 없음·1회·영어 선택 방향 유지가 완료 조건이다. T1~T6.
- R3: 현재 코드 근거와 로컬 검사 후 실제 UI 확인. 전체 회귀·타입/lint/구조·새 빌드·독립 리뷰·검증 기록이 완료 조건이다. T3~T6.

## 결정과 책임

- D1/D2: 기존 승인 순서와 로컬 범위 유지, 미결정0. DB/학생/자료/의존성/비용/커밋/업로드/배포 변경 금지.
- D3: 순서·방향·점수·재시험 입력을 중립 조건 UI로 이동한다. 신규 배정 UI는 필요한 값·관련 오류·개별 콜백만 받고 조립 계층이 연결한다. 오답·수정 소비자도 연결하되 수정 방향 잠금은 기존 fieldPolicy다.
- D4: 유형별 방향/일정 제한과 준비 상태는 domain 순수 정책, 한국어 탭·설명은 presentation, 문구는 기존 한국어 모음. 같은 정책을 초안·요청·서버 검사에 연결하며 기존 오류 위치/응답 모양을 유지한다.
- 직접 내부 서버 호출의 누락 방어도 기존 요청 계약과 같게 강화한다. 정상 API 요청의 허용 범위는 넓히거나 줄이지 않는다.
- D5: 날짜·여러 회차 허용과 유형 전환 시 범위 자동 수정은 별도 업무 변경이므로 하지 않는다. 단어장 전체 준비와 DAY별 최종 가능 수를 혼동하지 않는다.
- 대안 비교: 기존 공통 부품을 좁혀 이동한다. 새 만능 배정 UI나 전체 상태를 이름만 바꿔 전달하는 대안은 실제 독립 검사가 어려워 채택하지 않는다.

## 상태·흐름·검사

- 단어장 미선택: 선택 안내와 영영풀이/예문 잠금. 정상0건 안내 없음. 정보 누락: 확인 실패와 창 다시 열기 안내, alert/설명 연결. 정상 준비에 해당 유형 없음: 해당 문항 없음만 표시. T1/T2/T6.
- 준비된 영영풀이/예문: 영어 선택지4개, 현재 시험일 없이1회 지원 안내. 일정 부품도 같은 정책 결과를 표시하며 Preview라는 환경 안내를 제거한다. T1/T2/T3/T6.
- 방향/일정 위반: 기존 필드 오류·안전한 한국어·요청 오류 경로 유지. 저장 실패/인증/404/예상 밖 오류는 기존 경계를 보존하고 이번 전체 회귀와 구분해 기록한다. T3/T4.
- T1: 기존 판정과 모든 유형·방향·일정 경계 동등성, 표시 상태 구분. T2: 독립 조건 UI·콜백/오류/잠금/재시험 수명 및 실제 소비자.
- T3: 초안·요청·서버 동일 계약, 실패 시 자료 조회 전 차단, 전체 배정/오답/수정/권한/답 보호/캐시 회귀.
- T4: 관련/전체·타입/lint/구조/변경 연결·요청 캐시·새 격리 Next 빌드·현재 코드 해시. T5: 독립 읽기 리뷰. T6: 실제 로컬 단일/일괄 연결과 문구 확인; 계산·저장은 자동검사 선행.
- 생성/배정/응시/조회/검색/수정/삭제/기록: 기존 배정과 수정 조건만 재연결. 새 흐름 없음, 응시/삭제/기록은 회귀 보존. 권한·요청 수명·캐시·스트리밍·라우팅·스타일/공용 UI 변경 없음.
- 복구는 이번 파일만 역패치. APP02/03 근거는 당시 지문으로 보존하며 재서명하지 않는다. 실제 DB/운영 비용/모든 화면 폭은 별도 확인 없으면 미검증.

## 검사 보완 이력

- 전체 회귀에서 기존 DAY 계약 검사가 이동 전 조건 파일의 문자열을 찾았다. 실제 조립부 연결과 이동된 공통 부품을 각각 확인하도록 수정했다. 이 소스 계약 검사를 구조 보호선과 소유 지도에 명시 등록했다. 앱 동작을 검사에 맞춰 되돌리지 않았다.
- 이후 전체 386파일 2,272개 통과. 지도 등록/검사 목록만 후속 변경했고 구조 검사를 다시 통과했다. 실제 로컬 단일/일괄의 점수 변경·재시험 입력 보존 및 미선택 문구를 확인했다. 저장과 운영 자료 확인은 하지 않았다.
- 최종 사용자 지시의 캐시 개선→단어 보기 가리기→안전 확인 후 프로덕션 순서는 루트 대장을 따른다. 이 단계 자체는 로컬 검증이며 배포하지 않는다.
