# APP-20260907-01 목록 만료와 배정 작성 수명 분리

APP08/10/12의 배정 캐시 오류 보완. 원래 검증 기록은 당시 근거로 보존한다. 사용자 “그럼고쳐”에 따라 다른 기능은 시작하지 않고 이 오류만 고친다. 실제 상태는 루트 대장 한 곳이 기준이다.

## 요구·결정

- R1/D1: 학생 목록 조회60초 뒤 정상 통신에서도 배정창이 숨겨지는 오류를 수정한다. 단일·일괄의 실제 창과 작성값·초점은120초를 넘어도 유지한다.
- R2/D2: 같은 현재 화면에서 마지막으로 성공한 자료만 유지한다. 성공 때의 ticket을 별도로 보관하여 새 화면/탭 복귀 요청이 실패했는데 옛 자료에 새 승인 표시가 붙지 않게 한다. 현재401/403·계정/세대/로그아웃은 기존 즉시 숨김/폐기다.
- R3/D3: 배정 화면에만 opt-in. 재사용15초/보관120초·타화면 표시60초는 유지한다. 배정에서는 이전목록이라는 중립 안내와 수동 재조회를 제공하고 주기 자동조회는 하지 않는다. 준비·최종저장은 기존 서버가 현재학생/자료를 검증한다.
- 새 DB/API/의존성/비용서비스·학생응시·자동공개·채점 변경0. 기존 Preview 커밋 승인 경계는 유지하되 로컬 검증 전에 배포하지 않는다. 운영 배포를 로컬 완료와 합쳐 기록하지 않는다.

## 책임·상태

공용 session entry는 성공 출처·현재요청·대기/실패를 맡고, students 공개 어댑터가 배정용 유지 정책을 선택한다. CachedAssignmentWorkspace는 Notice/Button/기존 Dialog 표시만 조립한다. 단어 수·회차·학생 선택·배정/저장 규칙은 복제하지 않는다.

배정 UI 역할 지도에 공통 한국어 문구의 직접 참조만 추가했다. 기존 연결부 역할, 전체 상태 전달/HTTP 금지 검사는 유지한다. 독립 검토에서 공용 성공 출처와 UI 조립 경계의 차단 결함은 없었다.

- 단순60초 경과: “학생 목록은 이전에 불러온 내용입니다. 작성 중인 배정은 유지됩니다.” 중립 안내. 창/값/초점 그대로.
- 현재화면 수동갱신: “학생 목록을 새로 불러오는 중입니다.” 창 유지, 중복 재조회 잠금.
- 현재화면 조회실패: “학생 목록을 불러오지 못했습니다. 다시 불러와 주세요.” 실제 오류를 만료 안내로 덮지 않는다. 같은 성공출처의 작성값을 유지한다.
- 첫조회/복귀 인증 미확인: 자료 숨김과 실제 로딩/실패. 이전 화면 자료로 통과시키지 않는다.
- 인증실패: “로그인을 다시 확인해 주세요.” / “관리자 로그인”. 개인자료 폐기.
- 정상0/미선택/입력오류/저장실패/404/예외는 기존 좁은 안내·입력보존·오류경계를 유지한다. 상세 R/D/T의 uiStates와 연결한다.

생성·배정·조회/검색·수정·삭제·응시/점수는 기존 흐름을 유지하며 이번 변경은 작성 화면의 수명과 표시만이다. 직접경로/라우트 모달·서버인증·private no-store·최종서버검증을 우회하지 않는다.
