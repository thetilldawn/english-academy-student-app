# 구조 지침 현행화와 최종 통합 검사

R1/D1은 사용자 요청의 구조 검토와 순차 수리 통합 검증이다. 기능 수리는 APP-20260929-01~07 기록에 분리했다. 운영 배포·실학생 쓰기·패키지 업그레이드·전면 폴더 이동은 제외한다.

D2: 설치 Next16.2.12/React19.2.8을 기준으로 공식 인증/Server-Client/Parallel Routes/오류 처리 문서를 대조한다. 기능12개, client 일부 구현, 개인 목록 보관의 기본ON과 인증/활성화면 수명, R8공유 캐시 폐기를 구분한다. 오래된 계획은 이력으로 보존하고 현재 기준으로 들어오는 짧은 링크를 둔다. 파일 개수나 형태만으로 효율/올바름을 단정하지 않는다.

R2/D3: 구조 검사가 각 변경 파일마다 같은 작업의 전체 입력을 반복 읽는 비용을 없앤다. validateChangedCoverage 한 번 안에서 각 기록 객체별 현재/과거 파일Map을 한 번만 만들고 다음 호출에서는 다시 만든다. 하나가 통과해도 뒤 후보를 건너뛰지 않아 외부 경로·읽기 오류를 계속 거절한다. 앱 실행 캐시와는 무관하다.

T1은 호출수·기록격리·다음실행변경·뒤후보오류와 기존 보안 계약, T2는 독립 검토, T3는 전체 자동검사/빌드, T4는 실제 코드·현재/계획 문서·공식 근거 대조다. 완료 근거와 불확실한 운영 재현은 구분하며 과거 verified기록을 새 결과로 덮어쓰지 않는다.

통합 검사 보완: 새 배정 복구 검사를 실제 범위 생성/요일 배분/연속시험 흐름에 연결했다. APP03의 함수 이름이 바뀐 뒤 남은 정적 검사1건은 현재 이름/줄바꿈에 맞추되 복구 조회1회 제한을 유지한다. 해당 검사 경로를 이번 scope에 포함하고 전체 재검사를 수행한다.

빌드 환경: node_modules 공유 연결로 기본 Turbopack이 로컬 경계를 거절해, 설치본이 제공하는 --webpack으로 동일 앱의40페이지 빌드를 검증했다. 앱 설정/연결은 변경하지 않는다. 이 성공을 운영 기본 빌드/배포 성공으로 확대하지 않는다.
