# 오답 입력과 요약 분리

- 기존 계획 1-D, 사용자 계속 지시에 따른 현재 작업의 후속 단계. [R/D/T](../../architecture/work-records/records/APP-20260906-05.json), [개발 기준](../개발_지시서와_검증_기록.md).
- R1: 범위·오답 단계·계산 상태 및 최종 요약을 좁은 UI로 분리. 실제 오답 연결부·기존 조건/시간/공개/마감 부품을 유지한다. T1/T2/T3.
- R2: 미계산/null·정상0·조회 오류·계산 오류를 구분. 서로 다른 재시도·관련 오류·초점/단어장 찾기 참조 유지. T1/T2/T3.
- R3: 실제 소비자·기존 요청/상태 회귀와 타입/lint/구조/새 빌드/독립 리뷰의 현재 근거 기록. T3/T4/T5.

## 결정·설계

- D1 사용자: 캐시·구조 계획을 먼저 마무리하고 학생 단어 보기 가리기를 마지막에 한다. 이 단계는 로컬이며 최종 배포는 별도 단계다.
- D2 내부: 연결부는 전체 제어기를 소유할 수 있다. UI는 상태 표시값·작은 오류 묶음·개별 동작만 받고 요청/인증/계산을 하지 않는다. 상태/날짜/시간 문구는 presentation에서 생성한다.
- D3 내부: 요약을 아직 읽지 못한 전체 오답 수는 정상0으로 표현하지 않는다. 기존 오류의 안전한 문구와 다시 불러오기/다시 계산하기는 보존한다. 업무 변화 없음, 사용자 미결정0.
- 기존 UI/스타일을 그대로 조합한다. 모든 파일을 새 만능 부품으로 합치거나 폼 제어기 전체를 옮기는 대안은 채택하지 않는다.
- 생성/배정/조회: 오답 기존 흐름의 표시만 재연결. 응시·검색·수정·삭제·기록·권한·정답 payload·캐시·API는 변경 없이 관련 회귀로 확인한다.
- 초기·갱신: 계산 중 표시, 정상0: 현재 배정할 오답 없음, 실패: 안전한 안내/영역별 재시도. 입력 오류는 해당 위치, 저장 실패는 기존 입력 보존, 인증은 기존 숨김/로그인, 404/예상 밖 오류는 기존 경계 유지.
- 복구: 이 범위만 역패치. 실제 학생/원자료/DB/새 의존성/업로드/배포 변경 금지. 이전 검증 기록은 당시 근거로 보존한다.

## 검사

- T1 표시 변환: 모든 준비/계산 상태, null/0, 선택단계, 한국 시각, 시간 없음/전체/문제당.
- T2 독립 범위/요약 UI: 전체 controller 없이 렌더, 버튼 disabled/pressed, 서로 다른 재시도, 오류 위치/초점 참조.
- T3 실제 연결부 및 기존 제어기/요청 회귀: 선택/점수/순서/공개/마감/계산 오류 수명 유지.
- T4 전체 회귀·타입/lint/구조/요청 캐시·새 격리 빌드·현재 지문. T5 독립 리뷰. 화면 배치 변경이 없는 구조 분리로 실 오답 DB 테스트는 하지 않고 실제 연결부 렌더 검사와 브라우저 제한을 분리 기록한다.
