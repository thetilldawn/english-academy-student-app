# 새 시험의 중복 상태 저장 제거

작업 APP-20261004-03. 사용자 2026-10-04 정정과 기존 유지보수 실행 승인에 따른 같은 설계 오류 보완이다. 무료 한도 달성이나 부하 실험은 요구하지 않는다. 기준은 운영 코드51e0141·현재 기록37851e3이며 상태는 루트 대장만 따른다.

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 | 신규 기기시험 제출은 공용 뜻 상태를 한 번만 갱신하고 옛 단어장별 상태를 추가/갱신하지 않는다. 처음부터 맞은 단어의 불필요한 상태행도 생기지 않는다. | T1 |
| R2 | 기존 관리자·학생·학습 조회도 최신 문항의 뜻 키로 현재 상태를 읽는다. A/B의 같은 뜻은 함께 해결하고 C의 다른 뜻은 그대로 미해결이다. 과거 횟수·출처·응답 형식은 유지한다. | T2 |
| R3 | 기존 학생 행·옛 시험 쓰기·기기 미접수 답·점수·포인트·접수/시각·함수 권한을 유지한다. 새 SQL은 알려진 함수 원형에만 적용한다. | T1,T3 |
| R4 | 변경한 흐름의 검사와 실제 적용 보존만 확인한다. 이미 통과한 전체 시험·용량 증식·임계값 검사는 반복하지 않는다. | T1,T2,T3 |

결정 D1 사용자: 공용 단어 고유키·태그/뜻·작은 상태와 결과 기록으로 통일하며 불필요한 중복 저장을 고친다. D2 내부: 현재 관리자 화면·복습 배정은 이미 공용 상태를 읽으므로 화면/새 API를 만들지 않는다. 구형 조회3개의 resolution만 공용 뜻 상태 우선으로 연결하고 신규 제출1개의 구형 상태 투영 호출만 제거한다. D3 내부: 개별 접수는 번호/답 확인값만 보관하며 배열 중복도 이미 제거됐으므로 이번 작업에서 규격을 또 바꾸지 않는다. D4 사용자/내부: 기존 데이터는 삭제하지 않고 과거 쓰기 경로도 보존한다. 미결정 없음.

자료 소유자는 quiz-player/database-contract다. 생성·배정·검색·페이지/정렬·입력·삭제·파일/음원·브라우저 캐시는 바꾸지 않는다. 응시 종료의 DB 저장과 오답 조회의 현재 상태 판정만 바꾼다. 상태는 같은 학생의 공용 뜻 키로 연결하며 단어 키만으로 다른 뜻을 해결하지 않는다. 새 조회 함수를 늘리지 않고 공용 현재 상태를 조회당 한 번 계산한다.

인증·권한 확인, 학생→응시 잠금, 공식 채점, 늦은 접수·같은 요청 재전송·다른 내용 충돌·포인트의 기존 계약을 그대로 둔다. 과거 자료의 fallback과 횟수/출처를 남기고 기존 행을 일괄 수정하지 않는다. SQL 적용 자체는 함수를 교체할 뿐 학생 행을 갱신하지 않는다.

UI/상태 문구는 변경하지 않는다. 기존 정상 0건·조회 오류·인증/숨김404·저장 실패/결과 불명·기기 답 보존을 기존 화면에서 처리한다. 오류를 0건으로 바꾸지 않고 기존 RPC 응답을 유지하므로 새 브라우저 성능/레이아웃 검사는 필요하지 않다.

T1: 기존 기기시험 DB 검사에서 첫 정답·오답·재시험·재접수·늦은 제출·실패 취소가 정상이고 구형 상태 쓰기가 없는지 확인한다. T2: 같은 뜻 A/B 해결과 다른 뜻 C 미해결을 구형 조회3개에서도 확인한다. T3: SQL 적용 전후 기존 행/함수 메타 보존·원형 거절·옛 시험 저장을 확인하고 같은 SQL을 검토 환경에서 먼저 적용한다. 관련 타입/구조 검사를 수행하되 전체 5천여 검사를 반복하지 않는다.

복구는 보관한 기존 함수 본문으로 신규 제출의 옛 투영 호출을 되돌릴 수 있다. 새 저장 표나 새 응답 규격이 없으므로 기존 행의 복원/삭제는 필요 없다. 공용 상태를 우선 읽는 조회는 그대로 유지해도 된다. 실제 학생에게 새 시험이나 답을 만들어 검증하지 않는다.
