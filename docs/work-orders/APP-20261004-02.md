# 운영 전환 중 단어 내용 읽기 호환

M10 분석에서 구형fa4357의 예문 단어보기와 시험 준비가 새 NULL 본문 배정을 직접 읽는 경로를 확인했다. 기존 시험 종료가 자동으로 새 배정을 만들 수 있으므로 새 시작만 중지하는 것으로는 충분하지 않다. 기존 제출을 막지 않고 전환하는 내부 오류 보완이며 사용자 정책 추가는 없다.

R1/T1·T2 기존 본문은 원형대로 읽고 새 함수 호출0. R2/T1·T2·T4 NULL 문항만 당시 공용 내용으로 복원, 원뜻/출처/발음과 순서 유지. R3/T3·T4 진행 답/재시험·자동 배정·재접속 보존. R4/T1~T4 서비스 전용 권한·정확한 학생/준비 문맥·손상 거절.

D1 기존 계속 진행 승인 범위다. D2 별도fa4357 기반 앱에서 두 DB조회와 호출부 학생ID/공개 진입점만 연결한다. D3 미래 공용 함수로 고정 SQL을 위임하는 별도 이름의 SECURITY INVOKER RPC, service_role만 실행. D4 제어 선행→중지→호환 앱→나머지 SQL→최종 앱→재개; 과거 본문은 이전하지 않는다. D5 준비 경합으로 이미 시작했을 때만 같은 영수증으로 이어 간다.

이 앱은 임시 전환용으로 기존 화면/채점/전송 정책을 새 방식으로 교체하지 않는다. 최종 앱을 먼저 기존 DB에 연결하면 새 필수 조회가 없어서 실패하므로 그렇게 배포하지 않는다. 본문 NULL·없는 함수·잘못된 응답을 최신 사전값이나 빈 값으로 숨기지 않는다. 현재 공통 오류 표시/재시도는 유지한다.

변경은 두 서버조회·엄격한 응답검증·필수 호출부/공개 진입점·새 서비스 위임 SQL이다. UI/라우팅/클라이언트 상태/음원/캐시/답 쓰기는 확인만 한다. 기존 연습 RPC의 M11/M02 호환도 독립 확인한다. 시험 정답 정보는 기존 준비 소유권 검사를 그대로 거친다.

T1 공용검증, T2 두 소비자/혼합내용/준비경합, T3 기존 DB·권한·위임, T4 실제 순서의 결합 SQL/자동 후속배정/검토 앱/독립검토를 마친다. 기존 DB에서 동작하는 이유를 새 DB만으로 검증하지 않는다. SQL뒤 원형 앱 단독 복귀는 금지하고 기존 학생행을 되돌리지 않는다. 현재상태·순서는 루트 대장만 따른다.
