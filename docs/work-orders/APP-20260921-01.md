# 단어장 범위 편집과 저장 화면 보완

사용자 분석 요청의 결과를 확인한 뒤 받은 “ㄱㄱ”에 따른 별도 보완이다. 완료된 APP-20260920-01과 배포 이력은 유지한다.

## 요구와 완료 조건

- R1 빈 확정 구성과 잘못된 요청 차단: 이름/확정 범위/실제 포함 단어를 검사하고 입력 옆 오류와 저장 잠금. 기존 빈 판 조회와 완료 요청 재확인은 유지. (T1, T2, T3, T4)

- R2 자료별 독립 범위 편집: 모고/수능/교과서/단어장/학교 자료에 맞는 조건만 표시. 편집 중인 묶음 조건 변경은 해당 범위만 갱신하고 나머지 묶음은 유지. (T1, T2, T6)

- R3 수능과 장문, 연도 범위: 수능은 별도 종류로 표시하고 학년도/시행연도를 구별. 모고 년도 구간과 월/유형/번호 복수 선택, 자료 없는 유형 안내. (T1, T2, T6)

- R4 자동 태그와 이름 제안: 실제 포함 범위 및 용도/대상에서 태그를 파생. 이름 자동 제안은 수정 가능하며 사용자가 수정한 이름은 조건 변경으로 덮어쓰지 않음. (T1, T2, T6)

- R5 단계별 화면과 새 구성 진입 통합: 용도/대상, 자료와 범위, 전체 확인/저장의 번호 구간. 새 만들기는 새 편집. 중복 빈 틀 버튼과 합의 안 된 준비 파일 입력 제거. 입력 폐기 확인. (T2, T6)

- R6 기존 자료와 저장판 보존: 과거 빈 확정 판/복사/이전 버전의 조회 유지. 그룹 복구는 실제 ID/판/순서를 보존하고 교차조건을 임의 확대하지 않음. 원본/학생 기록 변경 없음. (T1, T3, T4, T7)

- R7 저장과 생성의 복구 유지: 준비 파일 pending 제거. 실제 POST 후 미확정 재시도는 동일 요청 유지, 다른 생성 명령으로 바뀌지 않음. 인증/충돌/단계 생성 복구 유지. (T2, T4, T7)

- R8 기존 단어장 구별: 기존 책은 유지하고 확인된 출처 정보에 따라 ‘원본 단어장’과 ‘범위로 만든 단어장’을 구분한다. 분류 근거 없는 자료는 추측하지 않는다. (T8, T7)

## 화면과 편집 기준

1. 용도와 대상: 필요한 경우 학교·대상 학년·학기·시험을 입력한다. 모두에게 필수로 요구하지 않는다.
2. 자료와 범위: 종류를 고르고 각 묶음 안에서 조건을 바꾼다. 모고는 원학년·시행연도·월·유형·번호, 수능은 시행연도와 학년도 안내·유형·번호, 단어장은 교재·DAY, 교과서는 교재·과, 학교 자료는 학교·자료·등록 범위다. 직전 대비는 용도이며 여러 자료 묶음을 함께 쓴다.
3. 전체 확인과 저장: 실제 포함 수와 차이, 자동 태그, 수정 가능한 이름을 확인한다. 오류는 입력 바로 아래 표시하고 저장을 막는다.

필터 변경은 편집 중인 묶음만 즉시 교체한다. 다른 묶음과 단어 제외는 도달 가능한 범위 안에서 보존한다. 잘못된 숫자 구간을 입력 중이면 기존 선택을 보존하고 저장을 막는다. 정상 0결과는 그 묶음을 0으로 바꾸며 원인을 안내한다.

저장 구조는 현재의 고정 scope ID/version 목록을 유지한다. 다시 열 때 자료 종류/교재별 연속 구간을 묶고, 조건을 역산한 결과가 정확히 같을 때만 사용한다. 그렇지 않으면 ‘개별 선택 범위’로 명시한다. 기존 2개 교차 범위를 8개 조합으로 확대하거나 원래 순서를 바꾸지 않는다.

자동 태그는 실제 선택한 버전의 범위에서 표시·검색한다. 저장한 최신 metadata.tags는 해당 저장 시점 값이며 과거 버전 카드에는 그 버전의 실제 태그를 따로 계산한다. 버전 저장에 선택 metadata를 함께 받아 제목/대상/태그를 원자적으로 갱신한다.

이전 수동 태그는 별도로 보존·표시하고 자동 태그와 함께 검색한다. 범위 변경 후 이전 연도·유형이 남지 않도록 최신 저장판에서 계산된 자동 태그와 구분한다. 저장 태그는 기존 30개 한도를 유지하며 이전 태그를 우선 보존한다. 표시·검색용 자동 태그는 저장 한도와 별도로 실제 범위에서 계산한다.

파일 입력과 읽기 대기 코드를 제거한다. pending은 실제 전송 직전에만 만든다. 결과 미확정이면 동일 요청을 재확인하고 새로운 생성 작업은 잠근다. 완료된 옛 요청의 재조회는 새 검증으로 차단하지 않는다.

비인증 목록 조회 실패가 이미 보낸 요청의 재확인을 막지 않게 한다. 인증 실패나 다른 관리자 계정은 계속 차단한다. 배정 창으로 돌아간 뒤에도 작성 중인 구성의 변경 상태를 상위 닫기 확인에 전달한다.

## 입력·보존·검증 경계

- 입력: 현 운영과 같은 실행 코드, 감사 보고서, 현재 원범위 분류 계약.
- 산출: 화면/상태/저장 보완, 새 DB 방어 파일, 가짜 자료 단위·화면·DB 검사와 PC/모바일 결과.
- 원자료·사전·발음·기존 단어장·학생 기록은 수정하지 않는다. 앱 등록된 수능 범위와 보유 원본을 구별한다.
- 수능 추가 원본 추출/등록과 운영 반영은 구체 명세를 따로 남긴다. 로컬 검사를 운영 관리자 확인으로 확대하지 않는다.
- 입력/오류/복구 상세와 T1~T8은 대응 v1 기록을 기준으로 한다. 설계 관문 후 코드에 착수한다.
