# 시험 시작과 학생 알림 동시 요청 오류 수리

## 확인된 문제

M10 실제 Preview에서 로그인 뒤 알림과 구형 시험 시작이 겹쳐 /api/student/notifications 500이 발생했다. 2026-10-03 14:18:39.683 UTC의 40P01은 학생 행과 배정 외래키 잠금의 반대 순서였다. 현재 학생행·답·점수 유실 증거는 없다. 상태와 우선순위는 루트 대장을 따른다.

## 요구와 결정

- R1/T1·T3: 알림과 시험 시작의 학생 잠금 순서를 맞춘다.
- R2/T1·T2·T3: 기존 수신 조건·중복 방지·권한·학생/수신 기록을 보존한다.
- R3/T2·T3: 학생 함수 1개만 바꾼다. 관리자 알림의 모든 경합까지 해결했다는 주장은 하지 않는다.
- D1 기존 유지보수 실행·계속 진행 승인에 포함된 수리다. 새 사용자 정책은 없다.
- D2 학생을 FOR UPDATE 한 뒤 별도 PL/pgSQL 문장에서 기존 두 INSERT CTE를 반환한다. 존재하지 않는 학생에는 기존 (0,0)을 유지하고 새 상태 조건/예외를 추가하지 않는다.
- D3 OID·owner·ACL·SECURITY INVOKER·search_path·반환형 유지, prolang/prosrc만 변경한다.
- D4 로컬 PGlite와 독립 검토 후 같은 SQL을 Preview에 적용한다. 실제 두 연결은 READ COMMITTED로 관찰하고, 운영 반영은 M10 통과 뒤다.

## 영향과 검사

변경: DB 학생 알림 함수·보존 검사·소유권 안내. 확인만: API/서비스/알림 조건/권한. 해당 없음: 화면 문구·경로·클라이언트 상태·채점·캐시·스타일. 새 화면은 없다.

T1은 기존 함수 원본으로 되돌린 가짜 DB에서 수신 이력/학생행·비대상 함수·메타를 비교하고 새 SQL을 재적용한다. T2는 기존 공개/미공개·취소·마감8시간·역할 검사를 그대로 실행한다. T3은 두 독립 연결에서 실제 Lock 대기와 차단 PID를 관찰한다. 알림 우선은 (1,1) 뒤 시험 시작 성공과 이후 (0,0), 시작 우선은 대기 뒤 (0,0)과 수신 추가0이어야 한다.

보존용 적용 거래는 notification_receipts를 명시적으로 포함한다. 기존 학생/배정/응시/포인트/답/오답·비대상 함수도 거래 내 전후 확인한다. 가짜 입력은 정확한 명세 ID만 종료하며 실제 기록은 남긴다.

복구는 적용 전 학생 함수 정의만 대상으로 하며 행 복구/삭제는 하지 않는다. 종전 교착이 재발할 수 있어 자동으로 되돌리지 않는다. Windows initdb는 실행하지 않는다.

[PostgreSQL 잠금](https://www.postgresql.org/docs/current/explicit-locking.html)과 [함수 snapshot](https://www.postgresql.org/docs/current/xfunc-volatility.html)을 현재 코드와 대조했다.
