# 공용 입력과 배정 표시

사용자 승인 검토안 R06~09/R12~15/R17~19를 연결한다. 상태·순서는 루트 대장, 실제 경로/설계/검사는 [RDT 기록](../../architecture/work-records/records/APP-20260908-03.json)이 기준이다. APP02의 실제 서버 확인을 누락 완료 처리하지 않고 별도 Preview 단계에 남긴다. 신규 배포·DB·정답·배정 규칙 변경은 없다.

## 책임과 상태

- 숫자 입력은 Input 스타일을 재사용하는 문자열 편집 부품. 공백은0이 아니며 확정001→1. 숫자/무효를 기능에 전달하고, domain의 유한수 검사로 미리보기·저장·시간버튼 저장을 모두 차단한다. 이전 숫자로 대신 저장하지 않는다. 휠/터치 스크롤은 값 변경을 하지 않는다.
- 책 미선택은 `단어장을 선택해 주세요.`. 정상조회 미지원은 disabled 탭의 호버/초점/터치 설명. 조회 실패는 별도 안전 안내를 유지한다. 기존 표준 Tabs/HelpTip를 연결하며 중첩 버튼을 만들지 않는다.
- 같은 DAY/과 연속번호만 압축하는 순수 공용 범위 표시. 서로 다른 시행·끊긴 범위는 생략/양끝 합치기 금지. 표시 변경과 실제 출제 계산 분리.
- 미리보기는 배정 학생 태그·회차 제목 옆 수량·실제 범위·오른쪽 공개/마감 칸. 공통/예외/배정불가 사유는 유지한다. 빈 선택 바구니도 같은 자리를 가지며 무한 높이 증가를 제한한다.
- Dialog는 공용 backdrop 흐림/어두움, 작은 모바일 크기, 중첩 focus/Escape/스크롤을 소유한다. 앱 내부 확인은 공용 Promise<boolean>, 중복은 false, 수명 종료는 false. 업무 요청은 기능이 소유하고 대상/버전을 승인 뒤 다시 확인한다.
- 경로 이동 가로채기의 반환은 동기 boolean 유지. 뒤로가기는 현재 편집 위치 복원 뒤 질문하며 승인 시만 원래 목적지로 진행한다. 브라우저 종료 경고는 기본 beforeunload를 유지한다.

## 검사 관문

독립 검토에서 초점 복귀·대상 변경 잠금·확인 직후 닫기·확인 직후 저장 시작·뒤로가기 복원 중 저장 성공 경합을 재현해 보완했다. 버전 검사는 질문 응답뿐 아니라 실제 요청/이동 직전에도 한다. 이미 전송한 변경은 완료 영수증으로 공용 조회를 무효화하되 다른 화면의 상태를 바꾸지 않는다. 구조 검사에서 발견한 controller→domain 직접 검증은 application의 완결성 결과로 바꾸고, 새 순수 표시 계산/작은 입력만 명시 등록했다. 검사를 끄거나 전체 경계 허용으로 우회하지 않는다.

T1 숫자/요청 차단 → T2 출제 자료 상태 → T3 범위 검산 → T4 회차/학생 표시 → T5 확인창·이탈 → T6 선택/정렬 → T7 전체/구조/타입/lint/빌드 → T8 필요한 실제 로컬PC/모바일 확인. 오류/0건/미입력은 구분하며 내부 오류 원문은 보여주지 않는다. 실제 학생·점수·정답 변경0. 사용자 결정은 모두 이전 승인 범위이며 새 내부 판단은 위 D번호 기록에 근거를 남긴다.
