# APP-20260906-14 첫 시험과 앞 마감 연동 공개 설계

기준: 앱 실행 코드 8c7bb64, 발음 검증 기록 커밋 0c9142720644a1de781a828e7b8e7bf3ad93544f.
2026-09-06 사용자 건너뛰기 답변으로 D1~D4가 확정됐다. 자동 공개 앱 구현·DB 변경·배포는 검증 기록에서 단계별로 구분한다.
실제 상태와 우선순위는 루트 작업 대장만 관리한다.

## 요구와 확정 결정

- R1/D1: 앞 회차 첫 시험의 `initial_completed_at`가 있으면 완료 조건을 충족한다. 합격·재시험 완료를 기다리지 않는다. 기존 응시 status/phase·답·점수는 바꾸지 않는다.
- R2/D2: 날짜가 있으면 앞 배정의 실제 `assignments.available_until + interval '12 hours'`도 충족한다. 응시 타이머 `quiz_attempts.deadline_at`를 사용하지 않는다. 기존 다음 회차의 예약 공개·마감은 보존한다. 날짜 없으면 첫 완료만 기다린다.
- R3/D3: 이미 만들어진 미응시 회차도 적용한다. 이미 공개됐어도 조건 전이면 잠길 수 있다는 설명에 사용자 `ㅇㅇ` 승인. 시작한 시험·재시험 보존, 실제 저장 관계만 사용한다.
- R4: 단일·일괄·큐 생성과 목록·응시 시작·단어 보기를 같은 서버 판정으로 연결한다. 날짜 충돌은 일정 확인 필요, 첫 시험 만료를 완료로 위조하지 않는다.

## R5/D4 — 관리자 건너뛰기는 보류 후 진행: 확정

사용자 답변: “건너뛰면 그걸 안하겠다는 거니까 보류 처리하고 넘어가야지?”

- 관리자가 명시적으로 건너뛰기를 실행한 회차는 보류로 보존한다. 완료·통과로 위조하거나 기록을 삭제하지 않는다. 자동으로 다시 배정하지 않는다.
- 보류 회차는 다음 회차의 첫 시험 완료와 그 회차 마감+12시간 조건을 막지 않는다. 아직 시험이 생성되지 않았어도 같은 수동 처리 기록을 사용하므로 가짜 마감 대체 시각을 만들지 않는다.
- 다음 회차 자체의 예약 공개·마감은 그대로 지킨다. 일반 취소·만료를 자동으로 관리자 건너뛰기로 간주하지 않는다. 시작한 응시·재시험·답·점수는 기존 보호 기준을 유지한다.
- 이전 권장안(건너뛰어도 앞 마감+12시간 유지)은 채택하지 않았다. D1~D3의 정상 회차 조건은 유지한다. 미결정 0건으로 설계 관문 뒤 구현한다.
- 독립 검토 3건을 메인 코드와 대조했다. 추가 독립 업무 결정은 발견하지 않았다. 기존 같은 회차 재배정은 새 일정 사용을 이미 명시적으로 확인받는 수동 동작이므로 자동 날짜 이동과 구분하여 유지한다.

## 캐시·로딩·권한

Next16.2.12/React19.2.8 유지. [공식 자료 보안](https://nextjs.org/docs/app/guides/data-security)과 [화면 갱신](https://nextjs.org/docs/app/api-reference/functions/use-router)을 2026-09-06 대조했다. 웹 문서의 새 버전을 앱에 자동 적용하지 않는다.

- 최초 학생 목록은 현재 학생 세션을 검증한 Server Component가 소유 query를 직접 호출한다. 개인 응답 private/no-store, 공유 캐시 추가 없음.
- 첫 시험 대기에는 공개 시각을 확정처럼 표시하거나 지난 시간으로 반복 새로고침하지 않는다.
- 첫 시험 완료 뒤 시간만 대기하면 기존 AssignmentBoundaryRefresh로 경계에 한 번 갱신한다. 저장 성공 뒤 기존 이동/갱신 경계를 재사용한다.
- 관리자 정상 복구는 같은 seriesId만 교체, 필요한 개인 목록 변경 신호 1회. 결과 불명확이면 명령을 반복하지 않고 현재 학생의 최신 첫 페이지로 확인한다.
- 권한 실패는 개인 자료 숨김, 대기/진짜 0건/404/조회 실패를 각각 구분한다. 미공개 데이터가 HTML·RSC·API·로그·접근성 문구에 포함되지 않게 검사한다.

## 구현·검사 연결 보완 — 2026-09-06

- 2026-09-07 사용자 실행 승인으로 Preview 검증 뒤 운영 DB/앱 적용을 진행한다. D6(내부 호환): 구버전 목록의 v1 계약은 그대로 보존하고 새 공개 상태를 반환하는 목록 v2를 추가한다. 신규 앱만 v2로 조회한다. 공개 판정·신규 응시/단어장 차단은 기존 설계를 유지하므로 구버전 목록 호환을 위해 권한을 완화하지 않는다. T3에서 v1/v2 동시 조회와 실제 신규 앱 계약을 대조한다.

- 새 공개 판정·첫 완료 촉발·보류·소급은 `20260906130402_add_first_attempt_assignment_release.sql` 한 건에 묶는다. 기존 migration은 변경하지 않는다.
- 단독/첫 예약 회차는 기존처럼 공개 전 단어 공부가 가능하다. 이번 선행 조건은 후속 회차에 적용한다. 이미 시작한 응시의 재시험·결과·학습은 보존하지만 새 응시는 항상 서버 판정을 확인한다.
- D5(내부 구현): `expectedItemId`를 요구하는 관리자 처리 v3와 처리 영수증을 연결한다. 구 v1/v2는 정확한 대상 없는 요청이 다음 회차까지 건너뛸 수 있어 공개 실행권한을 해제한다. 이것은 기존 호환 유지 기준의 좁은 안전 예외다. 구 화면에서 오류가 나면 최신 내역 확인 후 화면을 갱신하며 구 함수로 자동 우회하지 않는다.
- 자동 상태 전이에서는 기존 공개·마감 날짜 두 값을 정확히 보존한다. 기존 요일 보정 함수는 관리자가 명시적으로 날짜를 바꾸는 경우에만 적용하며, 첫 완료·보류 후 전이로 7일을 더하거나 기간을 덮어쓰지 않는다.
