# 검토 자료판의 중복 단어 목록 공유와 선택 복구

승인된 M08-A/OPS-20261003-01 D5의 같은 유지보수 보완이다. APP04 다음으로, `word_index.app_exam_use_release.package_json.entries`의 중복만 기존 원출현 키로 연결한다. 상태와 순서는 루트 대장만 관리한다.

## 요구·완료 조건

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 중복 제거 | 기존 등록기 자료의 배열 순서·제외 항목·추가 필드까지 원출현으로 정확 재조립 후에만 외부 사본/확인값과 함께 전환 | T1,T2 |
| R2 기존 소비자 보존 | 패키지 재등록 비교·오답 준비 전체 확인값·기존 범위판과 문항 ID 유지 | T1,T3 |
| R3 진행 작업 보존 | 전환 전 시작한 시험의 답/재시험/제출 재전송·전환 전 오답 준비의 저장/재전송 성공 | T3,T4 |
| R4 제한된 보관·복구 | 1건/시간/크기/환경·같은 등록 잠금·새 후보 재조회·취소/재요청·지정 본문만 파일 복구 | T2,T5 |

## 확정 결정

- D1 사용자: 승인된 M01/M08의 공용 값·키·태그 사용과 중복 본문 축소를 따른다. 원자료·배정·점수·오답·미접수 답을 보존한다. 계속 진행 승인 범위다.
- D2 사용자: 운영 적용·실제 정리는 M10/M08-B의 실제 사본·정확한 명세·복구 확인 뒤 수행한다. 이 작업은 도구 구현과 가짜 자료 검토 DB 검증이다.
- D3 내부: 첫 대상은 기존 검토 승인/원자료 release에 연결되어 원출현 변경이 차단된 자료판뿐이다. 직접 수정 가능한 옛 자료·생성 명세·g12-long-reading 특수 목록 갱신 대상은 이 단계에서 처리하지 않고 M08 잔여 목록에 남긴다. 운영 읽기에서27개 모두 원출현과 배열이 일치했고 그 중20개 검토 자료의 entries JSON text는32,819,561B다. 물리 용량이 아니다.
- D4 내부: 헤더는 기존 package_json에 남기고 entries 대신 명시적 참조 표시를 둔다. 작은 표에는 원래 source_row 순서·원패키지 확인값·헤더/참조 확인값·원행/고정열 확인값과 상태만 둔다. 다른 열·원출현 package_entry_json/audio_json·검토 bundle/payload는 바꾸지 않는다.
- D5 내부: 기존 자료는 있는 그대로 반환하고 참조 표시가 있는 자료만 불변 원출현에서 원래 배열 순서로 재조립한다. 배열 수·키 중복·원문 전체 확인값이 다르면 명시적으로 실패한다. 원행 전체 hash로 상위 전체문서 hash를 대체하지 않는다.
- D6 내부: 현행 importer의 기존 package_json 비교와 현행 오답 자료 확인 함수의 release 직렬화만 호환 읽기로 바꾼다. OID·서명·권한·설정·M02 문항 복원 등을 유지하는 정확한 치환을 검사한다. 범위판 함수는 변경하지 않는다.
- D7 내부: 현재 검토 등록기와 같은 dataset_key/9129 잠금 뒤 대상 release와 원출현을 잠근다. 한 건·원행16MiB/파일32MiB·statement30초/lock1초·READ COMMITTED를 요구한다. 새 요청의 현재 행을 다시 검사하고 동일 완료 요청은 처음 응답을 반환한다. 늦은 낮은 키는 새 목록으로 찾는다.
- D8 내부: package_json만 거래/연결/원행/다음행에 고정된 한 번 허용으로 바꾼다. 해당 release trigger만 바꾸고 기존 공용 보호 함수/원출현 보호는 보존한다. 정상 status/retired_at_utc 변경은 유지하며 복구가 이 값을 예전으로 되돌리지 않는다. 파일 원행 hash는 사본 검증에, 현재 고정열/본문 hash는 전환 검증에 따로 쓴다.
- D9 내부: 원래 PostgreSQL JSON 문자열을 모든 Git 밖 접근 제한 파일에 fsync하고 다시 읽어 확인한다. 실제 API 대상 환경은 호출자가 확인하고 DB는 검토 승인 환경과 대조한다. 앱은 외부 파일을 읽지 않는다. 실패하면 거래를 취소하며 학생 기록/DB 전체를 과거로 복원하지 않는다.

준비 응답 유실/파일 쓰기 실패는 원문이 남아 있는 prepared/restored 상태에서 같은 준비 응답을 재발급한다. 최초 status/retired_at_utc 두 값만 작은 명세에 보존하고 현재 고정열/본문이 같을 때 최초 원행 문자열·확인값을 재구성한다. 최신 상태를 되돌리지 않으며 기존 파일 확인값도 무효화하지 않는다. 이미 축약된 자료는 기존 사본을 요구한다.

## 변경 영향과 검사

DB의 호환 읽기·운영자 전환/복구와 파일 도구·계약 검사는 변경한다. 현재 서비스 응답/캐시/학생 상태는 확인만 하며 UI·경로·표시 문구·화면 상태는 변경하지 않는 내부 도구다. 공용48시간·미사용 준비24시간·미접수 답 보존은 동일하다.

T1 새 SQL 직전 실제 월별/수능 등록·적용 전후 전열/조회 비교. T2 순서 변경/제외/추가 필드·큰 정수/한글·파일 변조/환경/크기/보호된 위치·재조립 실패/대상 제외. T3 실제 패키지 재등록·같은 판의 다른 본문 거절·오답 준비 전체 확인값과 저장/재전송·범위 version 유지. T4 진행 중 M05 최초/재시험 제출/재접수와 새 답 이후 부분 복구·비대상 전열 보존. T5 실제 두 연결 등록/오답 저장/폐기/같은 요청·늦은 확정·취소·권한/보호. T6 관련 회귀·전체 검사·타입/린트/지도/구조/빌드·검토 DB 보존/가짜 종료·독립 검토.

운영 원고를 Git이나 가짜 테스트로 복사하지 않는다. 실제 보관/전환/복구와 물리 회수의 완료는 각각 분리한다.
