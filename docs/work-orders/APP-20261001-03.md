# 시험 준비와 문항 전환

- 요구: R1 정오답 100ms·준비가 늦을 때만 블러. R2 최초 준비 뒤 실제 시간 시작.
- 승인: 2026-10-01 현재 대화. 선택 20ms, 기존 채점·포인트·발음 우선순위 보존.
- 결정 D1~D4와 검사 T1~T5는 같은 번호의 JSON 기록이 기준이다.
- 순서: 설계 검사 → 전환과 준비 구현 → 격리 DB/화면 검사 → 독립 검토 → 완료 근거. 화면 고정 APP04, 운영 반영 DEPLOY02와 분리.
- 준비값은 실제 응시가 아니다. 준비 전에는 응시/답/점수가 생기지 않고 실제 시작은 서버에서 한 번만 확정한다. 중복 ready로 시간 연장하지 않는다.
- 자료에 없는 발음·예문은 이 작업에서 추측해 넣지 않는다. 특정 미연결 항목은 앞 진단의 확인 불가 상태를 유지한다.
- 화면이 JS 실행으로 완전히 멈춘 동안에는 새 로딩 표시도 그릴 수 없다. 필수 코드·자료를 먼저 준비하고, 통신 대기에는 자리 고정 안내를 사용한다.
- 100ms 경계에서 정상 다음 문항 응답이 도착했고 서버 시작 예약만 100ms 이하로 남았다면 기존 정답 표시를 잠시 유지한다. 입력과 음성은 실제 시작까지 잠그며 추가 대기나 시간 차감은 만들지 않는다. 응답 미도착·복구·긴 예약에만 블러를 표시한다.

## 검사

T1:100ms 빠른/느린 전환·선택/복구·준비 UI.
T2:타입/lint/기능 지도/작업 기록/빌드.
T3:독립 검토.
T4:격리된 가짜학생 실제 브라우저.
T5:최종 SQL 스키마에서 준비·최초시작·재시도·권한·원기록 보존.
