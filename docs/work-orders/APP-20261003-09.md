# 새 배정 문항의 중간 본문 저장 제거

승인된 M02/M09의 같은 저장 보완이다. [OPS02 D7](OPS-20261003-02.md)과 [제출 기록 보완 뒤 실측](../verification/OPS-20261003-02_제출기록보완후_결과.md)을 입력으로 한다. 최종 행의 열·학생 기록·보관 기간은 바꾸지 않고, 신규 구성 문항을 큰 본문으로 저장했다가 참조로 다시 쓰는 중간 단계를 없앤다. 현재 상태·순서는 루트 대장만 따른다.

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 처음부터 참조 저장 | INSERT 직후부터 본문은 비어 있고 공용 내용 키가 있다. 구성 배정 생성 중 해당 문항 UPDATE는0회 | T1/T2 |
| R2 내용과 결과 보존 | 같은 원문·보기·정답·순서·확인값·뜻 연결을 복원. 학생 시험·오답·포인트·재접수 동작 유지 | T1/T2/T4 |
| R3 보호와 취소 보존 | 출처·중복 보기·모호성·권한·기존 트리거를 유지. 실패한 생성은 공용 내용까지 전부 취소 | T3/T4 |
| R4 기존 자료 불변 | 이전 행 일괄변경0. 일반/오답장/과거 본문 복구 경로 보존. 함수OID/ACL/설정 유지 | T1/T4 |
| R5 효과와 한계 확인 | 동일32회 계측을 별도로 기록. 중간 쓰기 감소와 실제 공간 감소를 구별하며 로컬/검토/운영 구분 | T5 |

## 결정

- D1 사용자: 공용 본문과 개인 기록의 중복을 줄이고 배정·완료·점수·최초/재시험·오답·포인트·기기 미확인 답을 보존한다. 유지보수 완료·계속 진행 승인과 OPS02 D7의 누락 보완이다.
- D2 사용자: 시험 중 호출0, 종료 제출, 기한 안 기록한 답의 늦은 제출·원기기 재개·미확인 답 자동 삭제 금지, 공용48시간·미사용 준비24시간은 유지한다.
- D3 내부: private.register_new_composition_question_ref_v1 트리거 함수를 BEFORE INSERT에 연결한다. composition_verified_v1이고 내용 키가 없는 행만 기존 본문 검증·공용 등록 함수를 호출한다. 기존 출처/보기 보호 뒤, 기존 zzz_freeze 전 이름 순서로 실행하여 기존 freeze가 본문을 비우도록 한다. 기존 freeze·복구 특례는 수정하지 않는다.
- D4 내부: private.create_composition_bank_for_delivery_v1의 저장 후 본문 검사 두 곳만 복원 뷰로 읽는다. 모호성 자기비교는 해당 배정 결과를 MATERIALIZED CTE로 한 번 모아 사용한다. 원 검토 출처와의 비교·FK/UNIQUE·순서별 문항 확인값은 그대로다. 마지막 finalize_assignment_question_body_refs_v1은 당시 뜻을 고정하므로 유지한다.
- D5 내부: 새 함수는 기존 freeze와 같은 SECURITY DEFINER/빈 search_path이며 PUBLIC/anon/authenticated/service_role의 직접 실행권한은 없다. 원래 공개 배정 함수의 인증·학생 잠금·원자료 검사 안에서만 사용한다. 신규 열·색인·외부 응답·개인 캐시는 만들지 않는다.
- D6 내부: 새 migration 한 개를 추가한다. 기존 생성 함수는 정확한 두 치환 지점 확인 후 CREATE OR REPLACE하며 OID/소유자/ACL/설정은 유지한다. 복구는 새 트리거만 제거해 이전 INSERT→finalizer 경로로 돌아갈 수 있다. 복원 뷰 검사와 기존 두 저장형 판독기는 유지하며 새 참조행을 삭제하지 않는다.
- D7 내부: 로컬 PGlite로 먼저 검증하고 같은 SQL을 승인된 검토 DB의 작은 가짜 자료에만 적용·대조한다. Windows initdb·원격 대량 부하·운영 학생 쓰기·운영 배포·물리 재작성은 없다. 정리 주기/무작위키에 따른 페이지 차이 때문에 측정 전 절감량을 확정하지 않는다.

## 영향과 화면 상태

DB 저장 시점과 본문 검사 입력만 바뀐다. UI·경로·스타일·브라우저 상태·API·채점 계산·캐시·점진표시는 확인만 하며 변경하지 않는다. 일반 단일/일괄·예약·정확 오답·혼합 배정에서 구성 문항을 만드는 공통 함수가 대상이다. 운영상 비활성 관리자/소유권 정책은 F02 범위이며 여기서 바꾸지 않는다.

생성 실패는 기존 배정 화면에서 `단어 시험을 배정하지 못했습니다.`로 처리하고 입력을 보존한다. 성공 여부가 불확실하면 기존 요청 키·목록 확인으로 복구하며 무조건 새 배정을 만들지 않는다. 출처 오류를 빈 문항이나 성공으로 바꾸지 않으며 SQL 원문을 화면에 보이지 않는다. 성공/실패/권한/정상 빈 목록 등 기존 상태는 바꾸지 않는다. 순수 DB 저장 보완이므로 새 화면·실기기 음성 검사는 해당 없음이며 기존 API/화면 오류 대응의 회귀 검사를 실행한다.

## 검사

- T1: 적용 전 생성한 가짜 배정·본문·뜻·함수 속성 보존, 변경 전후 동일 원자료의 복원 전체 행 비교(개인 식별자·생성시각 제외), 기존 원문 확인값 유지.
- T2: AFTER INSERT/UPDATE 관찰로 최초 참조형·본문 없음·갱신0 검증. 50문항×100개 별도 배정에서 공용50·연결5000·뜻 연결5000, 준비/응시 본문 동일.
- T3: 잘못된 출처·중복 보기·모호성 검사, 후반 실패 시 배정/공용 내용/뜻 연결까지 전부 취소. 변조 참조·본문 수정 거절, 앱 역할 직접 실행권한0, 실행 순서 확인.
- T4: 일반/오답장·예전 준비·기기 계획·결과/오답/포인트·동일 재접수·M08 선택 복구의 관련 회귀, 적절한 전체 검사·타입·lint·지도·빌드. 검토 DB 기존행 보존·가짜 종료와 실제 공유 충돌 두 연결은 기존 공용 등록기를 새 삽입 시점에서 확인한다.
- T5: 기존 M09 원자료를 보존한 별도32회 측정·근거/입력 확인값·독립 검산. 제한 때문에 미실시한 원격 부하를 통과로 올리지 않는다.

트리거의 같은 이벤트 내 이름 순서와 BEFORE/AFTER 관찰 기준은 [PostgreSQL 공식 설명](https://www.postgresql.org/docs/current/sql-createtrigger.html)을 확인했다. 새 저장형은 도입하지 않으며 두 본문 검사의 복원 소비자를 함께 고치는 것이 구현 경계다.
