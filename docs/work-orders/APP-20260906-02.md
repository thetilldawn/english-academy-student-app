## 설계·영향

- dataFlow: 로컬 시작기→기존 Next 배포형 앱→현재 인증/서버 query→로컬 허용 목록 가짜 인증/읽기 응답. 브라우저는 실제 Next Link/API/모달, 실제 DB는 호출하지 않음. 생성/배정/수정/삭제 제출은 기존 대체 의존성 회귀에서만 검사.
- 검사 도구는 업무 기능이 아니므로 회귀 파일은 공용 `src/test-support/local-admin-baseline.test.mjs`에 둔다. 기능 지도상의 공용 검사 소유권과 경로 지문을 함께 갱신한다.
- reuse: 실제 앱 및 기존 flow/controller/계약 검사 재사용. 테스트 도구만 시작·응답 fixture·네트워크 보호로 분리. 앱에 만능 검사 모드나 인증 우회 Route 추가 없음.
- cache: 기존 Next/React 요청 재사용을 그대로 관찰. 개인 공유 캐시/새 TTL/저장소 없음. 응시/타이머/포인트/권한의 최신성 보존. 가짜 RPC 카운터를 실 DB/비용 감소로 표현하지 않음.
- compatibility: Next 16.2.12/React 19.2.8/Node 24.19.0 설치 유지. 이전 APP-20260906-01 및 미커밋 문서/검사 기록 보존. 알려지지 않은 요청은 가짜 성공으로 감추지 않고 실패 처리.
- rollback: 로컬 시작기/검사 탭 종료. 검사 전용 새 파일만 역패치 가능. 이전 앱 코드·실제 자료·DB·사용자 변경은 일괄 삭제하지 않음.
- 앱의 routing/state/domain/data/api/cache/asyncUi/security/styles는 확인만 한다. 1-A는 ui의 입력 계약과 tests만 변경하며 화면 동작은 유지한다.
- 새 검사 도구의 HTTP 자료는 가짜다. 실제 관리자 권한·DB 비용·운영 속도의 검증으로 표현하지 않는다.
- 기존 학생 등록 접힘의 두 SELECT는 코드상 기준일 뿐 실 DB 비용 측정이 아니다.
- 실제 앱의 로딩/없음/오류/로그인/404 경계는 변경하지 않는다. 0단계 도구는 제품 UI가 아니라 로그/계측 명령이며
  신규 상태 문구를 정의하지 않는다. 실제 화면의 원문 오류나 모순 발견 시 관찰 기록으로 남기고 임의로 다른 기능 수정에 섞지 않는다.
- 모의 응답은 현재 최소 계약만 제공하며 모르는 경로는 실패한다. 환경 파일이 있거나 실행 대상/호스트가 로컬이 아니면
  도구 시작을 거절한다. 임시 세션의 계측에는 개인 정보·토큰·원문 응답을 남기지 않는다.
- 설계 검토 비교: Preview fixture는 실제 DB 쓰기가 있어 제외. 별도 단순 SPA는 실제 Next Link/RSC를 측정하지 못하므로
  부품 시각 검사와 구분. 기존 Next 앱 + 로컬 가짜 HTTP 경계를 선택한다.

## 실행 검사 계획

- T1 (unit): 환경·루프백·요청 허용 목록·가짜 자격·쓰기 차단·표본 통계·계측 분류. 예상: 원격/실환경/알 수 없는 경로/쓰기 거절, 10회 표본의 정확한 중앙값/p95와 분리된 카운트.
- T2 (integration): 단일/일괄/오답/수정·날짜 없는 분할·반복 초과/축소·잠금·취소·재선택·실패 안내 기존 회귀. 예상: 검사 파일/수치/코드 근거 고정, 업무 동작 변경 없음.
- T3 (browser): 가짜 데이터의 실제 Next 첫 진입/Link 왕복/뒤앞/모달/필터, 사전 로딩 포함 요청·바이트/JS/표시 대기 분리, 조건별 10회. 예상: 실제 동작으로 기준 확인. 가짜 RPC/브라우저 호출 지연과 실 DB 미측정을 구분. 실행 실패는 통과로 기록하지 않음.
- T4 (review): 로컬 격리·범위·기존 연결·누락과 결과 과장 독립 검토. 예상: 미해결 중대 지적 0, 새 사용자 미결정이 있으면 구현 보류.
- T5 (build): 관련/전체 검사·타입·lint·구조·요청 캐시·빌드·문서/해시 연결. 예상: 실제 실행 통과와 현 코드 일치. 빌드 전 검사가 해당 빌드 완료 결과를 요구하지 않음.

- T2: 기존 assignment-flow-contract.characterization, assignment-request-contract.characterization,
  vocab-assignment-plan/planner-state/screen, direct-review-flow-adapter, edit-assignment-ui.contract,
  assignment-workspace 등의 실제 검사를 로컬에서 실행해 연결한다.
- T3: 준비 실행 후 10회 중앙값·상위95%를 원자료와 함께 기록. 클릭 시각/첫 유효 화면·RSC/목록 API/인증/가짜 RPC·바이트·JS를 분리한다.
  로컬 프록시에서만 DOM 관찰 스크립트를 삽입해 실제 입력 이벤트부터 가짜 목록/모달의 표시까지 기록한다.
  도구 호출 왕복 시간은 화면 속도로 쓰지 않는다. 관찰 스크립트와 로컬 프록시가 포함된 비교 환경이며 운영 수치가 아니다.
  실패·표본 부족·로컬 DB 없음은 명확히 남기며 실 DB 비용 개선으로 완료 판정하지 않는다.
- 읽기 전용 독립 검토 결과: 범위 입력은 작은 계약으로 분리 가능, 일정은 계산/상세/템플릿을 포함하므로 별도 후속 묶음.
- 공식 기준: [서버/브라우저](https://nextjs.org/docs/app/getting-started/server-and-client-components),
  [필요할 때 코드 로딩](https://nextjs.org/docs/app/guides/lazy-loading),
  [탐색/사전 로딩](https://nextjs.org/docs/app/getting-started/linking-and-navigating).

- 기존 변경 감지와 “입력한 배정 내용을 버리고 닫을까요?” 경고를 유지한다. 문구는 기존 한국어 내용 모음의 `adminLearningText.discardAssignment`가 소유한다.
- ‘계속 작성’·Escape·바깥 클릭·상단 닫기는 확인창만 닫는다. 부모 배정 폼을 유지하며 입력·선택·스크롤을 보존한다. 첫 초점은 ‘계속 작성’, 취소 뒤 초점은 원래 위치로 복귀한다.
- ‘버리고 닫기’만 저장 중 여부를 다시 확인한 뒤 기존 닫기를 한 번 호출한다. 확인창은 부모 폼 밖의 형제로 표시하며, 열려 있는 동안 부모 제출을 차단한다. 단어장 찾기 취소와 저장 잠금은 그대로다.
- 내부 표시 방식 변경으로 업무·보존·공개·비용·배포 결정은 변하지 않는다. 읽기 전용 독립 검토에서 추가 사용자 결정이 필요하지 않음을 확인했다.
- T8: 단일/일괄/오답의 변경 감지, 미변경 즉시 닫기, 취소 시 입력 보존, Escape/바깥 클릭, 초점, 중복 닫기와 저장 차단을 검사한다. T2/T4/T5를 재실행하고 T7은 새 로컬 빌드의 실제 확인창으로 별도 검증한다. 이전 기본 확인창 실패를 통과로 고쳐 쓰지 않는다.
