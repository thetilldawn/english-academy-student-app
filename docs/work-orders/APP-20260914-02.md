# 학교 일정 월별 표시와 영어 시험일 구분

## 요구와 결정

R1 / D1 / T1,T4: 사용자 후속 요청에 따라 모든 수행·지필·수능 행의 왼쪽 색상 바를 표시한다. 색상은 기존 초록·노랑·보라와 유형 글자를 유지한다. 아래 학습 기록처럼 둘레 테두리를 제거하고 같은 여백·호버 배경·접기 패턴을 사용한다.

R2 / D1 / T1,T4: '이후 일정 n개 날짜 묶음'을 없애고 월별로 독립 접기·펼치기를 제공한다. 한국의 당월은 펼치고 미래 월은 접는다. 연도가 다르면 연도도 표시한다. 가까운 일정은 월 안에서 표시하며 중복 복제하지 않는다.

R3 / D2 / T1,T2,T3,T4: 영어 지필시험일과 학교 전체 시험기간을 분리한다. 지필의 별도 subjectDate만 날짜 정렬·겹침·남은 일수에 사용한다. 미확인은 null이며 기존 startDate/endDate/precision/dateText는 학교 전체 기간의 설명으로 보존한다. 수행·수능의 기존 날짜 의미는 유지한다. 학교기간만 있는 과거 응답·개인 캐시도 영어 날짜로 오인하지 않는다.

R4 / D2 / T2,T3,T4: 수동입력에서 지필의 영어 시험일을 별도로 수정하고 학교 시험기간은 별도 설명 필드로 둔다. 지필 외 일정에 영어 시험일을 저장하지 않으며 미실시에는 날짜를 저장하지 않는다. 원천 없는 경우에도 실제 영어 날짜만 입력할 수 있다. 현재 관리자 검증·요청 중복/충돌·원천 보존·수동값 우선·저장 결과 확인을 유지한다.

R5 / D3 / T1,T4: 공식 월 근거가 있는 미정 일정은 해당 월의 '날짜 확인 필요'에 둔다. 지필 학교기간이 한 달 안에 있거나 수행 원문에 월/주차가 명시된 경우만 해당한다. 정확한 일자를 만들지 않는다. 월 근거가 없거나 여러 달에 걸친 미정 일정은 별도 '날짜 확인 필요'에 둔다. 진행 중인 월경계 일정은 당월에 한 번만 표시한다.

D1 사용자 확정: 현재 대화의 색상 바·아래 리스트와 스타일 일관성·9월 열기/10월 이후 닫기 요청.

D2 내부 설계: 하위 호환되는 선택 필드 subjectDate를 추가한다. 기존 학교기간은 원문 그대로 보존한다. 영어 날짜는 확인된 날짜 또는 관리자 입력한 날짜만 허용한다. 지필 기간의 상태와 영어 날짜 확인 여부는 분리하며 영어 날짜가 있으면 기간이 미확인이어도 일정 표시가 가능하다. 새 테이블·권한 확대·학생 기록 변경은 없다.

D3 내부 설계: 월은 정리용 단위이며 시험 날짜의 근거로 사용하지 않는다. 명시된 월 이외 추론·상식으로 날짜를 배정하지 않는다. 기존 CollapsibleStatusSection의 키보드·접기·모션 처리를 재사용하고 학생과 관리자가 같은 계산을 사용한다. 새 라이브러리는 추가하지 않는다.

## 경계·화면·검증

등록 자료→엄격한 계약→본인/관리자 조회→실제 평가일 계산→월별 표시. 편집은 기존 경로형 모달·초안 보호와 저장 절차를 사용한다. 공유 캐시는 만들지 않고 기존 개인 캐시는 선택 필드 없는 자료를 안전하게 읽는다. 등록과 수동 저장 양쪽 DB 검증을 함께 맞춘다. 원본·기존 수동 이력·학생 데이터는 보존한다.

미정에는 '영어 시험일 확인 필요', 기간 설명에는 '학교 시험기간'을 사용한다. 월 빈 결과는 '등록된 일정이 없습니다.'이며 서버 실패는 기존 재시도 안내를 유지한다. 월 제목과 버튼은 접힌 내용의 링크까지 포커스되지 않도록 기존 공용 패턴을 사용한다.

T1: 실제 영어 날짜 우선·미정/과거 기간·월경계·같은 날짜 여러 유형·월별 초기 상태·집계·학생 표시.
T2: 선택 필드 SQL 검증·잘못된 날짜·지필 외/미실시 거절·원천/수동 버전 및 권한 회귀.
T3: 편집 왕복·영어 날짜만 입력·기간 보존·종류 변경·저장/충돌/응답 유실·개인 캐시 회귀.
T4: 가상 자료의 PC·모바일·두 테마, 월 열기/닫기·행 스타일·수동 모달/날짜 입력·앞/뒤 탐색. 실제 학생 쓰기는 하지 않는다.
T5: 타입·lint·지도·R/D/T·전체 회귀·빌드·독립 검토. 운영 반영과 공식 원천 갱신은 별도 근거로 기록한다.

## 별도 후속

공식 날짜 일일 확인 루틴과 공용 갱신 지시서는 OPS-20260914-01에서 관리한다. 확인 시간 제안은 앱 표시 구현의 결정과 분리한다. 배포는 검토한 코드와 날짜 계약을 같은 버전으로 반영한 뒤 읽기로 검증한다.
