# 단어장 인증 조회 오류와 입력 보존

기준 dcca168. 단어장 API가 `getAdminContext`의 일시 장애 반환값 null을 비로그인 401로 응답한다. 클라이언트는 401을 받으면 개인 자료를 숨기면서 구성 입력도 닫는다. 초기 조사 당시에는 요청 로그를 확보하지 못했으며, 아래 후속 근거에서 운영의 인증 지연→401 사례를 확인했다.

## 요구와 결정

- R1: 인증 서버 지연·장애는 503과 기존 재시도 안내로 응답한다. 실제 로그인 없음 401, 관리자 불일치 403, 인증 실패 후 조회·저장 0은 유지한다. T1/T2/T3.
- R2: 인증 조회 장애 이후 템플릿 이름·범위 입력을 유지하고 읽기 재시도로 복구한다. 저장 결과가 불명확하면 기존 동일 요청 확인만 허용한다. 성공 전 저장 완료라고 주장하지 않는다. T1/T2/T3. 기존 범위 패널은 미리보기 실패 중 ‘0개 범위’를 표시할 수 있으며, 이 표시 문제까지 해결했다고 주장하지 않는다.
- R3: 기존 조회·저장·생성·오류 코드·개인 응답 no-store를 보존한다. 원자료·DB 구조·학생 배정·응시 동작은 이번 수정에 포함하지 않는다. T1/T2/T3/T4/T5.
- D1(사용자 기존 승인): 범위에 맞춘 템플릿 생성과 배정을 정상 완료한다. 새 제품 선택 사항은 없다.
- D2(내부): 단어장 API의 기존 try 안에서 `getAdminContextOrThrow`를 사용한다. 인증 공통 helper나 화면의 401/403 보호를 약화하지 않는다. 기존 503 문구·재시도·멱등 복구를 재사용한다.
- D3(내부): 운영 기준 격리본에서 로컬 수정·검증한다. 별도 미배포 시험 시간·음원 변경과 섞지 않는다. 새 API·DB migration·환경 변수·패키지 변경은 없다.

## 영향과 상태

경로/페이지·UI/스타일·브라우저 입력 상태·순수 계산·서버 조회/저장·DB·캐시 보관 코드는 확인만 한다. Route Handler 인증 오류 분류와 두 서버 검사, 입력 보존 검사를 변경한다. 개인 응답 no-store·인증 전 자료 미노출·401/403 차단을 유지한다. 로딩/빈 결과/404/422/409와 취소된 조회의 늦은 응답 처리는 기존 검사를 재실행한다. 응시·채점·배정·자료 삭제 정책 변경은 해당 없음이다.

조회 실패는 해당 범위 패널에 ‘자료를 불러오지 못했습니다. 다시 시도해 주세요.’를 표시하고 ‘다시 불러오기’로 복구한다. 입력은 유지한다. 저장 결과 불명확은 ‘저장 결과를 확인하지 못했습니다. 같은 내용으로 다시 확인해 주세요.’와 동일 요청 확인을 유지한다. 실제 인증 실패에는 기존 로그인 안내와 개인 자료 숨김을 유지한다.

## 검사와 완료 조건

- T1: legacy GET/POST의 인증 장애 503, 실제 401/403, 업무 RPC/생성 호출 0, no-store와 내부 오류 비노출.
- T2: query/commands의 동일 검사와 기존 200/404/409/422·멱등 결과·진행 헤더 보존.
- T3: 가짜 자료 화면에서 편집 중 읽기 503 후 이름/범위 유지·재시도 성공, 실제 401/403 차단, 저장 결과 불명확 복구. 인증 helper·상위 배정 경계·취소/늦은 응답 기존 회귀 포함.
- T4: 타입/lint/빌드·지도/구조·설계 및 변경 연결 확인.
- T5: 읽기 전용 독립 검토. 운영 요청 로그와 실제 운영 저장/학생 배정은 로컬 검사와 구별한다.

실행 근거와 입력 확인값은 같은 번호의 작업 기록 JSON과 검증 문서에 남긴다. 운영 접근 권한이 복구되기 전 외부 반영 완료로 표시하지 않는다.
