# 내역 변경 뒤 중복 조회 제거

- R1: 같은 범위/정규검색/상태/변경영수증에 구역3개 갱신도 전체첫목록 HTTP/RPC1회. 구역별 상태·빈 결과·읽기실패·커서는 기존 책임을 유지한다.
- R2: 개인 캐시가 아닌 진행요청 합침. 한 소비자 취소는 다른 요청을 취소하지 않으며 마지막 소비자/화면해제 때만 취소한다. 완료/실패 뒤 새 시도는 실제 요청이고 늦은 응답은 적용하지 않는다.
- R3: 새 DB 스냅샷은 변경 영수증보다 빠르면 거절한다. 구역/조건 계약 검증, 인증실패 전체숨김, 변경 뒤 옛행/개수/커서 제거, 실패한 변경을 재실행하지 않는 기존 정책을 보존한다.
- D1 사용자: 기존 캐시개선 우선, 단어 가리기 마지막. D2 내부: HistorySectionGroups 수명에 조정기1개를 만들고 readFreshSection만 하위 제어기에 주입한다. 전역 자료저장소/DB변경/새endpoint는 없다. D3 내부: 학생 저장소의 공동요청 소비자취소 helper를 lib/network로 추출해 학생/내역에서 재사용한다. 포인트/조건/권한 판단은 공통 helper에 넣지 않는다.
- T1 요청 합침/부분·전체취소·옛요청·실패재시도. T2 구역3개 실제부품+전송경계→1조회/정상빈결과/권한숨김/버전거절/커서폐기. T3 학생회귀+전체/타입/lint/구조/빌드.
- 생성/배정/응시/수정/삭제/기록 쓰기는 기존 기능으로 유지하며 이번에는 읽기만 최적화한다. 정상0/실패는 기존 HistoryReadFailure/EmptyState를 재사용한다.
- 내역 첫페이지 재방문 보관·신호/인증/성능 검증은 별도 다음 기록에서 시행한다. 이 작업만으로 내역 개인 캐시가 완료됐다고 하지 않는다.
- D4: DB 시각은 소수초/시간대 정밀도를 보존한다. 공동요청 소비자는 작은 참조 배열로 관리해 이탈을 한 번만 반영한다. 기존 자동 도구의 delete 메서드 탐지는 Set 제거도 DB삭제로 오인했으며 예외목록이나 검사기를 약화하지 않았다. 동적 가져오기 첫 컴파일의 검사 전용 대기만5초로 맞추며 앱 지연은 추가하지 않는다.
