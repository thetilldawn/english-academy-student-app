# 기존 자료 이전·복구 검증 — M08-A 실행 명세

사용자가 승인한 전체 유지보수 순서의 M08-A다. 현재 상태는 루트 대장만 관리한다. [원 지시](20261001_공용사전과학생기록_유지보수/08_기존자료이전과_용량회수.md)와 [M07 결과](../verification/APP-20261003-01_검증결과.md)를 입력으로 삼는다.

## 요구와 확인

| 요구 | 결과 | 확인 |
|---|---|---|
| R1 | 운영 읽기 기준선·표/열별 대상·제외·호출자와 사본 | T1 시각/최대 사건/수량/바이트/참조 누락, 사본 SHA-256 및 권한 |
| R2 | 새 SQL 적용 전의 가짜 자료에서 참조 전환·읽기 동일 | T2 기존 ID/FK/정답/발음/선택 뜻/오답/정책판/완료 응답 비교 |
| R3 | 중단·재시도·늦은 확정과 새 답 누락 방지 | T3 짧은 배치 취소/재실행, 원행 키+원행 판, 실제 두 연결 |
| R4 | 최근 답/결과를 유지한 선택적 복구 | T4 파일 사본 실제 재읽기, 필요한 본문/참조만 복구, 새 결과 불변 |
| R5 | 실제 비용·공간과 다음 단계 입력 | T5 내용량/관계/인덱스/전체 DB/최대 임시공간 구별, 운영 정리0 |

## 결정과 경계

- D1 사용자 확정: 학생 완료/미완료·배정·최초/재시험·오답과 원자료/공용 학습값을 보존하며 중복 본문만 줄인다. 승인된 M01~M08 요구가 근거다.
- D2 사용자 확정: M08-A는 격리 검증이며 운영 정리 M08-B는 배포·정확한 명세·복구 확인 뒤 별도로 수행한다. 기존 승인 순서를 변경하지 않는다.
- D3 내부 설계: 운영에서는 수량·크기·참조 상태·함수 확인값만 우선 읽는다. 실제 학생/교재 원문을 Git·채팅·앱 테스트에 복사하지 않는다. 로컬 사본은 자료 구역에 두고 접근 범위를 확인한다.
- D4 내부 설계: 기존 createFinalSchemaDatabase.beforeMigration과 구형 501항목/500처리 중단 검사를 재사용한다. 참조 연결 시 본문을 즉시 비우는 M02 함수는 이 단계에서 운영에 호출하지 않는다. 현재 보호 함수를 끄는 복원은 금지한다.
- D5 내부 설계: 과거 자료의 일괄 이전/복구 도구가 이미 완성됐다고 가정하지 않는다. 적용 전 자료→사본→참조 후보 대조→제한된 전환→읽기 비교→새 답→부분 복구를 각각 확인한다. 필요한 제품 보완은 별도 APP 기록으로 연결한다.

업무 정책 미결정은 발견되지 않았다. 읽기 조사 뒤 정확한 처리 명세를 고정하고 실행하며, 일반 조회 결과를 보존/복구 완료로 표시하지 않는다.
