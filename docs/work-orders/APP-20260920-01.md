## 데이터와 저장 설계

### 2026-09-20 온라인 등록 연결 보완 (R3,R4,R7 / D12 / T7,T8)

검토한 구성은 범위 ID·판·순서가 고정되어 있지만 화면에서 그 준비본을 불러오는 연결이 없었다. 목록의 표시 순서대로 다시 담으면 준비본의 순서와 달라질 수 있다. 기존 새 템플릿 편집기에 `준비한 구성 불러오기`를 추가한다. 읽기는 저장하지 않고 이름·태그·범위와 순서를 미리 보여 주며, 사용자가 기존 `템플릿 저장`을 누르면 정상 관리자 세션의 같은 API를 호출한다.

D12 내부 결정: 기존 create 계약만 받아 새 범위·권한·서버 기능을 추가하지 않는다. 파일은 최대2MB, 준비본의 실제 범위 ID·판과 현재 이용 가능 여부를 기존 선택 계산으로 검사한다. 현재 목록에 없는 범위 ID·다른 판·사용 불가 범위·생성/수정 명령은 거절하고 기존 편집 입력을 보존한다. 범위가 비어 있는 미확정 틀은 대조할 원자료가 없으므로 어느 환경에서 만든 것인지 판정하지 않는다. 같은 준비본의 요청 번호로 저장·재확인하며 사용자가 내용을 바꾸면 새 요청 번호를 사용한다. 읽는 동안 입력을 잠그고 이전 읽기/화면 종료의 늦은 응답은 반영하지 않는다. 데이터/API/DB/권한은 확인만, UI·입력 상태·연결과 T7/T8만 보완한다. 오류는 `준비한 구성을 읽지 못했습니다. 현재 자료에 맞는 파일인지 확인해 주세요.`로 안내하고 원인을 내부 오류로 노출하지 않는다.

원범위는 검토한 등록판·부모 단원·실제 원행·파일/범위 확인값·분류와 상태를 가진다. 등록기는 기존 `legacy_vocab`, `exam_use`, `reviewed_exam`를 실제 원자료 종류로 검증한다. 관리자는 등록된 범위의 ID·버전을 고르며 원자료나 사전 값을 수정하지 않는다. 하나의 부모 단원에 여러 부분 범위가 있어도 원행을 한 번만 포함한다.

템플릿은 표시정보와 불변 내용 버전을 나눈다. 저장 조건, 명시 추가/제외, 순서와 당시 해석한 범위를 버전에 둔다. 구성 변경은 기대 버전과 기존 구성 확인값을 검사해 한 거래에서 새 버전으로 저장한다. 동일 요청 ID는 같은 결과를 반환하고 다른 요청 내용의 재사용은409로 거절한다. 기존 자료가 갱신되면 차이를 확인해 다음 버전을 만든다.

실제 단어장은 구성에서 새 dataset/unit/entry와 출현 참조를 만들고, 기존 dataset을 덮어쓰지 않는다. 원출현·뜻·품사와 선택한 발음·보완 정보를 고정한다. 사전 의미의 동일성은 검토된 키가 있을 때만 시험 범위 선택 후 정리하며 철자만으로 합치지 않는다. 새 구성을 일반 학교 등록판이나 검토된 사전 항목으로 표시하지 않는다.

문항에는 `generated_meaning`과 `reviewed_item`의 출처를 구별한다. 일반 뜻 문제는 기존 `createExplicitTargetedQuizQuestions`의 모호성·적격성·4보기 검사를 재사용한다. 학교 문항은 원문항 ID·해시·보기·순서·정답 위치를 보존한다. 정답 대상은 구성 entry로 대응하고 범위 밖 보기의 원출처와 선택 음원은 별도 참조로 보존한다. 한 시험의 구성용 묶음과 각 원문항을 고정한 뒤 새 출처 증명 조건으로 저장한다.

자료의 원학년과 사용 대상, 시행연도와 수능학년도, 학습 회차와 문제번호를 혼동하지 않는다. 검색 결과에 현재 자료 상태·범위·원고 이름을 보여 준다. 수량은 원행·포함·검토/제외·실제 방향별 생성 가능 수를 구별한다.

## 경로·권한·화면 상태

기존 배정 창에서 공용 범위 선택을 사용하고 별도 전체 앱 페이지를 추가하지 않는다. 브라우저는 기능의 계약·선택 계산·상태·전송 계층을 이용하고, 서버는 관리자 인증 뒤 원범위 검증과 저장을 수행한다. 성공과 오류 응답 모두 `private, no-store`다. 창 수명 동안 입력을 보관하고 새 검색의 늦은 응답을 버린다. 저장 중 입력을 잠그고 결과가 불명확하면 동일 요청으로 확인한다. 관리자 권한이 바뀌면 이전 내용을 숨긴다.

## 구현 영향과 검사

범위 탐색/템플릿 조회·저장 계약과 서버, 부분 범위 저장·원출현/문항 참조 구조, 선택 UI와 상태, 배정/학습의 구성 참조 분기가 변경된다. 기존 학생 답 선택·시간·점수·세션 규칙은 확인만 한다. 새 공유 캐시·외부 공개·패키지 업그레이드는 없다. 실행 경로와 새 파일은 기능 지도에 연결한다.

T1 선택·제외·원행 중복·혼합 분류 / T2 표시 편집·버전·복사 / T3 DB 등록·검증·거래·멱등 / T4 원자료·발음·보완 참조 / T5 생성/학교 문항·보기 보존 / T6 배정·예약·학습·기존 시험 / T7 실제 컴포넌트와 화면 / T8 오류·권한·응답·복구 / T9 타입·lint·구조·회귀·빌드·독립 검토. 실행 결과는 검증 문서에 실제 시각·환경·확인값으로 남긴다.

기존 migration은 수정하지 않는다. CLI로 빈 파일을 만든 두 migration에서 단계별로 구현하며, 운영 적용은 이 지시의 완료 결과가 아니다. 되돌릴 때 새 진입을 중단하고 기존 고3 저장·기존 dataset/시험을 유지한다. 새 자료가 사용된 뒤에는 원출현과 문항 참조를 삭제하지 않는다.

공식 확인: [Supabase 함수와 권한](https://supabase.com/docs/guides/database/functions), [Supabase 변경 이력](https://supabase.com/changelog), [Next.js 요청 처리](https://nextjs.org/docs/app/getting-started/route-handlers). 설치 Next16.2.12·React19.2.8·Supabase JS2.110.8에 맞춰 기존 API를 재사용한다.
