# M09 · 무료 운영 인원과 관리자 수를 실측으로 검증

유형: OPS, 비용/성능 검사와 보고. 선행: 측정 대상 M01~M07 및 M08-A. 결정 D15. 사용자는 무료 유지·비상업적 이용을 전제로 요청했다. 요금제 변경·유료 부하 서비스·운영 학생 대상 부하 검사는 범위 밖이다.

## 1. 보고할 질문과 요구

**‘관리자 한 명당 무료 학생 수’라는 고정 할당은 없다. 같은 앱/DB를 쓰면 관리자들이 저장·전송·동시 처리 한도를 함께 사용한다.** 기술적으로 감당하는 학생 수와 교사가 확인·상담할 수 있는 학생 수를 분리해 보고한다.

| R번호 | 완료 조건 | 검사 |
|---|---|---|
| M09-R1 | 실제 요금제·DB 제한·전송/함수/인증 사용 범위와 시점 확인 | M09-T1 |
| M09-R2 | 공용 고정 비용·학생당 누적·월 전송·전환 중 공간을 별도 계산 | M09-T2/T3 |
| M09-R3 | 등록100명과 동시10/30명 등 측정 목표를 구별 | M09-T4/T5 |
| M09-R4 | 관리자1/3명의 배정·조회가 화면 진행·답 저장·공식 결과에 주는 영향 검사 | M09-T5/T6/T8 |
| M09-R5 | 확정 가능 범위와 미검증 한계를 인원 보고에 명시 | M09-T7 |

## 2. 비용 표에 넣을 실제값

조회 시각, 프로젝트/환경, 요금제, 데이터베이스/파일 저장/전송 한도의 공식 근거와 실제 잔여 사용량을 함께 적는다. 2026-10-01 분석의 Supabase Free DB500MB를 재사용할 때도 실행 시 실제 프로젝트 적용 상태를 확인한다. 현재 776.33MB와 무료 목표가 서로 맞지 않는 원인/운영 제한 상태도 별도로 확인한다. 다른 환경의 숫자를 섞지 않는다.

공식 확인 경로는 [Supabase 사용량](https://supabase.com/docs/guides/platform/manage-your-usage), [DB 크기](https://supabase.com/docs/guides/platform/database-size), [Vercel Hobby](https://vercel.com/docs/plans/hobby)다. 이 문서 작성에서 새로운 가격/한도 조사를 실행한 것은 아니다. 비용 보고 실행 때 현재 자료를 다시 확인한다.

| 항목 | 측정 방법 |
|---|---|
| 공용 고정 공간 | 사전 최소 사용값·원출처 색인·공용 세트판·관련 검색 구조 합계 |
| 학생 공간 | 배정·최초/재시험 결과·오답/해결 사건·현재 상태·포인트·필요한 개인 답안 |
| 기본/운영 공간 | 인증·활성 세션·보관 기간 내 로그·DB 시스템 기본 공간 |
| 임시 최고 공간 | 활성 응시·준비·이전·정리·실패 재시도 중 관찰된 최고값 |
| Supabase 전송 | 실제 DB/API/파일 응답 바이트·캐시 적용·월량 환산 |
| Vercel 사용 | 요청/함수·처리시간/CPU·메모리·전송 등 해당 계정의 실제 과금 지표 |
| 음원 | DB 텍스트가 아닌 파일 크기·출처 서비스·캐시 적중/실제 전송량 |

관리자 앱 계정 수와 Vercel 배포 팀 좌석 수를 혼동하지 않는다. 인원 계산을 위해 유료 좌석을 임의로 추가하지 않는다.

## 3. 저장 모형과 계산

기준 모형: 100가짜 학생 × 6개월 × 월20새응시 × 50문항. 최초오답20%, 그 오답의 재시험 실패20%. 별도 오답 시험도 월20회에 포함하며 더 많이 시행하면 그만큼 추가한다.

- 응시/결과12,000개, 최초 오답120,000 + 재시험 오답24,000 = 사건144,000개.
- 최초/정규 재시험 결과를 각각 보존하는 요약101B, 배정96B, 오답 사건112B, 단어 상태104B의 가짜 행을 측정한 과거 모형이 있다.
- 그 행 크기의 두 배 임시 예산에서 학생당 상태100/300/1,000행이면 총39.064/43.224/57.784MB였다. 두 배는 측정된 인덱스 상한이 아니다.
- **최종 스키마에 해결 사건·구간·권한·개인 선택 키가 더해지면 다시 측정한다.** 기존 모델 수치에 맞추려고 필수 필드를 빼지 않는다.
- M04의 기존 답안 보관분, 신규 오답 상세·미응답·요청 확인 키, 포인트·공용/기본 공간·음원/전송은 별도 더한다. 신규 정상 정답 문항의 장기 선택 상세 확대는 이번 범위 밖이다.

개선 후 계산식은 `고정 공용·기본 공간 + 학생수 × 기간별 실제 학생 기록 + 예상 새 공용 판 증가 + 임시 최고 공간 + 예비 공간`이다. 평생 고정 상태 수를 가정하지 않는다. 해결된 현재 카드가 없어져도 과거 사건은 쌓인다.

같은 세트1개를 1/10/100명에게 배정해 공용 본문 증가0과 개인 증가량을 분리한다. 학생마다 다른 세트를 쓰는 경우도 별도 측정한다. 관리자 수가 늘면 공용 세트 재사용률과 동시 배정 양이 달라질 수 있다.

## 4. 부하 검사 단계

실제 운영이 아닌 격리 환경의 가짜 학생을 사용한다. 검사 DB/배포가 무료 운영 목표와 자원·지역·설정이 다르면 결과에 이를 명시하고 운영 보장으로 환산하지 않는다. 로컬 PGlite는 보존/SQL 기능 검사에 쓰며 클라우드 동시 성능 증거가 아니다.

| 단계 | 자료/동시성 | 목적 |
|---|---|---|
| 1 | 등록100명·6개월 누적, 동시1명 | 기준 시간·저장량·실행 계획·첫/재방문 |
| 2 | 동시 시험10명 + 관리자1명 | 일반 응시·재시험·내 단어장·일괄 배정 |
| 3 | 동시 시험30명 + 관리자3명 | 동시 시작/종료·예약 배정·오답 많은 학생 |
| 4 | 10/30명 반복, 공용 세트 공유/서로 다른 세트 | 캐시 없는 첫 요청과 재사용 차이 |
| 5 | 앞 단계 통과 시 동시100명 또는 등록300명 | 필요 시 확장 한계 탐색. 자동으로 운영 규모 약속하지 않음 |

짧은 예비 검사→오류/비용 확인→30분 지속 검사를 목표로 하며 최대3회 반복한다. 실행 전 무료 사용량으로 가능한 검사 예산을 계산한다. quota 초과/지속 오류/잠금/응답 유실이 발생하면 부하 증가를 멈추고 원인을 기록한다. 운영 프로젝트가 잘못 선택되면 쓰기 시작 전에 중단한다.

기기 조작 속도와 서버 요청률을 구분한다. 문항 답 선택 간격5초/집중2초는 기기 채점·저장·화면 부하이며 서버 요청률이 아니다. 새 규격의 정상 풀이 중 시험 호출은0회다. 서버는 시작과 종료 제출을 각각60초 분산/5초 집중으로 검사하고, 최초·재시험 묶음 제출 수/크기/실제 처리율을 기록한다. 관리자당2분마다10명×50문항 일괄 배정1회와 목록/상세 조회의 가짜 부하 가정은 유지한다. 서버가 느려져 종료 요청률이 떨어지면 목표/실제 요청률·대기열을 보고한다.

합격 목표(달성 사실 아님): 정상 네트워크에서 화면의 답 선택→다음 조작 p95≤500ms/p99≤1초, 대표 목록 p95≤1초, 종류별 실제 HTTP 요청 중2초 초과<0.1%(시작/종료/관리자 요청 분리; 기기 클릭·묶음 내부 답·DB 문장은 분모에서 제외), 답안·점수·사건·포인트 중복/유실0, 교차 계정 노출0. 저장 확인과 공식 결과의 시간은 별도 분포·기한으로 보고한다. 지연을 의도적으로 넣은 복구 검사는 정상 요청 실패율과 섞지 않는다. 평균만으로 통과시키지 않는다.

M11의 구형 규격은 선택→서버 저장 확인→다음 조작을 측정한다. M05의 새 규격은 **① 선택→기기 기록/채점→다음 조작 ② 종료 묶음 제출 시작→서버 접수 확인 ③ 마지막 답 또는 최종 시간초과로 풀이가 닫힌 시각→공식 결과**를 측정한다. 500ms/1초는 기기 구간①의 정상 목표이며20ms 선택·100ms 표시를 포함한다. 정상 풀이 시험 호출0을 실제 네트워크 기록으로 검사한다. 선택→서버 접수 시간에는 의도된 풀이 시간이 포함되므로 서버 처리 지연으로 계산하지 않는다.

②③의 허용 시간은 D21의 답 인정/마감 정책과 측정 환경에 맞춰 실행 계획에서 숫자로 정하고 무제한 대기를 통과로 보지 않는다. 미제출 답 수·종료 뒤 제출 대기 시간·연결 복구 후 해소 시간·거절 이유도 보고한다. 화면이 빨라졌다는 결과만으로 저장/DB가 빨라졌다고 하지 않는다. API·DB·권한·잠금·브라우저 표시를 분해하고 첫 준비·재시험은 별도 분포로 남긴다.

## 5. 관리자별 인원 보고 형식

| 관점 | 반드시 보고할 내용 |
|---|---|
| 저장 | 현재/6개월/12개월 총량과 학생 수 범위, 가장 먼저 닿는 한도 |
| 월 사용 | 시험 횟수·문항 수·음원 재생/캐시 조건별 실제 전송·함수 사용 |
| 동시 처리 | 검사한 관리자·학생 조합, p95/p99·오류·잠금·검사 시간 |
| 권한 | F02 미구현이면 ‘여러 관리자 분리 운영 미검증’ 명시 |
| 담당 인원 | 총 허용량을 여러 교사가 공유. 균등 배분 예시는 권장 할당으로만 표시 |
| 교사 업무량 | 주간 관리시간×60÷학생당 관리분. 측정값 없으면 수치 확정 불가 |

예비 공간50MB나 공용 공간300MB는 검토용 예산일 뿐 달성 결과가 아니다. ‘100명 목표’와 ‘관리자1명당100명 보장’을 구별한다. 한계에 가까워지면 어떤 기록/전송/공용 판이 늘었는지 먼저 밝히며 유료 전환을 이번 작업의 자동 결론으로 삼지 않는다.

## 6. 검사·산출물

M09-T1: 같은 계정/프로젝트/시점의 실제 한도와 공식 근거 확인. M09-T2: 가짜 자료 수량·사건·현재 상태 검산. M09-T3: 내용/인덱스/TOAST 이중 합산0, 공용/개인 증가 분리. M09-T4: 최초/재시험/복구 요청과 바이트 측정. M09-T5: 관리자 동시 배정이 학생 답 저장에 주는 영향. M09-T6: 오류 뒤 모든 저장 결과·권한 대조. M09-T7: 가정/실측/미검증을 구분한 최종 인원 표.

산출물은 측정 스크립트/가짜 데이터 규격, 실행 환경·시각·커밋, 익명 결과 파일, 비용표, 인원 판단표다. 신규 사용자 UI·업무 상태 변경은 없어 해당 없음. 테스트 계정/자료 정리는 명시적으로 만든 격리 대상만 수행하며 운영 학생을 삭제하거나 되돌리지 않는다.

## 7. 새 전송 구조의 비용과 실패 검사

M05의 기기 답 보관과 서버 접수 확인 기록·묶음 전송·재전송·최종 확인 비용을 모형에 더한다. 답을 늦게 보낸다고 전체 DB 작업이 자동으로 줄어들지는 않는다. 미리 받기 취소·캐시 누락/변경·음원도 실제 요청/바이트에 포함한다.

M09-T8: M11 수리본과 M05 새 규격에서 정상/2초 이상 지연/응답 유실/연결 복구를 나눠 위①②③과 누적 미전송 수·해소 시간을 측정한다. 정상 구간의 수치 목표, D21 인정 결과, 최종 답/점수/오답/포인트 일치를 모두 충족해야 하며 화면 반응만으로 수용 인원을 늘려 보고하지 않는다. M09-R4의 성능·동시 처리 검사에 추가 연결한다.
