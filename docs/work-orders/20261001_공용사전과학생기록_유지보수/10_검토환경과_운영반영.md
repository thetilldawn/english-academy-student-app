# M10 · 검토 환경 확인과 운영 반영

유형: DEPLOY, 선택한 APP 결과의 배포·운영 검증. 선행: 해당 APP 로컬 완료. 자료 구조 전환은 M08-A 이전/복구 연습, 규모 검증이 필요한 릴리스는 M09. M11만의 좁은 수리는 사전 자료 이전을 선행 조건으로 삼지 않으며 해당 복구/종료 검토 DB·화면·호환 검사를 먼저 통과한다. 실제 운영 쓰기/배포 범위는 당시 승인된 작업지시를 따른다. 이 문서 작성은 배포 실행 승인이 아니다.

## 1. 요구와 완료 조건

| R번호 | 완료 조건 | 검사 |
|---|---|---|
| M10-R1 | 검토 환경에서 코드·DB·기능·권한·이전/복구가 검증됨 | M10-T1/T2 |
| M10-R2 | 같은 코드 커밋/SQL 확인값을 운영에 적용 | M10-T3 |
| M10-R3 | 진행 시험·학생 결과와 미전송 답을 잃지 않는 전환/복구 | M10-T4/T5/T8 |
| M10-R4 | 배포 성공·DB 적용·인증 화면·운영 사용자 검증을 구별 | M10-T6 |
| M10-R5 | 용량 회수·공지·후속 기능을 실제 완료 상태에 맞춰 연결 | M10-T6/T7 |

## 2. 실행 전에 채울 반영 명세

- 대상 작업 번호, 코드 커밋, 새 SQL 파일/각 SHA-256, 적용 순서, 환경별 현재 마이그레이션 상태.
- 새 표/열/함수·변경된 함수 정의·권한·RLS·예약 작업과 해당 기능 소유자.
- 자료 이전 대상/예외/배치 제한/복구본/중간 최고 공간. 운영 본문 정리는 M08-B로 별도 명세.
- 기능별 읽기·신규 쓰기 전환 방법, 구형/신규 형식 호환 기간, 되돌릴 수 있는 마지막 버전.
- 가짜 검사용 학생/관리자·검사 자료의 식별자와 환경. 실제 학생 새 응시/답안을 검사용으로 쓰지 않음.
- 실행 중단 기준: 보존 비교 불일치, 교차 접근/D20 허용 범위 밖 정답 노출, 중복·유실 답/포인트, 잠금/오류 급증, 공간 부족.

반영 명세가 비어 있으면 배포 도구부터 실행하지 않는다. 반영 대상과 상관없는 작업·기존 미완료 검사를 같은 커밋에 섞지 않는다.

## 3. 단계별 실행

1. **로컬 결과 고정:** 실제 요구/검사/디자인 관문, 관련 테스트·lint·typecheck·구조·빌드, 필요한 PC/모바일 검증을 확인한다. 변경 뒤 검사 이전의 커밋을 완료 근거로 쓰지 않는다.
2. **검토 DB 확장:** 학생 기록 삭제 없이 새 열/함수·권한을 적용한다. 구형 배포본도 읽을 수 있는지 확인한다. 실제 데이터가 필요한 검사는 승인된 익명/복사본 범위와 개인정보 분리를 지킨다.
3. **검토 앱:** 같은 코드로 Preview 배포. 가짜 자료 생성→배정→최초/재시험→오답 해결→결과/과거 상세→복구의 전체 흐름을 확인한다. DB 정의/앱 응답/실제 화면의 세 결과를 연결한다.
4. **운영 확장·전환:** 명세대로 추가 SQL→호환 앱→기존 참조 채우기→읽기 비교→신규 쓰기 전환 순서로 적용한다. 진행 응시가 예전 판을 읽는 동안 필요한 호환을 유지한다. 사용자 정답 제출을 요구하지 않고 읽기/집계로 기존 보존을 확인한다.
5. **운영 확인:** 대표 주소의 실제 배포 버전·인증 GET·권한 거절·기존 결과·DB 함수 확인값·초기 오류/잠금/공간을 확인한다. 검토 화면 통과를 운영 관리자 화면 통과로 쓰지 않는다.
6. **중복 본문 정리:** 운영 전환이 안정되고 별도 정리 범위가 준비되면 M08-B를 수행한다. 이 단계가 남으면 ‘구조 전환 완료/공간 회수 미실행’으로 구분한다.
7. **마감:** 정리 후 조회/결과/권한·용량을 다시 확인한다. F01이 구현된 경우 실제 반영 명세가 확인된 항목만 공지 공개 조건으로 보낸다. 구현 전에는 자동 공지 완료로 기록하지 않는다.

## 4. 복구표

| 실패 위치 | 즉시 조치 | 되돌릴 방법 |
|---|---|---|
| 새 SQL 적용 전 | 실행 중단 | 현재 운영 유지 |
| 추가 구조만 적용, 신규 쓰기 전 | 새 기능 노출 중지 | 기존 읽기/앱 유지, 추가 구조는 검토 후 남기거나 제거 |
| 신규 참조 쓰기 시작 | 해당 기능의 새 생성 제한, 답 저장 보호 | 새 참조를 읽는 호환 버전으로 복구. 참조 미지원 옛 앱 금지 |
| 새 답 전송 규격으로 응시 시작 | 신규 시작 제한, 이미 진행한 답의 수신/확정 유지 | 기기 보관·전송·시간 규격을 아는 호환 버전 사용. 미전송 답 삭제/구형 강제 전환 금지 |
| 오답 상태 전환 후 | 새 파생 집계 노출 중지, 사건 저장 보존 | 보존 사건·서버 순서로 검증된 파생 상태 재구성. 답 재제출/포인트 재실행 금지 |
| 본문 정리 후 | 다음 정리 배치 중단 | M08 사본에서 해당 공용/본문 연결만 복원. 최신 답을 지우는 전체 시점복원 금지 |
| 관리자 분리 후 | 분리 권한을 유지한 채 문제 기능 제한 | 전역 관리자 버전으로 복구 금지 |
| 공지 공개 후 되돌림 | 공지 상태 정정 | 사실에 맞는 후속 안내. 조용히 과거 사실 삭제 금지 |

서비스 전체를 무조건 내리거나 학생 시험 시간을 초기화하는 방식은 복구가 아니다. 진행 시험을 이어갈 수 있는 호환 코드/DB 조합을 연습 단계에서 준비한다.

## 5. 검사·완료 보고

M10-T1: 검토 환경의 새/구형 자료 생성·읽기·종료·오답·권한. M10-T2: 이전 중단/복구와 실제 PostgreSQL 독립 연결 경합. M10-T3: 커밋·SQL·함수·환경 설정 일치. M10-T4: 기존 학생 ID/배정/답안/점수/통과/포인트/날짜 비교. M10-T5: 새 응시·계정 변경·늦은 응답의 복구. M10-T6: 대표 주소·인증된 화면과 미검증 경계를 분리. M10-T7: 공간 회수/공지/운영 사용 증거.

| 보고 항목 | 기록할 값 |
|---|---|
| 구현 | 커밋과 실제 파일/SQL, 요구 번호 |
| 로컬 | 실행 검사 수·실패·보류·빌드·화면 환경 |
| 검토 DB/앱 | 적용 시각·확인값·배포 주소·가짜 전체 흐름 결과 |
| 운영 DB/앱 | 적용 시각·실제 대표 배포·읽기/권한 결과 |
| 보존/용량 | 기준선 대비 차이·실제 회수·남은 중복 |
| 실제 사용 | 관리자 저장/실기기/장시간 확인 여부. 하지 않았으면 미실시 |
| 복구/후속 | 복구 가능한 버전·잔여 항목·공지 공개 사실 |

운영 근거에는 학생 개인정보/정답/토큰/비밀키를 넣지 않는다. 문서/인계서의 실제 증거를 갱신하고 현재 상태와 우선순위는 루트 작업 대장 한 곳에만 기록한다.

## 6. M11 수리와 M05 구조 변경의 반영 경계

M11은 기존 응시 규격의 복구·종료 반복을 고치는 좁은 릴리스로 먼저 검토할 수 있다. M01~M08의 구조 이전을 기다리거나 묶어 배포할 필요가 없다. 실제 활성 순서 변경은 이 문서가 아니라 작업 대장의 절차를 따른다.

M05는 D20/D21과 새/구형 규격 호환이 확정된 뒤 신규 시험에만 적용한다. 응시 생성 시 자료판·시간 정책판·전송 규격판을 고정하고 진행 시험은 해당 규격으로 끝낸다. 배포 전후 기기에 남아 있는 미전송 답을 읽는 코드와 서버 접수 경로가 유지돼야 한다. 읽을 수 없는 구형 배포본으로 복귀하는 것을 롤백으로 승인하지 않는다.

M10-T8: 진행 중 구형 응시와 새 규격의 미전송 답·응답 유실·마지막 답 대기 상태에서 배포/되돌림을 연습한다. 답·결과·시간·접수 기록 보존, 새 생성 차단과 기존 답 수신의 분리, 다른 학생 자료 노출0을 확인한다. D20에 허용한 즉시 판정용 정보와 승인 밖 정답 노출을 구별하여 배포 중단 기준을 적용한다.
