# M08 · 기존 자료 이전과 실제 용량 회수

유형: OPS. A는 격리 환경 이전/복구 연습, B는 운영 전환 후 본문 정리다. 두 실행은 별도 기록한다. 코드/SQL 작성은 M01~M07의 APP 작업, 배포는 M10이다. 운영 정리 대상과 실행 권한은 실제 명세가 준비된 단계에서 확인한다.

## 2. 먼저 만드는 이전 명세

표마다 다음 열을 채운 CSV/JSON과 설명서를 만든다. `대상 표/필드, 현재 호출자, 옮길 공용 참조, 기존 ID 보존법, 대상 행 조건, 보존 예외, 전수 비교식, 중간 최대 공간, 실행 순서, 되돌릴 방법`이다. 애매한 대상을 ‘기타 정리’로 넣지 않는다.

| 우선 조사 대상 | 확인할 중복 | 보존 예외 |
|---|---|---|
| 범위용 사본 | 시험용 원행 전체·중첩 근거 | 기존 v1/고정 범위 복원에 아직 필요한 값 |
| app_exam_use_occurrence | 반복 입력/근거 묶음 | 원출현·자료판·선택 뜻·발음·원본 확인값 |
| composition_entries/items | 생성 앱 행의 본문·근거·발음 사본 | 공용 사용값/보기/문항판을 복원하는 최소값 |
| reviewed_mock_resources/releases | 전체 묶음과 행별 payload 중복 | 검토 승인·자료판·승인 당시 선택/확인값·복구 위치 |
| assignment_questions | 공용 문항 참조와 같이 저장된 본문/근거 | 기존 ID·학생 배정·순서·정답 관계·FK |
| quiz_questions | 반복 질문·보기 표시 본문 | 기존 ID·개인 답안·시각·단계·오답/큐/FK |

이 목록은 삭제 승인 목록이 아니다. 아직 실제 소비자가 읽는 필드는 M01~M05에서 전환하고 비교한 후에만 제거 후보가 된다. 단어 ID/출처 참조와 파일 색인 행은 파일 수와 다르므로 많다는 이유만으로 삭제하지 않는다.

## 3. A단계 — 격리 환경 연습

1. 실행 코드/DB 마이그레이션 목록/최신 함수 정의/설정의 확인값을 고정한다. 후속 SQL의 재정의까지 포함한다.
2. 운영은 읽기 전용으로 시각·최대 사건 ID·각 표 수/크기·참조 누락·학생 결과 합계의 기준선을 잡는다. 개인정보 원문은 채팅/Git에 남기지 않는다.
3. 복구 사본을 접근 제한한 로컬 자료 구역에 저장하고 파일 수·바이트·SHA-256·복원 명령·필요한 권한을 남긴다. Drive 동기화 완료를 자동으로 가정하지 않는다. 보관본에 필요한 원문/검토 내용이 실제 있는지 확인한다.
4. 격리 복사본 또는 동일 구조의 가짜 과거 데이터에 **새 SQL 적용 전** 자료를 넣는다. 최종 스키마에만 가짜 행을 넣는 검사는 이전 검사가 아니다.
5. 새 열/표/함수 추가→참조 연결→기존/신규 읽기 비교→신규 쓰기 확인 순서로 실행한다. 연결되지 않은 자료는 기존 경로 유지·이유 기록. 잘못된 연결을 조용히 구형 값으로 덮어 숨기지 않는다.
6. 배치를 중간에 끊고 재개한다. 병렬 세션에서 새 답/만료/오답 해결을 발생시켜 이전 때문에 사건이 빠지거나 두 번 처리되지 않는지 확인한다.
7. 정리 대상 후보를 추출한 뒤 실제 사본으로 복원 연습한다. 데이터베이스 전체를 과거로 되돌려서 최근 학생 답안을 잃는 방식은 합격이 아니다.

**증가하는 ID를 거래 확정 순서로 간주하지 않는다.** ID100을 받은 거래가 늦게 끝나고101이 먼저 확정될 수 있다. 기준선은 일관된 조회 시점을 사용하고, 처리된 실제 원행 키+원행 변경판의 기록을 남긴다. 최대 ID는 범위 설명/성능 보조값일 뿐 누락 없음의 증거가 아니다. 전환 직전 미연결·확인값 불일치 전체를 다시 대조하고, 관찰창에 겹쳐 재조회하거나 검증된 변경 추적/짧은 전환 잠금으로 늦은 확정을 포착한다. 방법·잠금 영향·수렴 조건을 이전 명세에 적는다.

## 4. B단계 — 운영 전환 후 정리

M10의 검토/운영 읽기 전환을 통과하고 당시 운영 정리 범위가 확인된 후에 실시한다.

1. 이전 명세·정확한 행 조건·예상 수·복구본·임시 공간 예산·실행 중 중단 기준을 제시한다.
2. 운영 기준선을 새로 읽고 A단계 이후 증가한 기록을 구분한다. 시각만으로 잘라 늦게 접수된 답을 누락하지 말고 고정 사건/처리 키와 변경판을 사용한다.
3. 기존 ID/FK를 유지한 채 짧은 배치로 참조를 채운다. 새 쓰기는 새 구조에 기록되므로 처리 범위를 고정하고 완료된 묶음만 재개한다.
4. 실제 앱 서버의 기존/신규 DTO를 전수 또는 동일 확인값 단위로 대조한다. 학생에게 새 답을 제출하게 하여 이전을 검증하지 않는다.
5. 읽는 호출자0·복원 일치·정리 명세 일치·진행/재시험 대상 제외를 확인한 필드만 비운다. 공용 판/개인 답안/사건 행을 통째로 지우지 않는다.
6. 일반 정리/통계 갱신 뒤 실제 관계 크기·재사용 여유를 다시 읽는다. 기대보다 파일이 줄지 않아도 학생 기록을 더 지우지 않는다.
7. 물리 재작성 필요 여부를 별도로 결정한다. 여유 디스크·WAL 증가·잠금 시간·서비스 중단 범위를 검토 환경에서 측정한 방법만 사용한다. `VACUUM FULL`이나 대량 인덱스 재생성을 자동 후속으로 실행하지 않는다.
8. M10의 운영 마감 검사로 돌아가 결과·권한·기존 응시 읽기·용량을 확인한다.

## 5. 공간과 인덱스 원칙

현재 약776.33MB에서 전체 사본을 DB 안에 한 벌 더 만드는 방식은 피한다. 최종 예상 공간과 **이전 중 최대 공간**을 따로 산정한다. 여유가 부족하면 외부 복구본과 작은 단계 이전으로 조정하고, DB 제한/잠금 때문에 안전한 실행이 불가능하면 삭제로 밀어붙이지 않는다.

크기는 `pg_database_size`, 기본 표·TOAST·인덱스·전체 관계를 구분해 측정한다. TOAST가 포함된 `pg_table_size`와 TOAST 표를 다시 합쳐 이중 계산하지 않는다. 바이트 원값, MB(1,000,000), 필요하면 MiB(1,048,576)를 병기한다.

사용 횟수0은 불필요한 인덱스의 증거가 아니다. 고유 제약·외래키 조회·중복 인덱스 정의·실행 계획·통계 초기화 시점을 확인한다. 약4.09MB 후보를 ‘모두 삭제 확정’으로 취급하지 않는다. 꼭 필요한 인덱스는 실제 새 조회/해결/페이지 쿼리로 검증한다.

운영 도구 작업이므로 신규 UI/state/style/cache는 해당 없음. 기존 조회/저장/인증/오류/진행 화면은 확인 대상이다. 검사 DB의 RLS와 고권한 함수 경계도 복원본에서 확인한다. 민감한 복구본의 상세 경로나 비밀키를 사용자 앱 오류에 출력하지 않는다.

완료 산출물: 이전 명세, 대상/제외 수, 배치 기록, 복구 연습, 전수 보존 비교, 내용 감소량과 실제 파일 회수량, 남은 원인. 줄어든 용량만 보고 성공으로 판정하지 않는다.

## 8. 새 시험 규격의 이전 경계

M05 적용 시 내용판뿐 아니라 응시의 전송/시간 정책판과 답별 접수 확인도 대조 목록에 넣는다. 진행 중 구형 시험을 새 규격으로 바꾸거나 종료된 것으로 추정하지 않는다. 기기 미전송 답을 서버 이전 작업만으로 모두 파악할 수 있다고 가정하지 말고, 새 규격 수신·최종 확인 호환 경로를 유지한다. 화면상 풀이 끝·서버 결과 미확정인 응시와 복구 기록은 정리에서 제외한다. M08-T3/T4/T8와 M05-T16에서 이전·정리·롤백 전후를 대조한다.
