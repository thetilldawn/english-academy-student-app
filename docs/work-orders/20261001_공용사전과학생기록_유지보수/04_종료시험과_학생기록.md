# M04 · 종료 시험의 결과를 작게 보존

유형: APP, 기록 저장/조회 보완. 선행: M01/M02. 결정: D05/D08/D10/D11. 사용자 미결정 없음. 사용자가 설명한 신규 종료 시험의 요약·오답 중심 보관을 기준으로 하며, 이미 저장한 답안과 현재 오답 상세에 필요한 키는 보존한다. 모든 정답 선택값의 장기 조회 확대는 별도 후속 요청으로 다룬다.

## 1. 목표와 요구

사용자가 필요한 것은 어떤 시험을 배정했고, 언제 몇 개를 맞히고 틀렸으며, 재시험에서 몇 점을 받고 통과했는지다. 단어·뜻·근거 본문은 공용 판으로 복원한다. 시험 기록을 삭제해 용량을 맞추지 않는다.

## 2. 남기는 기록

| 단위 | 필수 내용 |
|---|---|
| 배정 | 기존 배정 ID·학생·공용 단어장/세트판·배정/마감일·상태·취소/종료 사유 |
| 응시 | 기존 응시 ID·배정·최초/최종 시각·통과 기준판·현재/최종 상태·점수 확정값 |
| 최초 풀이 | 응시 문항 수·정답/오답/미응답 수·점수·통과 여부·시각 |
| 정규 재시험 | 시행 여부·대상 수·정답/오답/미응답 수·점수·통과 여부·시각·최초 풀이와의 연결 |
| 오답 사건 | 기존 사건 키·단어/뜻 선택·공용 문항·원출처·initial/retry·실제 발생일·해결 근거 |
| 개인 답안 호환 | 이미 저장한 답안과 진행 중 시험은 기존 문항 ID·공용 문항판·선택 위치/키·단계·채점값·시각 보존 |
| 신규 종료 오답 상세 | 최초 오답/미응답 문항의 선택 키·재시험 선택/판정·공용 문항 참조, 실제 보관된 시각 |
| 기타 연결 | 포인트 거래/후속 배정/정정 이력의 기존 키. 원래 거래를 재실행하지 않음 |

한 응시 안의 최초/재시험을 하나의 요약 행 또는 연결된 작은 단계 행으로 보존할 수 있다. 어느 쪽이든 단계별 정오답과 점수가 복원되어야 한다. 추가로 새 응시를 만들었다면 별도 결과로 남기며 ‘재시험’이라는 이름만 보고 합치지 않는다.

정답 수+오답 수+미응답 수=그 단계 대상 수를 검사한다. 시간 초과 미응답을 실제 오답 제출과 같은 사건으로 새로 생성하지 않는다. 기존 정책이 다른 시험 유형은 타입별 계약을 먼저 확인하고 보존한다. 이전에서 채점 정책을 바꾸지 않는다.

## 3. 종료 판정과 정리 조건

본문 정리 가능 = 서버가 확정한 종료 상태 + 남은 정규 재시험/복구 작업 없음 + 공용 문항 복원 성공 + 개인 기록/외래키 호환 성공. 날짜가 오래됐다는 이유만으로 종료 처리하지 않는다.

- 완료: 최초/정규 재시험 결과가 최종 확정되고 추가 단계가 없음.
- 만료: 실제 마감/응시 규칙이 확정한 종료. 미응시 배정도 배정 사실·만료 사유 보존.
- 마감 없는 최종 미통과: 허용된 정규 재시험이 끝났거나 기존 정책에 따른 명시적 종료. 단순 미통과 점수만으로 종료 추정 금지.
- 재시험 대기/진행/응답 유실 복구: 요약을 볼 수 있어도 활성 자료 정리 금지.

## 4. 선택 답안 정책 D11

| 기록 구분 | 이번 지시 | 화면/용량 영향 |
|---|---|---|
| 이미 저장된 기존 답안 | 모든 선택 답안을 작은 키로 유지 | 과거 정보 손실0, 긴 문항 본문만 공용 참조로 바꿈 |
| 진행/정규 재시험/응답 복구 중 | 답안·시각·문항·확인 영수증 유지 | 활성 시험이나 재전송을 종료 정리로 깨뜨리지 않음 |
| 앞으로 새로 종료되는 시험 | 요약·오답/미응답 상세·해결 키·공용 판, 필요한 요청 확인 키 | 정상 정답 문항의 선택값을 별도 장기 상세로 제공하지 않음 |
| 모든 정답 문항의 선택까지 장기 조회 | 이번 범위에서 새로 추가하지 않음 | 이후 필요하면 별도 기능/저장 예산으로 검토 |

**이미 저장한 과거 선택 답안은 유지한다.** 신규 종료 자료에는 보관 정책판을 남기고 필요한 화면에 “이 시험은 결과와 오답 기록을 보관합니다.”라고 표시한다. 없는 상세를 오류나0점으로 만들지 않는다. 상세를 제공하는 오답 문항은 짧은 선택/판정 키로 기존 화면을 유지한다. 이 추가 키와 미응답 기록의 비용은 약39~58MB 기본 모형에 따로 더해 실제 측정한다.

현재 관리자 UI는 최초 오답·미응답 문항을 골라 최초/재시험 선택을 표시한다. 서버가 모든 문항을 읽는 사실과 화면이 모든 정답 선택을 보여주는 것은 다르다. 기존 오답 상세의 선택값은 첫 이전에서 반드시 보존한다. 결과 응답에는 `상세 제공 / 요약 제공` 같은 명시적 상태를 두며, 요약 자료에 빈 `questions`만 반환해 ‘모두 정답’으로 표시하지 않는다. `실제 오답0`과 `상세를 보관하지 않음`을 M04-T8에서 따로 확인한다.

과거에 저장하지 않았던 재시험 시작 시각이나 선택 값은 추정해서 채우지 않는다. 원래 저장된 값·현재 복원 가능한 값·보관되지 않은 값을 구분해 표시한다.

## 5. 구현 경로·순서

1. [학생 결과 조회](../../../src/lib/services/quiz/attempt-result-query.ts), [관리자 상세 조회](../../../src/features/history/server/queries/admin-attempt-detail-query.ts), [오답 사건 FK SQL](../../../supabase/migrations/20260730130000_add_vocab_wrong_event_history.sql)의 의존 관계를 표로 만든다.
2. 기존 응시·문항·사건 ID를 유지하며 공용 문항 참조를 추가한다. 요약 읽기와 상세 읽기를 별도 계약으로 나눈다.
3. 종료 결과 작성은 답 저장/최종 확정 거래와 연결해 한 번만 수행한다. 요약 합계는 기존 확정 결과와 대조하며 과거 성적을 재채점하지 않는다.
4. 교사 내역/학생 내역/상세/포인트/오답 조회를 공용 판과 짧은 개인 기록으로 읽게 한다.
5. 과거 자료를 배치 이전한다. 처리 전후 ID·기존 점수·시각·통과·포인트·답안/사건 연결을 비교한다. 실패한 묶음만 재개한다.
6. 신규 보존 정책을 D11대로 적용한다. 종료 후에도 재전송 확인/FK에 필요한 작은 문항 연결과 요청 확인 자료는 유지한다. 본문 필드 제거와 기존 운영 자료 정리는 별도 M08에서 한다.

권한은 현재 학생 본인/허용된 관리자 조회를 보존한다. 검색·총수·다운로드가 새 상세를 우회해 다른 학생 자료를 반환하지 않게 한다. 거래 중복·취소·늦은 답은 기존 응시 최종성 검사를 따른다. 확정된 결과를 stale 요청으로 되돌리지 않는다.

## 6. 캐시·화면·영향

불변 결과 캐시 키는 학생 권한 범위+응시 ID+결과판이다. 정정이 허용되는 기존 기능은 정정판을 갱신하며 목록·상세를 같이 무효화한다. 로그아웃/계정 전환 시 개인 캐시 폐기. 15초 관리자 개인 목록 계약은 유지하며 최신 저장 직후는 강제 확인한다.

변경: 결과 data/domain/API·history UI/state·오류/빈 상세·검사. 확인만: 경로·스타일·서버 권한·포인트 정책. 공통 U1~U10과 M04-T8을 적용한다. 정상 보관 정책에 따른 상세 없음은 설명 문구, 조회 실패는 “시험 결과를 불러오지 못했습니다.”, 없는 응시는 404로 구별한다. 점수는 실패 시 0으로 대체하지 않는다.

## 8. 풀이 종료와 공식 결과 확정을 구별

M05의 기기 화면에서 마지막 문제를 풀었어도 답 전송/서버 접수/최종 채점이 미확정이면 이 문서의 종료 요약이나 정리 후보가 아니다. 서버의 답별 접수 또는 D21에 따른 명시적 최종 거절/미응답 판정을 대조한 뒤 공식 결과를 한 번 확정한다. 미확정 답이 뒤늦게 도착했을 때 조용히 버리거나 이미 확정한 점수를 임의로 덮지 않고 규격에 따른 처리 결과를 반환한다.

확정 대기에는 “답안 저장과 결과를 확인하고 있습니다.”를 표시하고 완료·0점·미통과로 미리 바꾸지 않는다. 재시험 대상과 오답·포인트도 공식 결과에만 연결한다. 새 규격의 답·접수 확인은 재전송/최종 처리 계약을 충족할 때까지 보호한다. 로그아웃 때 폐기하는 개인 결과 캐시와 미전송 답 보관을 혼동하지 않는다. M04-T3/T8, M05-T13/T16, M11-T6/T10을 함께 검사한다.
