## 2. 공개 계약

공지 단위는 커밋이나 배포 시도마다가 아니라 운영에 반영된 변경 묶음이다. 서비스 운영자만 공개한다. 변경 묶음 ID·작업 번호·프로젝트/환경, 실제 운영 코드/배포 ID, DB/SQL 확인값과 적용 결과, 검증·철회 상태, 짧은 제목/본문·대상·내용판·공개시각·중복 방지 키를 작은 기록으로 남긴다.

초안→검토 완료→적용 확인→공개 가능→공개로 구별한다. Preview 성공이나 실패/철회 배포를 공개하지 않는다. 사전에 확정한 문구·대상은 실제 운영 반영/검사 조건을 만족한 뒤 자동 공개할 수 있다. 원시 커밋 메시지는 학생에게 표시하지 않는다.

배포 이벤트는 서명·프로젝트·운영 환경을 검사하고 현재 운영 상태를 다시 확인하는 계기로만 쓴다. SQL만 반영한 경우에도 승인된 서버 절차가 현재 코드·연결 DB·해당 SQL의 검사 증거를 확인한 뒤 같은 공개기를 호출한다. 브라우저가 임의로 DB 적용 완료를 선언할 수 없다. 변경 없음과 증거 누락을 구분한다.

## 3. 토스트 동작과 기록

기존 앱 토스트 부품에 짧은 패치 안내를 표시한다. 이번에는 공지함·목록/상세 경로·뱃지·상세 열람의 읽음 기능을 만들지 않는다. 외부 푸시·이메일·카카오톡도 범위 밖이다.

시험/연습 도중에는 표시를 미루고 완료 후 또는 메인 복귀에서 안내한다. 강제 새로고침하거나 풀이를 가리지 않는다. 구버전 화면에는 “새 기능이 반영됐습니다. 시험을 마친 뒤 새로고침해 주세요.”처럼 현재 상태에 맞게 안내한다.

실제로 표시한 뒤에만 사용자+공지판의 표시 확인을 저장한다. 이것을 본문 열람/읽음으로 해석하지 않는다. 재시도·다중 탭에서는 동일 공지 표시를 조정하고, 계정 전환 시 이전 사용자의 대기 안내를 버린다. 표시 확인 실패는 시험을 막지 않고 다음 정상 확인 때 복구한다. 이 기록과 공개 원문은 이후 모아 보기 기능에서 재사용할 수 있게 보존한다.

공개 뒤 내용 정정이나 되돌림은 원래 적용 이력을 덮어 거짓으로 만들지 않는다. 현재 적용 사실에 맞는 후속 안내를 연결한다. 학원별 작성이나 학생 개인정보가 들어간 공지는 이번 기능에 포함하지 않는다.

## 4. 변경 경로와 상태

[알림 시작 부품](../../../src/components/notification-bootstrap.tsx), [알림 서버](../../../src/lib/services/notification-service.ts), [학생 API](../../../src/app/api/student/notifications/route.ts), [관리자 API](../../../src/app/api/admin/notifications/route.ts), [기능 지침](../../../src/features/notifications/AGENTS.md)에 공개/대상/표시 확인·시험 유예 흐름을 연결한다. 기존 확인 주기를 재사용하고 별도 반복 타이머를 늘리지 않는다.

공용 공개 문구·내용판과 개인 대상/표시 확인을 분리한다. 현재 인증을 검사하고 개인 결과는 계정별로 분리한다. 조회 실패를 “새 공지 없음”으로 기록하거나 표시 완료로 저장하지 않는다. 정상0건은 토스트 없음, 조회 실패는 다음 정상 주기 재시도, 권한 만료는 기존 인증 복구로 처리한다. 실패 안내가 시험 답 저장을 가로막지 않게 한다.

변경면: 기존 알림 UI/state/domain/API/server/DB/cache/asyncUi/security/tests. 새로운 공지 페이지 routing은 해당 없음. 실제 구현 착수 시 소유권 지도와 R/D/T 기록을 연결한다.
