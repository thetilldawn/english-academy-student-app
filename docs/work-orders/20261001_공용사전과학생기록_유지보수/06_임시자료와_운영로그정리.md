# M06 · 임시 자료와 운영 로그의 보관 기간

유형: APP, 정리 기능/설정 구현. 운영 최초 실행은 별도 OPS 기록. 선행: 준비 자료를 다루는 부분은 M05. 결정 D09/D12/D13. **2026-10-02 사용자 “나머진 오케”와 “24시간으로 일단 하자”, “계속 진행해 마저”로 D12/D13 기간을 모두 확정했다.** 승인된 기준으로 구현·검증하며 실제 운영 정리와 스케줄 활성화는 별도 OPS다.

## 1. 대상과 요구

큰 로그는 학생 접속 기록이 아니라 `cron.job_run_details`의 예약 작업 기록이다. 2026-10-01 분석에서 약39.27MB였고, 세션·로그인 시도·관리 감사 합계는 약0.71MB다. 당시 준비 표는0행이었다. 이 수치는 오늘 다시 측정한 용량이 아니다.

‘시험 준비 정보’는 시작 버튼을 누른 뒤 실제 응시를 만들기 전에 잠깐 보관하는 학생·배정 번호, 문항 번호·순서·방향·최소 채점 정보, 내용판 참조, 시작 가능 만료시각이다. 실제 응시를 만들면 그 응시 번호도 연결한다. 예를 들어 50문항을 준비하다 창을 닫아 실제 시험을 시작하지 않은 경우의 만료된 정보가 정리 검토 대상이다. 준비의 15분 유효시간은 실제 시험 제한시간이 아니다.

최근 M02/M05 수정본의 신규 준비는 단어·뜻·선택지 본문을 매번 복사하지 않고 공용 내용판을 참조한다. 따라서 ‘큰 준비 본문’은 옛 배열 형식의 중복 본문이 실제로 남아 있고 더 필요 없다고 확인된 경우를 뜻한다. 새 소형 참조가 큰 용량의 원인이라고 단정하거나 준비 기록을 통째로 지우지 않는다. 같은 시작 요청에 기존 응시를 돌려줄 작은 연결과 확정 만료 확인은 보존한다. 배정·응시 결과·오답·미접수 답·진행 중 자료와 공용 단어/뜻은 제외한다. D13의 미시작 만료 후24시간과 구형 본문의 종료/복원 검증 후24시간을 적용한다.

| R번호 | 완료 조건 | 소유·흐름 | 검사 |
|---|---|---|---|
| M06-R1 | 완료된 예약 작업 로그를 정해진 기간만 보존 | 운영 DB/예약 작업, 새 정리 흐름 등록 | M06-T1/T2 |

## 2. 보관 정책과 미결정 범위

| 자료 | 확정값 또는 제안 | 반드시 제외/보존 |
|---|---|---|
| 해당 앱 예약 작업 성공 상세 | 종료 후7일 | 실행 중, 이번 정리 실행, 알 수 없는 상태·다른 서비스 작업 |
| 해당 앱 예약 작업 실패 상세 | 종료 후30일 | 조사 보존 표시가 있는 사건, 종료 미확정 |
| 미시작 준비 정보 | 시작 가능15분이 지나 확정 만료된 뒤24시간, D13 확정 | 처리 중인 시작 요청과의 거래 확인, 동일 ID의 확정 만료 응답 |
| 시작된 구형 중복 준비 본문 | 응시 종료·공용 판 복원 검증 뒤24시간, D13 확정 | 준비 ID→응시 ID의 작은 확인 자료, 활성 응시/재시험. 신규 소형 참조를 큰 본문과 혼동하지 않음 |
| 시작/만료 확인 자료 | 재전송·복구 계약을 만족하는 기간 또는 작은 영구 연결 | 같은 요청으로 새 시험이 생기지 않음. D13 확정: 작은 확인 연결은 보존 |
| 로그인 성공/로그아웃 활동 | 신규 장기 학습 이력으로 쌓지 않음 | 현재 세션 발급·폐기 및 보안상 필요한 최소값 |
| 로그인 실패 시도 | 실패 후24시간, D12 확정 | 현행 최근15분 제한창 안의 시도, 조사 보존 대상. 성공 행에 실패 기준을 일괄 적용하지 않음 |
| 만료/폐기 세션 | 실제 사용 불가 확정 후7일, D12 확정 | 활성60일 세션·진행 요청·관리자 보안 기록. 발급일을 만료일로 사용하지 않음 |
| 배정·응시·오답·포인트 | 이 정리 대상에서 제외 | M04 계약으로 본문만 줄이고 결과/사건 유지 |
| 기기의 미전송 답·진행 중 전송 묶음 | 일반 캐시/로그 정리 대상에서 제외 | 접수 또는 명시적 최종 처리 전 삭제 금지, D21의 격리/복구 정책 |
| 서버 답 접수·종료 확인 기록 | 재전송 차단/결과 조회 계약이 충족될 때까지 유지 | 화면 이탈·계시 만료만으로 정리 금지, 미확정/처리 중 응시 보호 |

서버 시간은 UTC로 비교하고 표시만 KST로 한다. 경계 시각을 명시하여 ‘7일 전’의 날짜만으로 잘못 지우지 않는다. 적용할 값·정책판·변경자·적용일을 한 설정으로 관리하고 코드 곳곳에 숫자를 복제하지 않는다.

## 3. 구현 지시

1. 실제 활성 예약 작업 ID/소유/SQL·완료 상태값을 읽어 정리 대상 허용 목록을 만든다. 모든 cron 기록을 일괄 삭제하지 않는다.
2. 먼저 읽기 전용 미리보기를 구현한다. 정책판별 대상 수·최소/최대 일시·추정 내용 바이트·제외 이유를 출력한다. 실행에는 이 미리보기의 조건/상한 시각을 고정한다.
3. 기본 배치100~1,000행 중 검토 DB 잠금/시간을 측정해 내부값을 정한다. 실행당 최대행수·시간 제한·커서·중복 작업 잠금을 둔다. 실제값은 설계 검사에서 확정한다.
4. 삭제 조건에 완료 상태·보관 기간·허용 작업 ID를 모두 포함한다. 중단 후 같은 범위를 재실행해도 보존 대상은 영향을 받지 않는다.
5. 준비 정리는 본문/영수증을 구분하고 시작 거래와 같은 잠금 규칙을 쓴다. 정리가 먼저 만료를 확정했으면 시작은 만료 응답, 시작이 먼저 확정됐으면 기존 응시 반환이다.
6. 기존 예약 작업 하나에 효율적으로 연결하거나 하루 단위 정리를 검토한다. 불필요한 매분 작업을 새로 만들어 로그를 다시 늘리지 않는다. 자동 작업 설정은 OPS/배포 범위에 기록한다.
7. 실행 결과는 정책판·상한시각·대상/삭제/제외 수·오류 코드·처리시간만 짧게 남긴다. 삭제한 원문 전체를 다른 로그에 복사하지 않는다.

자료 근거는 [준비 SQL](../../../supabase/migrations/20261001014318_prepare_quiz_before_start.sql), [초기 로그인 제한 SQL](../../../supabase/migrations/20260728162905_initial_student_app_mvp.sql), [세션 기간 검사](../../../src/lib/auth/session-lifetime-contract.test.ts), [조회 근거](../../verification/20261001_사전공유와학생기록_조회근거.json)다. 실제 함수의 후속 재정의를 찾아 최신 계약에 적용한다.

## 4. 권한·화면·영향

실행은 운영 권한 전용이다. 일반 학생/관리자가 임의 기간이나 표 이름을 보내 삭제할 수 있는 API를 만들지 않는다. SQL 실행권한은 최소화하고 대상 표·열을 고정한다. 화면 신설은 필요하지 않으며 정리 도구의 미리보기/결과 파일로 충분하다.

변경: 운영 data/API·서버 작업·검사. 확인만: 인증·기존 준비 UI/캐시·실패 복구·경로. UI/state/style은 새 정리 화면을 만들지 않으므로 해당 없음; 학생이 만료된 준비를 사용하는 경우 M05의 만료/통신 실패 안내를 유지한다. 실패하면 정리만 중단하고 학생 결과를 변경하지 않는다.

로컬/검토 DB 검사 뒤 첫 운영 실행은 대상 수가 있는 미리보기·보존 설정·복구 가능 범위를 보고한다. 실제 삭제 수와 DB 파일 크기 감소는 다른 값이다. `VACUUM FULL`·표 재작성·인덱스 정리는 M08의 별도 검토 없이는 자동 실행하지 않는다. 복구는 정리 작업 비활성화와 확인된 보관본의 대상 로그 복원이며 학생 DB 전체를 과거로 되돌리지 않는다.
