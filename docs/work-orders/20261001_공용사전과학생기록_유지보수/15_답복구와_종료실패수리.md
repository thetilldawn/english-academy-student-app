# M11 · 답 저장 뒤 멈춤과 시험 종료 반복 수리

유형: APP, 현재 규격의 오류 수정. 2026-10-01 ‘앱’ 채팅과 앱 인계서의 최신 진단을 반영했다. 선행: M01/M02 자료 이전 불필요. 결정 D09/D10/D19의 기존 보존·단계 분리 적용. 사용자에게 새 학습 규칙을 선택받을 작업이 아니다. 구현·배포는 각각 정식 APP/DEPLOY 기록으로 진행한다.

입력: [진단 8절과 사용자 방향 9절](../../verification/20261001_시험멈춤과자료재사용_점검.md), [재현 수치](../../verification/20261001_첫답멈춤_재현근거.json), [실제 플레이어의 가짜 시험 화면](../../verification/20261001_첫답멈춤_가짜시험재현.png). 이 지시서는 문서로 수리를 정의하며 현재 수정 완료를 뜻하지 않는다.

## 4. 저장된 답 복구를 바로잡는 절차

1. 답 선택의 응시·문항·최초/재시험 단계·선택·요청 ID를 고정한다. 요청이2초를 넘었다는 사실을 ‘저장 실패’와 같게 취급하지 않는다. 느림 안내를 켜고 요청별 제한·복구 기준에 따라 결과를 확인한다.
2. 재조회에서 **같은 답이 실제 저장됐는지** 확인한다. 저장 전 조회라면 실패/성공을 추정하지 않고 선택을 유지한다. 다른 문항/다른 답/다른 계정의 늦은 응답은 현재 성공으로 반영하지 않는다.
3. 정상 저장 응답과 복구에서 확인된 저장 응답을 하나의 전환 절차에 넣는다. 현재 문항·단계를 서버가 검증한 뒤 사용하지 않은 예약만 줄이고 다음 시작 시각을 확정한다. 단순히 복구의 setTimeout 숫자만 줄이지 않는다.
4. 서버가 이미 다음 문항을 가리킨다는 사실만으로 예약 정리를 생략하지 않는다. **다음 문항이 잡혔어도 예약이 남으면3단계를 수행한다.** 이미 반영한 답 확정·피드백·화면 이동만 중복 실행하지 않는다. 완료/재시험 대기는 해당 결과로 연결한다. 원응답과 복구의 경합에서도 서버 시각 확인과 화면 이동을 구별한다.
5. 시각 확인 응답까지 잃으면 같은 응시/단계로 서버 상태를 확인한다. 반복 호출로 추가 시간을 얻거나 시간 기준을 새로 만들지 않는다. 실제 확인 대기에는 준비 안내를 유지한다.

정상 빠른 응답의100ms 표시와 불필요한 블러 없음은 유지한다. 느린 경우에는 확인된 판정 또는 준비 상태와 설명이 남아 있어야 한다. 시각을 모르는데 가짜 남은 시간을 채우지 않는다. `--:--` 자체가 필요한 미확인 상태라면 이유/복구 행동을 반드시 함께 표시한다.

7초 예약은 피드백·음성 동안 조기 시간 차감을 막던 서버 규칙이다. 이를 무조건 삭제하거나 브라우저가 임의로 시간을 더하지 않는다. 과거/현행/새M05 규격의 시간을 섞지 않는다. 이 작업은 현재 규격을 정상 작동하게 하는 수리다.

## 5. 종료 오류·반복 요청·옛 응시 처리

| 결과 종류 | 서버/화면 계약 |
|---|---|
| 이미 완료 | 기존 공식 결과 반환, 오답/점수/포인트 재반영 없음 |
| 아직 종료 불가·단계 충돌 | 현재 상태와 거절 이유 반환, 상태 변화 없이 무조건 자동 재시도 금지 |
| 인증/권한 실패 | 재인증/권한 안내, 자동 재전송 중지 |
| DB 시간 초과·일시 불가 | 재시도 가능 여부와 안전한 오류 식별자, 내부 SQL/학생 답 미노출 |
| 응답 유실·처리 결과 불명 | 같은 요청의 처리 상태 확인, 진행 중인 서버 종료와 중복 실행 방지 |
| 문항/원판 누락 등 복구 불가 | 명시적 오류·관리 확인 경로, 빈 시험·완료·점수0으로 위장 금지 |

HTTP 상태와 내부 원인 코드를 일치시킨다. 업무 충돌과 서버 시간 초과를 전부409로 합치지 않는다. 서버 내부 예외를 그대로 학생에게 보내지 않는다.

자동 재시도는 **같은 응시·단계·종료 요청에 대한 하나의 예산**으로 관리한다. 초기 구현 검토값은 최초 요청 뒤 일시 실패에 한해1초/3초 간격 추가2회이며, 실제값은 격리 환경 검사로 확정한다. 전체 조회·화면 재렌더·0초 타이머가 이 예산을 다시 초기화해서는 안 된다. 사용자가 재시도할 때도 먼저 기존 결과/진행 요청을 확인한다. 재시도 중에는 같은 종료 요청을 겹쳐 만들지 않는다.

복구 조회는 가능한 한 진행·접수·시간·결과 상태만 읽는다. 99문항/발음 재조합을 반복하지 않도록 기존 계약에서 줄일 수 있는 범위를 먼저 적용하고 M05의 공용 내용 계약으로 이어간다. 조회가 레거시상 만료 확정을 호출한다면 그 쓰기를 식별하고 단일 확정/중복 방지를 검사한다. ‘읽기’라는 함수명만 보고 부작용 없다고 취급하지 않는다.

준비는 만료 응시를 제외하지만 시작이 옛 진행 응시를 돌려주는 경우를 따로 처리한다. 서버가 그 응시의 종료/복구 상태를 분명하게 반환하고, 학생이 새 시험을 시작한 것으로 표시하지 않는다. 운영 학생의 응시를 지우거나 새로 만들어 해결하지 않는다.

## 6. DB 내부 지연은 측정 후 수리한다

관측할 구간은 답 접수/학생 행 잠금·단어 상태·복습 대기/배정 정리, 종료의 문항별 사건·상태·연결 처리다. 요청 전체 시간, SQL 수행, 잠금 대기, 반환 자료 조합을 구별한다. 9월30일 공용 출처 조회로 바뀐10개 함수는 비교 후보이며 원인 확정이 아니다.

가짜/익명 복사본의 실행계획·독립 연결 경합 검사로 중복 기록 후보 사전 제외, 변하지 않은 연결의 재검사 생략, 실제 조건에 맞는 인덱스 등을 판단한다. 쓰기 SQL의 실행 분석을 운영에서 시험하지 않는다. 운영 읽기도 시간 초과가 반복되면 추가 부하를 멈추고 확보한 근거와 한계를 남긴다.

결과는 ‘화면 복구 수리’, ‘종료 요청 반복 차단’, ‘DB 지연 원인 확인/개선’을 나눠 적는다. SQL 원인이 미확인이면 그대로 남기고 무료 요금제 변경을 해결 조건으로 강제하지 않는다. 광범위한 DB 구조 변경이 필요하면 별도 명세로 M01~M09와 연결한다.
