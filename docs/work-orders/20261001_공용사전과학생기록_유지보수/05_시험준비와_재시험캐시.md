# M05 · 공용 자료 재사용과 화면 진행·답 저장 분리

유형: APP, 시험 실행 구조 개선. 2026-10-02 사용자 보완을 반영한 3차 지시다. 선행: M01/M02 공용 판 계약과 M11 복구 회귀 기준. 연결: M03/M04/M06/M09/M10. 결정 D05/D09/D10/D19/D20, 구현 전 남은 업무 결정 D21. **공용 자료 48시간 재사용·준비 후 시작·기기 채점/답 보관·풀이 중 시험 호출0·종료 묶음 제출은 확정이다. 이를 다시 선택사항으로 묻지 않는다.**

## 3. 공용 내용, 개인 진행, 미전송 답을 구분한다

2026-10-02 사용자 보완: 공용 단어 자료의 기기 캐시는 약 2일(48시간)을 기준으로 재사용한다. 마우스 진입·키보드 초점 등으로 자료를 미리 준비하고, 준비된 시험의 문항 이동은 서버 응답을 기다리지 않는다. 마지막 선택과 진행 위치는 탭 종료·새로고침 뒤에도 복원 가능한 기기 저장에 먼저 기록한다. 48시간 만료는 공용 자료에만 적용하며 미전송·미확정 답의 삭제 조건으로 쓰지 않는다. 고정된 자료판·권한 변경은 시간만으로 무시하지 않고, 진행 중인 시험에 필요한 원래 판을 만료 시 강제로 지워 풀이를 중단시키지 않는다. 이는 기존 M05 방향의 구체화이며 작업 순서는 유지한다. D20의 내부 설계와 D21의 남은 업무 결정과 구현 완료 여부는 아래 기준대로 구분한다.

| 보관 종류 | 키·내용 | 수명·경계 |
|---|---|---|
| 공용 불변 내용 | 접근 범위+자료 종류+고유 ID+자료판+표시 계약판. 단어·선택 뜻·예문·발음·보기 표시값 | 배정/응시 ID에 묶어 사본을 만들지 않음. 같은 계정의 단어 보기→시험→다른 배정 재사용. 권한 확인은 별도 |
| 개인 시험 계획·진행 | 학생+응시+최초/재시험 단계+규격판. 고정 문항판·보기/문항 순서·서버 시작/마감·진행권한 세대 | 다른 학생/기기에 공유하지 않음. 늦은 응답이 화면을 이전 문항으로 돌리지 않음 |
| 미전송/미확정 답안 보관 | 응시+문항+단계+순서+선택 키+한 번 만든 요청 ID+전송 상태 | **캐시가 아닌 복구 기록.** 서버 접수 또는 명시적 최종 거절이 확인되기 전 일반 캐시 정리로 삭제 금지 |
| 준비·접수·종료 확인 자료 | 서버의 준비→응시 연결, 요청 ID/내용 확인값/처리 결과, 종료 결과판 | 중복 시작/채점 방지 수명 보존. M04/M06 계약과 연결 |
| 음원 | 실제 선택 음원 ID/판·기존 파일 참조 | 음원 본체를 학생 답/배정/로그에 복제하지 않음. 기존 권한·전송 정책 유지 |

지원 브라우저에서 새로고침·탭 종료 후 복구 가능한 저장을 사용한다. IndexedDB 등 저장 기술·용량 상한·전송 묶음 크기는 개발자가 실제 지원 환경을 검사해 정한다. 메모리만으로 미전송 답 보존을 보장하지 않는다. 저장 거절·공간 부족·사용자의 사이트 자료 삭제로 복구 불가능할 수 있는 한계를 검사/안내에 명시한다. 기기에 저장할 답에는 최소 선택 키만 쓰고 인증 비밀·학생 이름·원문 전문을 복사하지 않는다.

로그아웃/다른 학생 전환은 화면·메모리·전송 권한을 즉시 해제한다. 미전송 기록은 해당 학생의 재인증 전까지 표시/전송 불가 상태로 격리하고, 재인증 후 서버와 대조한다. 단순 계정 전환·만료·캐시 지우기를 답 삭제 조건으로 삼지 않는다. **자동 제출 재개는 풀이 종료가 기기에 기록된 응시이고, 같은 학생의 현재 권한을 확인한 뒤에만 허용한다.** 진행 중 응시는 복원만 하고 중간 전송하지 않는다. 실제 폐기/장기 미복구 처리 기준은 D21에서 정하고, 다른 계정에 자료가 남아 보이는 방식으로 보존하지 않는다.

이미 시작한 응시는 고정된 원래 판을 읽는다. 최신 사전판으로 덮거나 새 시험을 만들어 시간을 초기화하지 않는다. 원래 판 누락은 복구 오류이며 자동으로 최신 내용으로 바꾸지 않는다. 전역 Cache Components 재도입이나 로그인 세션 기간 변경은 이 작업의 목적이 아니다.

## 4. 자료 준비와 읽기 전용 미리 받기

1. 권한 있는 배정에서 필요한 ID/판 목록을 받아 기기의 같은 판과 대조한다. 단어 보기에서 단어·뜻을 받았어도 시험 보기/문항이 없으면 그 누락분만 받는다. ‘재요청0’은 이미 가진 동일 내용에 대한 기준이다.
2. 마우스 진입·키보드 초점·모바일에서 사용 가능한 진입 동작으로 미리 읽는다. 취소/중복 합치기/동시 요청 상한을 두어 목록 전체를 무제한 미리 받지 않는다. 경로 미리 읽기만 켜고 단어별 재사용까지 구현됐다고 하지 않는다.
3. 미리 받기는 응시 생성·시작 POST·타이머·점수·포인트 변경을 하지 않는다. 서버 준비 영수증이 쓰기를 필요로 한다면 실제 시작 동작에서만 만들고 사전 조회와 분리한다.
4. 전체 필수 문항·보기·해당 출제 방향의 필수 음원이 사용 가능한지 확인한 뒤 시작을 요청한다. 필수 음원과 선택 재생 음원의 구분은 현행 출제 계약을 따르고, 실패 시 임의로 무음 통과하지 않는다.
5. 시작 요청은 준비 ID/요청 키에 대해 같은 응시·시작/마감을 반환한다. 요청 응답만 잃었다고 새 시험을 만들지 않는다. 이후 정상 풀이에서는 전체 문항/발음 묶음을 다시 받지 않는다.

## 5. 답을 남기고 화면을 진행하는 계약

| 단계 | 처리와 불변 조건 |
|---|---|
| 선택 확정 | 현행 선택 확정 구간 후 답을 잠근다. 판정을 본 뒤 같은 문항의 선택을 교체할 수 없음 |
| 기기 기록 | 선택 답과 화면 진행 예정 위치를 한 저장 거래로 기록. 성공한 뒤에만 다음 조작 허용. 실패하면 현재 선택/안내 유지 |
| 화면 진행 | 준비된 고정판으로 기기 판정·다음 문항 구성. 문항마다 읽기·쓰기·시각 확인을 요청하지 않음 |
| 종료 묶음 제출 | 풀이가 끝난 뒤 모든 선택/시간초과를 같은 제출 ID로 한 번 전송. 통신 실패 때 같은 내용으로 재확인·재시도하고 인증/충돌/기한 거절을 구별. 풀이 중 배경 전송 금지 |
| 서버 접수 | 학생 소유권·응시·문항판·단계·진행권한·기한 검증, 고정판으로 채점. 같은 요청/내용은 같은 결과, 같은 요청/다른 내용은 충돌 |
| 접수 확인 | 서버가 실제 접수한 각 답 ID/내용 확인값과 대조. HTTP200 또는 가장 큰 순서 번호만으로 중간 답까지 접수됐다고 보지 않음 |
| 정리 | 확인된 답만 미전송 목록에서 해제. 접수 거절은 사유와 최종 처리 상태를 보존하고 조용히 버리지 않음 |

현재 RPC의 ‘서버 현재 문항만 제출’ 규칙에 비동기 호출을 붙이거나, 종료 때 기존 매 문항 RPC를 브라우저에서 반복 호출하는 것으로 구현하지 않는다. **하나의 종료 명령이 답안 묶음을 받아 문항별 고정판·선택·순서·누락을 검증하고 공식 결과를 확정하는 새 계약을 만든다.** 답별 접수 확인은 묶음 내부 모든 답의 처리가 확인됐다는 뜻이며 답마다 HTTP 요청한다는 뜻이 아니다. 부분 실패는 원자 복구하거나 명시적으로 표시하고, 접수되지 않은 답을 조용히 버리지 않는다.

잠금과 고유 제약은 응시/학생/답/오답/포인트의 기존 거래 순서를 조사해 정한다. 늦은 응답·재조회·중복 클릭이 한 답을 여러 번 확정하거나 화면을 되돌리지 않도록 상태판·요청 세대를 대조한다. 접수된 답은 수정 요청으로 덮어쓰지 않는다. 미전송 수·가장 오래 대기한 시간·재시도 횟수를 기록하되 정답·학생 원문을 운영 로그에 쓰지 않는다.

## 6. 즉시 판정과 시간 공정성의 상세 결정

**D20 — 기기 채점 정보 전달은 확정.** 실제 응시에 필요한 최소 채점 자료를 해당 학생에게 전달한다. 정확한 필드·공개 시점·응시별 보관 범위는 내부 설계로 정하며 일반 공용 조회로 전체 문제은행의 정답을 공개하지 않는다. 브라우저에서 열람 가능한 자료이며 서버는 종료 때 고정판으로 재채점한다. 서비스 비밀·다른 학생 답·권한 밖 자료는 전달하지 않는다.

**D21 — 종료 묶음의 늦은 도착과 기기 인계.** 준비·시작된 시험은 연결 확인 없이 기기에서 진행한다. 문항당 5/8/10초와 전체 4분의 시작·마감·시간 정책판은 한 번 고정하고, 기기가 선택/시간초과·경과시간을 기록한다. 기존 ‘각 답의 서버 도착 시각’ 규칙을 새 규격에 그대로 적용하지 않는다. 최초 시험과 재시험은 각 풀이 종료 시 별도로 묶음 제출한다.

남은 업무 결정은 종료 뒤 전송이 늦거나 장기 단절된 답의 인정 기간, 다른 기기의 이어 풀기/원래 기기 미제출 답 처리, 장기 미복구 답의 최종 거절·보관·폐기다. 2026-10-02 사용자에게 제출 인정 기간과 다른 기기 인계를 묶어 질문했으며 아직 답하지 않은 값을 임의 확정하지 않는다. 미확정 답은 그동안 일반 캐시 정리로 삭제하지 않는다. 기기 기록 시각의 검증 한계와 서버 공식 판단 기준을 설계·검사에 기록한다.

한 기기/탭의 진행권한·중복 방지 구현은 내부 설계로 정한다. 재접속·시계 변경·새로고침으로 시간을 초기화하거나 답을 뒤집지 못하게 한다. 계정 전환 시 개인 답을 숨기고 같은 학생의 현재 권한을 확인한다. 복구된 응시가 아직 풀이 중이면 자동 중간 전송하지 않는다. D21의 필요한 업무 답변 전에는 M05 구현 대신 설계 검토를 진행하며, 독립적인 M03/M04 작업을 계속한다.

## 7. 마지막 문항·재시험·화면 상태

마지막 답을 화면에서 골랐다는 사실과 공식 완료는 다르다. 서버가 모든 필수 답의 접수 또는 규칙에 따른 최종 거절/미응답을 확인하고 결과를 확정해야 한다. 재시도 가능한 미확정 답이 있는데 미응답으로 조용히 확정하지 않는다. M03의 오답·해결과 포인트는 서버가 인정한 답/종료 결과로만 바꾸며 기기 임시 판정을 반영하지 않는다.

종료 요청은 접수 목록/누락 목록을 확인할 수 있고 같은 요청에 같은 결과를 돌려줘야 한다. 마지막 답과 종료/0초가 경합해도 한 번만 채점한다. 실패는 M11의 분류·제한 재시도·명시적 복구를 사용한다. 미접수 이유가 확정되면 실제 사유와 최종 결과로 이동하고 무한 저장 대기로 남기지 않는다. 점수0·통과·오답 해결을 미리 확정해서 보여주지 않는다.

| 상황 | 학생에게 보일 상태 |
|---|---|
| 준비 중/실패 | “시험 자료를 준비하고 있습니다.” / “자료를 준비하지 못했습니다. 다시 시도해 주세요.”, 시작 시간 차감 없음 |
| 정상 답/다음 문항 | 고정 화면·선택/정오답 표시, 불필요한 블러나 서버 대기 없음 |
| 기기 기록 실패 | “답을 기기에 보관하지 못했습니다. 선택은 그대로 두고 다시 시도해 주세요.”, 다음 진행 보류 |
| 종료 제출 지연 | 풀이 종료 뒤 “답안을 제출하고 있습니다.”, 저장된 묶음 보존·같은 제출 결과 확인 |

변경: UI/state/API/data/cache/asyncUi/domain의 진행·접수 규격/검사. 확인만: 정답 기준본·점수/포인트 규칙·학생 소유권·단어 뜻/발음·기존 학생 기록. 시간·전달 정책은 명시적인 D20/D21 변경 범위로 관리한다.

## 8. 구현 순서와 복구

1. M11 재현 근거와 현재 API/SQL·기존 타이밍을 대조한다. 새 규격의 요청/응답/상태 전이/권한/시간 계약과 D20/D21을 먼저 기록한다.
2. 공용 내용과 개인 계획을 분리하고 단어 보기·미리 받기·준비·재시험의 누락분 조회를 연결한다.
3. 개인 답과 진행 위치의 지속 저장, 종료 제출 대기열, 묶음 내부 답별 접수 확인과 서버 새 규격을 구현한다. 구형 응시는 현재 규격으로 계속 처리한다.
4. 풀이와 종료 제출 상태를 분리하고 공식 종료/재시험 관문을 연결한다. 초기 풀이 종료→공식 재시험 대상 확인→기기 재시험→재시험 종료 묶음 제출 순서를 지킨다. 미확정 답/영수증을 보호한다.
5. 가짜 학생으로 T 전부와 M11 회귀를 검사하고 M09에서 부하·비용을 측정한다. 실제 학생 답을 검사용으로 제출하지 않는다.
6. M10에서 새 시험에만 새 규격을 열고 진행 중 구형 시험을 보존한다. 실패 시 신규 시작을 중지하되 기존 미전송 답을 수신·확정할 호환 경로는 유지한다.

표시 캐시만 비우는 복구와 개인 답안을 복원하는 복구를 구별한다. 새 전송·답 보관 규격을 모르는 옛 버전으로 되돌리지 않는다. 시간/응시 재생성·미전송 답 삭제로 복구했다고 하지 않는다.
