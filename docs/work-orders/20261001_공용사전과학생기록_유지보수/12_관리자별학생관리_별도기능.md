# F02 · 관리자별 담당 학생과 자료 권한

유형: APP, 기존에 없던 별도 신규 기능. 결정 D17/D18 확정 후 구현한다. 단어장/학생 기록을 줄이는 작업과 섞지 않는다. 공용 자료와 개인 상태를 분리하는 M01~M05는 이 기능을 나중에 붙일 수 있도록 학생 소유권을 유지한다.

## 1. 목표와 요구

**학생·시험·점수는 그대로 두고, 어떤 관리자가 그 학생을 관리할 수 있는지 연결한다.** 교사가 바뀐다고 학생이나 기록을 복제하지 않는다. 관리자별 화면 필터만으로 권한 분리가 완료됐다고 판단하지 않는다.

| R번호 | 완료 조건 | 소유자/검사 |
|---|---|---|
| F02-R1 | 소속·역할·담당 연결로 허용 범위를 중앙에서 판단 | session/학생 권한 / F02-T1/T2 |
| F02-R2 | 조회·검색·집계·직접 주소·변경·내보내기·알림·예약 작업에 동일 적용 | students/assignments/history/notifications / F02-T3 |
| F02-R3 | 공동 담당·이관·회수 중 학생 기록/진행 보존 | students/assignment-queue / F02-T4/T5 |
| F02-R4 | 공용/소속 공유/개인 자료와 캐시·커서의 범위 일치 | wordbook-compositions/session / F02-T6/T7 |
| F02-R5 | 기존 단일 관리자 자료를 손실 없이 연결하고 안전하게 복구 | 운영/DB / F02-T8 |

## 2. 권장 구조와 결정 대상

권장안은 **운영 소속(학원) + 관리자 역할 + 담당 학생 연결**이다. 실제로 여러 학원을 공개 운영할지와 별개로 소속 경계를 잡아 두되, 초기에는 사용자 소속 한 곳의 공동 담당/이관부터 연다. 사전·학생·배정 데이터 전체를 관리자마다 복제하는 구조를 만들지 않는다.

| 역할 권장안 | 기본 범위 | 결정할 권한 |
|---|---|---|
| 책임자 | 자기 소속 학생/관리자 전체 | 초대·회수·담당 이관·책임자 인계 |
| 관리자 | 자기 소속 학생 전체 | 배정/기록·담당 조정 범위 |
| 담당 교사 | 연결된 학생 | 배정·성적/오답 조회·공동 담당 여부 |
| 서비스 운영자 | 승인된 서비스 범위 | 공용 자료·패치 공지. 일반 교사와 분리 |

D17에서 책임자/관리자/담당 교사의 실제 권한, 공동 담당 허용, 기존 학생을 누구에게 연결할지 확정한다. 마지막 책임자를 후임 없이 회수하지 않도록 제약한다. D18에서 교사 초안/소속 공유/서비스 공용 자료의 공개 범위와 퇴사 시 보존을 확정한다. 학교·학년은 학습 분류이며 접근 소속으로 쓰지 않는다.

## 3. 자료 계약

| 역할 자료 | 최소 내용/제약 |
|---|---|
| 소속 | 안정된 ID·이름·활성 상태 |
| 관리자 소속 | 로그인 계정·소속·역할·활성/회수·권한 변경판 |
| 학생 소속 | 기존 학생 ID·소속. 과거 점수/배정은 기존 ID 관계 유지 |
| 담당 연결 | 학생·교사·동일 소속·시작/종료·공동 담당. 유효 연결 중복 방지 |
| 자료 접근 | 공용 판의 소유/공개 범위와 이용 소속 연결. 원문을 교사별 복제하지 않음 |
| 변경 이력 | 실행자·대상·이전/이후 역할/담당·사유·일시·요청 키 |
| 초대 | 대상 소속/역할·만료·수락/취소·1회 사용. 외부 발송은 승인된 방식만 |

학생 이관은 한 소속 안의 담당 관계 변경과 다른 소속으로 학생 기록을 옮기는 일을 구별한다. 후자는 별도 정책/작업이며 이름이 같다는 이유로 합치지 않는다. 기존 `created_by`는 작성 이력으로 보존하고 소유권으로 재해석하지 않는다.

## 4. 권한 검사 세 곳과 영향 목록

1. **앱 서버:** 로그인 계정뿐 아니라 현재 소속·역할·담당·권한 변경판을 읽는다.
2. **DB 공통 검사:** 요청자/대상 학생/행의 소속과 가능한 행위를 거래 안에서 확인한다.
3. **고권한 함수/비밀키 조회:** RLS를 우회할 수 있으므로 함수와 조회 경계에 같은 검사를 넣는다. RLS만 추가해서 완료하지 않는다.

대상 목록: 학생 목록/검색/필터/총수/페이지 표식, 학생 등록·수정·비활성화, 단일/일괄/반복/오답 배정, 답안·성적·포인트·오답·문제지/내보내기, 학습 자료/단어장, 알림 개수/공지, 예약 작업, 옛 RPC/직접 URL. 허용되지 않은 학생이 일괄 입력에 하나 섞이면 부분 저장 없이 거절한다는 안을 D17에 포함한다.

실제 시작점은 [기능 소유권](../../../architecture/기능_소유권.json)의 `session`, `students`, `assignments`, `assignment-queue`, `history`, `wordbook-compositions`, `notifications`와 연결된 모든 server/RPC다. 새 공통 권한 소유자를 지도에 등록하고 각 기능이 공개 진입점으로 사용하게 한다. 기존 함수 목록·권한·직접 조회를 읽기 전용으로 먼저 전수 수집한다.

## 5. 거래·회수·자동 작업·캐시

담당 종료+새 담당 추가는 한 거래로 처리하며 학생·진행 시험을 재등록하지 않는다. 권한 회수와 배정 저장이 경합하면 거래 안의 최신 권한판으로 판단한다. 토큰에 남은 옛 역할만으로 허용하지 않는다. 기존 예약 배정은 소속의 업무로 계속 처리하고 작성 교사의 이력은 남기되, 회수된 계정이 새 작업을 만들 수 없게 한다.

모든 개인 목록/상세/커서/작업 결과 캐시는 계정+현재 소속+권한판+조건에 묶는다. 소속 전환 시 선택 학생·목록·모달·검색·스크롤의 개인 결과를 비우고 새 권한으로 읽는다. 같은 화면에 늦게 온 옛 응답을 섞지 않는다. 15초 개인 캐시를 사용해도 새 요청의 권한 검사는 생략하지 않는다.

DB의 완료된 요청 영수증도 예외가 아니다. 예전 성공 요청을 찾았다는 이유로 대상 권한 확인 전에 결과를 반환하지 않는다. **변조하지 않은 본인의 예전 요청 키**로 재시도해도 현재 소속/담당/자료 권한을 검사한 뒤 반환한다. 담당 회수·소속 변경 후 과거 저장 결과가 개인 자료 우회 조회가 되지 않게 한다.

이미 브라우저에 표시된 정보를 서버가 소급 회수할 수 있다고 약속하지 않는다. 열린 화면은 다음 권한 확인/변경 신호에서 즉시 숨기고 모든 새 요청은 차단한다. 키 변조로 이전 결과를 읽는 경로도 검사한다.

## 6. 구현·전환 순서

1. D17/D18과 권한표·모든 조회/변경 목록을 확정한다.
2. 기존 학생/자료를 기본 소속에 연결하는 대응표를 읽기 전용으로 검토한다.
3. 소속/담당/권한 제약을 추가하고 기존 기록의 키만 연결한다. 개인정보·학생 결과를 복사하지 않는다.
4. 서버·DB·고권한 함수의 중앙 권한을 함께 적용하고 옛 우회 경로를 닫는다.
5. 가짜 두 소속·여러 역할에서 전체 허용/거절·회수 경합·커서/캐시를 검사한다.
6. 검토 환경에서 동일 소속 공동 담당/이관을 먼저 확인한 뒤 운영 개방한다. 다른 소속 개방은 별도 단계다.

변경: routing/UI/state/domain/data/API/cache/asyncUi/security/styles/tests 전반. 화면에는 현재 소속·담당 범위를 명확히 표시하고, 0명은 “담당 학생이 없습니다.”, 권한 회수는 “이 학생을 관리할 권한이 없습니다.”로 안내한다. 존재를 숨기는 기존 404 정책은 유지한다. 공통 U1~U10의 입력 보존/보안 폐기를 구별한다.
