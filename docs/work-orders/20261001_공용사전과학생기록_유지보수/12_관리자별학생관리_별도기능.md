# F02 · 관리자마다 학생을 완전히 분리

유형: APP, 별도 신규 기능. D17/D18은 2026-10-03 사용자 답변으로 확정했다. **각 관리자는 본인 학생만 관리하고, 초안은 개인·직접 공유한 단어장만 동료에게 공개한다.** 공용 사전은 함께 사용한다. 전체 학생을 보는 책임자·공동 담당의 이전 권장안은 채택하지 않는다. [결정 원문](20261003_공지와관리자_확정사항.md). 현재 순서는 루트 대장을 따른다.

## 1. 목표와 요구

학생·배정·시험·점수·오답의 기존 ID와 관계를 보존하면서 관리자별 접근 범위를 분리한다. 화면 필터만으로 권한 분리가 끝났다고 판단하지 않는다. 사전·학생·기록 전체를 관리자마다 복제하지 않는다.

| R번호 | 완료 조건 | 검사 |
|---|---|---|
| F02-R1 | 학생 한 명의 유효 관리자를 한 명으로 제한하고 중앙에서 권한 판단 | F02-T1/T2 |
| F02-R2 | 조회·검색·집계·직접 주소·수정·내보내기·알림·예약 작업에 같은 분리 적용 | F02-T3 |
| F02-R3 | 관리자 비활성화/접근 회수에도 기존 배정과 학생 기록 보존 | F02-T4/T5 |
| F02-R4 | 공용 사전·개인 초안·선택 공유 단어장과 캐시/커서 범위 일치 | F02-T6/T7 |
| F02-R5 | 기존 단일 관리자 자료를 기존 키로 연결하고 분리를 유지하며 복구 | F02-T8 |

## 2. 확정 권한

| 대상 | 허용 범위 |
|---|---|
| 학생·시험·점수·오답·포인트 | 해당 학생의 관리자만 |
| 학생 일괄 배정/수정 | 모든 대상이 본인 학생일 때만. 타 관리자 학생 한 명이라도 섞이면 전부 거절 |
| 공동 담당·전역 학생 열람 | 제공하지 않음. 서비스 공지 권한도 학생 열람 권한을 부여하지 않음 |
| 공용 사전·승인 공용 자료 | 기존 검토 기준을 유지하며 함께 사용 |
| 관리자 단어장 초안 | 작성자만 |
| 공유를 선택한 단어장 | 동료에게 열람/사용을 허용. 원본 편집권·학생 기록 접근권은 부여하지 않음 |
| 단어장 공유 해제 | 새로운 동료 접근을 막되 기존 배정에 고정된 자료판과 학생 기록 보존 |
| 담당자 비활성화 | 해당 관리자 요청만 차단. 기존 공유 선택을 자동으로 해제하지 않으며 기존 배정과 학생 기록 보존 |

공개 회원가입이나 새 역할별 조직 관리 화면은 이번 요청의 필수 기능으로 추가하지 않는다. 학생의 다른 관리자 이관을 공동 담당처럼 자동 제공하지 않는다. 이관이 필요하면 대상과 기록 보존을 확인한 별도 절차로 다룬다.

## 3. 자료와 기존 연결

명시적 관리자 소유 연결에 학생 ID·관리자 ID·활성 상태·변경판을 둔다. 학생당 유효 소유자가 복수로 생기지 않게 DB 제약으로 막는다. 학생의 학교·학년은 학습 분류이며 접근 권한으로 사용하지 않는다.

기존 created_by는 작성 이력으로 보존한다. 기존 단일 관리자 자료의 실제 계정/작성 관계를 읽기 전용으로 대조한 대응표를 만든 뒤 명시적 소유 연결을 추가한다. 연결이 모호하거나 없는 학생을 모든 관리자에게 공개하는 기본값을 두지 않는다. 학생/답안/배정 ID를 다시 발급하지 않는다.

단어장은 소유자·개인/공유 상태·공유 변경판을 따로 둔다. 공유는 원문을 관리자별로 복사하는 방식이 아니라 고정 자료판의 이용 권한이다. 공유 단어장을 사용한 배정과 개인 학생 결과가 다른 관리자에게 노출되지 않게 한다.

관리자 회수/비활성화는 새 관리자 요청을 차단한다. 기존 학생의 시험·완료 기록·확정 배정과 이미 승인된 예약 작업은 유지한다. 자동 작업은 등록 당시의 학생 소유 관계와 확정 배정 범위를 검사하여 처리하며 전역 관리자 권한으로 다른 학생을 섞지 않는다.

## 4. 권한 적용과 영향 경로

1. 앱 서버에서 현재 로그인 계정·활성 상태·대상 소유 연결·권한 변경판을 확인한다.
2. DB 공통 검사에서 요청자와 대상 학생/자료의 실제 관계를 같은 거래 안에서 확인한다.
3. RLS를 우회하는 고권한 함수와 비밀키 조회에도 같은 검사를 적용한다. RLS만 붙이고 완료하지 않는다.

학생 목록/검색/필터/총수/커서, 등록·수정·차단, 단일/일괄/반복/오답 배정, 답안·점수·포인트·오답·문제지/내보내기, 학습 자료, 알림, 예약 작업, 옛 RPC와 직접 URL을 전부 조사한다. [기능 소유권](../../../architecture/기능_소유권.json)의 session/students/assignments/assignment-queue/history/wordbook-compositions/notifications에서 실제 서버/DB 소비자까지 연결한다.

소유 관계/권한 회수와 저장이 겹치면 거래 안의 최신 상태로 판단한다. 완료된 옛 요청 키를 그대로 재시도하더라도 현재 권한 검사 전에 개인 결과를 반환하지 않는다. 정상 과거 영수증을 우회 조회 수단으로 쓰지 못하게 한다.

## 5. 캐시·화면과 안내

개인 목록/상세/검색/커서/작업 결과는 계정+권한 변경판+조건에 묶는다. 계정 전환·권한 회수 뒤 이전 학생 선택/목록/모달/늦은 응답을 폐기한다.15초 개인 캐시도 새 요청의 권한 확인을 생략하지 않는다.

화면에서 정상0명은 “등록한 학생이 없습니다.”, 본인 초안0개는 “만든 단어장이 없습니다.”로 구분한다. 조회 실패는 해당 영역의 재시도 안내로 표시한다. 다른 관리자의 대상을 직접 요청할 때는 기존 존재 숨김404 정책을 유지한다. 권한이 없어졌는데 이전 학생 목록을 계속 표시하지 않는다.

이미 내려받은 정보를 소급 회수할 수 있다고 약속하지 않는다. 다음 확인에서 개인 화면을 숨기고 새 요청은 차단한다. 공유 자료 변경은 이미 배정된 학생 시험의 고정 뜻/문항/음원을 바꾸지 않는다.

서버/DB/고권한 함수와 UI를 같은 변경으로 연결하고, 가짜 두 관리자와 학생으로 검증한 뒤 운영에 반영한다. 분리 운영이 시작되면 전역 관리자 권한을 가진 옛 앱으로 되돌리지 않는다. 분리를 유지하는 호환 버전으로 복구한다. 다중 관리자 수용 인원은 M09의 공유 총량/동시 처리 근거와 별개로 권한 검증을 마친 뒤 보고한다.
