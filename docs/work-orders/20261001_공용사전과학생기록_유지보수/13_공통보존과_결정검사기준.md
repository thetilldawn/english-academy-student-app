‘미확정’은 이번 문서의 질문 목록이다. 사용자에게 이미 이 선택을 물었거나 답변받았다는 뜻이 아니다. 실제 착수 때 현재 합의와 대조해 답이 있으면 그대로 기록한다. 아직 답이 없으면 해당 기능 전체 구현 전에 묶어 확인한다. 독립적으로 결정된 다른 지시서의 설계 검토까지 멈추지 않는다.

내부 표/함수 이름·고유 제약·잠금 방식·배치 수·CSS 부품 선택은 업무/권한/기록 보존을 바꾸지 않는 범위에서 개발자가 결정한다. 선택 근거와 실제 검사 결과를 남기고 불필요한 승인 항목으로 늘리지 않는다.

## 2. 자료별 보존 검사

| 자료 | 이전 전/후 비교할 최소 항목 |
|---|---|
| 원자료/사전 | 기존 ID, 경로/파일 판, 원출현, 선택 필드 확인값, 뜻/품사/정의/예문/발음/음원 참조 |
| 단어장/문항 | 범위/제외/순서, 선택 판, 문항 방향, 보기 항목/순서, 정답 관계, 출처 |
| 학생/배정 | 기존 ID, 학생 관계, 상태/날짜/마감/반복·후속 배정 관계 |
| 응시/답안 | 기존 ID/FK, 단계, 선택 위치, 정오답/미응답/시간초과, 서버 접수 순서/일시, 새 규격판·미확정 답·접수 확인 |
| 결과 | 최초/재시험 대상 수·정답/오답 수·점수·통과·확정 시각 |
| 오답/해결 | 기존 사건, 시험한 뜻 선택, 출처/단계/일시, 현재 구간/해결 근거 |
| 포인트/예약 | 거래 ID·사유·금액/수량·원인 응시, 예약/대기 대상·유효 상태 |
| 인증/권한 | 유효 세션, 실패 제한, 원래 접근 범위, 새 권한 체계의 허용/거절 |

비교는 실제값→계약 필드별 비교→안정된 직렬화 확인값 순으로 한다. 같은 null 두 개를 보고 보존됐다고 하지 않는다. 기준 원문에 값이 있으면 필수 전달 값으로 검사한다. 시각/원자료값을 추정해서 채워 일치한 것처럼 만들지 않는다.

실제 학생 원문·답안·성적을 앱 Git에 넣지 않는다. 검사용 파일은 가짜/익명 집계다. 필요한 운영 복구 사본은 별도 접근 제한 자료 구역에 보관하며 보고에는 수·바이트·확인값만 남긴다.

## 3. 모든 화면에 적용할 상태 계약

각 기능 문서의 ‘공통 U1~U10’은 아래 발생 조건·문구·복구·부품을 함께 적용한다는 뜻이다. 해당 기능의 T번호에서 실제 표현을 검사한다. 비화면 운영 도구는 화면 없음의 이유를 적고, 호출받는 기존 기능의 오류/복구를 검사한다.

| U번호·상태 | 발생 조건 | 부품/표시·실제 문구 | 보존·복구 |
|---|---|---|---|
| U1 초기 대기 | 현재 요청 진행·첫 자료 없음 | 기존 고정 화면 틀과 영역 skeleton, “자료를 불러오고 있습니다.” | 제목/메뉴 유지, 인증 전 개인 자료는 보이지 않음 |
| U2 갱신 | 같은 계정/조건의 새 요청 | 기존 목록+갱신 상태, “새 내용을 확인하고 있습니다.” | 안전한 이전 자료만 유지, 최신 요청 세대만 반영 |
| U3 미선택 | 필수 종류/자료/학생 미선택 | 공용 FieldHelp, “먼저 자료를 골라 주세요.” 등 기능별 문구 | 입력 유지, 선택 사항은 오류 처리 안 함 |
| U4 정상0건 | 현재 조건 성공 응답0건 | 공용 EmptyState, “이 조건에 맞는 내역이 없습니다.” | 조건 변경/추가 행동, 미조회·실패와 구별 |
| U5 입력 오류 | 필수 누락/범위·판 불일치 | FieldError, “범위의 시작과 끝을 확인해 주세요.” 등 구체 문구 | 해당 입력 유지·설명 연결·첫 오류 포커스 |
| U6 조회 실패 | 현재 요청의 서버/통신/형식 오류 | 기존 PanelLoadFailure/오류 영역, “불러오지 못했습니다. 다시 시도해 주세요.” | 같은 조건 재시도, 실패와 새0건 동시 표시 금지 |
| U7 저장 실패/불명 | 실패 확정 또는 응답만 유실 | 폼/시험의 오류 영역, 확정 “저장하지 못했습니다.” / 불명 “저장 결과를 확인하고 있습니다.” | 초안 유지, 같은 요청 키 조회 후 재시도, 무조건 새 요청 생성 금지 |
| U8 인증/권한 | 세션 만료·회수·다른 계정 | 기존 인증/권한 경계, “다시 로그인해 주세요.” / “이 작업을 할 권한이 없습니다.” | 개인 DOM·표시 캐시·커서/전송 권한 해제, 미전송 답은 M05의 격리/재인증 복구로 보호 |
| U9 없는 대상 | 실제 특정 대상 없음 또는 기존 숨김 정책 | 가까운 not-found, “페이지를 찾을 수 없습니다.”+목록 버튼 | 유효한 목록으로 이동; 통신 오류를404로 바꾸지 않음 |
| U10 예외 | 분류되지 않은 서버/화면 예외 | 좁은 error 경계, “처리 중 문제가 생겼습니다. 다시 시도해 주세요.”+안전한 식별번호 | 입력 가능한 범위 보존, 오류번호로 서버 기록 연결 |

실제 부품 파일은 기능 지도에서 현재 공개 진입점을 찾아 연결한다. 공용 부품이 없다는 이유로 이름만 같은 새 UI 체계를 복제하지 않는다. SQL·스택·토큰·학생 정보·정답은 오류 문구에 나오지 않아야 한다. 모달 닫기/뒤로가기/직접 주소/새로고침/포커스 복귀·390px·키보드·큰 글자를 필요한 UI 검사에 넣는다.

## 4. 구현 기록과 검사 명령

정식 작업 번호가 등록되면 `docs/work-orders/<번호>.md`에서 이 상세 지시서를 연결하고 `architecture/work-records/records/<번호>.json`을 작성한다. 문서 M/F번호와 정식 번호의 대응표를 그 기록에 둔다. 검증 결과는 `docs/verification/<번호>_검증결과.md`에 남긴다. 이 작성 단계에서는 미실행 검사를 통과한 JSON으로 등록하지 않는다.

필수 기록: 사용자/내부 R번호, 담당 owner·실제 흐름/경로, D번호와 출처, T번호별 입력·기대 결과·실행 근거, 변경/확인만/해당없음 영향표, 권한/정답노출/자료노출/캐시, 화면 상태와 실제 문구, 단계별 복구.

아래 명령은 앱 루트에서 설치된 정상 Node24.13이상/25미만과 프로젝트 npm으로 실행한다. 실제 작업 번호를 넣고 관련 기능/검사 경로는 개별 문서에서 고른다. 아래를 이번 문서 작성에서 실행·통과했다는 뜻은 아니다.

```powershell
npm run map:feature -- wordbook-compositions
npm run map:flow -- student-quiz-attempt
npm run verify:work-records -- --phase format
npm run verify:work-records -- --phase design --work <정식작업번호>
npm run test -- <관련검사파일>
npm run lint
npm run typecheck
npm run verify:architecture:static
npm run build
npm run verify:work-records -- --phase complete --work <정식작업번호>
```

명령의 `<...>`는 실행 전에 실제 값으로 바꾼다. 완료 관문은 최종 변경의 검사 근거·해시를 기록한 후 실행한다. 저장된 과거 검사 결과를 최신 변경의 통과로 재사용하지 않는다. 완성 여부는 테스트 개수보다 사용자 동작·보존·권한·복구의 실증으로 판단한다.

문자열 존재만 확인하는 SQL 검사는 의미 검증을 대신하지 않는다. PGlite로 과거 자료→새 SQL을 검사하고, 실제 PostgreSQL 독립 연결로 잠금/동시성/권한을 검사한다. 브라우저 가짜 서버는 UI/요청 계약, Preview 인증은 실제 연동, 운영 읽기는 기존 보존을 각각 확인한다.

## 7. 이번 작성에서 정밀하게 보완한 부분

- 최신 관리자 상세 UI는 **최초 오답·미응답 문항의 최초/재시험 선택**을 표시한다. 서버는 더 넓은 질문 자료를 읽더라도 화면이 맞힌 문항의 모든 선택을 보여주는 것은 아니다. M04의 보존 정책 판단은 이 차이를 기준으로 한다.
- `questions=[]`를 요약만 있는 시험에 보내면 기존 상세가 ‘모두 정답’으로 표현할 수 있다. 상세 제공 상태를 계약으로 구분해야 한다.
- 기존 범위에 이미 v2 소형 참조와 구형 사본 호환이 있다. 새 체계를 또 만들지 않고 범위·공용 문항·배정으로 확장한다.
- 오답4회 집계는 목록 필터만 고치는 문제가 아니다. 같은 응시 증가 제한·상태 갱신·큐·개인 오답 배정의 후속 SQL까지 확인한다.
- 선택한 과거 판의 태그와 최신 설명 metadata를 구별한다. 이름/종류 수정으로 내용판/학생 배정을 재생성하지 않는다.
- 초판은 진단의 종료 실패를 M05에 연결했다. 2차에서는 이후 추가된8절의 첫 답 복구 재현과9절의 사용자 방향을 반영해 M11 수리와 M05 새 규격을 분리했다. 복구 오류는 확인됐고 최초 SQL/잠금 지연 원인은 미확정이다.
- 공용 내용 캐시·개인 진행·미전송 답 보관은 서로 다르다. 메모리 한정/계정 전환 때 모든 자료 폐기라는 초판 제약을 제거하고 답의 격리·재접수·공식 종료 보호를 추가했다.
- 즉시 정답 표시와 채점 자료 전면 비공개를 동시에 약속하지 않는다. D20의 제한된 전달, D21의 시간/단절 규칙을 상세 설계로 남기며 사용자 확정 목표 D19는 다시 묻지 않는다.
