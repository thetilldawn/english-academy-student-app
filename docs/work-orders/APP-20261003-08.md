# 시험 제출 확인 응답의 중복 저장 축소

승인된 M02/M04/M05의 중복 저장 축소·학생 기록 보존 요구를 M09 실측에서 보완한다. [현재 계측](../verification/OPS-20261003-02_무료운영_중간결과.md)과 OPS-20261003-02 D7에 따른 첫 제품 보완이다. 회차 접수의 accepted 배열만 줄인다. 다른 저장 개선과 운영 반영은 별도다. 현재 상태와 우선순위는 루트 대장을 따른다.

## 요구와 검사

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 기존 응답 | 최초 응답·즉시/늦은 재접수·재시험 뒤 최초 재접수의 전체 값/JSONB text 확인값 불변 | T1,T2 |
| R2 작은 신규 저장 | 개별 접수·불변 단계 계획으로 accepted를 복원하고 실제 크기가 작은 경우만 축약 | T2,T3 |
| R3 자료 보존 | 기존 회차/개별 접수와 학생 답·결과·오답·포인트·시각·계획/기기 연결 불변 | T1,T4 |
| R4 권한과 실패 | 기존 인증/잠금/충돌 유지, 훼손 참조 거절, 마지막 저장 실패 전부취소 | T4,T5 |
| R5 호환 검증 | 실제 API 응답 검사와 기기의 접수 확인, 의미 있는 회귀·격리 검토·독립 검토 | T2,T6 |

## 결정

- D1 사용자: 단어 본문과 중복 저장을 줄이고 배정·완료·점수·최초/재시험·오답·기기 미접수 답은 보존한다. 사용자의 유지보수 완료·계속 진행 승인 범위다.
- D2 사용자: 시험 중 DB 호출0·종료 제출·기한 안 기록한 답의 늦은 제출·원기기 복원·미접수 답 자동 삭제 금지와 공용48시간/미사용준비24시간은 그대로다.
- D3 내부: private.local_quiz_phase_receipts.result의 신규 저장만 바꾼다. 기존 행을 UPDATE/DELETE하지 않으며 표·색인·시간·키·FK·RLS·불변 트리거를 유지한다. 저장 표현만 바꾸므로 보관 기한을 새로 만들지 않는다.
- D4 내부: 저장판 local-quiz-receipt-ref-v1에 원래 response에서 accepted만 뺀 값, acceptedCount, 원응답 JSONB text SHA-256을 둔다. nested result·retryTargets·헤더는 당시 값을 그대로 저장하며 현재 결과 조회로 재계산하지 않는다. 외부 응답에는 새 필드를 넣지 않는다.
- D5 내부: 단계 계획 배열 순서와 개별 접수의 문항ID/answerHash/server_sequence를 조합한다. 계획·응시·학생·문항/내용판·단계·제출ID·개수·순서·해시를 확인한다. 빠진 접수를 조용히 제외하거나 알 수 없는 저장판을 구형으로 처리하지 않는다. 최대500개 계획의 문항·접수 기본키만 조회하고 전체 접수표를 세지 않는다. 계획 밖에서 위조된 별도 행을 찾는 전역 무결성 감사는 이 응답 복원의 범위가 아니다.
- D6 내부: 새 내부 함수는 SECURITY INVOKER·빈 search_path·앱 역할 실행권한0이다. 기존 public 제출 함수의 인증/기기 검사와 잠금/충돌 검사 뒤에만 복원한다. 신규 접수는 저장 직후 복원하여 원응답 확인값까지 일치할 때만 같은 거래로 확정한다.
- D7 내부: 압축 결과가 pg_column_size 기준 원형보다 작을 때만 새 표현을 저장한다. 작은 문항 수에서 오히려 늘면 원형을 유지한다. 원형/축약형 모두 같은 외부 응답을 반환한다. 이를 실제 물리 절감이나 지원 인원 증가로 미리 환산하지 않는다.
- D8 내부: 적용된 migration은 고치지 않고 후속1개를 추가한다. public 함수는 변경 지점 두 곳을 정확히 확인한 CREATE OR REPLACE로 OID/소유자/ACL/설정을 보존한다. 복구 시 신규 쓰기를 원형으로 바꿔도 두 저장판의 수신/복원은 유지한다. 축약형을 모르는 옛 함수로 되돌리지 않는다.
- D9 내부: 먼저 PGlite·가짜 자료로 검사한다. Preview는 기존 승인 범위의 정확한 migration/집계 보존과 작은 두 연결 검사로 확인하며, M09에서 중단한 대량 부하는 추가하지 않는다. 운영 DB/실제 학생/배포/물리 회수는 이 작업에 포함하지 않는다.

## 영향과 기존 소비자

public.submit_local_quiz_phase_v1의 신규 INSERT·기존 응답 반환 두 곳을 바꾼다. begin_local_quiz_retry_v1의 초기 접수 존재 확인은 그대로다. 앱의 localReceiptSchema와 receiptConfirmsBatch는 기존 규격으로 결과를 검증한다. 회차 received_at·개별 accepted_at은 보존하며 새 외부 acceptedAt을 추가하지 않는다.

| 면 | 처리 |
|---|---|
| 경로/UI/스타일/기기 상태 | 변경 없음. 성공·충돌·저장 실패의 기존 화면과 미확인 답 보관 유지 |
| 순수 계산/API/server | 확인만. 최초/재접수 JSON은 기존 계약과 완전히 같음 |
| DB/권한 | 신규 압축·복원 내부 함수와 public 제출의 저장/반환 연결 |
| 캐시/점진 표시 | 변경 없음. 개인 접수 확인과 공용 캐시 수명 분리 유지 |
| 검사 | 새 SQL 통합검사·기존 종료 제출/오답/결과/포인트/보관 회귀 |

축약 참조가 훼손되면 정상 접수로 표시하지 않는다. 기존 안전한 저장 실패 안내와 다시 확인 동작을 사용하며 내부 SQL 원문을 표시하지 않는다. 기기는 답별 확인값 대조가 완료될 때까지 답을 보관한다. 인증 실패/다른 기기는 기존 거절을 유지한다. 정상 빈 접수 배열로 바꿔 응답하지 않는다.

## 검사와 실행 경계

T1: migration 전 실제 가짜 시험의 원형 접수 생성→적용→행/응답/권한 보존. T2: 신규 최초/재시험·이후 다른 시험 뒤 옛 재전송, API 파싱 결과 완전 동일·receiptConfirmsBatch true. T3: 1/4/50/500문항 원형/축약 크기와 작은 행 fallback, 정상·시간초과·미응답 순서/시각. T4: 잘못된 저장판/해시/참조/개수/순서/기기·같은 요청/다른 답 충돌·최종 저장 실패 시 모든 학생 기록 원자성. T5: 실제 두 연결의 같은 요청/다른 요청·직접 앱 접근 금지·불변 보호. T6: 적절한 전체 회귀/타입/lint/지도/빌드·Preview 기존행 보존/가짜 종료·독립 검토·완료 관문.

자료 저장 표현만 바꾸므로 기존 UI를 새 디자인으로 바꾸는 화면 검사는 해당 없음이다. 실제 응답 파싱과 기기 접수확인 계약을 코드 검사로 확인한다. 외부 통신 속도/인원은 이 결과로 주장하지 않는다. APP08 이후 준비·단계 계획/배정 참조/개별 접수/포인트의 추가 중복은 M09 보완 명세에서 별도로 판단한다.
