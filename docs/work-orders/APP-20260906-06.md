# 수량·단위 입력 분리와 재사용 검사

- [기록](../../architecture/work-records/records/APP-20260906-06.json), [개발 기준](../개발_지시서와_검증_기록.md), 기존 실행계획1-E.
- R1: 수량 UI와 하위 단위 입력에 전체 제어기 없이 값/콜백만 전달. 요약·남은 범위는 순수 표시 변환. 실제 일반 배정 연결부/기존 범위 조립 경로에 모두 적용. T1/T2/T3.
- R2: 직접 입력 활성화→값 변경 순서, 전체 전환의 숫자 보존, 여러 학생의 첫 학생 수치를 공통으로 표시하지 않음, 날짜 없는 분할·역순 남은 범위·오류 위치 유지. T1/T2/T3.
- R3: 전체 UI 역할 분류/이유·재사용 부품의 import/타입 의존 검사와 현재 실행 근거. 후속 분리/연결부 예외를 구분. T2/T4/T5.
- D1 사용자: 기존 구조·캐시 개선부터, 마지막 단어 보기 가리기 뒤 안전하면 배포. 이 단계는 로컬만.
- D2 내부: 조립부는 현재 제어기를 알아도 되지만 실제 수량/단위 표시 UI는 모른다. 작은 값/콜백 연결을 조립부에서 공유하고 기존 계산·제한/입력 수명은 유지한다.
- D3 내부: 재사용이 아직 어려운 나머지 파일은 이유 있는 후속 대상으로 분류한다. 이름만 바꾼 전체 상태를 공통 UI로 인정하지 않는다. 새 파일 누락·별칭/재수출 경로 우회를 검사한다.
- 생성/배정은 기존 입력 연결만 보완. 조회/검색/응시/수정/삭제/기록·API·DB·권한·캐시·스트리밍·CSS·의존성 변경 없음. 사용자 미결정0.
- 초기/갱신/정상0/미선택/실패는 기존 상태 소유자를 유지. 필드 오류는 입력 옆, 저장 실패 입력 보존, 인증은 개인 화면 숨김, 404/예상 밖 오류는 기존 경계. 시간 고정 로딩이나 새 자동조회 없음.
- T1: 수량·남은 범위 요약 모든 모드/단일·다수/null/역순·숫자 보존. T2: 독립 UI·콜백 순서·오류/초점/역할 의존 검사. T3: 실제 단일·일괄/범위 연결과 기존 계산/제어기/요청 회귀.
- T4: 전체·타입/lint/구조/요청 캐시/새 빌드/현재 해시. T5: 독립 리뷰. 새 배치가 없는 구조 분리의 실제 연결부 렌더는 화면 전폭/운영 저장 확인과 구분한다.
- 복구는 이번 범위만 역패치. 이전 기록 재서명 금지. 실제 DB·학생·자료·새 의존성·업로드·배포 변경 없음.

## 역할 검사 채택 근거

- 독립 읽기 조사47개 이후 신규 수량 UI를 포함해48개: 연결부9/순수21/상호작용6/후속12. 우선 분리 대상의 실제 입력은 좁혔고 수정·학생 행 등 후속12개는 완료로 보지 않는다.
- 모든 타입/재수출/동적 import를 허용 목록과 대조한다. 재사용 UI의 실제 타입 구조를 확인해 전체 제어기/초안의 별칭·인덱스·Pick·ReturnType·펼치기 우회를 잡는다. 새 부품 미등록도 실패한다.
- 후속12개의 의존 확대를 놓치지 않도록 당시 소스 지문(LF 정규화)을 고정한다. 다음 변경 시 그 작업에서 의존/상태 검토 후 지문을 갱신한다. 자동갱신 명령은 만들지 않는다. 이는 설계 타당성/보안 완전성 증명이 아니다.
- 독립 리뷰에서 좁은 수신 타입에 전체 객체를 개별 속성으로 전달하는 우회를 발견해, 모든 조립 호출부의 재사용 대상 속성/펼치기 원본 타입도 검사한다. 명시 any/unknown, 배열·튜플·인덱스의 타입 지우기를 검증한다. 라이브러리 추론 콜백 자리표시자는 앱 입력 선언과 구분한다. 실제 앱 전달 회귀가 아니라 검사기 누락을 보완한 것이다.
