# 임시 자료와 운영 로그 정리

APP-20261002-04 / M06. 기준 4611b9d1b00c2980542454b5e9b650588125aadf. 기존 상세 M06-R1~R4/T1~T8을 아래 앱 기록 R1~R4/T1~T8에 일대일 연결한다. 사용자 2026-10-02 “나머진 오케”, “24시간으로 일단 하자”, “계속 진행해 마저”로 D12/D13을 확정했다. 상태·순서는 루트 대장만 따른다.

## 승인된 기간과 보호

- 예약 실행 succeeded 상세는 종료 후7일, failed 상세는 종료 후30일. 실행 중/미확인 상태, 타 서비스, 조사 보존 표시와 현재 유지보수 상태/재시도 제어는 제외한다. succeeded는 SQL 실행 종료이며 개별 학생 처리 성공을 보장한다는 뜻은 아니다.
- 세션은 실제 사용 불가 시점 이후7일. expires_at, last_seen_at+60일, revoked_at의 가장 이른 시각으로 계산하고 행 잠금 후 갱신 여부를 다시 대조한다. 활성·진행 중 세션과 관리자 감사 기록은 제외한다.
- 로그인 실패 후24시간. 성공 행은 이번 정리 대상이 아니며 최근15분 제한은 그대로다.
- 미시작 준비는 만료가 확정된 후24시간. 실제 정규/자율연습 응시가 하나라도 있으면 미시작으로 분류하지 않는다. ID·학생·요청 키/해시·만료시각의 작은 확인 기록을 남겨 같은 요청으로 새 응시가 생기지 않게 한다.
- 시작된 구형 중복 본문은 종료 및 공용 내용판 복원 일치 검증을 마친 뒤24시간. 기존 새 소형 참조는 보존하고, 공용 내용판으로 복원할 수 없는 구형 자료는 M08 이전 검토까지 제외한다.
- 배정·실제 응시·문항·답·결과·오답·포인트·M05 진행/회차/접수 확인·기기의 미제출 답과 공용 단어 내용은 삭제하지 않는다. 음원 내용 검수는 사용자 지시로 추가하지 않는다.

## 설계와 실제 연결

운영 담당자 전용 private SQL 함수로 읽기 미리보기→조건을 고정한 제한량 실행→다음 위치 재개를 제공한다. 학생/관리자 화면과 공개 API는 추가하지 않는다. cron 작업 ID뿐 아니라 작업 이름·소유자·DB·전체 SQL을 허용 목록에 고정하고 현재 작업 및 개별 실행 행과 모두 대조한다. 등록되지 않았거나 명령이 바뀐 작업은 자동 제외한다. 정책·보존 표시·허용 목록 변경도 실행과 같은 거래 잠금을 사용한다.

미리보기는 고정 UTC 상한·정책/허용 목록 확인값·분류·한 번에 처리할 수·시각·본문 바이트·다음 위치를 표시한다. 제한량 표본을 전체 건수로 표시하지 않는다. 실행은 최대1,000행, 기본250행과 짧은 처리 예산을 사용한다. 잠긴 행은 건너뛰고 다음 전체 순회에서 다시 확인한다. 반복된 같은 배치 요청은 최근 접수 결과를 반환하고 학생 자료는 건드리지 않는다. 최신 작업 제어는 분류별 한 행에만 보관한다.

시험 준비는 학생 행→준비 행 순서로 잠근다. 미시작 여부는 begun_id뿐 아니라 정규 응시 ID, 자율연습 student/request_key/hash, M05 실행 관계를 함께 대조한다. 기존 실제 응시 응답을 먼저 반환한 뒤 작은 만료 확인표를 조회하는 보호를 regular/practice/local 시작과 practice 직접 시작·요청 조회에 연결한다. 기존 불변 참조 트리거를 약화하지 않는다.

R1 예약 실행 상세 기간 정리→T1/T2. R2 준비 본문과 시작/접수 보호→T3/T4/T8. R3 활성 세션·실패 제한·학생 기록 보존→T5. R4 미리보기·제한량·재개·중복/권한/오류→T6/T7.

T1/T2: 성공/실패 경계, 실행 중·타 작업·명령 변경·조사 보존. T3/T4: 시작과 정리 양방향 경합, 유실된 시작 응답, 같은 준비/요청 재전송, 구형 본문 일치/불일치·24시간. T5: 활성/폐기/만료/갱신 잠금과 최근 로그인 실패, 학생 기록 전후 비교. T6/T7: 고정 상한/정책 변경/잘못된 값/권한 거절/중단 재개/배치 반복/중복 실행. T8: M05 지연 답 접수·진행/재시험·기기 복원에 필요한 행 보존.

화면은 신설하지 않는다. 관리 도구는 잘못된 설정, 권한 없음, 정리 중 충돌, 확인값 변경을 각각 오류로 반환하고 실패를 정리0건으로 숨기지 않는다. 기존 학생 만료/다시 준비 안내와 응시 복구 경로를 회귀 검사한다. 앱 권한·채점 정보 공개·캐시·음원·화면 스타일 변경은 없다.

## 적용과 검증 경계

2026-10-03 실제 Preview 권한 보완: cron.job은 Supabase 소유이며 postgres에는 SELECT만 있다. 행 SHARE 잠금을 시도한 첫 SQL은 42501로 정리를 거절했고 실제 기존 로그 삭제는 없었다. 이미 반영된 SQL은 바꾸지 않고 별도 후속 SQL로 수정한다. 정리할 상세행만 잠그고 각 DELETE 문장 시작 때 보이는 확정된 현재 작업·과거 실행·허용값·기간·보존 표시·행 확인값을 모두 다시 대조한다. READ COMMITTED만 허용하며 실제 ROW_COUNT가 1일 때만 삭제 수를 늘린다. cron 설정의 동시 변경을 막는 잠금이 아니라, 각 DELETE의 확정된 조회 시점에서 조건을 만족하는 이미 종료된 허용 실행만 정리한다. 권한 확대·실제 일정 변경은 하지 않는다. SELECT-only 권한 재현과 높은 격리수준 거절을 T2/T7에 추가한다.

새 SQL·가짜 자료 PGlite 검사→전체 관련 회귀/타입/구조/빌드→독립 검토→동일 SQL Preview 적용·실제 잠금/기존 자료 보존 순서다. Preview 실제 기존 기록은 삭제하지 않고 가짜 행으로만 실행을 확인한다. Windows 임시 PostgreSQL 실행은 금지한다. 자동 스케줄을 이번 migration에서 활성화하지 않으며, 최초 운영 정리는 별도 OPS, 물리 공간 회수는 M08이다.

원격 적용 전 정확한 파일명·해시·추가 표/함수/권한·복구 명세를 작성한다. 복구는 정리 비활성화 및 검증된 대상 로그 복구이며 학생 DB 전체를 되돌리지 않는다. 새로운 만료 확인표를 읽는 시작 경로를 그 표 없이 되돌리지 않는다.
