# APP-20261001-01 — 통과한 시험만 포인트 정산

사용자 2026-10-01 요청과 기존 포인트 정책을 연결한다. 현재 상태와 순서는 루트 대장만 따른다.

## 범위와 결정
- R1/D1: 응시가 completed이며 passed=true인 시험만 기존 단가로 정산한다. 일반 1차 정답+2/오답·미응답·시간초과−3, 재시험 정답+2/그 외0. 독립 오답·혼합 내 오답 문항은 1차 정답+2/그 외0, 재시험 정답+1/그 외0.
- R2/D3: 기존 사건을 삭제·수정하지 않는다. 미통과 사건별 반대 보정을 추가하고, 진행 중 시험이 나중 통과하면 보정된 원사건만 한 번 복원한다. 원사건/보정의 학생·응시·문항·금액·규칙이 일치해야 한다.
- R3/D2: 시험 점수·통과 기준·답안·오답·배정·학생·단어 원문을 보존한다. 규칙 없는 도입 전 시험, 내 단어장 교사 배정과 자율연습은 기존처럼 포인트 제외다. 도입 전 신규 지급은 기존 합의와 다른 추가 작업이므로 이번에 하지 않는다.
- D4: 로컬(APP)→검토 DB→운영 DB와 실제 합계 정정(OPS). 기존 앱이 같은 RPC를 읽으므로 화면/Next 코드 재배포는 필요 없다.
- 기존 완료 작업의 상태를 되돌리지 않는 새 요청이다. 관련 없는 앱 확장 검토의 로컬 변경을 보존한다.

## 원인과 설계
현재 private.record_vocab_quiz_point_events에는 통과 검사가 없다. 1차 종료→review 또는 completed/expired 때 기록한다. 지연 트리거의 NEW.passed는 재시험 wrapper의 마지막 정정 전 값일 수 있으므로 현재 응시를 잠가 다시 확인한다.
현재 Production 원사건2,696개, 합계70, 원장/합계 불일치0, 응시 없는 사건0. 학생3명 합계1,343→2,269(차이+926); 테스트 계정−1,273→55(+1,328). 진행 중 결과가 바뀔 수 있어 적용 직전에 재검산한다. 실제 학생별 식별 자료는 영어/ 운영 구역에만 저장한다.
미통과 시험 요약은 event_count=0을 반환해 기존 서비스의 요약없음을 사용한다. 보정 양수를 정답 보상으로 잘못 세지 않는다. 통과한 시험은 기존 배점 때문에 음수일 수 있다.
권한·자료 노출·페이지/라우팅/클라이언트 상태/CSS/공유 캐시는 확인만. UI 변경이 없어 신규 상태/브라우저 검사는 해당 없음이며 기존 오류와 확인 불가 표시를 보존한다.

## 순서와 검사
1. T1: 최종 DB 가짜자료로 신규 최초/재시험 통과·실패·만료·미완료, 기존 오답 단가, 도입 전/연습 제외 검사.
2. T1: 기존 사건 보존·중립화 멱등·진행 중 이후 통과 복원·충돌/응시없는사건 거절·원장=합계·서비스 요약·권한.
3. T2: 타입·lint·관련 서비스 검사·지도·R/D/T 완료 관문. SQL만 실행 변경이므로 UI 빌드는 기존 빌드 결과로 신규 성공을 주장하지 않으며 필요성이 있으면 별도 실행한다.
4. T3: 읽기 전용 독립 검토 후 같은 파일 해시로 검토→운영. 적용 직전 데이터/함수/권한 확인값과 수정전 함수·원장 백업, 실행 후 보존·금액 대조. 실학생 답 제출로 검사하지 않는다.
