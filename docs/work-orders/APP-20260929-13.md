# APP-20260929-13 — 교사 개인별 오답 일괄 배정

입력: 승인 순차계획·APP10/11/12. 사용자 미결정0. APP12 로컬 완료 뒤 시작한다. 운영 반영 승인은 유지하되 이 단계는 로컬 구현/검증이며 실제 학생 배정 쓰기를 시험 수단으로 쓰지 않는다.

## 요구·결정·검사

- R1/D1: 기존 학생 선택 바구니를 재사용해 각 학생의 누적 initial 오답을 같은 횟수/검색 조건으로 고른다. 첫10개가 아니라 조건 전체다. 학생별 총수/출제 가능 수/제외 이유/실제 문항 단어를 확인한 뒤 저장한다. 0개/부족 학생은 명시 선택 해제로만 제외하며 몰래 일부 학생만 저장하지 않는다. T1/T2/T3/T4.
- R2/D2: 단어를 다른 책으로 복제하지 않는다. 각 문항의 실제 책·단원·항목·과거 뜻·원학생의 오답 사건·사전 식별자와 승인 발음을 유지한다. 검토 보기와 충돌하는 단어는 제외한다. 원문항과 다른 새 문제에는 새 내용 해시를 쓴다. T1/T2/T5.
- R3/D3: 정규 완료/미완료/성적/기존 재시험을 유지하고 이 배정만 포인트0이다. 배정 정책은 불변이며 응시 생성에서 기본값이 이미 들어와도 no-points-v1을 강제한다. 0점 포인트 이벤트도 만들지 않는다. 정상 오답 누적·정답 해결·후속 배정 절차는 보존한다. T2/T4/T5.
- R4/D4: 관리자 인증·서버 계산·DB 재검증·전체 거래·학생 순서 잠금·요청 영수증으로 보호한다. 같은 요청은 원천 재조회 전 저장 결과 반환, 다른 내용의 같은 키는409. 원천/학생/설정/제외대상 변경 시 새 미리보기. 최대210명·전체10,000문항·학생별1~500문항. T1/T2/T3.
- R5/D5: 기존 공통 시험 조건/시간 입력과 관리자 flat 모달을 재사용한다. 문항수·방향·통과점수·재시험·시간을 선택하며 새 채점 유형은 추가하지 않는다. 즉시 공개1회이며 일정 자동 분할은 이 개인 오답 기능의 범위 밖이다. 개인 정보는 private/no-store, 정답은 관리자 서버 내부 계획만 가진다. 실제 원책과 학생의 학년 차이는 단일 배정은 허용하고, 일괄 배정은 제외 후1명이어도 포함/제외를 확인한다. 탭 전환의 접속 재확인은 입력과 저장 요청을 보존하고 실제 계정 변경만 폐기한다. 저장 결과 불명 상태의 이탈은 기존 이동 보호 장치로 막는다. T3/T4.
- R6/D6: 학생/관리자 목록에 ‘개인 오답’·‘포인트 제외’와 실제 원책을 표시한다. 대표책을 전체 시험범위로 오인시키지 않는다. 기존 단일책 수정/복사로 들어가 정책이 사라지는 경로는 화면과 최종 DB에서 명시 거절한다. 기존 취소·결과·응시 경로는 유지한다. T2/T3/T4/T5.

## 구조 결정 기록 — 채택

상황: 기존 assignments.dataset_id와 문항/단원 복합FK는 한 책 전제이고, 학생별 누적 오답은 여러 책이다. 기존 오답 큐는 이력 전체와 다르다.

대안 비교: (1) 헤더 책을nullable로 전환하면 많은 기존 목록/정규 계약이 바뀜. (2) 가상 단어장에 단어를 복제하면 원출처/사전 식별자/승인 상태가 갈라짐. (3) **실제 출처 관계를 추가하고 기존 헤더는 호환용 대표 출처로 유지**하는 안을 채택한다.

- `assignment_sources(assignment_id,dataset_id)`에 기존은 단일 원책, notebook은 실제 복수 원책. 문항·단원 FK만 이 관계로 옮기고 실제entry/dataset 및 응시question/entry FK는 보존한다. 비-notebook 복수책 금지, 대표책은 실제 출처, 헤더 정책/출처 변경·삭제도 DB에서 검사한다. 기존 학생 문항은 다시 쓰지 않고 관계 행만 보강한다.
- `source_kind=notebook`, `assignment_purpose=review`, 실제 단원is_primary=false. 기존 문항판 응시 시작이 모든 문항을 복사한다. 새 provenance는 `notebook_snapshot_v1`이며 기존 승인상태로 위장하지 않는다.
- 새 문항의 source snapshot은 검증된 원학생 오답/단어 식별정보, 별도 frozen 발음 snapshot을 보존한다. 기존 사전 정체성 읽기 함수에는 명시적인 notebook 호환 조회만 연결한다. 시험용 원출현 승인표는 수정하지 않는다.
- 원책 전체를 학생당 새로 호출하지 않고 공통 원천/계산을 재사용한다. 개인별 미리보기는 서버에서 제한된 병렬 계산, 저장은 한 DB 거래다. `assignments`가 요청/설정/생성/UI를 소유하고 `quiz-player` 공개 서버 경계는 기존 출제·발음 고정 계산만 제공한다.
- 화면은 입력 UI·controller·transport·server use-case/persistence로 구분한다. Route Handler는 인증/검증/상태코드만 담당한다. RSC가 자기 HTTP API를 재호출하거나 조회에 Server Action을 사용하지 않는다.

독립 검토2건에서 위 관계 외에 단원 FK·사전 식별자·active 오답 조회의 대표책 제한·포인트 기본값·단일책 수정 경로가 필수임을 확인했다. 소스 관계 도입은 더 작은 변화지만 해당 접점을 함께 검증해야 한다.
