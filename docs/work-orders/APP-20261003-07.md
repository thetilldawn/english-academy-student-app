# 검토 증거의 중복 공유와 원형 복구

승인된 OPS-20261003-01 D5/M08-A의 보완이다. [원 지시](20261001_공용사전과학생기록_유지보수/08_기존자료이전과_용량회수.md)와 APP02~06을 입력으로 삼는다. 운영 변경 없이 구현·가짜 검토 DB에서 확인한다. 학생 기록·공용 학습값·음원 내용을 변경하지 않는다. 현재 상태는 루트 대장만 관리한다.

## 요구와 검사

| 요구 | 완료 조건 | 검사 |
|---|---|---|
| R1 원형 보존 | 알려진 검토 증거 위치의 동일 JSON text 객체만 공유하고 원행·본문·심사 확인값, 배열 순서/중복/누락/null/추가 값 보존 | T1,T2 |
| R2 실제 소비자 | 이전과 같은 payload를 기존 조회에 반환하고 권한·400개 한도·종료된 자료 읽기 유지 | T3 |
| R3 진행 작업 | 적용 전 시험의 첫 제출·재시험·재접수 및 오답 준비 첫 저장, 현재 학습 범위 보존 | T4 |
| R4 제한 이전·복구 | 외부 사본 재읽기→명시100행, 새 답 뒤 지정 payload만 복구, 중간 실패 전부취소·응답유실·두 연결 검증 | T5,T6 |
| R5 운영 경계 | 전역 객체의 불변성·직접 앱 접근 금지, 기존 행 보존·가짜 종료, 반복 본문 감소와 공간 비용 구별 | T6,T7 |

## 결정

- D1 사용자: 승인된 공용 사전·키·태그와 중복 저장 축소 원칙을 따른다. 배정·완료·점수·오답·미접수 답을 보존한다. 사용자의 계속 진행 승인 범위다.
- D2 사용자: 운영은 읽기만 수행한다. 구현/격리 검증 뒤 M09→M10→M08-B 순서를 따르고 운영 사본·정리 범위·적용은 별도 명세로 확인한다.
- D3 내부: private.reviewed_mock_source_resources_v1의 payload만 바꾼다. source_evidence 객체, dictionary/pos/pronunciation/definition/example의 evidence 배열, review_records 항목의 evidence 배열만 대상으로 한다. 다른 이름의 evidence나 실제 뜻·발음·학습 선택값을 재귀적으로 바꾸지 않는다.
- D4 내부: JSON text의 SHA와 전체 text가 같은 객체를 전역 불변 표에 한 번 저장한다. 배열 위치와 반복은 짧은 참조로 남긴다. 다른 숫자 표기·순서·추가 값은 합치지 않는다. 해시 충돌은 전체 text 대조로 거절한다.
- D5 내부: 명시된 묶음에서 반복이 확인되고 본문/참조/명세의 예상 비용보다 감소가 큰 객체 또는 기존 전역 객체와 정확히 같은 객체만 선택한다. 준비 때 공유 해시 집합을 행별 명세에 고정하고 큰 증거 본문은 전환 거래에만 넣는다. 한 행이라도 지원되지 않거나 이득이 작으면 해당 키를 포함한 예외로 준비 거래 전체를 취소한다. 성공 응답에서 행을 임의로 제외하지 않는다. 실제 전환 때도 고정한 해시는 바꾸지 않고 그 묶음과 현재 전역 표의 순감소를 다시 검사해 손해 나는 부분 전환을 거절한다. 예상 text 비용을 실제 DB 절감량으로 표시하지 않는다.
- D6 내부: 전환은 모든 공유 해시의 정렬 순서로 INSERT ON CONFLICT 후 별도 SELECT에서 전체 text를 대조한다. 다른 자료가 같은 객체를 동시에 등록해도 같은 행을 사용하며 한 거래의 잠금 한도를 넘으면 취소한다. 복구 때 전역 객체를 삭제하지 않는다.
- D7 내부: 원행·정체성·본문·참조 확인값을 검증해 원형으로 복원한다. 공개 자원 조회의 해당 읽기만 치환하고 OID/권한/설정/한도/종료된 자료 허용을 보존한다. 원자료 등록/심사와 기존 불변 보호는 유지하며 새 내부 표시와 입력의 충돌은 거절한다.
- D8 내부: 기존 등록기와 같은 dataset_key/9129→자료→자료판→검토 자원 순서로 잠근다. 명시1~100키·중복 정규화·READ COMMITTED·거래30초/잠금1초·원행1MiB/요청16MiB/파일32MiB를 지킨다. 마지막 키만 쫓지 않고 후보를 다시 읽는다.
- D9 내부: 모든 Git 밖 접근 제한 파일에 PostgreSQL 원행 문자열을 그대로 보존·fsync·재읽기한다. 준비 응답 유실은 원문이 남아 있을 때 동일 응답으로 복원한다. 한 번 쓰기 허용은 연결/거래/키/전후 확인값에 묶고 같은 요청은 최초 응답을 돌려준다. 복구는 지정 payload만 바꾸며 새 학생 기록과 최신 자료 상태를 유지한다.

## 검사 범위

T1 SQL 전 실제 등록·범위·시험/오답 준비. T2 여러 자료판 전역 공유·서로 다른 증거/숫자 표기/배열/누락·파일/한도/환경. T3 실제 자원 조회·등록 재접수·현재 범위와 확인값/종료 자료/권한. T4 이전 시험 첫 제출·재시험·재접수와 오답 준비 첫 저장. T5 실제 두 연결·같은 객체 경합·등록/복구·늦은 후보·마지막 행 오류/취소. T6 새 답 뒤 선택 복구·비대상 표/원행 보존·불변/권한. T7 전체 회귀·타입/lint/기능 지도/빌드·검토 DB 보존/가짜 종료·독립 검토.

원형 payload를 반환하므로 네트워크 전송량 감소를 주장하지 않는다. 기존 구성 문항의 필요한 source_proof, 직접 수정 가능한 옛 자료판, 진행·재시험·미접수 관련 보호 자료는 통합 제외 명세와 고정 공간에 포함한다. 이 목록이 추가 이전 기능을 모두 구현하라는 뜻은 아니다.
