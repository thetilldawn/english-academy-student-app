# 유지보수 검토 배포와 운영 반영 준비

승인된 M10의 실행 명세다. M11·M01~M08-A와 M09 계측 보완을 합친 앱을 검토 환경에서 확인한 뒤 같은 코드와 SQL을 운영에 반영한다. 현재 단계는 명세와 선행 조건 확인이며, 이 문서 작성으로 배포 완료를 주장하지 않는다. 상태와 순서는 루트 작업 대장만 따른다.

## 요구와 결정

- R1: 검토 DB 정의·권한과 앱 빌드가 같은 대상이어야 한다. T1/T2.
- R2: 구형 진행 시험, 새 시험의 최초·재시험·오답·결과를 실제 검토 앱에서 확인한다. T3/T4.
- R3: 배포와 호환 복귀 중 기기에 남은 답을 보존한다. 새 시작만 막아도 이미 진행한 시험의 재시험·늦은 답·재접수는 받는다. T4/T5.
- R4: 검토를 통과한 정확한 코드/SQL만 환경별로 빌드하고 운영 학생 기록을 보존한다. T6/T7.
- R5: DB 적용·배포 준비 완료·인증 화면·실사용·공간 회수의 실제 상태를 구분한다. T8.
- D1 사용자: 유지보수 완료·계속 진행 승인을 따르고, 실제 학생 시험/답안을 검사에 사용하지 않는다. 미확인 기기 답은 삭제하지 않는다.
- D2 내부: 운영 기준은 `fa4357e8bff2e9eb98e10c2b520c907f667a943b`; 현재 후보는 `39584224e9d3fc49237a85024d8ad1e9b1ca2721`이다. 선행 보완으로 코드가 바뀌면 새 후보와 근거를 고정한 뒤 배포한다. 후보를 최종 반영 승인본으로 오해하지 않는다.
- D3 내부: 아래 선행 조건이 남아 있으므로 지금은 새 배포/운영 SQL을 실행하지 않는다. 사용자 미결정은 없으며 기존 요구의 누락을 좁은 APP 보완으로 연결한다.
- D4 사용자: 공지는 토스트만, 관리자별 학생 완전 분리, 개인 초안·선택 공유를 유지한다. F01/F02는 이번 후보에 구현됐다고 주장하지 않는다. 발음 보완 WORD-20261003-01도 별도다.

- 로그인된 브라우저에서 운영 `dpl_8u64EVqGctosrAZHQbQRRHSH8Whg`와 검토 `dpl_HAcG5dXR1oKEK4KrPbECCYGv8E1v`, 두 코드 `fa4357e`를 확인했다. GitHub 두 브랜치도 같은 커밋이었다. MCP 프로젝트 조회 오류와 브라우저 로그인 상태를 혼동하지 않는다.

## 배포 전에 해결할 조건

1. **새 배정 시험 시작만 중지하는 운영 제어가 없음.** M10-T8의 명시 요구다. private 운영 설정 1행과 기존 신규 응시 INSERT 검사로 좁게 보완한다. 기본값은 정상 시작이며, 중지 중 기존 시작 재전송·구형/신규 재시험·답 제출·늦은 접수를 보존한다. 자율연습은 이 M05 전환 제어 범위 밖이다. 실제 두 연결로 중지 확정/시작의 순서를 확인한다.
2. **동일 주소에서의 배포/복귀 검증이 남음.** 새 규격을 모르는 `fa4357e`로 단순 복귀하지 않는다. 새 규격을 읽고 제출받는 호환 코드·DB 조합을 지정해 기존 탭/기기 저장소를 유지한 상태에서 연습한다.
3. **인증된 검토 앱 전체 흐름이 남음.** 기존 SQL 검사와 가짜 API 브라우저 검사는 서로 다른 근거다. 실제 검토 환경의 가짜 학생/관리자와 정확한 자료 식별자를 실행 명세에 고정하고 검사한다. 이전 검사 도구의 옛 주소/출력 경로/검사용 접근키 생성 절차를 그대로 재실행하지 않는다.

## 검사와 실행 순서

T1: 현재 이력·새 객체/변경 함수/권한/RLS/예약 작업을 읽고 SQL 순서·해시를 확인한다. 검토에 이미 적용된 SQL을 반복하지 않는다.

T2: 현재 코드의 타입/lint/관련 검사/구조/기록과 실제 빌드. 서비스워커·공용 HTML·JS/CSS/글꼴의 확인값, SW의 `no-store`와 공개 경로 범위를 확인한다.

T3: 검토 관리자에서 가짜 자료 생성·종류별 입력·미분류 보존→배정→학생 학습/최초·재시험→오답 해결→결과/과거 상세를 확인한다. PC/390px, 키보드·초점·실패/빈 결과 표시를 연결한다.

T4: 구형 진행 시험의 시간/답/재시험/포인트 보존, 신규 풀이 중 시험 API0, 회차 끝 묶음 제출과 응답 유실의 동일 재접수를 확인한다. CDN 음원 호출은 시험 API와 구분한다.

T5: 같은 주소에서 중간 오프라인·새로고침·마지막 답 제출 대기→배포/호환 복귀→원기기 복구·늦은 제출. 계정 변경·다른 기기·두 탭과 미확정 답 보존, 신규 시작 중지 중 기존 접수 유지까지 확인한다.

T6: 검토 통과 코드와 추가 SQL을 운영에 순서대로 적용한다. 실행 직전 학생 기록의 개수/전체 확인값·권한·불변 제약과 되돌릴 대상을 고정하고 비교 불일치·답 유실/중복·권한 누수·잠금 오류·공간 부족이면 중단한다.

T7: 별도 운영 빌드·대표 주소 연결·인증 읽기/권한 거절·기존 결과·초기 오류/잠금/공간을 확인한다. 실제 학생 새 시험/답 제출을 검사로 쓰지 않는다.

T8: 실제 완료/미검증 경계를 기록한다. M08-B 운영 사본/중복 정리·물리 회수, M06 최초 로그 정리/정기 실행 활성화, F01/F02와 WORD 발음 연결은 독립 작업이며 이 배포의 완료 항목으로 합산하지 않는다.

화면·API 구현은 해당 APP 지시서를 따른다. 이 DEPLOY 기록은 배포·보존·복구 검증만 소유한다. 기존 서비스워커와 기기 답을 지우거나, 공개 권한을 늘리거나, 보호 설정을 꺼서 검사를 통과시키지 않는다.
