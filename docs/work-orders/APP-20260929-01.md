# 인증 갱신 장애로 인한 로그아웃 방지

R1: 시간초과 후 정상 세션 보존·재시도 복구(T1/T2/T3/T4). R2: 장애503과 실제401, 철회 실패를 구분(T1/T3/T4). R3: 공식문서·기존 정책·구조 검증(T5/T6).

D1: 현재 사용자 수정 요청. D2: 합성408을 제거하고 서버 인증 장애를 별도로 전달. D3: 학생60일·24시간갱신과 권한·개인no-store 유지; 배포/운영자료 변경은 별도.

확정 원인: 만료된 관리자 access token 갱신 중 합성408이면 설치 Auth SDK가 저장 세션을 삭제한다. 관리자 인증 조회의 null변환, 학생 DB오류의 null변환은 별개의 잘못된 로그인 판정이다. 이 코드 재현을 사용자의 모든 개별 장애 원인으로 단정하지 않는다.

경로/Server Component 확인, UI 기존부품 확인, 브라우저 상태 확인, 순수 업무계산 변경없음, 사용사례 인증 실패 경계 수정, HTTP 인증오류 변환 수정, Route/Action 실패503, 서버 DAL 구분 수정, DB/RPC권한 변경없음, 캐시/쿠키 실제거절만 폐기, 오류/404 구분, 자동검사/독립리뷰와 가짜세션 SDK 검사 수행. 실제 운영·실학생 응시는 하지 않는다.

조회장애: ‘로그인 상태를 확인하지 못했습니다. 잠시 후 다시 시도해 주세요.’ 및 기존 다시 시도. 실제401에는 개인자료 숨김과 로그인. 로그아웃 실패에는 완료라고 표시하지 않으며 다시 시도한다. 초기대기/미입력/정상빈값/입력오류/404는 기존 상태 유지. 각 조건·문구·부품·검사는 동일 번호 JSON에 연결한다.

검사: T1 인증 DAL, T2 실제 SDK와 가짜 만료세션, T3 학생 조회/갱신/철회, T4 전체 관련API 장애응답, T5 타입·lint·구조·빌드·전체회귀, T6 독립검토. 상세 결과는 검증 문서에 별도 작성한다.
