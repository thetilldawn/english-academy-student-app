# 개발 기록 검사기

- 앱 기능·사용자 API가 아닌 로컬/CI 내부 검사다. DB·인증·배포를 호출하지 않는다.
- `schema.mjs`: 기록 형식 v1, 상태 열거, 고정 변경 추적 시작점.
- `context.mjs`: 앱 내부 기록과 기존 기능 지도를 읽고 실제 소유·흐름을 연결한다.
- `validation.mjs`: 형식/설계/완료와 기록 없는 변경 검증. 명령 실행·파일 쓰기를 하지 않는다.
- `evidence.mjs`: 코드·테스트·설정의 SHA-256. 기록 파일과 실행 결과 자체는 해시에서 제외한다.
- 상위 `check-work-records.mjs`: 옵션 처리와 출력만 담당한다.
- 신규 책임은 기존 기능 지도에 등록한다. 변경 추적 시작점을 HEAD로 옮겨 누락을 숨기지 않는다.
- 완료 결과를 prebuild에서 요구하지 않는다. 호스팅 형식 검사는 Git·앱 밖 작업 대장 없이 작동해야 한다.
- 보안·사용자 동의·설계 타당성의 완전성을 자동 검사 통과로 보증하지 않는다.
- 화면 상태는 미선택/404도 빠짐없이 기록하고 발생 조건·실제 쉬운 문구·복구·부품·T 연결을 검사한다.
  error-ui는 상태/복구, ui-copy는 문구 검사 계획이다. 문자열 존재와 연결을 검사할 뿐 문구 의미의 적절함을 자동 보증하지 않는다.
- 기준: `docs/개발_지시서와_검증_기록.md`. 회귀검사: `src/app/work-records.test.mjs`.
